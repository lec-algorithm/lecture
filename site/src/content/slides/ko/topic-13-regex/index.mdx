## 찾을 것을 정확히 모를 때
::sub[주제 10의 트라이는 찾을 문자열을 정확히 알 때의 도구였습니다]

- 전화번호처럼 보이는 것
- `.edu`로 끝나는 이메일 주소
- `gcg`로 시작해 `cgg`가 되풀이되다가 `ctg`로 끝나는 유전자 조각

<br/>

모양만 압니다. 그 모양을 적는 언어가 **정규식**이고,  
그것을 돌리는 기계가 **오토마타**입니다.

## 정규식
::sub[Regular Expression]

</Slide>

<Slide>

#### 개요
::sub[찾아야 할 부분 문자열 패턴에 대한 정보가 불충분한 상태에서의 탐색]

- 대단히 복잡한 $$M$$개 문자의 패턴을
- $$N$$개 문자 텍스트에서
- **$$MN$$에 비례하는 최악 조건 성능**으로 찾아냅니다.

<br/>

이 주제가 끝날 때 이 약속을 지키는 방법에 도착합니다.

</Slide>

<Slide>

#### 패턴의 표현
::sub[패턴 하나가 문자열의 집합을 가리킵니다]

- 이 집합을 **언어**(language)라고 부릅니다.
- 언어를 적는 표기가 **정규 표현식**(regular expressions)입니다.
- 웹 검색, 편집기의 찾기, 입력 검증에서 보편적으로 쓰입니다.

</Slide>

::sub[연결 · 또는 · 클로저, 그리고 괄호]

#### 연결
::sub[Concatenation]

- `AB`
  - `{AB}`를 의미합니다.
- 문자 A와 B가 연결된 길이 2인 문자열 한 개의 집합입니다.
- 연산 기호가 따로 없습니다. 나란히 쓰면 연결입니다.

</Slide>

<Slide>

#### 또는
::sub[Or · 선택적 대안]

- `A|B`
  - `{A, B}`를 의미합니다.
- `A|E|I|O|U`
  - `{A, E, I, O, U}`를 의미합니다.

</Slide>

#### 클로저
::sub[Closure · 패턴의 일부가 임의의 횟수만큼 반복되는 것]

- `AB*`
  - A 다음에 0개 이상의 B가 이어진 문자열들로 구성된 언어
  - `{A, AB, ABB, …}`
- `A*B`
  - 0개 이상의 A가 이어진 끝에 B가 붙어 있는 문자열들로 구성된 언어
  - `{B, AB, AAB, …}`

<br/>

`*`는 **바로 앞의 한 글자에만** 붙습니다.

#### 가장 직접적인 방법
::sub[`.`과 `x*`만 있는 정규식으로 시작합니다]

- **글자가 맞으면**
  - 패턴과 텍스트 둘 다 한 칸 전진해서 나머지를 맞춥니다.
- **`x*`를 만나면**
  - x를 0개 먹고 나머지를 시도합니다.
  - 안 되면 1개, 그래도 안 되면 2개, … 하나씩 늘려 봅니다.
- **패턴을 다 쓰면** 성공입니다.

<br/>

안 되면 앞의 선택으로 돌아가 다른 것을 시도합니다. **백트래킹**입니다.

#### 절차
::sub[`01_regular_expression/regexMatch.pseudo`]

```plaintext
ALGORITHM Match(pattern, text)
    if pattern이 비었으면 then return true          // 패턴을 다 썼으면 성공
    if pattern[1] = '*' then
        return MatchStar(pattern[0], pattern[2..], text)
    if text가 남았고 (pattern[0] = '.' 또는 pattern[0] = text[0]) then
        return Match(pattern[1..], text[1..])       // 한 글자씩 맞춰 나간다
    return false

ALGORITHM MatchStar(c, pattern, text)
    if Match(pattern, text) then return true        // c를 0개 먹고 나머지 시도
    while text가 남았고 (text[0] = c 또는 c = '.') do
        text <- text[1..]                           // c를 하나 더 먹고
        if Match(pattern, text) then return true    // 나머지를 다시 처음부터
    return false                                    // 모든 경우 실패
```

</Slide>

<Slide class="compact">

#### 코드로 옮기면
::sub[`regexMatch.c` · 호출 수와 깊이를 세는 줄은 뺐습니다]

```c
bool match(const char *pattern, const char *text) {
    if (*pattern == '\0') return true;                 /* 패턴이 끝나면 성공 */
    if (*(pattern + 1) == '*')                         /* x* 패턴 */
        return matchStar(*pattern, pattern + 2, text);
    if (*text != '\0' && (*pattern == '.' || *pattern == *text))
        return match(pattern + 1, text + 1);           /* 한 글자 맞추고 전진 */
    return false;
}
static bool matchStar(char c, const char *pattern, const char *text) {
    if (match(pattern, text)) return true;             /* 0개 매칭 시도 */
    while (*text != '\0' && (*text == c || c == '.'))  /* 1개 이상 */
        if (match(pattern, ++text)) return true;       /* 하나 더 먹고 다시 */
    return false;                                      /* 모든 경우 실패 */
}
```

- 틀리면 되돌아가서 다음 가능성을 처음부터 다시 따라갑니다.
- 웹 서비스가 정규식 하나 때문에 멈추는 사고도 있었습니다.
  - 이런 공격을 ReDoS(정규식 서비스 거부)라고 부릅니다.
- 재귀 깊이가 패턴 길이만큼 깊어지는 것도 부담입니다.

<br/>

다음 도구는 이것을 뒤집습니다. **되돌아가지 않습니다.**

## 예제 2. 유한 상태 오토마타
::sub[Finite State Automaton]

</Slide>

<Slide>

#### 개념
::sub[상태와 전이를 이용해 패턴 매칭을 수행합니다]

- **상태**(State): 매칭 과정에서의 현재 위치와 상황
- **전이**(Transition): 입력 문자에 따른 상태 변화
- **수락 상태**(Accept State): 패턴 매칭이 성공적으로 완료된 상태
- **엡실론 전이**(ε-transition): 입력 없이 발생하는 상태 전이

<br/>

입력이 끝났을 때 수락 상태에 있으면 받아들입니다.  
재귀적 백트래킹의 비효율성을 해결할 수 있습니다.

</Slide>

<Slide>

#### 간단한 예제: 패턴 ab\*c
::sub[상태는 다섯 개입니다]

| 상태 | 뜻 |
| --- | --- |
| S0 | 시작 상태 |
| S1 | `a`를 읽은 상태 |
| S2 | `b*` 시작 상태 (0개의 `b` 허용) |
| S3 | `b`를 1개 이상 읽은 상태 |
| S4 | `c`를 읽어서 패턴 매칭 완료 (수락 상태) |

<br/>

S1에서 S2로는 입력 없이 넘어갑니다. 이것이 ε 전이입니다.

</Slide>

<Slide>

#### S3에서 b를 읽으면
::sub[S2로 돌아가게 그려도 될까]

- **S2로 돌아가게** 그려도 받아들이는 문자열은 같습니다.
  - 다만 그러면 S3은 "b를 홀수 개 읽은 상태"가 됩니다.
  - 표의 설명 "b를 1개 이상 읽은 상태"와 맞지 않습니다.
- 그래서 **S3에 그대로 머물게** 그립니다.
  - 상태마다 뜻이 하나로 섭니다.

<br/>

`abbbbc`: S0 → S1 → S2 → S3 → S3 → S3 → S3 → S4

</Slide>

::sub[칸과 수락을 바꿔 보세요 · 마지막 열은 표를 실제로 돌린 결과입니다]

#### 절차
::sub[`02_finite_state_automaton/fsaSimple.pseudo`]

```plaintext
ALGORITHM Accept(input)
    state <- S0
    for 입력 문자 ch in input do
        if state = S0 and ch = 'a' then
            state <- S1
            state <- S2                     // ε 전이: 입력 없이 바로 S2로
        else if state ∈ {S2, S3} and ch = 'b' then
            state <- S3
        else if state ∈ {S2, S3} and ch = 'c' then
            state <- S4
        else
            return false                    // 갈 곳이 없으면 거부
    return state = S4                       // 끝났을 때 수락 상태여야 수락
```

</Slide>

<Slide class="compact">

#### 코드로 옮기면
::sub[`fsaSimple.c` · 실습 코드의 switch를 조건 네 줄로 줄이고 출력 줄은 뺐습니다]

```c
bool accept(const char *input) {
    State s = S0;                                    /* S0~S4는 열거형 */
    for (const char *p = input; *p != '\0'; p++) {
        if (s == S0 && *p == 'a') s = S2;            /* 'a'로 S1, ε 전이로 S2까지 */
        else if ((s == S2 || s == S3) && *p == 'b') s = S3;
        else if ((s == S2 || s == S3) && *p == 'c') s = S4;
        else return false;                           /* 갈 곳이 없으면 거부 */
    }
    return s == S4;                                  /* 수락 상태인지 확인 */
}
```

::sub[글자 하나에 전이 하나]

- 텍스트 길이가 $$N$$이면 $$O(N)$$에 끝납니다.

- 다만 이 그림은 **손으로** 그렸습니다.
  - 패턴이 바뀔 때마다 상태를 새로 설계해야 합니다.

## 예제 3. 정규식에서 NFA로
::sub[Regular Expression to NFA]

#### 클리니 정리
::sub[Kleene's theorem]

- 정규식으로 적을 수 있는 언어와 유한 상태 오토마타가 인식하는 언어는 **정확히 같습니다.**
- DFA로 바로 만들면 상태 수가 지수만큼 늘어날 수 있습니다.
- 그래서 **비결정적 유한 오토마타**(NFA)를 만듭니다.
  - 한 상태에서 갈 곳이 여럿일 수 있습니다.
  - ε 전이를 마음껏 씁니다.

</Slide>

#### 만드는 법
::sub[정규식 전체를 괄호로 감싸고, 글자 하나를 상태 하나로 · 상태 0…M, M이 수락]

- **매치 전이**
  - 글자 상태 $$i$$는 그 글자(`.`이면 아무 글자)를 읽고 $$i+1$$로 갑니다.
- **ε 전이**
  - `(`, `)`, `*`는 글자 없이 다음 상태로 갑니다.
  - `x*`, `(…)*`: 덩어리 시작과 `*` 사이를 양방향으로 잇습니다.
  - `(A|B)`: `(`에서 B의 시작으로, `|`에서 `)`로 갑니다.

<br/>

괄호의 짝은 스택으로 찾습니다.

#### 절차: 그래프 만들기
::sub[`03_nfa_regex/nfaRegex.pseudo` · 정규식을 한 번 훑으며 O(M)]

```plaintext
ALGORITHM BuildNFA(re)
    ops <- 빈 스택
    for i <- 0 to M-1 do
        lp <- i                                  // '*'가 붙을 덩어리의 시작
        if re[i] = '(' 또는 '|' then ops에 i를 넣는다
        else if re[i] = ')' then
            or <- ops에서 꺼낸다
            if re[or] = '|' then lp <- ops에서 꺼낸다; G에 lp -> or+1, or -> i 추가
            else lp <- or
        if re[i+1] = '*' then G에 lp -> i+1, i+1 -> lp 추가   // 0번, 한 번 더
        if re[i] ∈ { '(', '*', ')' } then G에 i -> i+1 추가   // 글자 없이 다음으로
```

</Slide>

<Slide>

#### 상태 집합으로 돌리기
::sub["지금 상태"가 하나가 아니므로, 있을 수 있는 상태 전부를 들고 다닙니다]

한 글자마다 두 걸음입니다.

1. **글자 읽기**
   - 집합에서 읽은 글자와 맞는 글자 상태만 한 칸 앞으로 갑니다.
2. **ε 닫힘**(ε-closure)
   - 거기서 ε 전이만 따라 갈 수 있는 상태를 모두 더합니다. DFS입니다.

<br/>

텍스트를 다 읽었을 때 집합에 수락 상태가 있으면 수락입니다.

</Slide>

#### 절차: 시뮬레이션
::sub[`nfaRegex.pseudo`]

```plaintext
ALGORITHM Recognizes(re, text)
    G <- BuildNFA(re)
    pc <- Closure(G, {0})                    // 지금 있을 수 있는 상태들
    for 글자 ch in text do
        match <- { i+1 : i ∈ pc, re[i]가 글자이고
                         (re[i] = ch 또는 re[i] = '.') }
        pc <- Closure(G, match)
    return M ∈ pc
```

## 남길 것

1. **정규식은 문자열의 집합(언어)을 적습니다.**
   - 연결, 또는, 클로저 세 연산과 괄호
2. **축약어는 세 연산의 줄임말입니다.**
   - 찾기는 `.*pat.*`에 속하는지 묻는 것과 같습니다.
3. **개수를 끝없이 세는 언어는 적지 못합니다.**
   - 괄호 짝, A와 B의 개수
4. **재귀와 백트래킹은 지수적으로 폭발할 수 있습니다.**
   - 한 번에 한 가능성만 들고 다니기 때문입니다.
5. **오토마타는 되돌아가지 않습니다.**
   - DFA는 $$O(N)$$, 정규식에서 만든 NFA는 최악 $$O(MN)$$
