## 오늘 할 일
::sub[채팅창에서 저장소 안으로]

- AI를 **채팅창에서만** 쓰던 방식에서 한 걸음 나갑니다.
- 같은 AI가 **저장소 안에서** 파일을 읽고, 고치고, 테스트를 돌리게 합니다.
- 일곱 단계를 따라 URL 단축기를 만듭니다.
- 마지막에는 **내 휴대폰**으로 짧은 링크를 열어 봅니다.

</Slide>

<Slide class="compact">

## 채팅과 에이전트
::sub[같은 AI, 다른 자리]

| | 채팅 | 에이전트 |
| --- | --- | --- |
| 내 코드를 아는가 | 붙여 넣은 만큼만 | 저장소의 파일을 직접 읽음 |
| 결과를 어디에 두나 | 내가 복사해서 붙여 넣음 | 파일을 직접 만들고 고침 |
| 돌려 보는가 | 돌려 보지 않음 | 테스트를 돌리고 실패를 봄 |
| 규칙을 기억하나 | 대화가 끝나면 잊음 | 규칙 파일을 매번 읽음 |

</Slide>

### Manual은 교육용입니다
::sub[에이전트가 하려는 일을 한 번씩 읽어 보기 위해서]

- 오늘은 명령마다 **직접 읽고 허락**합니다.
- 익숙해진 뒤 실제로 쓸 때는 **Assisted**나 **Allow all**이면 됩니다.
  - 그때 확인은 허락 버튼 대신 테스트, diff, 커밋으로 합니다.
- **Autopilot**도 익숙해진 뒤에 씁니다.

</Slide>

::sub[이 과제는 에이전트 요청 20회 안쪽으로 끝납니다]

  - 모호한 요청은 되묻는 데 한 번을 씁니다.
- **실패 메시지는 그대로** 붙여 넣습니다.
  - "안 돼요"보다 한 번에 고칩니다.
- **간단한 수정은 직접** 합니다.
  - 변수 이름 바꾸기에 요청을 쓰지 않습니다.

### 적지 않은 것은 AI가 정합니다
::sub[이 단계에서는 요청하지 않습니다]

`SPEC.md` 맨 위의 `TEMPLATE:` 줄을 지우고 직접 씁니다.

- **해시 테이블**: 충돌은? 해시 함수는? 언제 늘리나?
- **단축기**: 같은 URL을 두 번 넣으면? 없는 코드는?
- **잘못된 입력**: `ftp://`, 공백, 아주 긴 주소는?
- **경계 사례**: 목록으로 적습니다. 4단계의 테스트가 됩니다.

### 이 과제에서 정해 둔 것
::sub[해시 테이블을 직접 만드는 과제입니다]

- 충돌은 **선형 탐지**, 해시는 주제 08의 **호너 방식**
- Python의 `dict`, `set`, 내장 `hash()`는 쓰지 않습니다.
- 내장 `hash()`는 실행할 때마다 문자열의 해시값이 바뀝니다.
  - 6단계의 실험을 다시 돌리면 다른 숫자가 나옵니다.

</Slide>

### 계획만 받습니다

### 계획에서 자주 잡는 것

- URL→코드 저장에 **`dict`** 를 쓰겠다고 합니다.
  - 명세 위반입니다.
- 코드를 **URL의 해시값**으로 만들겠다고 합니다.
  - 서로 다른 URL이 같은 코드를 받을 수 있습니다.
  - 일련번호를 base62로 바꾸면 겹치지 않습니다.
- 테스트를 **맨 마지막**에 쓰겠다고 합니다.
  - 순서를 바꿉니다.

</Slide>

### 테스트만 먼저

```text

unittest로 옮겨 줘. 구현은 아직 하지 마.
```

- 테스트를 **읽습니다.** 경계 사례가 빠짐없이 들어갔나요?

<Slide class="compact">

### 그다음 구현

```text

```

- **"테스트는 고치지 마"가 중요합니다.**
  - 없으면 통과하지 못하는 테스트를 슬쩍 고쳐 놓기도 합니다.
- 끝나면 diff를 읽고 커밋합니다.

### 평가
::sub[에이전트가 잘했는지가 아니라, 내가 무엇을 잡아냈는지]

| 항목 | 배점 | 보는 것 |
| --- | --- | --- |
| 명세와 테스트 | 1 | 경계 사례를 직접 정하고, 테스트가 빠짐없이 검사하는가 |
| 규칙 파일 | 1 | 규칙이 구체적이고 실제로 효과를 냈는가 |
| 해시 테이블과 실험 | 1 | `dict` 없이 동작하고, 실험값을 이론과 비교해 해석했는가 |
| 작업 기록 | 1.5 | 틀린 곳을 어떻게 알아채고 고쳤는지 구체적인가 |
| 서비스 | 0.5 | `make serve`로 뜨고 짧은 링크로 이동되는가 |

## 오늘 가져갈 습관

1. 무엇을 만들지는 **명세로** 먼저 정한다.
2. 코드보다 **계획을** 먼저 받는다.
3. **테스트로** 말하고, 테스트는 고치지 말라고 한다.
4. 규칙은 **규칙 파일에** 둔다.
5. 결과는 **실행해서** 확인하고, 단계마다 **커밋**한다.
