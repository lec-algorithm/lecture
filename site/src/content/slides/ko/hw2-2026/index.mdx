- 같은 AI가 **저장소 안에서** 파일을 읽고, 고치고, 테스트를 돌리게 합니다.

## 채팅과 에이전트
::sub[같은 AI, 다른 자리]

| | 채팅 | 에이전트 |
| --- | --- | --- |

| 규칙을 기억하나 | 대화가 끝나면 잊음 | 규칙 파일을 매번 읽음 |

### git도 에이전트에게
::sub[명령어로도, 소스 제어 화면으로도 되지만 오늘은 에이전트로 관리합니다]

```text
이 저장소는 git flow로 관리하자.
먼저 main에서 develop 브랜치를 만들어 줘.
단계마다 GitHub 이슈를 하나씩 만들 거야. 이슈 번호는 단계 번호와 같아.
단계마다 develop에서 feature/<이슈번호>-<짧은 이름> 브랜치를 따서 작업하고,
작업하면서 그 이슈에 진행 상황을 댓글로 남겨 줘.
단계가 끝나면 커밋하고 develop에 머지한 뒤 이슈를 닫아 줘.
커밋 메시지는 "Step N: 한 일 (#이슈번호)" 형식으로 써 줘.
커밋하고 머지할 때마다 GitHub에도 push해 줘.
```

- 시작할 때 **한 번만** 시킵니다.
- 브랜치를 만들고, 커밋하고, 머지하는 일을 에이전트가 합니다.

</Slide>

### 왜 push에서 멈췄나
::sub[내 Codespace 밖으로 나가는 일이기 때문입니다]

- develop 브랜치를 **만드는 일은 묻지 않았습니다.** Codespace 안의 일입니다.
- GitHub로 **push하는 일은 멈추고 물었습니다.** 밖으로 나가 되돌리기 어렵습니다.
- 이유도 적어 줍니다: "develop을 올리라고는 따로 말하지 않았다"
  - 에이전트는 **내 요청을 기준으로** 범위를 따집니다.
- 묻지 않고 실행한 명령도 채팅에 남습니다. 무엇을 돌렸는지 읽어 봅니다.

</Slide>

::sub[이슈 → 요청 → 확인 → 커밋 → 기록]

| | 누가 | 어떻게 |
| --- | --- | --- |
| 이슈 | 나 | GitHub에서 단계마다 하나 |

## 2단계

AI가 초안, 내가 편집

</Slide>

<Slide class="compact">

### 초안은 AI가
::sub[명세 초안만 받습니다 · 코드는 아직]

```text
2단계야. 이슈 #2 작업이야.
#SPEC.md 틀을 채워서 우리가 만들 URL 단축 서비스의 명세 초안을 써 줘.
저장은 직접 구현한 해시 테이블(선형 탐지, 호너 해시)로 하고,
dict, set, 내장 hash()는 쓰지 마.
초안만 쓰고 코드는 쓰지 마.
커밋은 내가 고친 뒤에 하자.
```

- `#SPEC.md`처럼 `#`을 붙이면 파일이 요청에 붙습니다.

</Slide>

<Slide>

### 결정은 내가
::sub[초안을 읽고 직접 고칩니다]

- **해시 테이블**: 충돌은? 해시 함수는? 언제 늘리나?
- **단축기**: 같은 URL을 두 번 넣으면? 없는 코드는?
- **잘못된 입력**: `ftp://`, 공백, 아주 긴 주소는?
- **경계 사례**: 4단계의 테스트가 됩니다. 빠진 것을 더합니다.

<br/>

AI가 빈칸을 마음대로 채운 곳을 찾아 고치는 것이 이 단계의 일입니다.  
무엇을 고쳤는지는 `AGENT_LOG.md`에 적습니다.

</Slide>

<Slide class="compact">

### 고친 뒤 커밋

```text
2단계 이어서야. 이슈 #2 작업이야.
SPEC.md를 내가 고쳤어.
커밋하고 develop에 머지한 뒤 push해 줘.
```

- 요청 예시는 모두 첫 줄에 **단계와 이슈 번호**, 마지막 줄에 **커밋 문장**이 있습니다.

</Slide>

<Slide>

### 이 과제에서 정해 둔 것
::sub[해시 테이블을 직접 만드는 과제입니다]

- 충돌은 **선형 탐지**, 해시는 주제 08의 **호너 방식**
- Python의 `dict`, `set`, 내장 `hash()`는 쓰지 않습니다.
- 내장 `hash()`는 실행할 때마다 문자열의 해시값이 바뀝니다.
  - 6단계의 실험을 다시 돌리면 다른 숫자가 나옵니다.

</Slide>

## 3단계

코드보다 계획을 먼저

</Slide>

<Slide class="compact">

### 계획만 받습니다

```text
3단계야. 이슈 #3 작업이야.
SPEC.md를 읽고 구현 계획을 단계별로 세워서 PLAN.md에 저장해 줘.
아직 코드는 쓰지 마.
끝나면 커밋하고 develop에 머지한 뒤 push해 줘.
```

- Agent mode를 **Plan**으로 바꿔서 시켜도 됩니다. 끝나면 Autopilot으로 돌아옵니다.
- 계획에서 고친 것은 코드에서 고치는 것보다 훨씬 쌉니다.

</Slide>

<Slide>

### 계획에서 자주 잡는 것

- URL→코드 저장에 **`dict`** 를 쓰겠다고 합니다.
  - 명세 위반입니다.
- 코드를 **URL의 해시값**으로 만들겠다고 합니다.
  - 서로 다른 URL이 같은 코드를 받을 수 있습니다.
  - 일련번호를 base62로 바꾸면 겹치지 않습니다.
- 테스트를 **맨 마지막**에 쓰겠다고 합니다.
  - 순서를 바꿉니다.

</Slide>

## 4단계

테스트를 먼저, 구현은 에이전트가

</Slide>

<Slide class="compact">

### 테스트만 먼저

```text
4단계야. 이슈 #4 작업이야.
SPEC.md 6절의 경계 사례를 unittest로 옮겨 줘.
파일은 tests/test_hash_table.py와 tests/test_shortener.py야.
구현은 아직 하지 마.
끝나면 커밋하고 develop에 머지한 뒤 push해 줘.
```

- 테스트를 **읽습니다.** 경계 사례가 빠짐없이 들어갔나요?
- 빠진 것은 직접 더하고 커밋합니다.
- 지금 `make test`가 실패하는 것은 정상입니다.

</Slide>

<Slide class="compact">

### 그다음 구현

```text
4단계 이어서야. 이슈 #4 작업이야.
PLAN.md 순서대로 src/hash_table.py와 src/shortener.py를 구현하고,
make test가 모두 통과할 때까지 고쳐 줘.
테스트는 고치지 마.
끝나면 커밋하고 develop에 머지한 뒤 push해 줘.
```

- **"테스트는 고치지 마"가 중요합니다.**
  - 없으면 통과하지 못하는 테스트를 슬쩍 고쳐 놓기도 합니다.
- 끝나면 diff를 읽고 커밋합니다.

</Slide>

### 규칙 파일 예시
::sub[직접 씁니다]

```md
# 이 저장소에서 일하는 에이전트에게

- 코드를 쓰기 전에 SPEC.md를 읽는다.
- src/ 안에서 dict, set, 내장 hash()를 쓰지 않는다. 해시 테이블은 직접 만든 것을 쓴다.
- 코드를 고친 뒤에는 make test를 돌리고 결과를 보여 준다.
- 테스트가 실패하면 테스트가 아니라 코드를 고친다.
- 이슈마다 develop에서 feature/<이슈번호>-<이름> 브랜치를 따서 작업하고, 진행은 이슈 댓글로 남긴다.
- 끝나면 커밋하고 develop에 머지한 뒤 push하고, 이슈를 닫는다.
- 나는 1학년이다. 무엇을 바꿨는지 세 줄 이내로 요약한다.
```

- 처음에 채팅으로 시킨 git 규칙도 옮겨 둡니다. 새 채팅은 이전 대화를 모릅니다.

</Slide>

### 웹 서버 붙이기

```text
7단계야. 이슈 #7 작업이야.
SPEC.md 5절대로 src/server.py를 만들어 줘.
표준 모듈 http.server만 쓰고, make serve로 포트 8000에서 뜨게 해 줘.

```

- `make serve`로 띄웁니다.
- 아래쪽 패널의 **포트** 탭에 8000번이 나타납니다.

</Slide>

<Slide>

### 휴대폰으로 열기

1. **포트** 탭에서 8000번 줄을 오른쪽 클릭
2. **Port Visibility** → **Public**
3. **Forwarded Address**를 휴대폰으로 엽니다.
4. 긴 URL을 넣고, 받은 짧은 링크를 눌러 봅니다.

</Slide>

### 제출
::sub[11월 29일 23:59 · 저장소 URL + ZIP]

- `SPEC.md`: AI 초안을 직접 고친 것
- `.github/copilot-instructions.md`: 직접 쓴 것
- `src/`, `tests/`: 해시 테이블, 단축기, 서버와 테스트
- `experiments/`: 실험 스크립트, `results.csv`, 그래프
- `AGENT_LOG.md`: 단계별 기록, 틀린 곳 둘 이상, 채팅과의 비교, 소감
- 단계별 커밋 이력: 제출 전에 develop을 **main에 머지하고 push**
- push하지 않은 것은 제출되지 않습니다. GitHub 화면에서 확인합니다.

### 평가
::sub[에이전트가 잘했는지가 아니라, 내가 무엇을 잡아냈는지]

| 항목 | 배점 | 보는 것 |
| --- | --- | --- |
| 명세와 테스트 | 1 | AI 초안에서 무엇을 고쳤는지 남겼고, 테스트가 경계 사례를 빠짐없이 검사하는가 |
| 규칙 파일 | 1 | 규칙이 구체적이고 실제로 효과를 냈는가 |
| 해시 테이블과 실험 | 1 | `dict` 없이 동작하고, 실험값을 이론과 비교해 해석했는가 |
| 작업 기록 | 1.5 | 틀린 곳을 어떻게 알아채고 고쳤는지 구체적인가 |
| 서비스 | 0.5 | `make serve`로 뜨고 짧은 링크로 이동되는가 |

</Slide>

### 사람이 맡는 몫
::sub[AI를 쓰는 과제여도 정해져 있습니다]

- `SPEC.md`는 AI 초안을 **직접 고칩니다.**
- `AGENT_LOG.md`는 **직접 씁니다.**
  - AI가 쓴 기록은 기록이 아닙니다.
- 규칙 파일은 초안을 받아도 되지만, 무엇을 넣을지는 내가 정합니다.
- 수업에 오지 못한 학생도 같은 과제, 같은 마감입니다.
  - 안내 글만 보고 끝까지 할 수 있습니다.

</Slide>

## 오늘 가져갈 습관

1. 무엇을 만들지는 **명세로** 먼저 정한다.
2. 코드보다 **계획을** 먼저 받는다.
3. **테스트로** 말하고, 테스트는 고치지 말라고 한다.
4. 규칙은 **규칙 파일에** 둔다.
5. 결과는 **실행해서** 확인하고, 단계마다 **커밋**한다.

</Slide>
