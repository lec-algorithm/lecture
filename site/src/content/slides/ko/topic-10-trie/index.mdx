## 키를 쪼개서 저장한다
::sub[주제 07은 이진 탐색 트리, 주제 08은 해시 테이블이었습니다]

- **이진 탐색 트리**: 키 전체를 비교하며 내려갑니다.
- **해시 테이블**: 키 전체로 해시값을 셉니다.
- **트라이**: 문자열 키를 **문자 하나씩 쪼개** 트리의 경로로 저장합니다.

<br/>

찾는 시간이 키가 몇 개인지가 아니라 **키가 몇 글자인지**로 정해집니다.  
접두사로 시작하는 키를 모두 찾는 일도 덤으로 얻습니다.

  - 문자 몇 개만 검사하고 끝납니다.

## 트라이
::sub[Trie · 접두사 트리, 디지털 트리]

</Slide>

<Slide>

#### 트라이
::sub[이름은 검색(retrieval)에서 왔습니다]

- 문자열 검색을 위한 트리입니다.
  - 접두사 트리(prefix tree), 디지털 트리(digital tree)라고도 부릅니다.
- 문자열의 집합을 저장하고 검색하는 데 맞춘 구조입니다.
- 각 노드는 문자 하나를 나타냅니다.
  - 루트에서 어떤 노드까지의 경로가 문자열 하나입니다.
- 키의 마지막 문자에 해당하는 노드에 값을 둡니다.

</Slide>

<Slide>

#### 노드
::sub[TrieNode]

- **children[26]**: 다음 노드를 가리키는 링크 배열
  - 문자를 인덱스로 바로 씁니다. `b`는 1번 칸, `s`는 18번 칸
- **hasValue**: 이 노드에서 끝나는 키가 있는지
- **value**: 그 키의 값

<TrieFigure kind="node" chars="bst" caption="여섯 키를 넣은 트라이의 루트: 26칸 중 b, s, t 세 칸만 씁니다" slide />

</Slide>

<Slide class="compact">

#### 노드를 코드로
::sub[`01_trie/trie.c`]

```c
#define ALPHABET_SIZE 26 /* R: 알파벳 크기 (a-z) */

typedef struct TrieNode {
    struct TrieNode *children[ALPHABET_SIZE]; /* a-z 링크. 비어 있으면 NULL */
    bool hasValue;                            /* 이 노드에서 끝나는 키가 있는가 */
    int value;                                /* 그 키의 값 */
} TrieNode;
```

링크가 없으면 NULL, 새 노드는 26칸을 모두 NULL로 채워 만듭니다.

</Slide>

#### 그림을 읽는 법
::sub[노드의 글자는 들어오는 링크의 문자입니다]

- 노드가 글자를 저장하는 것이 아닙니다.
  - 부모의 몇 번 칸에서 왔는지가 곧 글자입니다.
- 노드 옆의 파란 숫자가 값입니다.
  - `she`의 마지막 문자 `e`에 0이 있습니다.
- `s` 링크 아래에는 **s로 시작하는 모든 키**가 있습니다.
  - `sh` 아래에는 sh로 시작하는 키 전부가 있습니다.

</Slide>

<Slide>

#### 특징
::sub[공유하는 것과 낭비하는 것]

- **공통 접두사 공유**
  - `sea`와 `sells`는 `se`를, `she`와 `shells`는 `she`를 함께 씁니다.
- **빠른 검색**: 키 길이 $$m$$에 대해 $$O(m)$$
- **키-값 저장**: 단어와 연결된 값을 함께 둡니다.
- **메모리 집약적**
  - 노드마다 링크 26개, 442개 중 쓰는 것은 16개뿐입니다.

</Slide>

#### 삽입
::sub[키의 문자들을 길잡이 삼아 루트에서 내려갑니다]

- **마지막 문자 전에 NULL 링크를 만나면**
  - 새 노드를 만들어 답니다.
- **마지막 문자의 노드에 닿으면**
  - 그 노드에 값을 둡니다.
  - 이미 값이 있었다면 새 값으로 바꿉니다.

### 한 걸음씩: 키 여섯 개
::sub[지나간 노드는 파랑, 새로 만든 노드는 초록]

<TrieDemo slide />

</Slide>

<Slide class="compact">

#### 삽입을 코드로
::sub[`01_trie/trie.pseudo`]

```plaintext
ALGORITHM Insert(root, word, value)
    current <- root
    for i <- 0 to length(word)-1 do
        index <- word[i] - 'a'          // 문자를 배열 인덱스로 (a=0, b=1, ...)
        if current.children[index] = NULL then
            current.children[index] <- CreateTrieNode()   // 링크가 없으면 새 노드
        current <- current.children[index]
    current.hasValue <- true            // 키의 마지막 문자에 해당하는 노드에 값
    current.value <- value
```

## 트라이 검색
::sub[Search]

</Slide>

<Slide>

#### 검색
::sub[루트에서 시작해 키의 문자를 차례로 따라갑니다]

- NULL 링크를 만나거나 마지막 문자에 닿을 때까지 되풀이합니다.
- **성공**: 마지막 문자의 노드에 값이 있다.
- **실패** 두 가지
  - 링크가 없어서 더 내려가지 못한다.
  - 끝까지 갔는데 그 노드에 값이 없다.

</Slide>

<TrieDemo mode="search" slide />

</Slide>

<Slide>

#### 네 번의 결과
::sub[실패도 두 가지 모양입니다]

- **get("shells")**: 마지막 `s`에 값 3, 성공
- **get("shell")**: 마지막 `l`까지 갔지만 값이 없습니다.
  - `shell`은 `shells`의 접두사일 뿐 키가 아닙니다.
- **get("she")**: 중간 노드라도 값이 있으면 성공, 0
- **get("shore")**: `sh` 다음에 `o` 링크가 없습니다.
  - 노드 세 개만 보고 실패합니다.

</Slide>

<Slide class="compact">

#### 검색을 코드로
::sub[`01_trie/trie.pseudo` · 실습 코드는 실패하면 -1]

```plaintext
ALGORITHM Search(root, word)
    current <- root
    for i <- 0 to length(word)-1 do
        index <- word[i] - 'a'
        if current.children[index] = NULL then
            return -1                   // 링크가 없다: 실패
        current <- current.children[index]
    if current.hasValue then
        return current.value
    return -1                           // 노드는 있지만 값이 없다: 실패
```

#### 접두사로 모두 찾기
::sub[검색창에 sh까지 치면 she, shells, shore가 뜹니다]

`sh` 노드 아래에 **sh로 시작하는 키가 전부** 있습니다.

1. 접두사를 따라 마지막 문자의 노드까지 내려갑니다.
2. 그 아래 서브트라이를 돌며 값이 있는 노드의 키를 모읍니다.

<br/>

자식을 a부터 z 순서로 돌므로 결과가 **사전 순**입니다.

#### 모으기를 코드로
::sub[`01_trie/trie.pseudo` · 값을 먼저 보고 자식으로 내려갑니다]

```plaintext
ALGORITHM GetAllWordsHelper(node, prefix, results)
    if node = NULL then return
    if node.hasValue then
        results에 (prefix, node.value) 추가
    for i <- 0 to 25 do                 // a부터 z 순서라 결과가 사전 순
        if node.children[i] != NULL then
            GetAllWordsHelper(node.children[i], prefix + ('a' + i), results)
```

## 트라이 삭제
::sub[Delete]

</Slide>

<Slide>

#### 삭제
::sub[값을 지운 뒤, 쓸모없어진 노드를 아래에서부터 떼어 냅니다]

1. **탐색으로 키의 노드를 찾아 값을 NULL로**
2. **돌아 올라오며 정리**
   - 자식 링크 중 NULL이 아닌 것이 있다면 아무것도 지우지 않습니다.
   - 값도 없고 자식 링크도 모두 NULL이면 노드를 지웁니다.
   - 그래서 부모의 자식 링크가 모두 NULL이 되면 부모도 지웁니다.

</Slide>

<Slide>

### 한 걸음씩: delete("shells")
::sub[지울 노드는 빨강 점선, 멈추는 노드는 초록 테두리]

<TrieDemo mode="delete" slide />

</Slide>

<Slide class="compact">

#### 삭제를 코드로
::sub[`01_trie/trie.pseudo` · 루트는 지우지 않습니다]

```plaintext
ALGORITHM DeleteHelper(node, word, index)
    if index = length(word) then        // 키의 마지막 문자 노드에 도착
        if not node.hasValue then return false    // 없는 키
        node.hasValue <- false
        return node에 자식이 하나도 없는가
    child <- node.children[word[index] - 'a']
    if child = NULL then return false   // 없는 키
    if DeleteHelper(child, word, index + 1) then
        child를 해제하고 그 링크를 NULL로
        return (not node.hasValue) and node에 자식이 하나도 없는가
    return false
```

</Slide>

## 트라이 분석
::sub[모양, 시간, 공간]

</Slide>

<Slide>

#### 모양은 키 집합이 정한다
::sub[링크 구조는 넣고 지운 순서와 무관합니다]

- **트라이**: 키 집합이 정해지면 모양이 하나로 정해집니다.
  - 여섯 키를 어떤 순서로 넣어도 같은 그림입니다.
- **이진 탐색 트리**: 넣는 순서에 따라 모양이 다릅니다.
  - 정렬된 순서로 넣으면 한 줄로 늘어섭니다. 주제 07에서 본 최악입니다.

</Slide>

<Slide>

#### 이진 탐색 트리는 순서를 탄다
::sub[5, 3, 9, 4, 7, 12, 6, 8, 20 순서로 넣은 트리]

<TreeFigure tree={{ v: "5", l: { v: "3", r: { v: "4" } }, r: { v: "9", l: { v: "7", l: { v: "6" }, r: { v: "8" } }, r: { v: "12", r: { v: "20" } } } }} slide />

같은 수를 3, 4, 5, …, 20 순서로 넣으면 오른쪽으로만 뻗은 한 줄이 됩니다.

</Slide>

<Slide>

#### 탐색과 삽입의 최악
::sub[키를 찾거나 넣을 때 거치는 노드]

- 루트를 포함해 **키의 길이에 1을 더한 값**이 최대입니다.
  - 문자 하나에 링크 하나, 키의 끝에 닿으면 멈춥니다.
  - 재귀로 쓰면 깊이가 0에서 시작해 키의 길이에 닿을 때 멈춥니다.
- 키 길이 $$m$$에 대해 $$O(m)$$
  - **키가 몇 개 있는지와 상관없습니다.**

<br/>

실행 결과: `shells`(6글자)는 `visited 7`

</Slide>

<Slide>

#### 탐색 실패 시간의 기댓값
::sub[크기 R인 알파벳의 무작위 키 N개로 만든 트라이]

- 검색 실패가 검사하는 노드는 평균 약 $$\log_R N$$개입니다.
- **탐색 실패의 소요 시간은 키의 길이와 무관합니다.**
  - 영어 사전에서 `xmcwkeicowalcoeks`를 찾으면 서너 글자에서 없다는 것을 압니다.
- 백만 개의 무작위 키가 든 트라이라면
  - 7자리 번호판이든 20자리 계좌번호든 노드 네댓 개에서 끝납니다.

</Slide>

#### 실험: 7글자 무작위 키
::sub[`01_trie/` · 무작위 키로 1000번 찾아 거친 노드 수(루트 포함)의 평균]

- 실행

```console
search miss, random keys of length 7, 1000 searches
  N = 100    average visited = 2.15
  N = 1000   average visited = 2.82
  N = 10000  average visited = 3.45
```

키가 열 배가 될 때마다 0.6\~0.7개씩 늘어납니다.  
$$\log_{26} 10 \approx 0.71$$, 곧 $$\log_R N$$을 따라 자랍니다.

</Slide>

<Slide>

#### 공간
::sub[크기 R인 알파벳의 키 N개, 키의 평균 길이 w]

- 노드마다 링크가 $$R$$개입니다.
- 링크의 개수는 **$$RN$$에서 $$RNw$$ 사이**입니다.
  - 루트의 $$R$$개는 따로 셉니다.
- **키가 짧거나 접두사를 많이 공유하면** $$RN$$에 가깝습니다.
- **키가 길고 서로 다르면** $$RNw$$에 가깝습니다.
- $$R$$을 줄이면 공간을 상당히 아낄 수 있습니다.

</Slide>

#### 단일 분기를 없애면
::sub[압축 트라이 (radix tree, Patricia trie)]

- 값이 없고 자식이 하나뿐인 노드를 아래 노드와 합칩니다.
  - 갈라지는 곳만 남고, 노드에 문자열 조각이 붙습니다.
- 이 주제에서는 구현하지 않습니다.

## TST
::sub[Ternary Search Tree · 삼진 탐색 트리]

</Slide>

<Slide>

#### 개요
::sub[트라이의 메모리 효율적인 변형]

- 각 노드가 자식 링크를 **3개만** 갖습니다.
  - 트라이의 지나친 공간 소모를 피할 수 있습니다.
- 이진 탐색 트리와 비슷한 구조로 문자를 저장합니다.
  - 트라이에서는 링크의 위치가 문자였습니다.
  - TST에서는 **노드가 문자를 직접** 갖습니다.

</Slide>

<Slide>

#### 링크 세 개
::sub[트라이의 노드 하나가 작은 이진 탐색 트리가 됩니다]

- **left**: 같은 자리에서 이 노드의 문자보다 작은 문자
- **middle**: 이 문자가 맞았을 때, 다음 자리의 문자
- **right**: 같은 자리에서 이 노드의 문자보다 큰 문자

<br/>

왼쪽·오른쪽은 **같은 자리**, 가운데만 **다음 자리**입니다.

</Slide>

<Slide>

#### 노드를 코드로
::sub[`02_tst/tst.c` · 트라이는 노드 17개에 링크 442개였습니다]

```c
typedef struct TSTNode {
    char data;               /* 이 노드가 나타내는 문자 */
    bool hasValue;           /* 이 노드에서 끝나는 키가 있는가 */
    int value;               /* 그 키의 값 */
    struct TSTNode *left;    /* data보다 작은 문자 (같은 자리) */
    struct TSTNode *middle;  /* 다음 자리의 문자 */
    struct TSTNode *right;   /* data보다 큰 문자 (같은 자리) */
} TSTNode;
```

::sub[지금 문자와 노드의 문자를 비교합니다]

::sub[예전 강의가 한 장씩 넘기며 보인 장면]

- `i`를 넣으려는데 `e`가 이미 있고 `e < i`

  - 여기서 다음 문자로 넘어갑니다.
- `a`를 넣으려는데 `c`가 이미 있고 `a < c`
  - 왼쪽으로 갑니다.
- 그 자리가 비어 있으므로 `a n c e`를 새 노드로 채웁니다.

#### 삽입을 코드로
::sub[`02_tst/tst.pseudo` · 왼쪽·오른쪽은 index 그대로, 가운데만 index+1]

```plaintext
ALGORITHM Insert(root, word, value, index)
    c <- word[index]
    if root = NULL then
        root <- CreateTSTNode(c)        // 아무것도 없으면 새 노드
    if c < root.data then
        root.left <- Insert(root.left, word, value, index)        // 같은 자리
    else if c > root.data then
        root.right <- Insert(root.right, word, value, index)      // 같은 자리
    else if index < length(word)-1 then
        root.middle <- Insert(root.middle, word, value, index+1)  // 다음 자리
    else
        root.hasValue <- true           // 마지막 문자: 값을 둔다
        root.value <- value
    return root
```

## 트라이와 TST
::sub[Trie vs. TST]

</Slide>

<Slide>

#### 나란히 놓으면
::sub[같은 키 7개(apple..)로 센 링크 · n은 키 개수, m은 키 길이]

| 특성 | 트라이 | TST |
| --- | --- | --- |
| 노드당 링크 | $$R$$개 (영어 소문자 26) | 3개 |
| 같은 키 7개의 링크 | 650 | 72 |
| 다음 노드를 찾는 법 | 배열 인덱스로 바로 | 같은 자리에서 이진 탐색 |
| 검색 (성공) | 노드 $$m + 1$$개 | 가운데 $$m$$번 + 옆으로 몇 번 |
| 검색 (실패) | 평균 약 $$\log_R n$$ | 평균 약 $$\ln n$$ 비교 |
| 모양 | 넣는 순서와 무관 | 넣는 순서에 따라 다름 |
| 구현 | 단순 | 중간 |

</Slide>

<Slide>

#### TST의 검색 시간
::sub[예전 강의의 표에서 고친 칸]

- `cat`을 찾으면
  - **트라이**: 배열 칸 하나씩, $$O(1)$$ 접근 세 번
  - **TST**: 자리마다 작은 이진 탐색 트리, 문자 $$k$$종이면 $$O(\log k)$$
- 옆으로 비켜 가는 몫은 **문자마다 붙지 않습니다.**
  - 첫 몇 자리에서 키들이 갈라지면 같은 자리에 남는 문자가 적습니다.
  - Sedgewick: 무작위 키라면 성공한 검색은 평균 약 $$m + \ln n$$ 비교
- 실행 결과: `applaud`(7글자) 노드 8개, `application`(11글자) 노드 12개

</Slide>

<Slide>

#### 트레이드오프
::sub[무엇을 아끼고 무엇을 내주는가]

- **트라이**: 빠른 검색 $$O(m)$$, 그 대가로 많은 메모리
- **TST**: 적은 메모리, 그 대가로 약간 느린 검색

<br/>

예전 강의의 "캐시 효율성" 칸은 뺐습니다.  
트라이 노드는 크고 대부분 비어 있고, TST 노드는 작지만 포인터를 더 많이 따라갑니다.  
어느 쪽이 유리한지는 구현에 따라 다릅니다.

</Slide>

<Slide>

#### 심볼 테이블로 나란히
::sub[주제 07, 08과 함께 · n은 키 개수, m은 키 길이]

| | 이진 탐색 트리 | 해시 테이블 | 트라이 | TST |
| --- | --- | --- | --- | --- |
| 키를 다루는 단위 | 키 전체를 비교 | 키 전체로 해시 | 문자 하나씩 | 문자 하나씩 |
| 검색 (평균) | 비교 $$O(\log n)$$번 | $$O(m)$$ | $$O(m)$$ | 약 $$m + \ln n$$ 비교 |
| 사전 순으로 꺼내기 | 중위 순회 | 안 됨 | a부터 z 순회 | 중위 순회 |
| 접두사로 모두 찾기 | 범위 검색으로 | 안 됨 | 자연스럽다 | 자연스럽다 |
| 공간 | 노드 $$n$$개 | 표 + 충돌 처리 | 노드마다 $$R$$개 | 노드마다 3개 |

</Slide>

## 남길 것

1. **트라이는 키를 문자 하나씩 경로로 저장합니다.**
   - 노드마다 링크 $$R$$개, 마지막 문자 노드에 값을 둡니다.
2. **검색과 삽입은 키 길이에 비례하고, 키 개수와 무관합니다.**
   - 검색 실패는 평균 약 $$\log_R n$$개 노드에서 끝납니다.
3. **접두사의 노드 아래에 그 접두사의 키가 전부 있습니다.**
   - 삭제는 값을 지우고 빈 노드를 아래에서부터 떼어 냅니다.
4. **트라이는 링크 대부분이 NULL입니다.**
   - 링크 수는 $$RN$$에서 $$RNw$$ 사이입니다.
5. **TST는 링크를 3개로 줄입니다.**
   - 작으면 왼쪽, 크면 오른쪽, 같으면 가운데로 다음 문자에 갑니다.
