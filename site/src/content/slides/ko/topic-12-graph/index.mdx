## 그래프

#### 그래프란
::sub[정점(vertex)들의 집합 V와 간선(edge)들의 집합 E]

- **정점**: 노드라고도 합니다. 개수는 $$n$$ 또는 $$V$$
- **간선**: 정점의 쌍입니다. 개수는 $$m$$ 또는 $$E$$
  - 무방향: 순서 없는 쌍 (친구 관계)
  - 방향: 순서 있는 쌍 (팔로우)
- **경로**: 간선으로 이어진 정점들의 순서열
- **사이클**: 첫 정점과 마지막 정점이 같은 경로
- **차수**: 한 정점에 붙은 간선의 수

</Slide>

<Slide>

#### 세상의 그래프
::sub[같은 두 정점을 잇는 간선이 여럿이면 평행 간선, 이 주제에는 없습니다]

- **소셜 네트워크**: 친구 관계(Facebook), 팔로워 관계(Instagram)
- **교통**: 지하철 노선도, 도로망, 항공편
- **웹**: 웹 페이지의 링크 구조, PageRank
- **추천 시스템**: 사용자와 상품의 관계(주제 15)
- **생물정보학**: 단백질 상호작용 네트워크

</Slide>

<Slide>

#### 간선은 몇 개까지
::sub[정점 n개, 평행 간선 없음, 연결된 무방향 그래프]

- **최소** $$n - 1$$개
  - 한 줄로 잇습니다. 하나라도 빼면 덩어리가 둘로 갈라집니다.
- **최대** $$\dfrac{n(n-1)}{2}$$개
  - 모든 쌍을 잇습니다. $$(n-1) + (n-2) + \dots + 1$$
  - 정점이 5개면 $$4 + 3 + 2 + 1 = 10$$개

<br/>

이 차이가 그래프 알고리즘의 비용을 가릅니다.

</Slide>

<Slide>

#### 그래프의 종류
::sub[간선의 수, 방향, 사이클]

- **희소**(sparse): $$m = O(n)$$
  - 소셜 네트워크
- **밀집**(dense): $$m = O(n^2)$$
  - 완전 그래프
- **방향 / 무방향**
- **사이클 있음 / 없음**
  - 방향이 있고 사이클이 없으면 DAG(directed acyclic graph)

</Slide>

<Slide>

#### 그래프로 묻는 질문
::sub[한 끗 차이로 쉬움과 어려움이 갈립니다]

| 질문 | 내용 | 어려움 |
| --- | --- | --- |
| 경로, 최단 경로 | s와 t 사이의 (가장 짧은) 경로 | 쉬움, 이 주제 |
| 연결성, MST | 모두 이어져 있나, 가장 싸게 잇기 | 쉬움, 이 주제 |
| 오일러 투어 | 모든 **간선**을 한 번씩 지나는 사이클 | 쉬움, $$O(V + E)$$ |
| 해밀턴 사이클 | 모든 **정점**을 한 번씩 지나는 사이클 | NP-complete |
| 평면성 | 간선이 교차하지 않게 그릴 수 있나 | $$O(V)$$지만 복잡 |
| 그래프 동형 | 두 인접 목록이 같은 그래프인가 | 아직 모름 |

</Slide>

#### 인접 행렬과 인접 목록
::sub[필요한 공간이 다릅니다]

- **인접 행렬**: $$n \times n$$ 행렬, $$A_{ij} = 1$$이면 i-j 간선이 있다.
  - 간선 개수나 가중치를 적는 변형도 있습니다.
  - 공간 $$\Theta(n^2)$$
- **인접 목록**: 정점마다 이웃의 목록
  - 정점 배열, 간선 배열, 서로를 가리키는 포인터
  - 공간 $$\Theta(n + m)$$, 무방향 간선은 양 끝에 한 칸씩

## 그래프 탐색
::sub[Graph Search]

</Slide>

<Slide>

#### 무엇을 하려는가
::sub[시작 정점 s에서 갈 수 있는 모든 정점을, 두 번 보지 않고, O(m + n)에]

**일반 탐색 알고리즘**

1. 처음에 s만 탐색했습니다.
2. 가능한 동안 되풀이합니다.
   - u는 탐색했고 v는 탐색하지 않은 간선 (u, v)를 고릅니다.
   - v를 탐색한 것으로 표시합니다.

<br/>

**주장**: 끝났을 때 v가 탐색됨 ⇔ s에서 v로 가는 경로가 있음

</Slide>

<Slide>

#### 왜 맞는가
::sub[귀류법: 경로가 있는데 v가 탐색되지 않았다고 해 봅시다]

- s는 탐색했고 v는 탐색하지 않았습니다.
- 그러면 경로 위에 "탐색한 u 다음에 탐색하지 않은 x"인 간선 (u, x)가 있습니다.
- 그런 간선이 남아 있으면 알고리즘은 끝나지 않습니다.
  - 모순입니다.

<br/>

남은 질문은 하나입니다.  
**경계에 걸친 간선이 여럿일 때 무엇부터 고르는가?**

</Slide>

<Slide>

#### BFS와 DFS
::sub[같은 일반 탐색, 고르는 순서만 다릅니다]

| | BFS | DFS |
| --- | --- | --- |
| 넓히는 방식 | 층별로, 가까운 것부터 | 한 갈래를 끝까지, 막히면 되돌아온다 |
| 자료구조 | 큐(FIFO) | 스택(LIFO) 또는 재귀 |
| 실행 시간 | $$O(m + n)$$ | $$O(m + n)$$ |
| 잘하는 일 | 가중치 없는 최단 경로, 연결 요소 | 위상 정렬, 연결 요소, 사이클 탐지 |

</Slide>

#### BFS
::sub[층(layer)별로 퍼져 나갑니다]

- s를 표시하고 FIFO 큐에 넣습니다.
- 큐가 빌 때까지 되풀이합니다.
  - 가장 먼저 들어온 정점 v를 꺼냅니다.
  - v의 이웃 중 표시되지 않은 것을 표시하고 큐에 넣습니다.

<br/>

간선 1개 거리를 모두 본 뒤에야 2개 거리로 넘어갑니다.  
이웃은 편의상 작은 번호부터 봅니다.

</Slide>

### 한 걸음씩: BFS(0)
::sub[초록은 다 본 정점, 파랑은 큐 안, 주황은 지금 꺼낸 정점 · 파란 숫자는 거리]

<GraphSearchDemo slide />

</Slide>

<Slide class="compact">

#### 절차
::sub[`01_bfs/bfs.pseudo` · 넣을 때 표시합니다]

```plaintext
marked[s] <- true,  dist[s] <- 0
enqueue s into Q
while Q가 비어 있지 않은 동안 do
    v <- dequeue from Q                 // 가장 먼저 들어온 정점
    for each w in adj[v] do             // 편의상 오름차순
        if not marked[w] then
            marked[w] <- true
            from[w] <- v
            dist[w] <- dist[v] + 1      // 한 층 아래
            enqueue w into Q
```

</Slide>

<Slide class="compact">

#### 실행
::sub[`01_bfs/` · 거리 1인 1, 2, 5, 6을 다 꺼낸 뒤에야 3, 4]

#### BFS의 성질과 최단 경로
::sub[n_s, m_s: s에서 닿는 정점과 간선의 수]

- **주장 1**: 끝났을 때 v가 탐색됨 ⇔ s에서 v로 가는 경로가 있음
- **주장 2**: 실행 시간 $$O(n_s + m_s)$$
  - 정점은 큐에 한 번 들어가고 한 번 나옵니다.
  - 간선은 양 끝에서 한 번씩 봅니다.
- **최단 경로**: $$\text{dist}(w) = \text{dist}(v) + 1$$
  - from을 거슬러 올라가면 경로가 나옵니다. 4 ← 5 ← 0
  - **모든 간선의 길이가 같을 때만** 최단입니다.

</Slide>

<Slide class="compact">

#### 응용: 연결 요소
::sub[아직 탐색되지 않은 정점마다 탐색을 한 번씩 시작합니다]

```plaintext
모든 정점을 탐색되지 않음으로 표시
for i <- 1 to n do
    if i가 아직 탐색되지 않았으면 then
        BFS(G, i)                       // i에서 닿는 정점이 한 연결 요소
```

- 여러 번 부르지만 정점과 간선은 통틀어 한 번씩만 봅니다.
  - $$O(m + n)$$
- DFS로도 같은 일을 합니다. 실습 코드는 DFS로 합니다.

</Slide>

#### DFS
::sub[한 갈래를 끝까지 파고든 뒤 되돌아옵니다]

- 정점 v를 방문한 것으로 표시합니다.
- v의 이웃 중 표시되지 않은 것마다 같은 일을 재귀적으로 합니다.
- 재귀 대신 LIFO 스택을 쓸 수도 있습니다.

<br/>

실습 코드의 스택 DFS는 **꺼낼 때** 표시합니다.  
같은 정점이 스택에 두 번 들어갈 수 있어서, 이미 방문했으면 버립니다.

</Slide>

#### 절차
::sub[`02_dfs/dfs.pseudo` · 스택 칸에는 (정점, 넣은 정점)]

```plaintext
push (s, -1) into S
while S가 비어 있지 않은 동안 do
    (v, p) <- pop from S                // 가장 나중에 넣은 정점
    if marked[v] then continue          // 이미 방문했으면 버린다
    marked[v] <- true                   // 꺼낼 때 표시한다
    from[v] <- p
    for each w in adj[v] do             // 편의상 오름차순으로 넣는다
        if not marked[w] then
            push (w, v) into S
```

#### 위상 정렬: 나가는 간선을 다 본 뒤에 번호를 준다

```plaintext
    for each 간선 (s, v) do

```

#### DFS로 하는 다른 일
::sub[경로, 도달 가능성, 사이클, 강하게 연결된 요소]

- **도달 가능성**
  - 닿지 않는 코드 제거, 빠져나올 수 없는 반복 탐지
  - 마크 스윕 가비지 컬렉터
- **방향 사이클 탐지**
  - Java의 순환 상속, 엑셀의 순환 참조
  - 방문 중인 정점으로 돌아가는 간선(back edge)이 있으면 사이클
- **강하게 연결된 요소**
  - Kosaraju-Sharir 알고리즘: DFS 두 번

</Slide>

#### BFS vs. DFS

#### Cut 속성

<div>

- **cut**: 정점을 비어 있지 않은 두 집합으로 나누기
- **crossing edge**: 두 집합을 잇는 간선
  - 파란 점선
- 가장 가벼운 0-2(0.26)가 MST에 있습니다.

#### Cut 속성의 증명
::sub[가장 가벼운 crossing edge e가 MST에 없다고 해 봅시다]

1. **MST에 e를 더하면 사이클이 생깁니다.**
2. **사이클의 다른 간선 f도 crossing edge입니다.**
   - 출발한 쪽으로 돌아오려면 cut을 한 번 더 건너야 합니다.
3. **f를 빼고 e를 넣어도 스패닝 트리입니다.**
4. **e가 f보다 가벼우므로 더 가벼운 스패닝 트리가 생깁니다.**
   - MST보다 가볍다. 모순입니다.

</Slide>

<Slide>

#### Greedy MST
::sub[cut 속성을 그대로 알고리즘으로]

1. 모든 간선을 칠하지 않은 채 시작합니다.
2. 칠한 crossing edge가 없는 cut을 찾아, 가장 가벼운 crossing edge를 칠합니다.
3. 칠한 간선이 $$V - 1$$개가 될 때까지 되풀이합니다.

<br/>

칠한 간선은 언제나 MST의 간선입니다.  
예: 0-2, 5-7, 6-2, 0-7, 2-3, 1-7, 4-5 순서로 칠해도 같은 MST  
"어떤 cut을 고르는가"를 정한 것이 Kruskal과 Prim입니다.

</Slide>

<Slide>

#### Greedy, Kruskal, Prim
::sub[모두 cut 속성 위에 선 그리디]

| | Greedy MST | Kruskal | Prim |
| --- | --- | --- | --- |
| 접근 | cut 속성 직접 | 간선 중심, 전역 선택 | 정점 중심, 지역 확장 |
| 시작점 | 아무 데나 | 가장 가벼운 간선 | 정한 정점 하나 |
| 시간 | 구현에 따라 | $$O(E \log E)$$ | $$O(E \log V)$$ |
| 전처리 | 없음 | 간선 정렬 | 없음 |
| 구현 | 어려움 (cut 관리) | 중간 (union-find) | 쉬움 (우선순위 큐) |

</Slide>

#### Kruskal
::sub[가벼운 간선부터, 사이클을 만들지 않는 한 넣습니다]

- 간선을 가중치 오름차순으로 정렬합니다.
- 정점마다 `comp`(덩어리 번호)를 둡니다. 처음에는 저마다 혼자입니다.
- 간선의 두 끝이
  - **다른 덩어리**면 넣고 덩어리를 합칩니다.
  - **같은 덩어리**면 이미 경로가 있으니 넣으면 사이클입니다. 버립니다.
- 간선이 $$V - 1$$개가 되면 멈춥니다.

### 한 걸음씩: Kruskal
::sub[먼저 가중치 순으로 줄 서고, 정점 옆 파란 숫자가 comp입니다]

#### 절차
::sub[`03_mst_kruskal/kruskal.pseudo` · 덩어리 번호는 그 안의 가장 작은 정점]

```plaintext
edges <- G의 간선을 가중치 오름차순으로 정렬
comp[v] <- v  (모든 v)
for each (u, v, w) in edges do
    if comp[u] != comp[v] then          // 다른 덩어리 -> 사이클 없음
        mst에 (u, v, w) 추가
        comp[u]와 comp[v]인 정점을 모두 min(comp[u], comp[v])로
        if |mst| = V - 1 then break
    else                                // 같은 덩어리 -> 넣으면 사이클
        (u, v)를 버린다
```

## 예제 4. 우선순위 큐와 최소 힙
::sub[Priority Queue, Min Heap]

</Slide>

<Slide>

#### 우선순위 큐
::sub[Prim, Dijkstra, 허프만이 모두 "지금 가장 작은 것"을 원합니다]

- **일반 큐**: FIFO
  - A, B, C, D를 넣으면 A → B → C → D
- **우선순위 큐**: 우선순위가 가장 높은 원소가 먼저
  - A(3), B(1), C(5), D(2)를 작은 값부터: B → D → A → C
- **같은 우선순위끼리의 순서는 보장하지 않습니다.**
  - 실습 코드와 데모는 먼저 넣은 것부터 꺼내도록 정했습니다.

</Slide>

<Slide class="compact">

#### 힙
::sub[완전 이진 트리 + 힙 속성]

- **완전 이진 트리**: 마지막 층만 빼고 꽉 차 있고, 마지막 층은 왼쪽부터
- **최소 힙**: 부모 값 ≤ 자식 값, 루트가 최솟값
- **최대 힙**: 부모 값 ≥ 자식 값, 루트가 최댓값

```plaintext
           1                 배열   [1, 2, 3, 4, 5, 6, 7, 8, 9]
       2       3             인덱스  0  1  2  3  4  5  6  7  8
     4   5   6   7
    8 9                      i의 부모 (i-1)/2,  자식 2i+1, 2i+2
```

</Slide>

<Slide>

#### 삽입과 최솟값 꺼내기
::sub[둘 다 한 층에 비교 한 번]

- **삽입**
  1. 가득 찼는지 확인합니다.
  2. 맨 끝 빈자리에 넣습니다.
  3. 부모보다 작으면 바꾸고 한 층 올라갑니다. **sift up**
- **최솟값 꺼내기**
  1. 비었는지 확인하고 루트를 저장합니다.
  2. 마지막 원소를 루트로 옮깁니다.
  3. 더 작은 자식보다 크면 바꾸고 한 층 내려갑니다. **sift down**

</Slide>

<Slide>

### 한 걸음씩: 최소 힙
::sub[insert 10, insert 0, extract min · 주황은 움직이는 원소, 파랑은 비교 상대]

#### 절차
::sub[`04_min_heap/minHeap.pseudo`]

```plaintext
HeapifyUp(heap, i):                       // sift up
    while i > 0 do
        p <- (i - 1) / 2
        if heap[i] >= heap[p] then break  // 부모보다 작지 않으면 제자리
        swap heap[i], heap[p],  i <- p

HeapifyDown(heap, i):                     // sift down
    loop
        m <- i, l <- 2i + 1, r <- 2i + 2
        if l < size and heap[l] < heap[m] then m <- l
        if r < size and heap[r] < heap[m] then m <- r
        if m = i then break               // 두 자식보다 크지 않으면 제자리
        swap heap[i], heap[m],  i <- m
```

</Slide>

- **힙 정렬**: 다 꺼내면 오름차순, $$O(n \log n)$$
- **주제 06의 허프만 코드**

  - 숲을 최소 힙에 담으면 $$O(k \log k)$$

## 예제 5. Prim 알고리즘
::sub[Prim's Algorithm, 1959]

</Slide>

<Slide>

#### Prim
::sub[정점 하나에서 트리를 욕심껏 키웁니다]

- 정점 0에서 시작합니다.
- 정확히 한 끝만 트리에 있는 간선 중 가장 가벼운 것을 더합니다.
- `key[v]`: 트리에 붙는 가장 가벼운 간선의 가중치
  - 최소 힙에서 key가 가장 작은 정점을 꺼냅니다.
  - key가 줄면 고쳐서 **새로 넣습니다.** 낡은 항목은 꺼낼 때 버립니다.

<br/>

주제 06에서 말한 "지금 가장 가까운 것"이 바로 이 정점입니다.

</Slide>

<Slide>

### 한 걸음씩: Prim
::sub[`0.26:2`는 key 0.26으로 정점 2 · 줄 그어진 항목은 낡은 항목]

<HeapGraphDemo mode="prim" slide />

</Slide>

<Slide class="compact">

#### 절차
::sub[`05_mst_prim/prim.pseudo`]

```plaintext
key[s] <- 0,  insert (0, s) into PQ
while PQ가 비어 있지 않고 |mst| < V - 1 동안 do
    (k, u) <- ExtractMin(PQ)            // 지금 트리에 가장 가까운 정점
    if inTree[u] then continue          // 낡은 항목은 버린다
    inTree[u] <- true
    if u != s then mst에 (via[u], u, k) 추가
    for each (u, v, w) in adj[u] do
        if not inTree[v] and w < key[v] then
            key[v] <- w,  via[v] <- u   // 더 가벼운 간선
            insert (w, v) into PQ       // 갱신 대신 새로 넣는다
```

</Slide>

<Slide class="compact">

::sub[`05_mst_prim/` · 4의 key는 0.38, 0.37, 0.35로 두 번 줄었습니다]

```console
pop 4 (key 0.35): add 5-4
pop 4 (key 0.37): skip, already in tree
pop 4 (key 0.38): skip, already in tree
pop 6 (key 0.40): add 2-6

```

트리에 붙는 순서는 0, 7, 1, 2, 3, 5, 4, 6입니다.

#### 분석
::sub[Kruskal과 같은 간선 일곱 개, 같은 1.81]

- **정확성**: Greedy MST의 특수한 경우
  - "지금의 트리"와 "나머지"를 cut으로 보면, 고른 간선이 가장 가벼운 crossing edge
- **시간**: $$O(E \log E) = O(E \log V)$$
  - 힙 항목은 간선마다 많아야 하나
  - $$E \le V^2$$이므로 $$\log E \le 2 \log V$$
- **Kruskal과 다른 점**
  - Kruskal은 여러 덩어리가 자라다 합쳐집니다.
  - Prim은 처음부터 끝까지 한 덩어리가 자랍니다.

</Slide>

뒤 절반: 같은 힙 틀로 **가장 짧은 길**을 찾습니다.

## 최단 경로
::sub[Shortest Path]

</Slide>

<Slide>

#### 최단 경로
::sub[가중치가 있는 방향 그래프 G = (V, E)]

- s에서 t까지 간선 가중치의 합이 가장 작은 경로
  - 무방향 그래프는 양방향 간선 둘을 둔 방향 그래프로 봅니다.
- **변형**
  - 한 쌍: s에서 t까지
  - 단일 출발점: s에서 다른 모든 정점까지 (Dijkstra)
  - 모든 쌍
- 길이는 간선 수가 아니라 **가중치의 합**입니다.

</Slide>

<Slide>

#### 왜 또 다른 최단 경로 알고리즘인가
::sub[BFS가 이미 선형 시간에 최단 경로를 구하지 않나요?]

- BFS는 **모든 간선의 가중치가 1일 때만** 최단입니다.
- 간선 셋을 지나는 3 + 3 + 3 = 9짜리 길과 간선 하나짜리 20짜리 길이 있으면?
  - BFS는 간선 하나짜리를 먼저 찾고 멈춥니다.

<br/>

**해결책: Dijkstra 최단 경로 알고리즘**

## 예제 6. Dijkstra 알고리즘
::sub[Dijkstra's Algorithm]

</Slide>

<Slide>

#### Dijkstra
::sub[출발점 하나에서 다른 모든 정점까지의 최단 거리]

1. $$\text{dist}[s] = 0$$, 나머지는 $$\infty$$
2. 확정한 정점의 집합 $$X = \{s\}$$
3. $$X \ne V$$인 동안
   - v ∈ X, w ∉ X인 간선 중 $$\text{dist}[v] + w(v, w)$$가 가장 작은 w를 X에 넣습니다.
   - w에서 나가는 간선으로 이웃의 dist를 줄여 봅니다. **완화**(relaxation)

<br/>

거리가 멀어지는 순서대로 하나씩 확정해 나갑니다.

</Slide>

<Slide>

#### Dijkstra와 Prim
::sub[둘 다 최소 힙으로 "지금 가장 작은 값"을 고르는 그리디]

| | Dijkstra | Prim |
| --- | --- | --- |
| 목적 | 최단 경로 | 최소 스패닝 트리 |
| 고칠 때 쓰는 값 | $$\text{dist}[u] + w(u, v)$$ | $$w(u, v)$$ |
| 값의 뜻 | 출발점부터 **쌓인** 거리 | 간선 **하나**의 가중치 |
| 결과 | 모든 정점까지의 최단 거리 | 모든 정점을 잇는 최소 비용 |

</Slide>

### 한 걸음씩: Dijkstra

#### 절차
::sub[`06_dijkstra/dijkstra.pseudo` · Prim에서 바뀐 것은 값을 고치는 한 줄]

```plaintext
dist[s] <- 0,  insert (0, s) into PQ
while PQ가 비어 있지 않은 동안 do
    (d, u) <- ExtractMin(PQ)            // 확정 안 된 정점 중 가장 가까운 것
    if done[u] then continue            // 낡은 항목은 버린다
    done[u] <- true                     // 이 거리는 이제 바뀌지 않는다
    for each (u, v, w) in adj[u] do
        if not done[v] and dist[u] + w < dist[v] then
            dist[v] <- dist[u] + w      // 완화
            from[v] <- u
            insert (dist[v], v) into PQ
```

</Slide>

<Slide class="compact">

#### 실행
::sub[`06_dijkstra/` · 2의 거리는 17, 15, 14로 줄었습니다]

- 실행 (끝부분)

```console
  v  dist  from
  0     0     -
  1     5     0
  2    14     5
  3    17     2
  4     9     0
  5    13     4
  6    25     2
  7     8     0
path 0 -> 6: 0 4 5 2 6 (25)
```

확정 순서 0, 1, 7, 4, 5, 2, 3, 6  
확정한 거리 0, 5, 8, 9, 13, 14, 17, 25는 줄어들지 않습니다.

</Slide>

#### 왜 맞는가
::sub[가중치가 음수가 아닌 방향 그래프]

- 간선 v → w는 v를 확정할 때 **정확히 한 번** 완화됩니다.
  - 그 직후 $$\text{dist}[w] \le \text{dist}[v] + w(v, w)$$
- 이 부등식은 끝날 때까지 유지됩니다.
  - $$\text{dist}[w]$$는 줄어들기만 합니다.
  - $$\text{dist}[v]$$는 확정 뒤 바뀌지 않습니다. 가중치가 음수가 아니니까요.
- 끝나면 모든 간선에서 성립하므로 dist가 최단 거리입니다.

</Slide>

<Slide>

#### 실행 시간
::sub[우선순위 큐를 무엇으로 만드느냐에 따라 · * 분할 상환]

| 자료구조 | 넣기 | 최솟값 꺼내기 | 값 고치기 | 합계 |
| --- | --- | --- | --- | --- |
| 정렬 안 된 배열 | $$1$$ | $$V$$ | $$1$$ | $$V^2$$ |
| 이진 힙 | $$\log V$$ | $$\log V$$ | $$\log V$$ | $$E \log V$$ |
| d-way 힙 | $$\log_d V$$ | $$d \log_d V$$ | $$\log_d V$$ | $$E \log_{E/V} V$$ |
| 피보나치 힙 | $$1^*$$ | $$\log V^*$$ | $$1^*$$ | $$E + V \log V$$ |

<br/>

밀집 그래프는 배열, 희소 그래프는 이진 힙이 낫습니다.  
피보나치 힙의 합계는 $$E + \log V$$가 아니라 $$E + V \log V$$입니다.

</Slide>

## 예제 7. A* 알고리즘
::sub[A Star Algorithm]

#### A*
::sub[목표 하나까지, 남은 거리의 추정값으로 목표 쪽부터]

- Dijkstra는 **모든** 정점까지 구합니다. 길찾기는 대개 **목표 하나**면 됩니다.
- 게임, 로봇 경로 탐색, 지리 정보 시스템(GIS)
- 노드마다 세 값
  - $$g(n)$$: 시작에서 n까지의 **실제** 거리
  - $$h(n)$$: n에서 목표까지 남은 거리의 **추정**(휴리스틱)
  - $$f(n) = g(n) + h(n)$$: 이 노드를 거치는 경로의 예상 총비용
- $$f$$가 가장 작은 노드부터 엽니다.

</Slide>

<Slide>

#### 휴리스틱 함수 h(n)
::sub[진리관 A에서 메가박스까지 · 기숙사 C동 앞에서 친구에게]

- "한 10분이면 가." 실제에 가깝고 넘지 않습니다. **좋은 추정**
- "2분이면 가." 넘지는 않지만 너무 낙관적이라 **길잡이가 못 됩니다.**
  - 모든 곳에서 0이면 Dijkstra와 같습니다.
- 15분 걸리는 곳을 "30분"이라 하면 그 길을 피하다 **최단 경로를 놓칩니다.**

<br/>

거리 휴리스틱: 직선 거리, 맨해튼 거리, 체비쇼프 거리

</Slide>

<Slide>

#### 가까워 보이는 곳이 답은 아니다
::sub[여기까지 2분 걸려 왔고, 갈 수 있는 곳이 셋]

| 다음 지점 | 걸리는 시간 | $$g$$ | $$h$$ | $$f = g + h$$ |
| --- | --- | --- | --- | --- |
| A동 | 5분 | $$2 + 5 = 7$$ | 10 | 17 |
| C동 | 3분 | $$2 + 3 = 5$$ | 10 | **15** |
| 종합관 | 1분 | $$2 + 1 = 3$$ | 17 | 20 |

<br/>

가장 가까운 종합관은 목표에서 멀어지는 쪽입니다. A*는 C동을 고릅니다.

</Slide>

### 한 걸음씩: 다시 열지 않는 A*

#### 26은 최단이 아니다
::sub[같은 그래프에서 Dijkstra는 0 → 4 → 5 → 2 → 6, 25]

- 0 → 7 → 2 → 6, **26**은 최단 경로가 아닙니다.
- 갈림길은 5를 닫을 때입니다.
  - 5에서 2로 가면 $$g = 14$$, 지금의 15보다 짧습니다.
  - 그런데 2는 이미 닫혀 있어 그냥 지나갑니다.
  - 2의 $$g$$가 15로 굳고, 6도 26으로 굳습니다.

</Slide>

<Slide>

#### 휴리스틱의 두 조건
::sub[h*(n): n에서 목표까지의 실제 최단 거리]

- **허용성**(admissible): $$h(n) \le h^*(n)$$
  - 과대평가하지 않습니다. **다시 열기를 허용하면** 최단 경로를 찾습니다.
- **일관성**(consistent): $$h(n) \le c(n, n') + h(n')$$
  - **다시 열지 않아도** 최단 경로를 찾습니다. 더 강한 조건입니다.
- 이 예의 h는 허용적이지만 일관적이지 않습니다.
  - $$h(4) = 11 > 4 + h(5) = 10$$
  - $$h(5) = 6 > 1 + h(2) = 5$$

</Slide>

### 한 걸음씩: 다시 열기
::sub[닫힌 정점으로 가는 더 짧은 길을 찾으면 다시 엽니다]

<HeapGraphDemo mode="astar" slide />

</Slide>

#### 절차
::sub[`07_a_star/aStar.pseudo` · Dijkstra와 다른 곳: 키가 g + h, 목표에서 멈춤, 다시 열기]

```plaintext
g[s] <- 0,  insert (g[s] + h[s], s) into open
while open이 비어 있지 않은 동안 do
    (f, u) <- ExtractMin(open)          // f가 가장 작은 정점
    if closed[u] then continue          // 낡은 항목은 버린다
    if u = t then return 경로, g[t]
    closed[u] <- true
    for each (u, v, w) in adj[u] do
        if g[u] + w >= g[v] then continue
        if closed[v] and not reopen then continue
        closed[v] <- false              // (reopen일 때) 다시 연다
        g[v] <- g[u] + w,  cameFrom[v] <- u
        insert (g[v] + h[v], v) into open
```

</Slide>

<Slide class="compact">

```console
  3: g 17, f 19
  6: g 25, f 25

```

#### 분석
::sub[b: 분기 계수, d: 최적해의 깊이]

- **시간**: 최악 $$O(b^d)$$, 실제로는 휴리스틱에 달려 있습니다.
  - 완벽한 휴리스틱($$h = h^*$$): $$O(d)$$, 이 예에서는 0, 4, 5, 2만 닫습니다.
  - 정보 없는 휴리스틱($$h = 0$$): Dijkstra와 같습니다.
- **공간**: $$O(b^d)$$, 열린 목록과 닫힌 목록을 모두 들고 있습니다.
- **더 다듬기**
  - IDA*(메모리), 양방향 A*, 계층적 경로 탐색
  - 패턴 데이터베이스, 머신러닝 휴리스틱

</Slide>

## 남길 것

1. **인접 목록은 $$\Theta(n + m)$$, 인접 행렬은 $$\Theta(n^2)$$입니다.**
   - 탐색에는 목록이 맞습니다.
2. **BFS와 DFS는 같은 일반 탐색입니다.**
   - 큐면 층별로 가서 최단 경로를, 스택이면 깊이 먼저 가서 위상 정렬을 풉니다.
   - 둘 다 $$O(m + n)$$
3. **cut 속성 위에 Kruskal과 Prim이 섭니다.**
   - 고르는 cut만 다른 그리디, 예제의 MST는 1.81
4. **최소 힙은 sift up, sift down 모두 $$O(\log n)$$입니다.**
5. **Prim, Dijkstra, A*는 같은 틀입니다.**
   - 힙의 키가 간선 하나, 쌓인 거리, 쌓인 거리 + 추정
