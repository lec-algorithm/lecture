### 分治
::sub[divide and conquer · 三个步骤]

- **分（divide）**
  - 把问题拆成同样形状的小问题。
- **治（conquer）**
  - 解决小问题。
  - 足够小就直接解，否则继续拆。
- **合（combine）**
  - 把小答案拼成整体的答案。

</Slide>

::sub[主题 01 的二分查找就是分治]

- **合**：无事可做。

<br/>

#### 参考：乘法也能拆
::sub[卡拉楚巴（Karatsuba）· 大乘法拆成小乘法]

$$
1234 \times 5678 = (12 \cdot 100 + 34)(56 \cdot 100 + 78)
$$

$$
= a \cdot 10^4 + b \cdot 10^2 + c
$$

<br/>

- $$a = 12 \times 56$$
- $$b = 12 \times 78 + 34 \times 56$$
- $$c = 34 \times 78$$

<br/>

直接算需要 **4 次**两位数乘法。

</Slide>

<Slide>

#### 4 次乘法变 3 次
::sub[用 a 和 c 换掉 b]

$$
b = (12 + 34)(56 + 78) - a - c
$$

- $$a$$ 和 $$c$$ 反正都要算。
- 新的乘法只有 $$(12+34)(56+78) = 46 \times 134$$ **一次**。

<br/>

- 递归地做下去，$$O(n^2)$$ 变成 $$O(n^{\log_2 3}) \approx O(n^{1.585})$$。
- 验算：$$672 \cdot 10^4 + 2840 \cdot 10^2 + 2652 = 7{,}006{,}652$$

#### 写成过程
::sub[单个元素本来就有序，那里是递归的底部]

```plaintext
ALGORITHM MergeSort(A, lo, hi)
    if lo >= hi then return          // 单个元素：本来就有序
    mid <- (lo + hi) / 2
    MergeSort(A, lo, mid)            // 左半
    MergeSort(A, mid+1, hi)          // 右半
    Merge(A, lo, mid, hi)            // 合并有序的两半
```

和主题 01 的斐波那契一样，是**调用自己的定义**。  
不同之处：左右两段不重叠，同一个值不会被算两遍。

#### 写成代码 1. merge
::sub[`01_merge_sort/` · `<=` 让相同的值左边先出：稳定]

<div class="aas-split">
<div>

- `mergeSort.c`

```c
static void merge(int a[], int lo, int mid,
                  int hi, int temp[],
                  int *comparisons, int *moves) {
    int i = lo;
    int j = mid + 1;
    int k = lo;
    while (i <= mid && j <= hi) {
        (*comparisons)++;
        if (a[i] <= a[j]) {
            temp[k++] = a[i++];
        } else {
            temp[k++] = a[j++];
        }
        (*moves)++;
    }
    while (i <= mid) {
        temp[k++] = a[i++];
        (*moves)++;
    }
    while (j <= hi) {
        temp[k++] = a[j++];
        (*moves)++;
    }
    for (k = lo; k <= hi; k++) {
        a[k] = temp[k];
        (*moves)++;
    }
}
```

</div>
<div>

- `merge_sort.py`

```python
def _merge(a, lo, mid, hi, temp, counts):
    i, j, k = lo, mid + 1, lo
    while i <= mid and j <= hi:
        counts[0] += 1
        if a[i] <= a[j]:
            temp[k] = a[i]
            i += 1
        else:
            temp[k] = a[j]
            j += 1
        counts[1] += 1
        k += 1
    while i <= mid:
        temp[k] = a[i]
        i += 1; k += 1
        counts[1] += 1
    while j <= hi:
        temp[k] = a[j]
        j += 1; k += 1
        counts[1] += 1
    for k in range(lo, hi + 1):
        a[k] = temp[k]
        counts[1] += 1
```

```c
void mergeSort(int a[], int lo, int hi,
               int temp[],
               int *comparisons, int *moves) {
    if (lo >= hi) {
        return;
    }
    int mid = lo + (hi - lo) / 2;
    mergeSort(a, lo, mid,
              temp, comparisons, moves);
    mergeSort(a, mid + 1, hi,
              temp, comparisons, moves);
    merge(a, lo, mid, hi,
          temp, comparisons, moves);
}
```

#### 为什么是 n log n
::sub[任何一层，被合并的元素加起来都是 n]

```plaintext
第 0 层              [########  n  ########]      代价 n
第 1 层          [### n/2 ###]  [### n/2 ###]     代价 n
第 2 层        [ n/4 ] [ n/4 ]  [ n/4 ] [ n/4 ]   代价 n
  ⋮                       ⋮                        ⋮
第 log n 层    [1] [1] [1]  ⋯   [1] [1] [1]       （底部）
```

- 对半分，层数是 $$\log_2 n$$。
- 每层代价 $$n$$，所以总共 $$O(n \log n)$$。

</Slide>

<Slide>

#### 换了输入
::sub[最好、平均、最坏都是 O(n log n)]

| 输入 | 比较次数 | 移动次数 |
| --- | --- | --- |
| 示例数组 | $$22$$ | $$68$$ |
| 已排序 | $$19$$ | $$68$$ |
| 逆序 | $$15$$ | $$68$$ |

<br/>

- **移动永远是 68 次。**每次归并整段都经 temp 往返。
- **逆序比已排序的比较更少。**一边提前取完，
  剩下的不用比较直接倒进去。

</Slide>

<Slide>

#### 付出的代价
::sub[不是免费的]

- **空间 $$O(n)$$**
  - 需要临时数组 temp。
  - 主题 02 的四种排序全是 $$O(1)$$。
- **稳定排序**
  - `merge` 里的 `<=` 让相同的值左边先出。
  - 改成 `<`，答案不变，稳定性没了。

</Slide>

<Slide>

### 决策树
::sub[把比较画成一棵树 · n = 3]

```plaintext
              a[0] < a[1] ?
        是 ↙              ↘ 否
  a[1] < a[2] ?          a[0] < a[2] ?
   ↙        ↘             ↙        ↘
[0 1 2]  a[0] < a[2]?  [1 0 2]  a[1] < a[2]?
          ↙    ↘                 ↙    ↘
      [0 2 1] [2 0 1]        [1 2 0] [2 1 0]
```

- 每个结点一次比较，分支是它的结果。
- 叶子是排序结果（排列）。$$3! = 6$$ 种全在。

</Slide>

<Slide>

#### 叶子 n! 个，高度就是比较次数
::sub[三行的证明]

1. 叶子**至少要有 $$n!$$ 个**。
   - 少了哪个排列，算法在那个输入上就错。
2. 高度为 $$h$$ 的二叉树，叶子**至多 $$2^h$$ 个**。
3. 于是 $$2^h \geq n!$$，即 $$h \geq \log_2(n!)$$。

<br/>

而 $$h$$ 正是**最坏情况的比较次数**。

</Slide>

<Slide>

#### 下界：Ω(n log n)
::sub[斯特林近似收尾]

$$
\log_2(n!) \approx n \log_2 n
$$

- **任何比较排序在最坏情况下都要比较 $$\Omega(n \log n)$$ 次。**
- 归并排序的阶已经贴着这条下界。
  - 没有比较排序能好过这个阶。

</Slide>

<Slide>

#### 用数字量一下
::sub[n = 10]

- $$\lceil \log_2 10! \rceil = 22$$
- 10 个元素靠比较来排，最坏至少要比 **22 次**。
- 我们的归并排序在示例数组上用的恰好是 **22 次**。

</Slide>

<Slide class="center">

#### 写成过程
::sub[计数、累加、从后往前放]

```plaintext
ALGORITHM CountingSort(A, n, k)
    // 1) 计数：每个值有几个
    for v <- 0 to k do count[v] <- 0
    for i <- 0 to n-1 do
        count[A[i]] <- count[A[i]] + 1

    // 2) 累加：值 v 结束的位置（个数和）
    for v <- 1 to k do
        count[v] <- count[v] + count[v-1]

    // 3) 放置：从后往前读，放进该去的位置
    for i <- n-1 downto 0 do
        count[A[i]] <- count[A[i]] - 1
        B[count[A[i]]] <- A[i]
```

```c
void countingSort(const int a[], int b[],
                  int n, int count[],
                  int *moves) {
    for (int v = 0; v <= MAX_KEY; v++) {
        count[v] = 0;
    }
    for (int i = 0; i < n; i++) {
        count[a[i]]++;
    }
    for (int v = 1; v <= MAX_KEY; v++) {
        count[v] += count[v - 1];
    }
    for (int i = n - 1; i >= 0; i--) {
        count[a[i]]--;
        b[count[a[i]]] = a[i];
        (*moves)++;
    }
}
```

### 为什么从后往前
::sub[给相同的值挂名牌：甲乙丙的顺序保住了]

#### 稳定性成立的原因
::sub[累加数组记着每个值的最后一个位置]

- 累加值是值 $$v$$ 那一段的**结束位置**。
- 从后往前读，相同值里靠后的拿到靠后的位置。
  - 原来的顺序保住了。**稳定排序**。
- 改成从前往后读，结果照样有序，但相同值的顺序翻过来。
  - 实践代码的**改改看**会带着做。

</Slide>

<Slide>

#### 分析
::sub[不是打破下界，而是站在前提之外]

- 计数 $$O(n)$$，累加 $$O(k)$$，放置 $$O(n)$$ → 总共 $$O(n + k)$$
- $$k$$ 和 $$n$$ 差不多大时，相当于 $$O(n)$$。
- $$\Omega(n \log n)$$ 是**比较排序**的下界。
  - 不做比较，决策树的论证就套不上来。

</Slide>

<Slide>

#### 付出的代价
::sub[不是免费的]

- **键必须是窄范围的整数。**
  - 实数、字符串、范围未知的值都不行。
  - 比较排序只要能比较，什么都能排。
- **空间 $$O(n + k)$$**
  - `MAX_KEY` 提到一百万：11 个元素配一百万个格子。

<br/>

分数（0\~100）、年龄、月份（1\~12）：**又窄又密的整数键**
才是计数排序的主场。

</Slide>

### 六种排序并排看
::sub[付出什么，得到什么]

| 排序 | 最好 | 平均 | 最坏 | 空间 | 稳定性 | 类别 |
| --- | --- | --- | --- | --- | --- | --- |
| 选择 | $$O(n^2)$$ | $$O(n^2)$$ | $$O(n^2)$$ | $$O(1)$$ | 不稳定 | 比较 |
| 插入 | $$O(n)$$ | $$O(n^2)$$ | $$O(n^2)$$ | $$O(1)$$ | 稳定 | 比较 |
| 希尔 | $$O(n \log n)$$ | $$O(n^{1.5})$$ | $$O(n^2)$$ | $$O(1)$$ | 不稳定 | 比较 |
| 冒泡 | $$O(n^2)$$ | $$O(n^2)$$ | $$O(n^2)$$ | $$O(1)$$ | 稳定 | 比较 |
| 归并 | $$O(n \log n)$$ | $$O(n \log n)$$ | $$O(n \log n)$$ | $$O(n)$$ | 稳定 | 比较 |
| 计数 | $$O(n+k)$$ | $$O(n+k)$$ | $$O(n+k)$$ | $$O(n+k)$$ | 稳定 | 非比较 |

## 要带走的

1. **分治缩小的是活本身。**
   - 分、治、合。一个人做也变快。
2. **拆与合是跷跷板。**
   - 归并排序拆免费，快速排序合免费。
3. **归并排序：每层 n，共 log n 层。**
   - 最好、平均、最坏一致，稳定，付 $$O(n)$$ 空间。
4. **比较排序的下界是 $$\Omega(n \log n)$$。**
   - 决策树至少要 $$n!$$ 个叶子。
5. **计数排序站在下界的前提之外。**
   - 窄范围整数键：零比较，$$O(n + k)$$。

</Slide>
