比较任何东西

*高级算法*

## 要做的事只有一件
::sub[主题自由，做的事固定]

- 选一个你感兴趣的问题。
- 找出已经在解决它的**三种以上现有方法**。
- 在**相同条件**下亲手运行这三种方法。
- 说明什么在哪里更快、什么在哪里崩掉，以及为什么。
- 整理优缺点，并写出发展方向。

</Slide>

## 主题的条件有三个
::sub[守住这三条，选什么都可以]

| 条件 | 含义 |
| --- | --- |
| 能以代码运行 | 能产生结果，并且可以测量时间或次数 |
| 存在多种方法 | 解决同一问题的方法已经有三种以上 |
| 可以公开 | 不使用无法放进公开仓库的数据 |

</Slide>

## 先定下比较标准
::sub["哪一个更好"，没有标准就无法回答]

- **速度**：运行时间，或比较次数、运算次数
- **内存**：额外占用的空间
- **结果的质量**：准确率、压缩率、命中率
- **随输入的变化**：规模变大时、输入有偏时
- **实现成本**：代码长度、花掉的时间

<br/>

标准要定**两个以上**。  
除此之外，只要是能用数值表示的项目都可以。

</Slide>

<Slide>

### 把表上的阶和测到的数字对照
::sub[对不上的地方，正是报告的核心]

- 标着 $$O(n \log n)$$ 的方法在小输入上更慢是常见的事。
- 常数、缓存和实现上的差别会在那里显现。
- 不要把[[time-complexity]]写进表格就算完事。
  - 要和实际测到的数字对照。
  - 对不上时，说明**为什么对不上**。

</Slide>

### 中期提交（10 月 18 日）
::sub[大约 10 页幻灯片，以 PDF 提交]

| 页 | 内容 |
| --- | --- |
| 1 | 标题、学号、姓名 |
| 2 | 选定的主题和选它的理由 |
| 3 | 用一句话写出要解决的问题 |
| 4\~6 | 要比较的三种方法，每种一页 |
| 7 | 比较标准与测量方法 |
| 8 | 实验设计（输入数据、规模、重复次数） |

这八页必须有，剩下的页数自由使用。

</Slide>

<Slide>

### 最终提交 ① 报告
::sub[12 月 13 日，以 PDF 提交]

1. 主题与动机
2. 三种方法的说明
3. 比较标准与实验设计
4. 实验结果（表 · 图表 · 运行画面截图）
5. 解读：为什么会出现这样的结果
6. 优缺点整理
7. 发展方向
8. 参考资料与 AI 使用记录

<br/>

篇幅最少 5 页，最多 20 页。  
用 Markdown、Word 或 Hangul 写都可以，**提交的是 PDF**。

</Slide>

<Slide>

### 最终提交 ② 代码
::sub[别人要能照着跑起来]

- 必须提交 GitHub 仓库 **URL**，写在报告第一页。
- 同时提交 **Code > Download ZIP** 下载到的 zip 文件。
- 把运行方法写进 `README.md`。
- 实验用的输入数据也要上传。
  - 数据太大时，上传生成数据的脚本。

</Slide>

## 评分考察的五点

- **能跑起来的代码**：三种方法确实都能运行，并在相同条件下比较
- **测量**：标准明确，数字可以再次得到
- **解读**：把结果与理论联系起来加以说明
- **结论**：优缺点与发展方向出自你自己的判断
- **文档**：别人读了就能照着运行

<br/>

主题有多难不计入分数。  
把简单的主题做到底的一方得分更高。

</Slide>

<Slide>

## 必须遵守的事

- **可以使用 AI**。
  - 用它来理解自己不懂的方法，甚至是推荐的做法。
  - 在报告里写清楚你问了什么、得到了什么。
- **可以使用别人的代码**。
  - 写明出处，并说明自己改了哪里。
  - 没有出处而照搬的代码不给分。
- 报告和代码用**韩语或英语**撰写。
- 仓库是公开的。不要使用包含个人信息的数据。

</Slide>
