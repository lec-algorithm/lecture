## 本主题
::sub[从主题 03 的计数排序出发]

- **基数排序**：把键拆成位，每一位做一次计数排序。
  - 从低位开始（LSD），从高位开始（MSD）
- **后缀数组**：把字符串的所有后缀排好序。
  - LCP 数组、最长重复子串、最长公共子串
- **栈与队列**：基数排序的桶应该是哪一种？

</Slide>

## 从计数排序到基数排序
::sub[Radix Sort]

</Slide>

<Slide>

#### 计数排序的局限
::sub[主题 03：不做比较，O(n + k)]

- 数出每个值有几个，做累加，再从后往前放到该放的位置。
- 元素之间不做比较，所以处在 $$\Omega(n \log n)$$ 下界的**前提之外**。
- **代价是需要与值域 $$k$$ 一样大的计数数组**。
  - 值在 0 到 999 之间，就要 1000 格。
  - 范围是一百万，就有近百万格闲着、几乎全是 0。

</Slide>

<Slide>

#### 把键拆成位
::sub[基数（radix）= 进制的底 = 一位能取的值的个数]

- 十进制的一位只有 0 到 9 这**十种**。
- 三位数不跑一次 1000 格的计数排序，  
  而是**跑三次 10 格的计数排序**。
- 字符串的话一个字符就是一位，一个字节有 256 种取值。

<br/>

| 方向 | 名称 |
| --- | --- |
| 最低位 → 最高位 | **LSD**（least significant digit） |
| 最高位 → 最低位 | **MSD**（most significant digit） |

</Slide>

#### LSD 基数排序
::sub[从最低位开始，不做比较的排序]

- **核心思想**
  - 对每一位应用计数排序。
  - 这个计数排序必须是**稳定**的。
  - 按从低位到高位的顺序排序。

<br/>

`437 42 531 8 74` → 对齐位数成 `437 042 531 008 074`  
按个位、十位、百位的顺序排三次。

#### 写成过程
::sub[`01_lsd_radix_sort/lsdRadixSort.pseudo`]

```plaintext
ALGORITHM LsdRadixSort(A, n)
    max <- A 的最大值
    exp <- 1
    while max / exp > 0 do              // exp = 1, 10, 100, ...
        CountingSortByDigit(A, n, exp)
        exp <- exp * 10

ALGORITHM CountingSortByDigit(A, n, exp)   // 主题 03 的计数排序，键是一位
    for i <- 0 to n-1 do                   // 1) 计数
        count[(A[i] / exp) mod 10] += 1
    for d <- 1 to 9 do                     // 2) 累加
        count[d] += count[d-1]
    for i <- n-1 downto 0 do               // 3) 从后往前放：稳定
        d <- (A[i] / exp) mod 10
        count[d] -= 1
        B[count[d]] <- A[i]
    A <- B
```

</Slide>

#### 写成代码
::sub[`01_lsd_radix_sort/lsdRadixSort.c`]

```c
void countingSortByDigit(int a[], int n, int exp) {
    int output[MAX_N];
    int count[RADIX] = {0};
    for (int i = 0; i < n; i++) {               /* 1) 计数 */
        count[(a[i] / exp) % RADIX]++;
    }
    for (int d = 1; d < RADIX; d++) {           /* 2) 累加 */
        count[d] += count[d - 1];
    }
    for (int i = n - 1; i >= 0; i--) {          /* 3) 从后往前放 */
        int d = (a[i] / exp) % RADIX;
        output[--count[d]] = a[i];
    }
    /* 4) 把 output 复制回 a */
}
```

`lsdRadixSort` 以 `exp = 1, 10, 100` 调用这个函数三次。

#### 为什么必须稳定
::sub[每一趟都保持的一条性质]

> **第 $$p$$ 趟结束后，只看低 $$p$$ 位就是有序的**。

<br/>

第 $$p + 1$$ 趟中，两个元素的第 $$(p + 1)$$ 位

- **不同**：这一趟会把顺序排对。
- **相同**：顺序该由低 $$p$$ 位决定，而这个顺序已经在数组里了。
  - 这一趟**不能去动**这个顺序。这就是稳定性。

</Slide>

#### 分析
::sub[d：位数，k：一位能取的值的个数]

- **时间** $$O(d(n + k))$$
  - 做 $$d$$ 次 $$O(n + k)$$ 的计数排序。
  - 不管输入如何都要看完所有位，所以最好、平均、最坏都一样。
- **空间** $$O(n + k)$$
  - 输出数组 $$n$$ 格加计数数组 $$k$$ 格

</Slide>

<Slide>

#### 优缺点
::sub[LSD Radix Sort]

| 优点 | 缺点 |
| --- | --- |
| 稳定排序，相同键的顺序得以保持 | 需要额外内存 $$O(n + k)$$ |
| 位数固定时是线性时间 $$O(n)$$ | 只适用于能拆成位的键（整数、定长字符串） |
| 性能与输入无关，始终如一 | 位数一多，趟数增加，速度变慢 |

</Slide>

<Slide>

#### 怎样避开比较排序的下界
::sub[不是违反了下界，而是处在下界的前提之外]

- 决策树论证的前提是**只要靠比较元素来排序**。
- 基数排序的元素之间一次也不比较。
  - 读出一个数字，直接用这个值算出位置。
  - 决策树的分叉是两路，基数排序的一步是 $$k$$ 路。

</Slide>

<Slide>

#### 并不是免费的
::sub[位数 d 随 n 一起增长时]

- 要装下 $$n$$ 个互不相同的值，位数至少是 $$\log_k n$$。
- 值的范围随 $$n$$ 增长时，$$O(d \cdot n)$$ 又回到 $$O(n \log n)$$ 的形状。

<br/>

基数排序大放异彩的地方是**键长固定**的数据。  
像 32 位整数、身份证号、邮政编码这样 $$d$$ 已经定好，就是 $$O(n)$$。

</Slide>

#### MSD 基数排序
::sub[从最高位开始，分治]

- 按最高位做计数排序，相同数字的元素聚在同一段里。
  - 这一段就是**桶**。桶与桶之间的顺序已经定了。
- 只有**元素不少于两个的桶**才对下一位递归。
- 只有一个元素的桶就此结束。

<br/>

来给 `170 45 75 90 2 802 24 66` 排序。

</Slide>

<Slide>

### 一步一步：一次一个递归调用
::sub[上方橙色括号是当前区间，下方括号是桶。只有橙色桶递归，绿色是处理完的元素]

<MsdRadixDemo slide />

</Slide>

#### 写成过程
::sub[`02_msd_radix_sort/msdRadixSort.pseudo`]

```plaintext
ALGORITHM MsdRecursive(A, lo, hi, exp)
    if lo >= hi or exp = 0 then return     // 元素不超过一个，或者没有位了

    // 1) 只对 A[lo..hi] 按 exp 位做稳定的计数排序
    //    size[d]：数字为 d 的元素个数 = 桶 d 的大小
    CountingSortByDigit(A, lo, hi, exp, size)

    // 2) 每个桶对下一位递归
    start <- lo
    for d <- 0 to 9 do
        if size[d] > 1 then
            MsdRecursive(A, start, start + size[d] - 1, exp / 10)
        start <- start + size[d]
```

第一次调用是 `MsdRecursive(A, 0, n-1, 100)`。802 的最高位是百位。

</Slide>

<Slide class="compact">

#### 写成代码
::sub[`02_msd_radix_sort/msdRadixSort.c`]

```c
void msdRecursive(int a[], int lo, int hi, int exp, int depth) {
    if (lo >= hi || exp == 0) {
        return;
    }

    int size[RADIX];                             /* 桶的大小 */
    countingSortByDigit(a, lo, hi, exp, size);   /* 只排 a[lo..hi] */

    int start = lo;
    for (int d = 0; d < RADIX; d++) {
        if (size[d] > 1) {
            msdRecursive(a, start, start + size[d] - 1,
                         exp / RADIX, depth + 1);
        }
        start += size[d];
    }
}
```

#### 稳定性是必需的吗
::sub[和 LSD 不同，把值排对并不需要]

- 桶与桶之间的顺序已经确定，**不会再混在一起**。
  - 同一个桶内部的顺序由下一位重新决定。
- 要保住相同键的原有顺序，**每一步都必须稳定**。
  - 对 `(分数, 姓名)` 来说，相同分数的记录要保持输入顺序。

<br/>

| | 要把值排对 | 还要保住相同键的顺序 |
| --- | --- | --- |
| LSD | 必须稳定 | 必须稳定 |
| MSD | 不需要 | 必须稳定 |

<br/>

后面的比较表把 MSD 标为稳定，是因为它用了稳定的计数排序。

</Slide>

#### 用在字符串上
::sub[很适合长度各不相同的键]

- 先按首字符分，再把每个桶按第二个字符分，……
  - 桶里只剩一个时，其余字符就不再看。
- **字符串的结尾排在任何字符之前**。
  - `she` 和 `shells` 前三个字符相同，先结束的 `she` 在前。
- **完全相同的键必须看到最后**。
  - 相同的键一多，MSD 也要读完所有字符。

</Slide>

#### 分析
::sub[MSD Radix Sort]

- **最好** $$O(n + k)$$：在第一位上就全部分进了不同的桶。
- **最坏**：一直分不开时，会像 LSD 那样读 $$n \times d$$ 次位。
  - 此外**每次递归调用**还要加上清空并累加计数数组的 $$O(k)$$。
- **空间** $$O(n + dk)$$：输出数组，加上随递归深度叠起来的计数数组

<br/>

小桶一多，扫描空计数格的时间反而比处理元素还多。  
所以实际的实现会在桶变小时改用插入排序。

</Slide>

<Slide>

#### 基数 k
::sub[一位能取的值的个数，也是计数数组的格数]

| 值 | $$k = 10$$ | 各位 | $$k = 256$$ | 各位 |
| --- | --- | --- | --- | --- |
| 100 | 1×100 + 0×10 + 0×1 | 1, 0, 0 | 0×256 + 100×1 | 0, 100 |
| 300 | 3×100 + 0×10 + 0×1 | 3, 0, 0 | 1×256 + 44×1 | 1, 44 |
| 400 | 4×100 + 0×10 + 0×1 | 4, 0, 0 | 1×256 + 144×1 | 1, 144 |

- 值不变，变的只是写法。`1, 44` 是 256 进制的**两位**。
- 一位能放 0 到 255，所以位数变少。
  - 小于 $$2^{32}$$ 的整数，$$k = 10$$ 时 10 位，$$k = 256$$ 时 4 位。
- 代价是**每次调用要扫描** $$k$$ 格。
  - LSD 只跑 $$d$$ 趟，而 MSD 的调用可以多到几百次。

</Slide>

<Slide>

#### 字符串和整数上的 k = 256
::sub[无论哪种，都是按字节读键]

| 键 | 字节（从高位起） | 各位的值 |
| --- | --- | --- |
| 字符串 `she` | `s`, `h`, `e` | 115, 104, 101 |
| 16 位整数 300 | 十六进制 `01`, `2C` | 1, 44 |

<br/>

- **字符串**本来就是字节的序列，一个字符就是一位。
- **整数**要把值拆成字节。下一个开销演示的 $$k = 256$$ 就是这种。
- 把整数当成 `"300"` 这样的文字，增大 $$k$$ 没有好处。
  - 位数还是 3，256 格中有 246 格总是空的。
  - `"45"` 会排在 `"170"` 后面，所以长度也要补齐，写成 `045`。

</Slide>

::sub[`08_msd_cost/msdCost.pseudo` · 大小不超过定值就不再递归]

```plaintext
ALGORITHM MsdRecursive(A, lo, hi, exp)
    if lo >= hi or exp = 0 then return
```

- 定得太大又会回升。$$k = 10$$ 时，大小 9 是 4,481，大小 32 是 8,544。

#### LSD 与 MSD
::sub[LSD vs. MSD]

| 特点 | LSD 基数排序 | MSD 基数排序 |
| --- | --- | --- |
| 排序方向 | 低位 → 高位 | 高位 → 低位 |
| 方式 | 迭代 | 递归（分治） |
| 提前结束 | 不可能 | 可能 |
| 变长键 | 不利 | 有利 |
| 局部性 | 每一趟扫描整个数组 | 只在一个桶内 |
| 实现 | 简单 | 复杂 |

</Slide>

<Slide>

#### 各在什么情况下有利
::sub[长度相同的整数用 LSD，长度不一或前面就能分开的键用 MSD]

| 情况 | 有利的一方 | 原因 |
| --- | --- | --- |
| 长度相同的键（整数、日期） | LSD | 实现简单，调用次数固定为位数 |
| 高位相同或相同的键很多 | LSD | MSD 也要读到最后，调用还更多 |
| 基数大且小桶很多 | LSD | MSD 每次调用扫描 $$k$$ 格，需要截断值 |
| 长度不一的字符串 | MSD | 不需要补齐长度 |
| 高位就能分开的键 | MSD | 分开后就不再读 |
| 只需要前面一部分 | MSD | 只递归需要的桶 |

<br/>

`ant bee cat dog elk fox` 的 18 个字符只读 6 个，`sea sea sea sea` 的 12 个字符全部要读。

</Slide>

```c
    int j = *(const int *)b;
```

### LCP 数组
::sub[LCP[j] = 后缀 SA[j-1] 与 SA[j] 的最长公共前缀长度 · 点击一行，与前一个邻居对照]

<SuffixTableDemo lcp slide />

#### Kasai 算法
::sub[不按排序顺序，而按文本位置顺序 i = 0, 1, 2, ...]

> 如果后缀 $$i$$ 与它前一个邻居的 LCP 是 $$h$$，  
> 那么后缀 $$i + 1$$ 与它前一个邻居的 LCP **至少**是 $$h - 1$$。

<br/>

- 后缀 $$i + 1$$ 就是后缀 $$i$$ 去掉首字符。
- 前一个邻居 $$j$$ 去掉首字符成为 $$j + 1$$，两者仍共享 $$h - 1$$ 个字符。
- 所以这 $$h - 1$$ 个字符**不比较、直接跳过**。

</Slide>

<Slide>

### 一步一步：Kasai
::sub[橙色是后缀 i，蓝色是前一个邻居 j · 灰色是跳过的字符，绿色是匹配，红色是不匹配]

<KasaiDemo slide />

</Slide>

<Slide class="compact">

#### 写成过程
::sub[`04_lcp/lcp.pseudo`]

```plaintext
ALGORITHM BuildLcpKasai(T, SA, n)
    for j <- 0 to n-1 do rank[SA[j]] <- j  // 第 1 步：SA 的逆
    h <- 0
    for i <- 0 to n-1 do                   // 第 2 步：按文本位置顺序
        if rank[i] > 0 then
            j <- SA[rank[i] - 1]           // 排序中紧挨着的前一个邻居
            while T[i + h] = T[j + h] do   // 跳过 h 个字符后比较
                h <- h + 1
            LCP[rank[i]] <- h
            if h > 0 then h <- h - 1       // 下一个至少共享 h-1 个字符
        else
            h <- 0                         // 最前面的后缀没有邻居
```

省略了 while 的范围检查（`i + h < n and j + h < n`）。

</Slide>

<Slide class="compact">

#### 运行结果
::sub[`04_lcp` · start h 是跳过的字符数]

```console
   i  suffix    rank  j  start h  lcp  compares
   0  banana$      4  1        0    0         1
   1  anana$       3  3        0    3         4
   2  nana$        6  4        2    2         1
   3  ana$         2  5        1    1         1
   4  na$          5  0        0    0         1
   5  a$           1  6        0    0         1
   6  $            0  -        -    -         -
char compares: kasai 9, naive 12
```

- `i = 2` 的 `nana$` 是 `anana$` 去掉 `a` 得到的，所以跳过 2 个字符。
- 换成 `aaaaaaaa$`，Kasai 是 15 次，从头比较是 36 次。

</Slide>

<Slide>

#### 分析
::sub[Kasai 是 O(n)]

- $$h$$ 每个位置最多减 1，而且不会超过 $$n$$。
- 所以 while 里 $$h$$ 增加的次数加起来不超过 $$2n$$。
- 不匹配的比较每个位置一次。

<br/>

有了后缀数组，LCP 数组就能在 $$O(n)$$ 内**几乎白送**。

</Slide>

## 要带走的

1. **基数排序把键拆成位，每一位做一次计数排序**。
   - 时间 $$O(d(n + k))$$，不做比较，所以处在下界的前提之外。
2. **LSD 从低位开始，每一趟都必须稳定**。
   - MSD 从高位开始分桶，分开了就不再往下读。
3. **后缀数组是把所有后缀排好序后的起始位置数组**。
   - 朴素方法把后缀当作字符串比较来排序。
4. **LCP 数组用 Kasai 在 $$O(n)$$ 内构造**。
   - LRS 是 LCP 的最大值，LCS 只看来自不同字符串的邻居。
5. **栈是 LIFO，队列是 FIFO**。
   - LSD 的桶必须是队列。
