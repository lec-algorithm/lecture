## 主题 01 的承诺
::sub[斐波那契递归为什么慢]

- 原因不在递归，而在于**把同一个值一遍又一遍地重新计算**。
- 只要把算过的答案记下来，指数时间就变成线性时间。

<br/>

把这个想法依次用到找零钱、最长递增子序列、网格路径、最短路径、0/1 背包上。  
再沿着表格倒着走，把**得出答案的选择**也还原出来。

</Slide>

#### 两个条件与两种方法
::sub[名字里的 dynamic 并不是"运行时会变"的意思]

- **重叠子问题**（overlapping subproblems）
  - 同一个小问题出现多次。
- **最优子结构**（optimal substructure）
  - 大问题的最优解由小问题的最优解构成（最优化问题时）。
- **存答案的方法有两种。**
  - 记忆化：保留递归，把答案记下来。
  - 递推填表：从小问题开始往上填表。

</Slide>

<Slide>

#### 什么是最优子结构
::sub[整体最优，则构成它的部分也最优]

- **例**：从首尔经大田到釜山最快的路
  - 其中首尔 → 大田这一段，也是从首尔到大田最快的路。
- **为什么**：替换一下就知道了。
  - 如果首尔 → 大田有更快的走法，换上去整体就更快。
  - 这与整体最快矛盾，所以没有那样的走法。
- **反过来并不自动成立。** 部分最优不代表整体最优。
  - 经江陵走的话，两段各自最快也是绕路。
  - 所以动态规划把拆分的位置**全部**比较。

</Slide>

#### 斐波那契递归
::sub[主题 01 的代码原样照搬]

```plaintext
ALGORITHM FibRecursive(n)
    if n <= 1 then
        return n
    return FibRecursive(n-1) + FibRecursive(n-2)
```

- **时间** $$O(2^n)$$：指数级增长。准确地说是 $$\Theta(\varphi^n)$$，$$\varphi \approx 1.618$$
- **空间** $$O(n)$$：递归栈
- **问题**：重复同样的计算。

</Slide>

<Slide>

#### 斐波那契的计算量
::sub[调用次数 C(n) = C(n-1) + C(n-2) + 1]

| 要求的项 | 调用次数 | 其中 $$F(3)$$ | 其中 $$F(2)$$ |
| --- | --- | --- | --- |
| $$F(0)$$, $$F(1)$$ | 1 | | |
| $$F(2)$$ | 3 | | 1 |
| $$F(3)$$ | 5 | 1 | 1 |
| $$F(4)$$ | 9 | 1 | 2 |
| $$F(5)$$ | 15 | 2 | 3 |

一个 $$F(5)$$ 要调用 15 次，不同的值只有 6 个。  
$$C(n) = 2F(n+1) - 1$$，$$n$$ 每增加 1 大约变成 1.6 倍。

</Slide>

#### 哪里不一样了
::sub[下去的路相同，回来的路不同]

- 求出 $$F(2) = 1$$，写进 `memo[2]`。
- $$F(4)$$ 再次调用 $$F(2)$$ 时，从 `memo[2]` 取出。
  - **不再分叉。**
- $$F(5)$$ 右边的 $$F(3)$$ 也从 `memo[3]` 取出。
  - 它下面的 4 次调用消失了。

<br/>

调用 **15 次 → 9 次**，$$n \ge 1$$ 时是 $$2n - 1$$ 次。  
`memo[0]`、`memo[1]` 在基本情况里直接返回，所以保持 -1。

</Slide>

<Slide class="compact">

#### 把答案记下来
::sub[`01_fibonacci/fibonacci.c` · 只加了检查的 if 和记录的赋值]

```c
long long fibMemo(int n) {
    if (n <= 1) {
        return n;                       // 1. 基本定义
    }
    if (memo[n] != -1) {
        return memo[n];                 // 2. 已经记下的值直接返回
    }
    memo[n] = fibMemo(n - 1) + fibMemo(n - 2);  // 3. 递归求出
    return memo[n];                     // 4. 记下再返回
}
```

- **时间** $$O(n)$$：每个值只算一次。
- **空间** $$O(n)$$：memo 数组 + 递归栈

#### 从下往上
::sub[一个循环加一个数组]

```plaintext
ALGORITHM FibTabulation(n)
    if n <= 1 then
        return n
    dp[0] <- 0
    dp[1] <- 1
    for i <- 2 to n do
        dp[i] <- dp[i-1] + dp[i-2]    // 前两格已经填好
    return dp[n]
```

- **时间** $$O(n)$$：每格一次
- **空间** $$O(n)$$：一张表，不用栈。
- 只留前两格，空间就降到 $$O(1)$$。

</Slide>

<Slide>

#### 这不就是普通的循环吗？
::sub[没错。主题 01 的迭代正是递推填表]

- **不同的不是结果，而是出发点。**
  - 主题 01：**已经知道**把前两项相加就行，才写了循环。
  - 递推填表：从递归定义（递推式）出发，把循环**推导出来**。
- **推导的步骤**
  1. 把递归要解的每个子问题定为表的一格。（`dp[i]` = $$F(i)$$）
  2. 安排顺序，让被参照的格先填好。（从小的 $$i$$ 开始）
- 斐波那契的格排成一行，顺序一目了然，所以看起来就是普通循环。
  - 在找零钱、LIS、背包里，同样的方法会推导出你没见过的循环。

</Slide>

#### 斐波那契迭代
::sub[主题 01 的代码 · 就是省了空间的递推填表]

```plaintext
ALGORITHM FibIterative(n)
    if n <= 1 then return n
    prev <- 0, curr <- 1
    for i <- 2 to n do
        next <- prev + curr
        prev <- curr
        curr <- next
    return curr
```

- **时间** $$O(n)$$ · **空间** $$O(1)$$

#### 记忆化 vs. 递推填表
::sub[同一个递推式，不同的方向]

| | 记忆化 | 递推填表 |
| --- | --- | --- |
| 计算方式 | **lazy**（只算需要的格） | **eager**（事先定好的格一个不漏） |
| 起点 | 上 → 下，大问题 → 小问题 | 下 → 上，小问题 → 大问题 |
| 谁决定顺序 | 递归，在需要的那一刻 | 程序员，事先 |
| 常见实现 | 递归 + 表 | 循环 + 表 |
| 直观性 | 照搬递推式 | 要确定填表顺序 |
| 稳定性 | 有栈溢出风险 | 不用栈 |
| 空间优化 | 困难 | 容易 |

<br/>

两者都用表。区分它们的不是递归还是循环，而是**由谁决定顺序**。

</Slide>

<Slide>

#### 两种方式的性格
::sub[自顶向下（top-down）与自底向上（bottom-up）]

- **记忆化**
  - 在递归调用中保存算好的结果，避免重复计算。
  - 像 $$F(4)$$、$$F(3)$$ 这样从大问题往下走，**只算需要的**。
  - 带有递归调用的开销。
- **递推填表**
  - 从小问题开始按顺序填表。
  - 像 $$F(2)$$、$$F(3)$$ 这样从小的开始解**所有子问题**。
  - 只用循环，所以高效。

</Slide>

#### Python 的生成器
::sub[lazy 的列表]

```python
def squares_eager(n):          # 把所有值存进内存
    result = []
    for i in range(n):
        result.append(i * i)
    return result

def squares_lazy(n):           # 需要时才算一个
    for i in range(n):
        yield i * i

numbers = squares_eager(1000000)   # 生成一个 100 万个元素的列表
numbers = squares_lazy(1000000)    # 还什么都没算
```

</Slide>

<Slide class="compact">

#### 函数式编程的 lazy evaluation
::sub[先定义无限的斐波那契，再按需取用]

```python
def fibonacci_infinite():      # "定义"无限多个斐波那契数
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b

fib = fibonacci_infinite()
first_10 = [next(fib) for _ in range(10)]   # 实际只算了 10 个
```

Haskell 这样的语言在语言层面就这样做。  
生成器**只是推迟，并不记录。** 记忆化是推迟再加上记录。

#### 什么时候 lazy 更好
::sub[记忆化这一边]

- **答案只需要一部分格时**
  - 凑 80 韩元，填表要 80 格，记忆化只要 **8 格**
  - $$F(50)$$ 需要从 $$F(0)$$ 起的全部，所以不算这一类。
- **难以预先知道哪些格有用时**
  - 按条件分叉的问题，格子用得稀疏的问题
- **填写顺序难定时**
  - 递归自己会按需要的顺序往下走。
- **快速原型**
  - 照搬递推式，再加一张表就行。

</Slide>

<Slide>

#### 什么时候 eager 更好
::sub[递推填表这一边]

- **反正需要全部结果时**
  - 像斐波那契这样要经过每一格的问题
- **重视稳定性时**
  - 用 `{1, 5, 10}` 凑 100 韩元，记忆化的递归会叠到 **101 层**。
- **打磨性能时**
  - 去掉递归调用的开销。
- **节省内存时**
  - 只留前面几格就行（斐波那契 $$O(1)$$，背包 $$O(W)$$）

</Slide>

#### 最后付出的那枚硬币
::sub[用 2、3、5 韩元硬币凑 6 韩元最少几枚？2 枚（3 + 3）]

- 贪心先付 5 韩元，剩下的 1 韩元凑不出，就卡住了。
- 动态规划按**最后付出的硬币** $$c$$ 拆开。
  - 剩下的 $$a - c$$ 韩元又是同一个问题。

$$
C(a) = \begin{cases}
0 & a = 0 \\
\min\limits_{c \,\in\, \text{coins},\ c \le a} \bigl( C(a - c) + 1 \bigr) & a > 0
\end{cases}
$$

凑不出的金额记为 $$\infty$$（代码里是 `INF`）

#### 记忆化
::sub[`02_coin_change/` · 和斐波那契一样的四步]

```plaintext
ALGORITHM CoinChangeMemo(amount, coins, m, memo)
    if amount = 0 then return 0          // 1. 基本情况：0 元需要 0 枚
    if amount < 0 then return INF        //    负数金额凑不出
    if memo[amount] != -1 then           // 2. 已经求过的金额直接返回
        return memo[amount]
    best <- INF                          // 3. 每种硬币各付一枚，剩下的递归
    for i <- 0 to m-1 do
        r <- CoinChangeMemo(amount - coins[i], coins, m, memo)
        if r != INF and r + 1 < best then
            best <- r + 1
    memo[amount] <- best                 // 4. 记下再返回
    return best
```

#### 递推填表
::sub[`02_coin_change/` · 每当最小值改变，就把那枚硬币记进 choice]

```plaintext
ALGORITHM CoinChangeTab(amount, coins, m)
    dp[0] <- 0                           // 1. 初始化
    for a <- 1 to amount do dp[a] <- INF
    for a <- 1 to amount do              // 2. 从小金额起一个不漏
        for i <- 0 to m-1 do
            c <- coins[i]
            if c <= a and dp[a - c] != INF and dp[a - c] + 1 < dp[a] then
                dp[a] <- dp[a - c] + 1
                choice[a] <- c           //    这个金额最后付出的硬币
    if dp[amount] = INF then return INF  // 3. 凑不出的金额
    a <- amount                          // 4. 沿 choice 倒着走
    while a > 0 do
        print choice[a]
        a <- a - choice[a]
    return dp[amount]
```

#### 记忆化：选，还是不选
::sub[剩下的事由（现在要看的元素 i，最后选的元素 prev）决定]

```plaintext
ALGORITHM LisHelper(arr, n, i, prev)
    if i = n then return 0                       // 1. 基本情况：没有元素可看了
    if memo[i][prev+1] != -1 then                // 2. 已求过的 (i, prev) 直接返回
        return memo[i][prev+1]
    exclude <- LisHelper(arr, n, i+1, prev)      // 3. 不选 arr[i] 的情况
    include <- 0
    if prev = -1 or arr[i] > arr[prev] then      //    如果可以选 arr[i]
        include <- 1 + LisHelper(arr, n, i+1, i) //    选的情况
    memo[i][prev+1] <- max(include, exclude)     // 4. 记下两者中较大的
    return memo[i][prev+1]
```

- 不加记忆 $$O(2^n)$$，加记忆 $$O(n^2)$$
- 为了把 `prev = -1`（还没选）放进第 0 列，用 `prev + 1`

</Slide>

<Slide>

#### 递推填表：以这里结尾的最长长度
::sub[dp 的一格 = 以该元素结尾的最长递增子序列的长度]

$$
dp[i] = 1 + \max \{\, dp[j] : j < i,\ arr[j] < arr[i] \,\}
$$

- 没有这样的 $$j$$ 时 `dp[i] = 1`
- 填一格时要看前面**好几格**。
- 答案不是 `dp[n-1]`，而是 **`dp` 的最大值**。
- 把选中的 $$j$$ 记进 `prev[i]`，就能还原序列。
- 时间 $$O(n^2)$$ · 空间 $$O(n)$$

</Slide>

#### [参考] 每个长度最小的结尾值
::sub[`08_lis_nlogn/lisNlogn.pseudo`]

```plaintext
ALGORITHM LisTails(arr, n)
    len <- 0
    for i <- 0 to n-1 do
        x <- arr[i]
        pos <- LowerBound(tails, len, x)   // 第一个不小于 x 的格，没有则为 len
        tails[pos] <- x                    // 替换，或接在后面
        if pos = len then len <- len + 1
    return len
```

- 每个元素一次二分查找，时间 $$O(n \log n)$$ · 空间 $$O(n)$$
- `tails` 总是严格递增，所以能用二分查找。
- 只有**长度**是对的。`[3, 4, 1]` 的 `tails` 是 `[1, 4]`，但它不是子序列。

#### 递推式
::sub[S(u, v, k)：从 u 用 k 条边到 v 的最小代价]

$$
S(u, v, k) = \begin{cases}
0 & k = 0,\ u = v \\
\infty & k = 0,\ u \ne v \\
\min\limits_{u \to x} \bigl( w(u, x) + S(x, v, k-1) \bigr) & k > 0
\end{cases}
$$

<br/>

- **实现 1**：原样写成递归
- **实现 2**：加上 `memo[k][u][v]` 表的记忆化
  - 除了值，还记下**最便宜的第一步** `next[k][u][v]`。

</Slide>

::sub[蓝色虚线是正在尝试的边，深蓝是给出最小值的边，粉色是还原出的路]

<PathDpDemo slide />

#### 实现 2：记忆化
::sub[`05_shortest_path/shortestPath.pseudo`]

```plaintext
ALGORITHM ShortestMemo(u, v, k, memo, next)
    if k = 0 then
        if u = v then return 0 else return INF
    if memo[k][u][v] != -1 then return memo[k][u][v]
    best <- INF
    for each edge u -> x do
        r <- ShortestMemo(x, v, k-1, memo, next)
        if r != INF and w(u, x) + r < best then
            best <- w(u, x) + r
            next[k][u][v] <- x        // 记下最便宜的第一步
    memo[k][u][v] <- best
    return best
```

</Slide>

#### 路径还原
::sub[决定值时把所选的一起记下，再从起点沿着走]

```plaintext
ALGORITHM RestorePath(u, v, k, next)
    path <- [u]
    while k > 0 do
        u <- next[k][u][v]            // 沿记下的第一步走
        append u to path
        k <- k - 1
    return path
```

- 沿着走

```plaintext
next[3][0][3] = 2    0 → 2   (代价 2)
next[2][2][3] = 4    2 → 4   (代价 3)
next[1][4][3] = 3    4 → 3   (代价 1)
```

#### 实现 3：递推填表
::sub[`10_shortest_path_tab/shortestPathTab.pseudo`]

```plaintext
ALGORITHM ShortestTab(dst, K)
    for each vertex u do S[0][u] <- INF
    S[0][dst] <- 0
    for k <- 1 to K do                      // 从剩余边少的层开始
        for each vertex u do
            S[k][u] <- INF
            for each edge u -> x do
                if S[k-1][x] != INF and w(u, x) + S[k-1][x] < S[k][u] then
                    S[k][u] <- w(u, x) + S[k-1][x]
                    next[k][u] <- x
    return S, next
```

- 每层每条边看一次，时间 $$O(K(V+E))$$ · 空间 $$O(KV)$$
- 不还原的话只留两层，$$O(V)$$

#### 一行就够，空间 O(W)
::sub[只看上一行，所以反复改写一行]

```plaintext
ALGORITHM Knapsack1D(w, v, n, W)
    for c <- 0 to W do dp[c] <- 0
    for i <- 1 to n do
        for c <- W downto w[i] do            // 从大容量开始
            dp[c] <- max(dp[c], dp[c - w[i]] + v[i])
    return dp[W]
```

- **从大容量开始**填，`dp[c - w]` 还是看物品 $$i$$ 之前的值。
- **从小容量开始**填，参照的格里已经有物品 $$i$$。
  - 得到的是同一物品可多次使用的**完全背包**的答案。
- 时间仍是 $$O(nW)$$，但没有整张表，所以**不能还原。**

#### 什么时候能用
::sub[小问题重叠，小答案能组成大答案]

- **像分治一样拆开，但子问题彼此重叠时**
  - 先解小的存起来，之后取出来用。
- **最优化问题，则要有最优子结构**
  - 找零钱、LIS、找路、背包都是这样。
  - 贪心跟着一个候选走，动态规划把候选**全部**比较。
- **计数问题也能用。**
  - 斐波那契和网格路径求的不是最优，而是**值和个数**。
  - 子问题的答案加起来就行，所以不谈最优子结构。

</Slide>

- 80 韩元从 34 次减到 17 次。贪心只看 4 次，却错了。

#### 最优性原理
::sub[The principle of optimality]

- 一个问题实例的最优解
  - 对构成它的子实例来说也是最优解。
- **例：最短路径**
  - 若 $$v_k$$ 在从 $$v_i$$ 到 $$v_j$$ 的最优路径上
  - 则从 $$v_i$$ 到 $$v_k$$、从 $$v_k$$ 到 $$v_j$$ 的部分路径也是最优的。
- **反例：最长简单路径**
  - 把部分路径分别拉到最长，顶点可能重复。

</Slide>

#### 分治 vs. 动态规划

| | 分治 | 动态规划 |
| --- | --- | --- |
| 方向 | 自顶向下：拆开往下走 | 自底向上（递推填表）或自顶向下（记忆化） |
| 子问题 | 彼此不重叠 | 彼此重叠 |
| 效率 | 子问题独立时高效 | 存下重叠的答案，消除重复计算 |
| 例子 | 归并排序、快速排序、二分查找 | 斐波那契的记忆化与填表、找零钱、LIS、背包 |

<br/>

斐波那契递归是分治的形状，但子问题重叠，所以正适合动态规划。

#### 设计的顺序
::sub[先确定表的一格是什么]

1. **确定子问题。**
   - 像"`dp[a]` 是凑出 `a` 韩元的最少硬币数"这样用一句话写出
2. **建立递归性质（递推式）。**
   - 通常按最后一次选择拆开。
3. **确定基本情况。**
4. **确定计算方向。**
   - 记忆化就在递归上加表，递推填表就安排填表顺序
5. **需要时记录选择并还原。**
   - `choice`、`prev`、`next`，或像背包那样再比较一次表

#### [参考] 编辑距离
::sub[把一个词改成另一个词所需的最少编辑次数]

- 编辑有三种，**删除 · 插入 · 替换**
- 按最后一个字符怎么处理来拆开。

$$
dp[i][j] = \begin{cases}
\max(i,\ j) & i = 0 \text{ or } j = 0 \\
dp[i-1][j-1] & a_i = b_j \\
1 + \min\bigl(dp[i-1][j],\ dp[i][j-1],\ dp[i-1][j-1]\bigr) & a_i \ne b_j
\end{cases}
$$

- `dp[i][j]` 是把前 $$i$$ 个字符改成前 $$j$$ 个字符的次数，时间 $$O(nm)$$
- 拼写纠正和 DNA 序列比较都从这张表开始。

## 要记住的

1. **动态规划只解一次重叠的子问题。**
   - 最优化问题要有最优子结构。
2. **记忆化是自顶向下（lazy），递推填表是自底向上（eager）。**
   - 斐波那契 15 次变 9 次，$$O(2^n)$$ 变 $$O(n)$$
3. **找到贪心错过的答案。**
   - 80 韩元是 40 + 40，0/1 背包是 220
4. **路径还原：把所选的记下，再沿着走。**
   - `choice`、`prev` 倒着走，`next` 往前走，背包再比较一次表。
5. **设计从确定表的一格是什么开始。**
