#### 高度与节点数
::sub[第 l 层最多有 2^l 个节点]

高度为 $$h$$ 的 full tree 每一层都是满的。

$$
N = 2^0 + 2^1 + \cdots + 2^{h-1} = 2^h - 1
$$

反过来解，高度就是节点数的对数。

$$
h = \log_2(N + 1) = O(\log N)
$$

<br/>

高度按**层的个数**来算。和按链接数来算的教材差 1。

</Slide>

::sub[Binary Search Tree (BST)]

</Slide>

<Slide>

#### 定义
::sub[每个节点都遵守的规则]

- **左子树中的所有键**都小于该节点的键。
- **右子树中的所有键**都大于该节点的键。
- 左右子树也各自是二叉搜索树。

<br/>

假定键互不相同。再次插入相同的值时什么也不做。

</Slide>

<Slide>

#### 只和子节点比较是不够的
::sub[常见误解："比左子节点大、比右子节点小"就够了]

<div class="aas-split">
<div>

<TreeFigure tree={{ v: "5", l: { v: "3", r: { v: "7", tone: "focus" } }, r: { v: "8" } }} />

</div>
<div>

- 每一对父 · 子都满足规则。
  - 3 < 5，8 > 5，7 > 3
- 但 7 在 5 的**左子树**里。
  - 找 7 时会在 5 处往右走，找不到。
- 规则必须作用于**整棵子树**。

</div>

#### 和二分查找是同一个思路
::sub[主题 01：和中间比较，丢掉一半]

- **二分查找**每次和中间值比较。
- **二叉搜索树**事先把那个"中间"立在根上。
  - 每棵子树也立好各自那一部分的基准值。
- 不同之处在于它是用链接串起来的。
  - 所以插入和删除很容易。

<br/>

**查找失败的位置就是插入的位置**。示例 1 会直接用到它。

</Slide>

#### 查找步骤
::sub[只沿从根到叶子的一条路往下走，所以是 O(h)]

```plaintext
ALGORITHM Search(root, key)
    node <- root
    while node != NULL do
        if key = node.key then
            return node                 // 找到了
        if key < node.key then
            node <- node.left           // 小于就只看左子树
        else
            node <- node.right          // 大于就只看右子树
    return NULL                         // 碰到空位：没有
```

</Slide>

#### 节点数据与创建节点
::sub[新节点没有子节点，所以两个地址都是 NULL]

```c
typedef struct TreeNode {
    int key;
    struct TreeNode *left;   /* 左子节点的地址 */
    struct TreeNode *right;  /* 右子节点的地址 */
} TreeNode;

TreeNode *createNode(int key) {
    TreeNode *node = (TreeNode *)malloc(sizeof(TreeNode));
    node->key = key;
    node->left = NULL;
    node->right = NULL;
    return node;
}
```

#### 插入 = 失败的查找 + 挂上去
::sub[利用二叉搜索树的性质，把新元素插到正确的位置]

- 像**查找**要插入的值那样往下走。
  - 小往左，大往右
- 碰到**空的子节点位置**，就把新节点挂在那里。
- 相同的值已经存在时什么也不做。

<br/>

已有的节点一个都不动。  
不必像往数组里插入那样把后面挪开。

</Slide>

<Slide>

#### 节点出现在原位的原因
::sub[横向位置就是排序后的名次]

- 演示里的节点从一开始就出现在自己的位置上。
- 把所有节点放到底部排成一行，就是：
  - `3 4 5 6 7 8 9 12 20`
- 从左到右有序。**BST 规则说的正是这个性质**。

</Slide>

<Slide class="compact">

#### 插入步骤
::sub[每次调用都遵守"把 key 插进这棵子树并返回它的根"的约定]

```plaintext
ALGORITHM Insert(root, key)
    if root = NULL then
        return 新节点(key)               // 正是查找失败的那个位置
    if key < root.key then
        root.left <- Insert(root.left, key)
    else if key > root.key then
        root.right <- Insert(root.right, key)
    // 相等时什么也不做（键只插入一次）
    return root
```

</Slide>

<Slide class="compact">

#### 写成代码
::sub[`01_search_insert/bstSearchInsert.c` · 调用方用返回的根替换原来的根]

```c
TreeNode *insert(TreeNode *root, int key) {
    if (root == NULL) {
        return createNode(key);
    }
    if (key < root->key) {
        root->left = insert(root->left, key);
    } else if (key > root->key) {
        root->right = insert(root->right, key);
    }
    return root;
}

TreeNode *root = NULL;
root = insert(root, 5);       /* 空树时根从 NULL 变成新节点 */
```

#### 不平衡的树
::sub[查找时间变长，所以并不可取]

- 偏向一边的树**和链表一样**。
  - 查找退回到 $$O(n)$$。
- 插入 $$n$$ 个有序的键，比较 $$\dfrac{n(n-1)}{2}$$ 次。
  - 7 个就是 21 次，光建树就要 $$O(n^2)$$
- **红黑树**、AVL 树这样的平衡树
  - 每次插入删除时调整形状，把高度限制在 $$O(\log n)$$。
  - C++ `std::map`、Java `TreeMap` 用的就是它。

</Slide>

#### 删除的顺序与条件

- **顺序**：先找到要删的值，再删掉那个节点。
- **条件**：BST 的性质必须得到保持。
  - 左小右大

<br/>

| 情形 | 要删的节点 | 做法 |
| --- | --- | --- |
| 1 | 0 个子节点（叶子） | 直接摘掉 |
| 2 | 1 个子节点 | 把那个子节点直接接到父节点上 |
| 3 | 2 个子节点 | 复制后继，再删掉原来的后继 |

</Slide>

#### 情形 3：有两个子节点时
::sub[父节点只有一个子节点位置，接不下两个]

去找**能放进 D 位置的另一个值**。  
它必须比 D 左边所有的值都大、比右边所有的值都小。

- **后继**（successor）：右子树中最小的值
  - 往右走一次，再一路往左走到底
  - 按中序紧跟在 D 后面
- **前驱**（predecessor）：左子树中最大的值
  - 按中序紧挨在 D 前面

</Slide>

#### 后继没有左子节点
::sub[所以删除原来的后继总是以情形 1 或 2 结束]

- 后继是"最左端"。
  - 如果有左子节点，它会更小，后继就不是它了。
- 删除原来的后继时不会再出现情形 3。
- 复制的那一刻同一个值出现在两处，但马上就删掉一个。

#### 用递归来看删除

- **问题规模**：树的节点数
- **基本情形**：找到了要删的键
  - 按三种情形之一处理。
- **一般情形**：选左子树或右子树
  - 在选中的子树里删除，再把返回的根接回去。

</Slide>

#### 删除步骤
::sub[情形 1 和情形 2（只有右子节点）合成了一行]

```plaintext
ALGORITHM Delete(root, key)
    if root = NULL then
        return NULL                         // 没有要删的值
    if key < root.key then
        root.left <- Delete(root.left, key)
    else if key > root.key then
        root.right <- Delete(root.right, key)
    else                                    // root 就是要删的节点
        if root.left = NULL then            // 情形 1·2：没有子节点或只有右子节点
            return root.right
        if root.right = NULL then           // 情形 2：只有左子节点
            return root.left
        succ <- FindMin(root.right)         // 情形 3：后继
        root.key <- succ.key                // 把后继的键复制到这里
        root.right <- Delete(root.right, succ.key)   // 再删掉原来的后继
    return root
```

::sub[`02_delete/bstDelete.c` · 摘下的节点用 free 归还]

```c
} else {
    /* 情形 1·2：没有子节点或只有一个 */
    if (root->left == NULL) {
        TreeNode *temp = root->right;   /* free 之前先保存要留下的子节点 */
        free(root);
        return temp;
    }
    if (root->right == NULL) {
        TreeNode *temp = root->left;
        free(root);
        return temp;
    }
    /* 情形 3：有两个子节点。复制后继，再删掉原来的后继。 */
    TreeNode *succ = findMin(root->right);
    root->key = succ->key;
    root->right = deleteNode(root->right, succ->key);
}
```

</Slide>

  inorder = A B C D E G

#### 三种遍历
::sub[区别只有一个：何时输出当前节点]

| 遍历 | 顺序 | `D B F A C E G` 这棵树的结果 |
| --- | --- | --- |
| 中序（inorder） | [左] [当前] [右] | `A B C D E F G` |
| 前序（preorder） | [当前] [左] [右] | `D B A C F E G` |
| 后序（postorder） | [左] [右] [当前] | `A C B E G F D` |

<br/>

数组从头读就行，但树在每个岔路口都要决定先看哪边。

</Slide>

<Slide>

#### 三种遍历说明了什么

- **中序**：先看完左边再输出
  - 在 BST 上**总是得到有序序列**，与插入顺序无关。
- **前序**：根在最前面
  - 父节点总是先于子节点。
- **后序**：根在最后面
  - 子节点总是先于父节点。

</Slide>

<Slide>

#### 层序
::sub[Level order · 从上层到下层，同一层从左到右]

- 不用递归，而用**队列**（queue）。
  - 从队首取出一个节点输出，再把它的子节点放到队尾。
  - 重复到队列为空。
- `D B F A C E G` 这棵树的层序是 `D B F A C E G`。
  - 和插入顺序相同。
- 主题 12 里从近到远遍历图的 **BFS** 正是这个方法。

</Slide>

<Slide>

#### 遍历步骤
::sub[前序和后序只是把中序里那一行输出换了个位置]

```plaintext
ALGORITHM Inorder(node)                 // 中序：[左] [当前] [右]
    if node != NULL then
        Inorder(node.left)
        输出 node.key
        Inorder(node.right)

ALGORITHM Preorder(node)                // 前序：[当前] [左] [右]
    if node != NULL then
        输出 node.key
        Preorder(node.left)
        Preorder(node.right)

ALGORITHM Postorder(node)               // 后序：[左] [右] [当前]
    if node != NULL then
        Postorder(node.left)
        Postorder(node.right)
        输出 node.key
```

#### 遍历的代价

- **时间**：四种遍历都对每个节点恰好输出一次。
  - $$O(n)$$
- **额外空间**
  - 递归遍历在调用栈里堆着从根到当前节点的路径。$$O(h)$$
  - 层序的队列里可能整整放下一层。最多 $$O(n)$$

#### 用哪种遍历
::sub[取决于父节点和子节点该先处理谁]

| 要做的事 | 遍历 | 理由 |
| --- | --- | --- |
| 按有序顺序输出 | 中序 | BST 的中序是升序 |
| 按形状输出 | 前序 | 先写出父节点，才能在下面缩进写子节点 |
| 释放（free） | 后序 | 先删父节点就会丢失通往子节点的地址 |

    if (root != NULL) {
        clearTree(root->left);
        clearTree(root->right);

```c
TreeNode *copyTree(TreeNode *root) {
    if (root == NULL) {
        return NULL;
    }
    TreeNode *copy = createNode(root->key);
    copy->left = copyTree(root->left);
    copy->right = copyTree(root->right);
    return copy;
}
```

#### 保存后重建
::sub[写进文件，下次运行时读出来重新插入的话]

- **用中序写**
  - 保存的是有序序列。
  - 重新插入就长成只往一边长的树，原来的结构消失了。
- **用前序写**
  - 父节点总是先于子节点出现。
  - 重新插入后每个键都回到原位，得到**同一棵树**。

#### BST 与链表
::sub[确切地说，查找·插入·删除都是 O(h)]

| 操作 | BST（平衡） | BST（最坏） | 有序链表 |
| --- | --- | --- | --- |
| 创建 | $$O(1)$$ | $$O(1)$$ | $$O(1)$$ |
| 释放 | $$O(n)$$ | $$O(n)$$ | $$O(n)$$ |
| 是否为空·是否已满 | $$O(1)$$ | $$O(1)$$ | $$O(1)$$ |
| 查找 | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |
| 插入 | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |
| 删除 | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |

<br/>

$$O(\log n)$$ 背后藏着 $$h = O(\log n)$$ 这个假设。一旦不成立，BST 也会和链表一样。

</Slide>

<Slide>

#### 和有序数组放在一起
::sub[主题 01 的二分查找]

- **有序数组**
  - 查找用二分查找，$$O(\log n)$$
  - 插入删除要前后挪动元素，$$O(n)$$
- **平衡的 BST**
  - 查找·插入·删除都是 $$O(\log n)$$
  - 因为只要改链接就能插入和删除。

</Slide>

## 要带走的

1. **BST：整棵左子树更小，整棵右子树更大**。
   - 只和一个子节点比较的规则是不够的。
2. **查找就是小往左、大往右**。
   - 插入是挂在查找失败的位置上。两者都是 $$O(h)$$
3. **插入顺序决定形状**。
   - 按有序顺序插入会变成链表，退化为 $$O(n)$$。
4. **删除按子节点个数：摘掉、接上、用后继替换**。
   - 后继没有左子节点，所以以情形 1·2 结束。
5. **遍历只是输出时机不同**。
   - 有序用中序，释放用后序，复制与保存用前序，层序用队列
