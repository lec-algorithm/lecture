#### Two properties of a binary tree

<div class="aas-split">
<div>

- **Property 1**
  - From the root to every other node there is **exactly one** path.
  - If a link loops back, it is not a tree.
- **Property 2**
  - Each node has **at most two** children.
  - A left child and a right child.

#### Vocabulary

| Term | Meaning |
| --- | --- |
| node · link | a circle holding a value · a line connecting nodes (edge) |
| root | the topmost node. The only node without a parent |
| parent · child | nodes directly above · below each other along a link |
| leaf | a node with no children |
| subtree | a node and everything below it. A tree in its own right |
| level | how many links down from the root. The root is level 0 |
| height | the number of levels. A root alone has height 1 |
| full tree | every non-leaf has two children, all leaves on one level |

</Slide>

<Slide>

#### Height and node count
::sub[Level l holds at most 2^l nodes]

A full tree of height $$h$$ has every level filled.

$$
N = 2^0 + 2^1 + \cdots + 2^{h-1} = 2^h - 1
$$

Solving backwards, the height is the log of the node count.

$$
h = \log_2(N + 1) = O(\log N)
$$

<br/>

Height counts **levels**. Textbooks that count links get one less.

</Slide>

## Binary Search Trees
::sub[Binary Search Tree (BST)]

</Slide>

<Slide>

#### Definition
::sub[The rule every node follows]

- **Every key in the left subtree** is smaller than the node's key.
- **Every key in the right subtree** is larger than the node's key.
- The left and right subtrees are binary search trees as well.

<br/>

Keys are distinct. Inserting an existing value does nothing.

</Slide>

<Slide>

#### Comparing with children is not enough
::sub[Correcting the old slides' "larger than the left child, smaller than the right"]

- Every parent–child pair follows the rule.
  - 3 < 5, 8 > 5, 7 > 3
- But 7 sits in 5's **left subtree**.

#### The same idea as binary search
::sub[Topic 01: compare with the middle, discard half]

- **Binary search** compared with the middle value every time.
- A **binary search tree** places that "middle" at the root in advance.
  - Each subtree carries its own pivot value too.
- The difference is that it is held together by links.
  - So inserting and deleting are easy.

<br/>

**Where a search fails is exactly where to insert.** Example 1 uses this.

</Slide>

<Slide class="compact">

#### Search procedure
::sub[One path from the root toward the leaves, so O(h)]

```plaintext
ALGORITHM Search(root, key)
    node <- root
    while node != NULL do
        if key = node.key then
            return node                 // found it
        if key < node.key then
            node <- node.left           // smaller: only the left subtree matters
        else
            node <- node.right          // larger: only the right subtree matters
    return NULL                         // reached an empty spot: not there
```

</Slide>

#### Representing it with links
::sub[A linked-list node holds one address, a tree node two]

```plaintext
linked-list node    [ value | next address ]

tree node        [ left address | value | right address ]
                        |                     |
                        v                     v
          [ left | value | right ]  [ left | value | right ]
```

#### Node data and node creation
::sub[A new node has no children, so both addresses are NULL]

```c
typedef struct TreeNode {
    int key;
    struct TreeNode *left;   /* address of the left child */
    struct TreeNode *right;  /* address of the right child */
} TreeNode;

TreeNode *createNode(int key) {
    TreeNode *node = (TreeNode *)malloc(sizeof(TreeNode));
    node->key = key;
    node->left = NULL;
    node->right = NULL;
    return node;
}
```

## Example 1. Search and Insert
::sub[Search and Insert]

</Slide>

<Slide>

#### Insert = failed search + hang it there
::sub[Use the BST property to put a new item in the right place]

- Go down **as if searching** for the value.
  - Smaller goes left, larger goes right.
- On reaching an **empty child spot**, attach a new node there.
- If the value is already there, do nothing.

<br/>

Not a single existing node moves.  
Unlike an array insert, nothing behind has to shift.

</Slide>

::sub[The horizontal position is the rank in sorted order]

- The demo's nodes appear in their final places from the start.
- Drop every node to the floor into one row and you get
  - `3 4 5 6 7 8 9 12 20`
- Sorted from the left. **That is exactly the BST rule.**

<Slide class="compact">

#### Insert procedure
::sub[Each call promises: "insert key into this subtree and return its root"]

```plaintext
ALGORITHM Insert(root, key)
    if root = NULL then
        return new node(key)            // exactly where the search failed
    if key < root.key then
        root.left <- Insert(root.left, key)
    else if key > root.key then
        root.right <- Insert(root.right, key)
    // if equal, do nothing (each key goes in only once)
    return root
```

</Slide>

<Slide class="compact">

#### In code
::sub[`01_search_insert/bstSearchInsert.c` · the caller replaces its root with the one returned]

```c
TreeNode *insert(TreeNode *root, int key) {
    if (root == NULL) {
        return createNode(key);
    }
    if (key < root->key) {
        root->left = insert(root->left, key);
    } else if (key > root->key) {
        root->right = insert(root->right, key);
    }
    return root;
}

TreeNode *root = NULL;
root = insert(root, 5);       /* on an empty tree the root goes from NULL to the new node */
```

#### Unbalanced trees
::sub[They make search slow, which is undesirable]

- A tree leaning to one side **is a linked list.**
  - Search falls back to $$O(n)$$.
- Inserting $$n$$ sorted keys costs $$\dfrac{n(n-1)}{2}$$ comparisons.
  - 21 for 7 keys; building alone is $$O(n^2)$$
- Balanced trees such as the **red-black tree** and the AVL tree
  - reshape on every insert and delete to keep the height at $$O(\log n)$$.
  - This is what C++ `std::map` and Java `TreeMap` use.

</Slide>

## Example 2. Delete
::sub[Delete]

</Slide>

<Slide>

#### Steps and the condition for deletion

- **Steps**: find the value, then delete that node.
- **Condition**: the BST property must still hold.
  - left is smaller, right is larger

<br/>

| Case | Node to delete | What to do |
| --- | --- | --- |
| 1 | 0 children (leaf) | just detach it |
| 2 | 1 child | link that child directly to the parent |
| 3 | 2 children | copy the successor, then delete the original successor |

</Slide>

#### Case 3: with two children
::sub[The parent has one child slot, so it cannot link both]

Look for **another value** to put in D's place.  
It must be larger than everything to D's left and smaller than everything to its right.

- **Successor**: the smallest value in the right subtree
  - right once, then all the way left
  - the value right after D in inorder
- **Predecessor**: the largest value in the left subtree
  - the value right before D in inorder

</Slide>

::sub[So deleting the original successor always ends in case 1 or 2]

- The successor is "the far left".

- Case 3 never comes up again when deleting the original successor.
- The value exists twice right after the copy, but one is deleted at once.

#### Deletion as recursion

- **Problem size**: the number of nodes in the tree
- **Base case**: the key to delete has been found
  - Handle it with one of the three cases.
- **General case**: pick the left or right subtree
  - Delete in that subtree and link the returned root back.

</Slide>

<Slide class="compact">

#### Delete procedure
::sub[Case 1 and case 2 (right child only) merge into one line]

```plaintext
ALGORITHM Delete(root, key)
    if root = NULL then
        return NULL                         // nothing to delete
    if key < root.key then
        root.left <- Delete(root.left, key)
    else if key > root.key then
        root.right <- Delete(root.right, key)
    else                                    // root is the node to delete
        if root.left = NULL then            // cases 1·2: no child, or only a right one
            return root.right
        if root.right = NULL then           // case 2: only a left child
            return root.left
        succ <- FindMin(root.right)         // case 3: the successor
        root.key <- succ.key                // copy the successor's key here
        root.right <- Delete(root.right, succ.key)   // and delete the original successor
    return root
```

</Slide>

<Slide class="compact">

#### In code
::sub[`02_delete/bstDelete.c` · a detached node is handed back with free]

```c
} else {
    /* cases 1·2: zero children or one */
    if (root->left == NULL) {
        TreeNode *temp = root->right;   /* save the child to keep before free */
        free(root);
        return temp;
    }
    if (root->right == NULL) {

        free(root);

    /* case 3: two children. Copy the successor, then delete the original. */

```

::sub[Traversal]

#### Three traversals
::sub[The only difference is when the current node is printed]

| Traversal | Order | Result for the `D B F A C E G` tree |
| --- | --- | --- |
| inorder | [left] [current] [right] | `A B C D E F G` |
| preorder | [current] [left] [right] | `D B A C F E G` |
| postorder | [left] [right] [current] | `A C B E G F D` |

<br/>

An array is read from the front, but a tree forces a choice at every fork.

</Slide>

<Slide>

### Step by step: traversal
::sub[Switch tabs. The orange outline is the call stack; printed nodes get numbers]

<TraversalDemo slide />

</Slide>

<Slide>

#### What the three traversals show

- **Inorder**: print after the whole left side
  - On a BST it is **always sorted**, whatever the insertion order.
- **Preorder**: the root comes first
  - A parent always comes before its children.
- **Postorder**: the root comes last
  - Children always come before their parent.

</Slide>

<Slide>

#### Level order
::sub[Level order · top level first, left to right within a level]

- It uses a **queue** instead of recursion.
  - Take the front, print it, add its children to the back.
  - Repeat until the queue is empty.
- The level order of the `D B F A C E G` tree is `D B F A C E G`.
  - The same as the insertion order.
- This is exactly **BFS**, which sweeps a graph outward in Topic 12.

</Slide>

#### Traversal procedures
::sub[Preorder and postorder only move the one print line of inorder]

```plaintext
ALGORITHM Inorder(node)                 // inorder: [left] [current] [right]
    if node != NULL then
        Inorder(node.left)
        print node.key
        Inorder(node.right)

ALGORITHM Preorder(node)                // preorder: [current] [left] [right]
    if node != NULL then
        print node.key
        Preorder(node.left)
        Preorder(node.right)

ALGORITHM Postorder(node)               // postorder: [left] [right] [current]
    if node != NULL then
        Postorder(node.left)
        Postorder(node.right)
        print node.key
```

#### The cost of a traversal

- **Time**: all four print each node exactly once.
  - $$O(n)$$
- **Extra space**
  - Recursion stacks the path from the root to the current node. $$O(h)$$
  - Level order can hold a whole level in the queue. Up to $$O(n)$$

</Slide>

## Example 4. Print, Free, Copy
::sub[Print, Free, Copy]

</Slide>

<Slide>

#### Which traversal to use
::sub[Decided by whether the parent or the children must be handled first]

| Task | Traversal | Why |
| --- | --- | --- |
| print in sorted order | inorder | a BST's inorder is ascending |
| print the shape | preorder | the parent is written before indenting its children |
| free | postorder | freeing the parent first loses the child addresses |
| copy | preorder | the parent must exist before children hang on it |

</Slide>

#### Free: postorder
::sub[`04_print_free_copy/treeOps.c` · free every child, then the node itself]

```c
TreeNode *clearTree(TreeNode *root) {
    if (root != NULL) {
        clearTree(root->left);
        clearTree(root->right);
        free(root);              /* safe: every child is already freed */
    }
    return NULL;                 /* use as root = clearTree(root); */
}
```

#### Copy: preorder
::sub[The node must be made first so the copied children can hang on it]

```c
TreeNode *copyTree(TreeNode *root) {
    if (root == NULL) {
        return NULL;
    }
    TreeNode *copy = createNode(root->key);
    copy->left = copyTree(root->left);
    copy->right = copyTree(root->right);
    return copy;
}
```

#### Save and rebuild
::sub[Write it to a file, then read it back and insert again on the next run]

- **Written in inorder**
  - The sorted order is saved.
  - Re-inserting grows a one-sided tree. The original structure is lost.
- **Written in preorder**
  - A parent always comes before its children.
  - Re-inserting puts every key back in place: **the same tree**.

</Slide>

#### BSTs and linked lists
::sub[Strictly, search, insertion and deletion are all O(h)]

| Operation | BST (balanced) | BST (worst) | Sorted linked list |
| --- | --- | --- | --- |
| constructor | $$O(1)$$ | $$O(1)$$ | $$O(1)$$ |
| destructor | $$O(n)$$ | $$O(n)$$ | $$O(n)$$ |
| empty?·full? | $$O(1)$$ | $$O(1)$$ | $$O(1)$$ |
| search | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |
| insert | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |
| delete | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |

<br/>

Once the old slides' "assuming $$h = O(\log n)$$" breaks, a BST is just a linked list.

</Slide>

## What to keep

1. **BST: the whole left subtree is smaller, the whole right larger.**
   - A rule that compares with one child only is not enough.
2. **Search: smaller goes left, larger goes right.**
   - Insertion hangs the node where the search failed. Both $$O(h)$$
3. **The insertion order decides the shape.**
   - Sorted order makes a linked list: $$O(n)$$.
4. **Delete by detaching, linking or replacing with the successor.**
   - The successor has no left child, so it ends in case 1 or 2.
5. **Traversals differ only in when they print.**
   - Sorting: inorder; freeing: postorder; copying and saving: preorder; level order: a queue

</Slide>
