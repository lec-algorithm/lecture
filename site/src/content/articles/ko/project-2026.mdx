## 무엇을 하는 프로젝트인가 \{#what}

과제1에서는 정렬 셋을 골라 비교했습니다. 개인프로젝트는 그 틀을 그대로 쓰되,
비교하는 대상이 정렬이 아니라 **본인이 고른 주제**입니다.

- 관심 있는 문제를 하나 고릅니다.
- 그 문제를 이미 푸는 방식, 즉 기존 해결책을 **셋 이상** 찾습니다.
- 셋을 직접 구현하거나 실행해서 같은 조건으로 돌립니다.
- 무엇이 어디에서 빠르고 어디에서 무너지는지, 왜 그런지를 설명합니다.
- 장단점을 정리하고, 더 해 볼 만한 발전 방향을 적습니다.

## 주제 고르기 \{#topic}

주제는 자유지만 조건 셋은 지켜야 합니다.

| 조건 | 뜻 |
| --- | --- |
| 코드로 돌아갈 것 | 결과가 나오고, 시간이나 횟수를 잴 수 있어야 합니다 |
| 방식이 여럿일 것 | 같은 문제를 푸는 방법이 이미 셋 이상 존재해야 합니다 |
| 공개할 수 있을 것 | 공개 저장소에 올릴 수 없는 데이터나 코드는 쓰지 않습니다 |

주제는 컴퓨터 분야에 한정되지 않습니다. 통신, 회로와 신호, 나노와 재료,
생물처럼 본인의 전공이나 관심 분야에서 골라도 됩니다.
코드로 돌려 비교할 수만 있으면 됩니다.

아래는 예입니다. 그대로 써도 되고 힌트로만 봐도 됩니다.

| 분야 | 비교해 볼 만한 것 |
| --- | --- |
| 문자열 | 부분 문자열 검색 (단순 비교 · KMP · 보이어-무어 · 라빈-카프) |
| 압축 | 파일 압축 (허프만 · RLE · LZ77) |
| 경로 | 지도 위 최단 경로 (BFS · 다익스트라 · A\*) |
| 추천 | 영화나 음악 추천 (인기순 · 협업 필터링 · 콘텐츠 기반) |
| 이미지 | 이미지 축소 (최근접 이웃 · 이중선형 보간 · seam carving) |
| 자료구조 | 자동완성 (정렬 배열 이진 탐색 · 트라이 · 해시) |
| 생성 | 미로 생성 (재귀 백트래킹 · 프림 · 크루스칼) |
| 데이터 | 중복 제거 (해시 · 정렬 후 스캔 · 블룸 필터) |
| 통신 | 오류 정정 부호 (해밍 · CRC · 리드-솔로몬) |
| 신호 · 회로 | 신호에서 주파수 찾기 (DFT 직접 계산 · FFT · 자기상관) |
| 나노 · 재료 | 격자 위 확산 시뮬레이션 (오일러 · 룽게-쿠타 · 몬테카를로) |
| 생물 | DNA 서열 정렬 (니들만-분쉬 · 스미스-워터만 · BLAST식 휴리스틱) |

주제를 미리 승인받는 절차는 없습니다. 중간 제출로 주제가 확정됩니다.

## 비교 기준을 먼저 정합니다 \{#criteria}

"무엇이 더 좋은가"는 기준 없이 답할 수 없습니다.
기준을 **둘 이상** 정하고, 그 기준으로 셋을 같은 조건에서 잽니다.

- **속도**: 실행 시간, 또는 비교 횟수나 연산 횟수처럼 세는 값
- **메모리**: 추가로 쓰는 공간
- **결과의 품질**: 정확도, 압축률, 추천 적중률처럼 주제마다 다른 값
- **입력에 따른 변화**: 크기를 키울 때, 치우친 입력을 줄 때 어떻게 달라지는지
- **구현 난이도**: 코드 길이나 붙잡고 있던 시간처럼 솔직한 값이면 됩니다.

[[time-complexity|시간 복잡도]]는 표에 적고 끝내지 말고, 실제로 잰 숫자와 맞는지
확인합니다. $$O(n \log n)$$으로 적힌 방식이 작은 입력에서 더 느린 일은 흔합니다.
그 어긋남을 찾아 설명하는 것이 좋은 보고서입니다.

## 중간 제출 (10월 18일) \{#interim}

무엇을 할지와 어떻게 비교할지를 **슬라이드 10장 정도**로 설명합니다.
아직 실험 결과가 없어도 됩니다. 계획을 보는 자리입니다.

| 장 | 담는 것 |
| --- | --- |
| 1 | 제목, 학번, 이름 |
| 2 | 고른 주제와 고른 이유 |
| 3 | 풀려는 문제를 한 문장으로 |
| 4\~6 | 비교할 방식 셋, 각각 한 장씩 |
| 7 | 비교 기준과 측정 방법 |
| 8 | 실험 설계 (입력 데이터, 크기, 반복 횟수) |

- 위의 여덟 장이 반드시 들어갈 것이고, 남는 장은 자유롭게 씁니다.
- 형식은 **PDF**입니다. 만드는 도구는 무엇이든 상관없습니다.
- 10장은 기준이고 8\~12장이면 괜찮습니다.

## 최종 제출 (12월 13일) \{#final}

### 보고서 \{#report}

- **PDF** 파일로 냅니다. 분량은 최소 5장, 최대 20장
- 첫 장에 GitHub 저장소 URL을 적습니다.

목차는 이렇게 잡으면 무난합니다.

1. 주제와 동기
2. 비교하는 방식 셋의 설명 (원리, 의사코드 또는 핵심 코드)
3. 비교 기준과 실험 설계
4. 실험 결과 (표 · 그래프 · 실행 화면 캡처)
5. 해석: 왜 이런 결과가 나왔는가
6. 장단점 정리
7. 발전 방향: 더 한다면 무엇을 할 것인가
8. 참고 자료와 AI 사용 내역

보고서는 마크다운으로 써도 되고 워드나 한글로 써도 됩니다.
**내는 것은 PDF입니다.**

## 평가 \{#grading}

보는 것은 다섯 가지입니다.

- **돌아가는 코드**: 셋이 실제로 실행되고 같은 조건에서 비교되었는가
- **측정**: 기준이 분명하고 숫자를 다시 얻을 수 있는가
- **해석**: 결과를 이론과 이어서 설명했는가
- **정리**: 장단점과 발전 방향이 본인의 판단으로 적혀 있는가
- **문서**: 남이 읽고 그대로 돌려 볼 수 있는가

주제가 얼마나 어려운지는 점수에 넣지 않습니다. 쉬운 주제를 끝까지 파고든
보고서가 어려운 주제를 겉만 훑은 보고서보다 높습니다.

## 지켜야 할 것 \{#rules}

- **AI를 써도 됩니다.** 수업에서 다루지 않은 방식을 이해하는 데 쓰는 것은
  오히려 권합니다. 대신 무엇을 어떻게 물었고 무엇을 받았는지 보고서에 적습니다.
- **남의 코드를 가져다 써도 됩니다.** 출처를 적고 어디를 고쳤는지 밝힙니다.
  출처 없이 옮긴 코드는 점수를 받지 못합니다.
- 보고서와 코드는 **한국어 또는 영어**로 작성합니다.
- 저장소는 공개됩니다. 개인정보가 들어간 데이터는 쓰지 않습니다.

## 자주 나오는 질문 \{#faq}

- **과제1과 같은 주제로 해도 되나요?** 정렬 비교를 그대로 다시 내는 것은
  안 됩니다. 과제1을 출발점으로 삼아 범위를 넓히는 것은 괜찮습니다.
- **셋을 전부 직접 구현해야 하나요?** 아닙니다. 라이브러리를 써도 됩니다.
  다만 무엇이 본인 코드이고 무엇이 라이브러리인지 밝힙니다.
- **언어는 정해져 있나요?** 아닙니다. C와 Python이 편하겠지만 다른 언어도
  됩니다. 셋을 **같은 언어와 같은 환경**에서 비교하는 것만 지키면 됩니다.
- **혼자 하나요?** 개인프로젝트이므로 혼자 합니다.
- **주제를 중간에 바꿔도 되나요?** 됩니다. 바꾸면 메일로 알려 주세요.
