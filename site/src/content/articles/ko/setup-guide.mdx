준비물은 셋입니다. **Git**, **Docker**, **GitHub 계정**.
컴파일러와 Python은 설치하지 않습니다. 컨테이너 안에 이미 들어 있습니다.

## 왜 Docker인가 \{#why-docker}

C 컴파일러는 운영체제마다 설치 방법이 다르고, Python은 버전이 갈립니다.
같은 코드가 사람마다 다르게 도는 상황을 없애기 위해 실행 환경을 컨테이너로
고정합니다. 여러분의 노트북이 무엇이든 컨테이너 안은 똑같습니다.

## 1. Git \{#git}

받는 곳: [git-scm.com/downloads](https://git-scm.com/downloads)

| 운영체제 | 준비 방법 |
| --- | --- |
| macOS | 터미널에서 `xcode-select --install` |
| Windows | [git-scm.com/download/win](https://git-scm.com/download/win)에서 설치 관리자 실행 |
| Linux | `sudo apt install git` |

```sh
git --version
git config --global user.name "본인 이름"
git config --global user.email "본인 이메일"
```

버전 번호가 찍히면 됩니다. 2.x면 충분합니다.

## 2. Docker \{#docker}

받는 곳: [docker.com/get-started](https://www.docker.com/get-started/)

Docker Desktop을 설치합니다. Windows는 WSL2가 함께 켜져야 하고, 설치 관리자가
안내하는 대로 따라가면 됩니다. Apple Silicon과 Intel용 파일이 따로 있으니
받을 때 확인하세요.

설치 후 **Docker Desktop을 실행해 두어야** 아래 명령이 동작합니다.

```sh
docker --version
docker compose version
```

두 명령 모두 버전이 찍혀야 합니다. `Cannot connect to the Docker daemon`이
나오면 Docker Desktop이 꺼져 있는 것입니다.

## 3. GitHub 계정 \{#github}

만드는 곳: [github.com/signup](https://github.com/signup)

개인프로젝트는 GitHub 저장소 제출이 필수입니다. 학기 초에 만들어 두세요.
학교 메일로 가입하면 [GitHub Student Developer Pack](https://education.github.com/pack)을
신청할 수 있습니다. 수업에 필수는 아닙니다.

## 4. 실습 코드 받기 \{#clone}

```sh
git clone https://github.com/lec-algorithm/algorithm-code.git
cd algorithm-code
docker compose up -d
```

처음 한 번은 이미지를 받느라 몇 분 걸립니다. 이후에는 몇 초면 뜹니다.

저장소는 주제별로 폴더가 나뉘고, 한 예제 안에 의사코드와 두 구현이 함께
있습니다.

```plaintext
algorithm-code/
├── compose.yml                      # 실습 컨테이너 정의
├── Dockerfile                       # gcc · gdb · python3가 들어 있는 이미지
└── topic-01-intro-search/
    └── 01_sequential_search/
        ├── sequentialSearch.pseudo  # 기준이 되는 절차
        ├── sequentialSearch.c       # C 구현
        └── sequential_search.py     # Python 구현
```

저장소 폴더가 컨테이너의 `/work`에 그대로 연결됩니다. 코드는 **호스트에서
평소 쓰는 편집기로 고치고**, 실행만 컨테이너에서 합니다.

## 5. 첫 예제 돌려보기 \{#run}

컨테이너 셸로 들어가서 평소처럼 명령을 칩니다.

```sh
docker compose exec lab bash
```

프롬프트가 바뀌면 그 다음부터는 컨테이너 안입니다.

```console
root@8f3c1d2a4b5e:/work# ls
Dockerfile  compose.yml  topic-01-intro-search  ...
```

셸에 들어가지 않고 명령 하나만 던질 수도 있습니다. 컨테이너 안에 무엇이
들어 있는지는 이렇게 확인합니다.

```sh
docker compose exec lab gcc --version | head -1
docker compose exec lab python3 --version
```

```console
gcc (Debian 14.2.0-19) 14.2.0
Python 3.13.5
```

```sh
cd topic-01-intro-search/01_sequential_search
gcc -o sequentialSearch sequentialSearch.c && ./sequentialSearch
python3 sequential_search.py
```

두 구현이 같은 결과를 내면 준비가 끝난 것입니다.

```console
n = 15, key = 51
index = 6, comparisons = 7
```

컨테이너에서 나올 때는 `exit`를 칩니다. 컨테이너는 계속 떠 있습니다.

### 한 줄로 실행하기 \{#one-liner}

셸에 들어가지 않고 바로 돌릴 수도 있습니다. `-w`로 작업 폴더를 지정합니다.

```sh
docker compose exec -w /work/topic-01-intro-search/01_sequential_search lab \
  sh -c "gcc -o sequentialSearch sequentialSearch.c && ./sequentialSearch"
```

## 6. 정리 \{#down}

```sh
docker compose down     # 컨테이너 중지
```

컨테이너를 지워도 코드는 호스트에 그대로 남습니다.

## 자주 막히는 곳 \{#troubleshooting}

| 증상 | 확인할 것 |
| --- | --- |
| `docker: command not found` | Docker Desktop이 설치되어 있고 **실행 중인지** 확인하세요 |
| `Cannot connect to the Docker daemon` | Docker Desktop이 꺼져 있습니다. 실행한 뒤 다시 시도하세요 |
| `service "lab" is not running` | `docker compose up -d`를 먼저 실행해야 합니다 |
| 고친 코드가 반영되지 않음 | 저장했는지 확인하세요. 폴더가 마운트되어 있어 저장하면 바로 반영됩니다 |
| 한글이 깨져 보임 | 터미널 인코딩을 UTF-8로 바꿉니다 |
| 이미지 빌드가 너무 느림 | 학교 네트워크에서 처음 한 번은 오래 걸립니다. 집에서 미리 받아 두세요 |

## 컨테이너 없이 돌리려면 \{#native}

로컬에 이미 C 컴파일러와 Python 3.11 이상이 있다면 예제를 그대로 돌려도
됩니다. 다만 질문을 받을 때 기준은 컨테이너입니다. 환경 차이로 결과가 달라지면
컨테이너에서 한 번 확인해 주세요.
