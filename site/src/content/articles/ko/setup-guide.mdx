실습 코드는 **컨테이너 안에서** 돕니다. 컴파일러와 Python은 그 안에 이미
들어 있어 설치하지 않습니다. 시작하는 방법은 둘입니다.

| 방법 | 필요한 것 | 언제 |
| --- | --- | --- |
| **GitHub Codespaces** | GitHub 계정 하나 | 권장. 설치할 것이 없습니다 |
| 로컬 Docker | Git · Docker Desktop | 본인 노트북에서 돌리고 싶을 때 |

어느 쪽이든 **같은 컨테이너**입니다. 저장소의 `compose.yml` 하나를
Codespaces와 로컬이 함께 씁니다.

## 저장소 둘을 구분해서 씁니다 \{#two-repos}

| 저장소 | 무엇에 | 어떻게 |
| --- | --- | --- |
| [`algorithm-env`](https://github.com/lec-algorithm/algorithm-env) | 과제 · 개인프로젝트 | **Use this template**으로 내 저장소를 만듭니다 |
| [`algorithm-code`](https://github.com/lec-algorithm/algorithm-code) | 수업 예제 | **여기서 바로 Codespace**를 만듭니다 |

**`algorithm-code`는 복사하지 마세요.** 학기 중에 주제가 계속 추가되는데,
사본을 만들면 새 주제를 받을 방법이 없습니다. 저장소에서 바로 Codespace를
만들거나 클론해서 `git pull`로 받으면 됩니다.

## 왜 컨테이너인가 \{#why-container}

C 컴파일러는 운영체제마다 설치 방법이 다르고, Python은 버전이 갈립니다.
같은 코드가 사람마다 다르게 도는 상황을 없애기 위해 실행 환경을 고정합니다.
여러분의 노트북이 무엇이든 컨테이너 안은 똑같습니다.

## 방법 1. Codespaces \{#codespaces}

브라우저만 있으면 됩니다. 먼저
[github.com/signup](https://github.com/signup)에서 GitHub 계정을 만들어 두세요.
개인프로젝트 제출에도 필요합니다.

### 수업 예제: Codespace 만들기 \{#code-codespace}

[lec-algorithm/algorithm-code](https://github.com/lec-algorithm/algorithm-code)로
가서 초록색 **Code** 버튼 → **Codespaces** 탭 →
**Create codespace on main**을 누릅니다.

<Image src={codeCodespace} alt="algorithm-code 저장소에서 Code 버튼을 누르고 Codespaces 탭의 Create codespace on main을 누르는 화면" />

만들어진 codespace는 `main` 브랜치에 붙습니다.

<Image src={codeRunning} alt="Codespaces 탭에 만들어진 codespace가 main 브랜치에 Active 상태로 나열된 화면" />

새 주제가 올라오면 codespace 터미널에서 `git pull`로 받습니다.

### 과제용 내 저장소 만들기 \{#use-template}

과제와 개인프로젝트는 **본인 저장소**에서 합니다. `algorithm-env`는
**template 저장소**이고, 여기서 내 계정에 사본을 만들면 같은 환경으로
깨끗하게 출발할 수 있습니다.

[lec-algorithm/algorithm-env](https://github.com/lec-algorithm/algorithm-env)로
가서 **Use this template** → **Create a new repository**를 누릅니다.

<Image src={repoTemplate} alt="algorithm-env 저장소 상단의 Use this template 버튼과 그 아래 펼쳐진 Create a new repository 메뉴" />

저장소 이름은 `my-algorithm-code`처럼 알아볼 수 있게 짓고
**Create repository**를 누릅니다.

<Image src={repoCreate} alt="Create a new repository 화면. Start with a template에 lec-algorithm/algorithm-env가 선택되어 있고, Repository name에 my-algorithm-code를 입력한 뒤 Create repository 버튼을 누른다" />

만든 저장소에서도 같은 방법으로 Codespace를 열면 됩니다.

처음 한 번은 컨테이너를 만드느라 몇 분 걸립니다. 준비가 끝나면 브라우저에
VS Code가 뜨고, **그 터미널이 곧 컨테이너 안**입니다. 아래
[예제 하나 돌려보기](#run)로 바로 넘어가면 됩니다.

만들어 둔 codespace는 [github.com/codespaces](https://github.com/codespaces)에서
다시 열 수 있습니다. 쓰지 않으면 자동으로 멈추고, 코드는 그대로 남습니다.

## 방법 2. 로컬 Docker \{#local}

본인 노트북에서 돌리려면 Git과 Docker 둘을 설치합니다.

### Git \{#git}

받는 곳: [git-scm.com/downloads](https://git-scm.com/downloads)

| 운영체제 | 준비 방법 |
| --- | --- |
| macOS | 터미널에서 `xcode-select --install` |
| Windows | [git-scm.com/download/win](https://git-scm.com/download/win)에서 설치 관리자 실행 |
| Linux | `sudo apt install git` |

```sh
git --version
git config --global user.name "본인 이름"
git config --global user.email "본인 이메일"
```

### Docker \{#docker}

받는 곳: [docker.com/get-started](https://www.docker.com/get-started/)

Docker Desktop을 설치합니다. Windows는 WSL2가 함께 켜져야 하고, 설치 관리자가
안내하는 대로 따라가면 됩니다. Apple Silicon과 Intel용 파일이 따로 있으니
받을 때 확인하세요.

설치 후 **Docker Desktop을 실행해 두어야** 아래 명령이 동작합니다.

```sh
docker --version
docker compose version
```

### 저장소를 받고 컨테이너 안으로 \{#clone}

수업 예제를 로컬에서 보려면 `algorithm-code`를 클론합니다.

- 실행

```sh
git clone https://github.com/lec-algorithm/algorithm-code.git
cd algorithm-code
docker compose up -d
docker compose exec lab bash
```

- 결과

```console
root@d38ddee8c2a8:/work#
```

프롬프트가 바뀌면 그 다음부터는 컨테이너 안입니다. **Codespaces 터미널과
같은 자리**이므로, 이후 명령은 두 방법이 완전히 같습니다.

**`docker compose` 명령은 저장소 폴더 안에서 칩니다.** `compose.yml`이 거기
있기 때문입니다. 다른 폴더에서 치면 `no configuration file provided` 오류가
납니다.

VS Code를 쓴다면 Dev Containers 확장의 **Reopen in Container**를 골라도
됩니다. Codespaces와 같은 설정을 씁니다.

## 예제 하나 돌려보기 \{#run}

여기서부터는 두 방법이 같습니다. 컨테이너 안에서 칩니다.

먼저 무엇이 들어 있는지 봅니다.

- 실행

```sh
gcc --version | head -1
python3 --version
```

- 결과

```console
gcc (Debian 14.2.0-19) 14.2.0
Python 3.13.5
```

이제 첫 예제를 돌립니다.

- 실행

```sh
cd topic-01-intro-search/01_sequential_search
gcc -o sequentialSearch.out sequentialSearch.c && ./sequentialSearch.out
python3 sequential_search.py
```

- 결과

```console
n = 15, key = 51
index = 6, comparisons = 7
```

두 구현이 같은 결과를 내면 준비가 끝난 것입니다.

저장소는 주제별로 폴더가 나뉘고, 한 예제 안에 의사코드와 두 구현이 함께
있습니다.

```plaintext
my-algorithm-code/
├── .devcontainer/devcontainer.json  # Codespaces 설정
├── compose.yml                      # 실습 컨테이너 정의
├── Dockerfile                       # gcc · gdb · python3가 들어 있는 이미지
└── topic-01-intro-search/
    └── 01_sequential_search/
        ├── README.md                # 이 예제의 실행 방법
        ├── sequentialSearch.pseudo  # 기준이 되는 절차
        ├── sequentialSearch.c       # C 구현
        └── sequential_search.py     # Python 구현
```

주제 폴더는 진도에 맞춰 하나씩 추가됩니다.

실행 파일은 `*.out`으로 만듭니다. `.gitignore`가 그것만 걸러내므로,
컴파일한 결과물이 커밋에 섞이지 않습니다.

## 정리 \{#down}

Codespaces는 쓰지 않으면 자동으로 멈춥니다. 로컬은 아래처럼 내립니다.

```sh
docker compose down
```

컨테이너를 지워도 코드는 그대로 남습니다.

## 자주 막히는 곳 \{#troubleshooting}

| 증상 | 확인할 것 |
| --- | --- |
| Codespace 생성이 오래 걸림 | 처음 한 번은 컨테이너를 만드느라 몇 분 걸립니다. 두 번째부터는 빠릅니다 |
| `docker: command not found` | Docker Desktop이 설치되어 있고 **실행 중인지** 확인하세요 |
| `Cannot connect to the Docker daemon` | Docker Desktop이 꺼져 있습니다. 실행한 뒤 다시 시도하세요 |
| `no configuration file provided` | 저장소 폴더 안에서 실행해야 합니다. `cd my-algorithm-code` |
| `service "lab" is not running` | `docker compose up -d`를 먼저 실행해야 합니다 |
| `gcc: command not found` | 컨테이너 밖에서 치고 있습니다. `docker compose exec lab bash`로 들어가세요 |
| 고친 코드가 반영되지 않음 | 저장했는지 확인하세요. 폴더가 마운트되어 있어 저장하면 바로 반영됩니다 |
| 한글이 깨져 보임 | 터미널 인코딩을 UTF-8로 바꿉니다 |

## 컨테이너 없이 돌리려면 \{#native}

로컬에 이미 C 컴파일러와 Python 3.11 이상이 있다면 예제를 그대로 돌려도
됩니다. 다만 질문을 받을 때 기준은 컨테이너입니다. 환경 차이로 결과가 달라지면
컨테이너에서 한 번 확인해 주세요.
