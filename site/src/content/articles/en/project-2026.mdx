## What the project is \{#what}

In Assignment 1 you picked three sorting algorithms and compared them. The
project keeps that shape exactly, except that what you compare is **a topic of
your own** rather than sorting.

- Pick one problem you find interesting.
- Find **three or more** existing approaches that already solve it.
- Implement or run all three under the same conditions.
- Explain what is fast where, what breaks down where, and why.
- Write up the trade-offs and where you would take it next.

## Choosing a topic \{#topic}

The topic is yours, but three conditions hold.

| Condition | Meaning |
| --- | --- |
| It runs as code | It must produce a result and let you measure time or counts |
| Several approaches exist | Three or more known ways of solving it must already exist |
| It can be made public | Do not use data or code that cannot go into a public repository |

The topic need not be a computing one. Communications, circuits and signals,
nano and materials, biology: anything from your own major or interests works,
as long as you can run it as code and compare.

Some examples. Take one as it is, or read them as hints.

| Area | Worth comparing |
| --- | --- |
| Strings | Substring search (naive · KMP · Boyer-Moore · Rabin-Karp) |
| Compression | File compression (Huffman · RLE · LZ77) |
| Paths | Shortest path on a map (BFS · Dijkstra · A\*) |
| Recommendation | Film or music recommendation (popularity · collaborative filtering · content-based) |
| Images | Image downscaling (nearest neighbour · bilinear · seam carving) |
| Data structures | Autocomplete (binary search on a sorted array · trie · hash) |
| Generation | Maze generation (recursive backtracking · Prim · Kruskal) |
| Data | Deduplication (hashing · sort then scan · Bloom filter) |
| Communications | Error-correcting codes (Hamming · CRC · Reed-Solomon) |
| Signals · circuits | Finding a frequency in a signal (direct DFT · FFT · autocorrelation) |
| Nano · materials | Diffusion on a lattice (Euler · Runge-Kutta · Monte Carlo) |
| Biology | DNA sequence alignment (Needleman-Wunsch · Smith-Waterman · BLAST-style heuristic) |

There is no approval step to clear beforehand. The interim submission is what
fixes your topic. (You may still change it afterwards.)

## Decide the criteria first \{#criteria}

"Which one is better" cannot be answered without criteria.
Fix **two or more** of them, then measure all three under the same conditions.

These are examples.

- **Speed**: wall-clock time, or a counted value such as comparisons or operations
- **Memory**: the extra space an approach uses
- **Quality of the result**: accuracy, compression ratio, hit rate, whatever your topic measures
- **Behaviour as the input changes**: what happens as the size grows, or when the input is skewed
- **Implementation cost**: lines of code, or the hours it took you, honestly reported

Anything else you can put a number on works as a criterion just as well.

Do not let [[time-complexity]] sit in a table and stop there. Check it against
the numbers you actually measured. An approach labelled $$O(n \log n)$$ being
slower on small inputs is common. Finding and explaining that gap is what makes
a good report.

| 4\~6 | The three approaches, one slide each |

## Final submission (December 13) \{#final}

### Report \{#report}

- A **PDF** file. At least 5 pages, at most 20
- Put the GitHub repository URL on the first page.
- Show results as **screenshots and graphs**. A report that only lists numbers is hard to read.

This table of contents works well.

1. Topic and motivation
2. The three approaches (how each works, pseudocode or the core code)
3. Criteria and experiment design
4. Results (tables · graphs · screenshots of runs)
5. Interpretation: why the numbers came out this way
6. Trade-offs
7. Where to take it next
8. References and a record of how you used AI

Write the report in Markdown, Word, or Hangul, whichever you prefer.
**What you submit is a PDF.**

### Code \{#code}

- Submitting the GitHub repository **URL is required**. Put it in the report.
- Also submit the zip from the repository's **Code > Download ZIP**.
- Put the run instructions in `README.md`. A reader must be able to follow them as written.
- Include the input data you measured with. If it is large, include the script that generates it.

Create the repository any way you like. Starting from
[`algorithm-env`](https://github.com/lec-algorithm/algorithm-env) with
**Use this template** brings the lab environment along with it, but a
repository you set up yourself is equally fine. See
[Setting up the lab](/article/setup-guide/) for how the template works.

## Grading \{#grading}

Five things are looked at.

- **Code that runs**: all three actually execute and are compared under the same conditions
- **Measurement**: the criteria are clear and the numbers can be obtained again
- **Interpretation**: the results are tied back to the theory
- **Conclusions**: the trade-offs and next steps are your own judgement
- **Documentation**: someone else can read it and run it as written

How hard the topic is does not count toward the grade. An easy topic followed
all the way through scores higher than a hard one skimmed on the surface.

## Rules \{#rules}

- **You may use AI.** Using it to understand an approach the course did not
  cover is encouraged. In return, record in the report what you asked and what
  you got back.
- **You may use other people's code.** Cite the source and say what you changed.
  Code copied without a source receives no credit.
- Write the report and the code in **Korean or English**.
- The repository is public. Do not use data containing personal information.

## Common questions \{#faq}

- **Can I reuse the topic from Assignment 1?** Not as it stands. Handing in the
  same sorting comparison again does not count. Taking it as a starting point
  and widening the scope is fine.
- **Do I have to implement all three myself?** No. Libraries are allowed. Just
  make clear which part is your code and which part is the library.
- **Is the language fixed?** No. C and Python will be the most comfortable, but
  others are allowed. What matters is that all three are compared in the
  **same language and the same environment**.
- **Is this individual work?** Yes. It is an individual project.
- **Can I change the topic partway?** Yes. Send an email when you do.
