实验代码在**容器中**运行。编译器和 Python 已经在里面，无需安装。
开始的方式有两种。

| 方式 | 需要什么 | 何时使用 |
| --- | --- | --- |
| **GitHub Codespaces** | 一个 GitHub 账号 | 推荐。无需安装任何东西 |
| 本地 Docker | Git · Docker Desktop | 想在自己电脑上运行时 |

两种方式用的是**同一个容器**。仓库中的一份 `compose.yml` 同时服务于
Codespaces 和你的笔记本。

## 两个仓库，用法不同 \{#two-repos}

| 仓库 | 用于 | 怎么用 |
| --- | --- | --- |
| [`algorithm-env`](https://github.com/lec-algorithm/algorithm-env) | 作业 · 个人项目 | 用 **Use this template** 创建自己的仓库 |
| [`algorithm-code`](https://github.com/lec-algorithm/algorithm-code) | 课堂示例 | **直接在这里创建 Codespace** |

**请不要复制 `algorithm-code`。** 学期中会不断添加主题，复制之后就没有办法
接收新主题。直接在该仓库创建 Codespace，或者克隆后用 `git pull` 获取。

## 为什么用容器 \{#why-container}

C 编译器在每个操作系统上的安装方式都不同，Python 版本也会各不相同。固定运行
环境可以消除同一份代码在不同人手上表现不同的情况。无论你的笔记本是什么，
容器内部都完全一样。

## 方式一：Codespaces \{#codespaces}

有浏览器就够了。请先在 [github.com/signup](https://github.com/signup) 注册
GitHub 账号，提交个人项目时同样需要它。

### 课堂示例：创建 Codespace \{#code-codespace}

打开
[lec-algorithm/algorithm-code](https://github.com/lec-algorithm/algorithm-code)，
点击绿色的 **Code** 按钮，切换到 **Codespaces** 标签页，再点击
**Create codespace on main**。

<Image src={codeCodespace} alt="在 algorithm-code 仓库点击 Code 按钮，Codespaces 标签页中出现 Create codespace on main" />

创建好的 codespace 挂在 `main` 分支上。

<Image src={codeRunning} alt="Codespaces 标签页中列出的 codespace，处于 Active 状态并挂在 main 分支" />

有新主题发布时，在 codespace 终端中用 `git pull` 获取。

### 作业用的自己的仓库 \{#use-template}

作业与个人项目在**自己的仓库**中完成。`algorithm-env` 是 **template 仓库**，
在自己账号下创建副本即可用同样的环境干净地开始。

打开
[lec-algorithm/algorithm-env](https://github.com/lec-algorithm/algorithm-env)，
点击 **Use this template** → **Create a new repository**。

<Image src={repoTemplate} alt="algorithm-env 仓库顶部的 Use this template 按钮，下方展开的 Create a new repository 菜单" />

取一个容易辨认的名字，例如 `my-algorithm-code`，然后点击 **Create repository**。

<Image src={repoCreate} alt="Create a new repository 界面。Start with a template 处已选择 lec-algorithm/algorithm-env，Repository name 中填入 my-algorithm-code，底部是 Create repository 按钮" />

在那个仓库中用同样的方法打开 Codespace 即可。

第一次会花几分钟构建容器。准备好后浏览器中会打开 VS Code，**那个终端就是容器
内部**。可以直接跳到[运行一个示例](#run)。

已创建的 codespace 可以从 [github.com/codespaces](https://github.com/codespaces)
再次打开。闲置时会自动停止，代码会保留。

## 方式二：本地 Docker \{#local}

想在自己电脑上运行，需要安装 Git 和 Docker。

### Git \{#git}

下载地址：[git-scm.com/downloads](https://git-scm.com/downloads)

| 操作系统 | 方法 |
| --- | --- |
| macOS | 终端中执行 `xcode-select --install` |
| Windows | 从 [git-scm.com/download/win](https://git-scm.com/download/win) 下载安装程序 |
| Linux | `sudo apt install git` |

```sh
git --version
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
```

### Docker \{#docker}

下载地址：[docker.com/get-started](https://www.docker.com/get-started/)

安装 Docker Desktop。Windows 需要同时启用 WSL2，安装程序会引导完成。
Apple Silicon 与 Intel 的安装包不同，下载时请确认。

安装后**必须运行 Docker Desktop**，下面的命令才有效。

```sh
docker --version
docker compose version
```

### 克隆自己的仓库并进入容器 \{#clone}

若想在本地查看课堂示例，克隆 `algorithm-code`。

- 执行

```sh
git clone https://github.com/lec-algorithm/algorithm-code.git
cd algorithm-code
docker compose up -d
docker compose exec lab bash
```

- 结果

```console
root@d38ddee8c2a8:/work#
```

提示符变化后就进入了容器内部。这和 **Codespaces 终端所在的位置相同**，
因此之后的命令两种方式完全一致。

**`docker compose` 命令要在仓库文件夹内执行。** `compose.yml` 在那里。
在其他文件夹执行会报 `no configuration file provided` 错误。

如果使用 VS Code，也可以用 Dev Containers 扩展的 **Reopen in Container**，
它使用同一份配置。

## 运行一个示例 \{#run}

从这里开始两种方式相同。以下命令都在容器内执行。

先看看里面有什么。

- 执行

```sh
gcc --version | head -1
python3 --version
```

- 结果

```console
gcc (Debian 14.2.0-19) 14.2.0
Python 3.13.5
```

然后运行第一个示例。

- 执行

```sh
cd src/topic-01-intro-search/01_sequential_search
gcc -o sequentialSearch.out sequentialSearch.c && ./sequentialSearch.out
python3 sequential_search.py
```

- 结果

```console
n = 15, key = 51
index = 6, comparisons = 7
```

两种实现输出相同，说明准备完成。

仓库按主题分文件夹，每个示例中伪代码与两种实现放在一起。

```plaintext
algorithm-code/
├── .devcontainer/devcontainer.json  # Codespaces 配置
├── compose.yml                      # 实验容器
├── Dockerfile                       # 镜像：gcc · gdb · python3
└── src/
    └── topic-01-intro-search/
        └── 01_sequential_search/
            ├── README.md                # 该示例的运行方法
            ├── sequentialSearch.pseudo  # 作为基准的流程
            ├── sequentialSearch.c       # C 实现
            └── sequential_search.py     # Python 实现
```

主题文件夹会随着教学进度逐个添加。

编译产物请命名为 `*.out`。`.gitignore` 正好过滤这一类文件，构建结果不会混入
提交。

## 收尾 \{#down}

codespace 闲置时会自动停止。本地这样关闭。

```sh
docker compose down
```

删除容器不会影响代码。

## 常见问题 \{#troubleshooting}

| 现象 | 检查什么 |
| --- | --- |
| 创建 codespace 很慢 | 第一次构建需要几分钟，之后会很快 |
| `docker: command not found` | 确认 Docker Desktop 已安装**并正在运行** |
| `Cannot connect to the Docker daemon` | Docker Desktop 未运行。启动后重试 |
| `no configuration file provided` | 需要在仓库文件夹内执行：`cd algorithm-code` |
| `service "lab" is not running` | 先执行 `docker compose up -d` |
| `gcc: command not found` | 你在容器外执行。用 `docker compose exec lab bash` 进入 |
| 修改的代码没有生效 | 确认已保存。文件夹是挂载的，保存后立即生效 |

## 不用容器运行 \{#native}

如果本地已经有 C 编译器和 Python 3.11 以上版本，示例可以直接运行。不过答疑时
以容器为准。如果因环境差异导致结果不同，请在容器中确认一次。
