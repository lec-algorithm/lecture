## 什么是推荐系统 \{#overview}

**推荐系统**（recommender system）根据用户的兴趣和偏好推荐合适的项目。它在
生活中随处可见。

- **Netflix**：用户可能喜欢的电影
- **Spotify**：个性化的音乐
- **Amazon**：值得一起买的商品

把用户放在行、物品放在列，格子里写上评分，就得到**评分矩阵**。一个人能看的
电影只占全部的极小一部分，所以这个矩阵大部分是空格。推荐就是**预测空格里的
评分，并从预测高的开始展示**。填空的方法大致有两种。

- **协同过滤**（collaborative filtering）：以其他人的评分为线索。
- **基于内容的过滤**（content-based filtering）：以物品的特征（类型、演员、
  导演）为线索。

## 协同过滤 \{#collaborative}

协同过滤根据**用户过去的行为数据**（评分、购买记录）找到相似的用户或物品来
推荐。它又分两种。

- **基于用户**（user-based）：推荐和我口味相似的用户喜欢过的物品。
- **基于物品**（item-based）：推荐和我喜欢过的物品相似的其他物品。这里的
  "相似"不看内容，而看**是否被同一批人打出相似的评分**。

### 看喜欢的电影清单 \{#taste-lists}

下面是四位用户喜欢的电影。

| 用户 A | 用户 B | 用户 C | 用户 D |
| --- | --- | --- | --- |
| 犯罪都市3 | 疯狂元素城 | 首尔之春 | 极限逃生 |
| 壮志凌云：独行侠 | 阿拉丁 | 闲山：龙的出现 | 寄生虫 |
| 阿凡达：水之道 | 阿凡达：水之道 | 阿凡达：水之道 | 犯罪都市2 |
| 蜘蛛侠：英雄无归 | | 蜘蛛侠：英雄无归 | 复仇者联盟4：终局之战 |

A 和 C 有《阿凡达：水之道》《蜘蛛侠：英雄无归》两部重合。和 B 重合一部，和
D 一部也没有。那么**把 C 喜欢的《首尔之春》推荐给 A**，A 大概也会喜欢吧。
这就是基于用户的协同过滤的全部想法。

这种方式不需要知道电影是什么。它不看类型也不看导演，只看谁喜欢了什么。
**不需要领域知识**是协同过滤最大的优点。

## 把相似度变成数字：余弦相似度 \{#cosine}

"重合的电影数"太粗糙，分不出 5 分和 1 分。把一个用户的评分看成向量，衡量
**两个向量指向同一方向的程度**，评分的大小也就算进去了。这就是**余弦
相似度**（cosine similarity）。

$$
\text{cos}(a, b) = \frac{a \cdot b}{\lVert a \rVert \, \lVert b \rVert}
= \frac{\sum_i a_i b_i}{\sqrt{\sum_i a_i^2} \, \sqrt{\sum_i b_i^2}}
$$

- 方向相同为 1，垂直为 0，相反为 -1。
- 因为除以了长度，看的不是打了**多少**，而是按**什么比例**打的。

用一个小矩阵来算一算。4 位用户、4 个物品，0 表示还没看过。

| | 物品 1 | 物品 2 | 物品 3 | 物品 4 |
| --- | --- | --- | --- | --- |
| 用户 A | 5 | 3 | 0 | 0 |
| 用户 B | 4 | 0 | 0 | 0 |
| 用户 C | 0 | 0 | 5 | 4 |
| 用户 D | 0 | 0 | 4 | 0 |

A 和 B 的物品 3、4 都是 0，所以可以原样画在物品 1、2 的平面上。拖动端点试试。
方向不变、只改长度，余弦不变；把一个向量贴到坐标轴上构成直角，余弦就变成 0。
评分不会是负数，所以两个向量的夹角不会超过 90 度。

<CosineDemo />

$$
\text{cos}(A, B) = \frac{5 \cdot 4 + 3 \cdot 0}{\sqrt{5^2 + 3^2} \, \sqrt{4^2}}
= \frac{20}{5.831 \times 4} = 0.857
$$

同样地，C 和 D 是 $$\dfrac{20}{\sqrt{41} \times 4} = 0.781$$，而 A 和 C
没有任何重合的物品，内积为 0，相似度也是 0。实验代码的第一张表就是这个计算。

```console
  B       0.857  1.000  0.000  0.000
  C       0.000  0.000  1.000  0.781
  D       0.000  0.000  0.781  1.000
```

**A 和 B 相似，C 和 D 相似。** 那就互相推荐对方喜欢的：把 A 评过的物品 2
推荐给 B，把 C 评过的物品 4 推荐给 D。

这个计算把没看过的格子当作 **0 分**放了进去。这是一种简化，分不出"没看过"
和"不喜欢"。下面的例子会看到这个简化在哪里出问题。

## 例 1. 基于用户的协同过滤 \{#user-based}

换一个稍大的矩阵，一直算到预测。5 位用户、6 部电影，**A 的 M3 和 M6 是
空格**。填好这两个格子，就决定了给 A 推荐什么。

| | M1 | M2 | M3 | M4 | M5 | M6 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 5 | 5 | **?** | 4 | 2 | **?** |
| B | 5 | 4 | 5 | 4 | 3 | 1 |
| C | 4 | 4 | 4 | 3 | 1 | 2 |
| D | 1 | 2 | 1 | 1 | 4 | 5 |
| E | 4 | 3 | 4 | 4 | 5 | 5 |

M1 犯罪都市3 · M2 壮志凌云：独行侠 · M3 阿凡达：水之道 · M4 蜘蛛侠：英雄无归 ·
M5 疯狂元素城 · M6 首尔之春

A 给动作片（M1、M2、M4）打了高分，给《疯狂元素城》（M5）打了低分。步骤有三步。

1. 计算 A 与其他每位用户的**相似度**。
2. 在相似度大于 0 的用户中，按从大到小选出 $$k$$ 位作为**邻居**。
3. 对每个空格，把邻居的评分**按相似度加权平均**。越相似的邻居占的比重越大。

$$
\hat{r}_{A,i} = \frac{\sum_{v \in N} \text{sim}(A, v) \, r_{v,i}}{\sum_{v \in N} \text{sim}(A, v)}
$$

### 用余弦挑邻居 \{#user-cosine}

先直接用上面的余弦相似度，取 $$k = 3$$ 运行。右边一列逐个填上相似度，被选为
邻居的用户变成绿色。最后只留下空格所在列里邻居的评分，做加权平均。

<CollabFilterDemo measure="cosine" />

B 0.835、C 0.820、E 0.705、D 0.466。邻居是 B、C、E，M3 为 4.354，M6 为
**2.542**。不过这些数字有点奇怪。

- **D 的口味和 A 正好相反。** A 打 5 分的电影 D 打了 1、2 分，A 打 2 分的
  电影 D 打了 4 分。可相似度却有 0.466，相当高。
- **E 的走向也和 A 不同。** A 打分最低的 M5，E 打了最高的 5 分。可 E 以
  0.705 成了邻居，E 给 M6 的 5 分把 A 的 M6 预测拉高了。

评分在 1\~5 之间，**全是正数**。正向量之间的夹角不会超过 90 度，余弦不可能
小于 0，连相反的口味看起来都挺相似。

### 皮尔逊相关 \{#pearson}

解决办法是**先减去各自的均值**再衡量。这样只剩下"比平时打得高还是低"。只用
两人都看过的电影这样计算出的余弦，就是**皮尔逊相关系数**（Pearson
correlation coefficient）。

$$
\text{pearson}(a, b) = \frac{\sum_{i} (a_i - \bar{a})(b_i - \bar{b})}{\sqrt{\sum_{i} (a_i - \bar{a})^2} \, \sqrt{\sum_{i} (b_i - \bar{b})^2}}
$$

求和只在两人**都看过的电影**上进行，$$\bar{a}$$ 和 $$\bar{b}$$ 也是这些电影
上的均值。

先用柱子看。选一位比较对象，再点**减去均值**。只留下两人都看过的电影，柱子按
各自的均值下移，比平时打得低的电影落到 0 以下。选 C 时两组柱子形状完全相同，
D 和 E 则方向相反。

<PearsonDemo />

再手算一下。A 与其他四人都看过的电影是 M1、M2、M4、M5。

| | M1 | M2 | M4 | M5 | 均值 | 减去均值 | 皮尔逊 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 5 | 5 | 4 | 2 | 4 | (1, 1, 0, -2) | |
| B | 5 | 4 | 4 | 3 | 4 | (1, 0, 0, -1) | 0.866 |
| C | 4 | 4 | 3 | 1 | 3 | (1, 1, 0, -2) | 1.000 |
| D | 1 | 2 | 1 | 4 | 2 | (-1, 0, -1, 2) | -0.833 |
| E | 4 | 3 | 4 | 5 | 4 | (0, -1, 0, 1) | -0.866 |

- **C 只是每部都比 A 少打 1 分，口味完全一样。** 减去均值后得到和 A 相同的
  向量，所以是 1.000。用余弦算时 C 只有 0.820，比 B 还低。
- A 和 E 是 $$\dfrac{0 - 1 + 0 - 2}{\sqrt{6} \times \sqrt{2}} = -0.866$$，
  **口味相反以负数显现出来**。D 是 -0.833。

用皮尔逊运行同一个演示。只有两人都看过的格子保持亮着。

<CollabFilterDemo />

大于 0 的邻居只有 C 和 B 两位。即使 $$k = 3$$，为负的 D 和 E 也会被排除。

$$
\hat{r}_{A,\text{M3}} = \frac{1.000 \times 4 + 0.866 \times 5}{1.000 + 0.866} = 4.464,
\qquad
\hat{r}_{A,\text{M6}} = \frac{1.000 \times 2 + 0.866 \times 1}{1.000 + 0.866} = 1.536
$$

- 伪代码

```plaintext
ALGORITHM PearsonSimilarity(a, b, n)
    common <- 满足 a[i] > 0 且 b[i] > 0 的 i   // 只用两人都评过的物品
    if common 为空 then return 0
    ma <- a 在 common 上的均值,  mb <- b 在 common 上的均值
    num <- 0,  da <- 0,  db <- 0
    for i in common do                       // 减去各自的均值再计算
        num <- num + (a[i] - ma) * (b[i] - mb)
        da <- da + (a[i] - ma)^2
        db <- db + (b[i] - mb)^2
    if da = 0 or db = 0 then return 0
    return num / sqrt(da * db)

ALGORITHM PredictUserBased(R, sim, neighbors, item)
    num <- 0,  den <- 0
    for v in neighbors do                    // sim > 0 中最大的 k 位
        if R[v][item] > 0 then               // 邻居评过这个物品
            num <- num + sim[v] * R[v][item] // 越相似比重越大
            den <- den + sim[v]
    if den = 0 then return 0
    return num / den                         // 按相似度加权的平均
```

- C 实现（节选）

```c
double predictUserBased(const int ratings[][ITEMS], const double sim[],
                        const int neighbors[], int count, int item) {
    double num = 0.0, den = 0.0;
    for (int i = 0; i < count; i++) {
        int v = neighbors[i];
        if (ratings[v][item] > 0) {
            num += sim[v] * ratings[v][item];
            den += sim[v];
        }
    }
    return den == 0.0 ? 0.0 : num / den;
}
```

`math.h` 的 `sqrt` 在 Linux 上需要额外的链接选项（`-lm`），所以实验代码自带
一个用牛顿法求平方根的 `squareRoot`。Python 也用同样的函数，输出一字不差。

**代价**：有 $$m$$ 位用户、$$n$$ 个物品时，一个相似度是 $$O(n)$$，目标用户与
其余所有人是 $$O(mn)$$。要预先算好所有用户对，需要 $$O(m^2 n)$$。用户多达数亿时，
这个平方就成了问题。

### 换算打分严格的人的评分 \{#mean-centered}

皮尔逊选了 C 作邻居，但加权平均里用的仍是 C 的**原始评分**。C 每部都比 A
少打 1 分，所以 C 的 4 分在 A 的尺度上是 5 分。因此实际常用的公式是把邻居
**偏离自身均值的部分**加权平均，再加到目标用户的均值上。

$$
\hat{r}_{A,i} = \bar{r}_A + \frac{\sum_{v \in N} \text{sim}(A, v) \, (r_{v,i} - \bar{r}_v)}{\sum_{v \in N} \lvert \text{sim}(A, v) \rvert}
$$

实验代码用的是简单的加权平均，这个公式留作练习。

### 基于物品 \{#item-based}

这次对齐的不是行而是**列**。把 M3 这一列与 A 已经看过的电影的列逐一用余弦
比较，选出最相似的 $$k = 2$$ 部，把 **A 自己给这些电影的评分**按相似度加权
平均。列之间的相似度逐个填在最下面一行。

- M3（《阿凡达》）和同一批人打分相近的 M4（《蜘蛛侠》）、M1（《犯罪都市3》）
  最接近。A 给这两部打了 4、5 分，所以是 **4.497**。
- M6（《首尔之春》）和 M5（《疯狂元素城》）最接近，A 给 M5 的 2 分占了很大
  比重，结果是 **2.811**。
- 一次都没看类型，动作片却和动作片、剧情片却和剧情片归到了一起。仅凭**同一批人
  打分相近**这一事实，内容上的相似就显现出来了。

物品之间的相似度比用户之间的更稳定。用户的口味会因一条新评分而变化，但被数万人
评过的两部电影之间的关系很少变化。所以物品相似度适合预先算好，Amazon 的
"买了这件商品的人也买了"就以这种方式闻名。预先计算的代价是 $$O(n^2 m)$$。

## 协同过滤的局限 \{#cf-limits}

### 数据稀疏 \{#sparsity}

协同过滤需要大量数据，而要有大量数据就得有大量用户。这就是**数据稀疏**
（sparsity）问题。

- 真实的评分矩阵几乎全是空格。Netflix 曾经公开的竞赛数据集，接近 99% 的格子
  是空的。
- 于是两人都看过的电影只有一两部的情况很常见，这样的相似度很难信任。

### 冷启动 \{#cold-start}

没有记录，就什么也做不了。这叫**冷启动**（cold start）问题。人和物品两边
都会发生。

- **新用户**：用户 E 刚注册，只看过《极限逃生》。和任何人都没有重合的电影，
  相似度全是 0，没有邻居也没有推荐。

| 用户 A | 用户 B | 用户 C | 用户 E（新来） |
| --- | --- | --- | --- |
| 犯罪都市3 | 疯狂元素城 | 首尔之春 | 极限逃生 |
| 壮志凌云：独行侠 | 阿拉丁 | 闲山：龙的出现 | |
| 阿凡达：水之道 | 阿凡达：水之道 | 阿凡达：水之道 | |
| 蜘蛛侠：英雄无归 | | 蜘蛛侠：英雄无归 | |

- **新物品**：新的复仇者联盟电影上映了。还没有人看过，那一列全是空格，无论
  基于用户还是基于物品，都无法把它推荐给任何人。

在例 1 的矩阵里亲手制造这两种情况。打开**新电影 M7** 会多出没人评过的一列，
打开**新用户 F** 会多出没有评分的一行。点击新格子输入评分，就会重新计算皮尔逊
（$$k = 3$$）预测。只给 F 一个评分时，减去均值后只剩 0，仍然无法计算相似度；
要给两个以上才可能出现邻居。M7 要等某位邻居评过分才会有预测。

## 例 2. 基于内容的过滤 \{#content-based}

基于内容的过滤以**物品本身的属性**（特征）为依据，推荐与用户喜欢过的物品特征
相似的其他物品。如果我喜欢的电影是动作片，就推荐其他动作片。Netflix 上
"为你推荐的动作电影""为你推荐的喜剧动作电影"这样的栏目就是这个样子。

### 类型向量与口味向量 \{#genre-vector}

给每部电影一个用 0 和 1 标出类型的向量。小例子里用三个类型（动作、喜剧、
剧情）。用户喜欢动作和喜剧，所以口味向量是 (1, 1, 0)。

| 电影 | 动作 | 喜剧 | 剧情 | 与口味 (1, 1, 0) 的余弦 |
| --- | --- | --- | --- | --- |
| 电影 1 | 1 | 0 | 0 | 0.707 |
| 电影 2 | 1 | 1 | 0 | 1.000 |
| 电影 3 | 0 | 0 | 1 | 0.000 |

动作加喜剧的电影 2 排第一，只有动作的电影 1 以
$$\dfrac{1}{\sqrt{2}} = 0.707$$ 排第二。这又是余弦相似度。

### 用评分建立画像 \{#profile}

用户不会亲手写出口味向量，要从他们打的评分里建出来。对每部看过的电影，按
**(评分 - 3)** 把它的类型加进去。3 分是一般，加 0；打高分的电影的类型为 +，
打低分的为 -。这就是**用户画像**。

用例 1 的 A 来试试。再加一个类型（科幻），并加入刚上映、**还没人评过的 M7**
（新的复仇者联盟）。

- 伪代码

```plaintext
ALGORITHM BuildProfile(F, r, n, g)
    profile <- g 个 0
    for i <- 0 to n-1 do
        if r[i] > 0 then
            w <- r[i] - 3                   // 3 分是一般，高为 +，低为 -
            for t <- 0 to g-1 do
                profile[t] <- profile[t] + w * F[i][t]
    return profile

ALGORITHM RankByContent(F, r, n, g, profile)
    candidates <- []
    for i <- 0 to n-1 do
        if r[i] = 0 then                    // 只看没评过的物品（包括新物品）
            score[i] <- CosineSimilarity(profile, F[i], g)
            把 i 加入 candidates
    candidates 按 score 降序排序
    return candidates
```

- C 实现（节选）

```c
void buildProfile(const double features[][GENRES], const int ratings[],
                  int n, int g, double profile[]) {
    for (int t = 0; t < g; t++) {
        profile[t] = 0.0;
    }
    for (int i = 0; i < n; i++) {
        if (ratings[i] > 0) {
            int w = ratings[i] - 3;
            for (int t = 0; t < g; t++) {
                profile[t] += w * features[i][t];
            }
        }
    }
}
```

### 基于内容的优点与局限 \{#content-limits}

- **需要事先分析。** 得有人先确定这部电影是动作片还是喜剧片。这里只用了类型，
  但也可以用演员、导演信息。
  - 喜欢的演员出演的其他电影
  - 与喜欢的演员相似的其他演员的电影
- **能解决新物品的冷启动。** 只要有特征，没有评分也能打分。
- **新用户的冷启动依旧存在。** 一个评分都没有时，画像是零向量，所有分数都是
  0。所以只能说"部分"解决了冷启动。
- **只推荐相似的东西。** 喜欢动作片的人只会看到动作片，遇到口味之外的好电影的
  机会就少了。协同过滤能像 C 看过的《首尔之春》那样做出跨类型的推荐。

预测，基于内容的方法却给出 0.764。打开 F，画像是零向量，内容分数也全是 0。

## 两种方式的差别 \{#comparison}

| | 协同过滤 | 基于内容的过滤 |
| --- | --- | --- |
| 看什么 | 其他用户的评分 | 物品的特征与我的评分 |
| 内容分析 | 不需要 | 需要 |
| 搬到其他领域 | 在电影上研究的方法可以直接用于音乐、食物 | 音乐要重新做类型、创作者等分析 |
| 新物品 | 无法推荐 | 有特征就能推荐 |
| 新用户 | 无法推荐 | 无法推荐 |
| 推荐的广度 | 可以跨类型 | 容易困在相似的东西里 |

协同过滤还**很容易改动方法本身**。本资料用了余弦和皮尔逊，但也可以换别的
相似度、改挑选邻居的规则，或者故意混入预测偏低的项目来推荐，做各种实验。
因为这个流程与物品是什么无关。

## 混合过滤 \{#hybrid}

**混合过滤**（hybrid filtering）把两种方式结合起来。最简单的办法是把两个
结果按权重混合。

$$
\text{score}_i = \alpha \cdot \text{cf}_i + (1 - \alpha) \cdot \text{content}_i
$$

先看一个小例子：混合三个物品的协同过滤分数 (0.8, 0.7,
0.3) 与内容分数 (0.6, 0.9, 0.4)。对 A，则把例 1 的皮尔逊预测除以 5 调到
0\~1，再与例 2 的分数混合。没有协同过滤分数的 M7 直接使用内容分数。

拖动 $$\alpha$$ 试试。每根柱子由协同过滤部分和内容部分叠成，各行按分数调换
位置。小例子里 $$\alpha$$ 大于 0.75 后，物品 1 超过物品 2。A 的顺序无论
$$\alpha$$ 怎么变都是 M3、M7、M6。

- 两种方式都给了高分的 M3 稳居第一。
- 新电影 M7 靠内容分数进了推荐列表。等评分积累起来，它也会有协同过滤分数。
- 两者互相弥补缺点，但要同时运行两个系统并决定 $$\alpha$$，所以**实现会
  复杂一些**。

实际服务除了加权求和，也会切换：对新用户先用基于内容的过滤，记录积累起来后再
转到协同过滤。

## 本主题要带走的 \{#takeaway}

- 推荐就是**预测评分矩阵的空格，并从高的开始展示**。
- **协同过滤**：只看别人的评分。基于用户对相似的人的评分、基于物品对我给相似
  物品的评分，按相似度加权平均。
- **余弦相似度**衡量两个向量的方向。评分全为正数时连相反的口味也显得相似，所以
  **减去各自均值再算的皮尔逊相关**更好。
- 协同过滤的弱点是**稀疏与冷启动**。新用户和新物品都无法推荐。
- **基于内容的过滤**：比较物品特征与用户画像。能解决新物品，解决不了新用户，
  而且需要先做内容分析。
- **混合方式**把两种分数混合，互相填补空隙。
