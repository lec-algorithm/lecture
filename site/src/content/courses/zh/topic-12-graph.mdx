## 什么是图 \{#graph}

[[graph|图]] (graph) G 由**顶点**（vertex）的集合 V，以及把顶点两两相连的
**边**（edge）的集合 E 组成。

把描述图的术语一个个点开看看。点击术语，下面的图中它所指的部分就会上色；点击顶点，
那个顶点就成为基准。邻居、度、路径和环都以选中的顶点为准来显示。这个图有 7 个顶点、
9 条边，后面 BFS 和 DFS 的例子会一直用到。

<GraphTermsDemo />

所有顶点的度加起来是 18，正好是 9 条边的两倍。因为一条边会让两端顶点的度各加一。
整理如下。

- **顶点**：也叫节点（node）。个数通常记作 $$n$$ 或 $$V$$。
- **边**：顶点的对。个数记作 $$m$$ 或 $$E$$。
  - **无向**（undirected）：无序对。像朋友关系一样，两边相同。
  - **有向**（directed）：有序对。像关注一样，只朝一个方向。
- **路径**（path）：由边连接起来的顶点序列。两个顶点之间有路径时，称这两个顶点
  **连通**。
- **环**（cycle）：首尾顶点相同的路径
- **度**（degree）：连在一个顶点上的边数

世界上很多东西都是图。

- **社交网络**：朋友关系（Facebook）、关注关系（Instagram）
- **交通**：地铁线路图、道路网、航班
- **网页**：网页之间的链接结构。给搜索结果排序的 PageRank 就在这张图上运行。
- **推荐系统**：用户与商品的关系（主题 15）
- **生物信息学**：蛋白质相互作用网络

连接同一对顶点的边有两条以上时，称为**平行边**（parallel edges, multi-edges）。
本主题的图里没有平行边。

### 最多有多少条边 \{#edge-count}

考虑一个有 $$n$$ 个顶点、没有平行边、连通（是一整块）的无向图。边最少几条，
最多几条？

- **最少** $$n - 1$$ 条：把顶点连成一条线是用边最少的方法。
  去掉任何一条，整块就会断成两块。
- **最多** $$\dfrac{n(n-1)}{2}$$ 条：所有顶点对都相连。第一个顶点可选的对象有
  $$n-1$$ 个，第二个去掉已连的有 $$n-2$$ 个，…… 所以是
  $$(n-1) + (n-2) + \dots + 1$$。顶点有 5 个时是 $$4 + 3 + 2 + 1 = 10$$ 条。

这个差距决定了图算法的代价。

- **稀疏**（sparse）图：边数接近顶点数。$$m = O(n)$$，社交网络就是这样。
- **稠密**（dense）图：边数接近顶点数的平方。$$m = O(n^2)$$，完全图就是这样。

此外，图还可以按有没有方向（有向/无向）、有没有环（cyclic/acyclic）来分类。
有方向且没有环的图称为 **DAG**（directed acyclic graph）。

### 图能回答的问题 \{#problems}

| 问题 | 内容 | 难度 |
| --- | --- | --- |
| 路径 | s 和 t 之间有没有路径 | 容易，本主题 |
| 最短路径 | s 和 t 之间最短的路径是什么 | 容易，本主题 |
| 连通性 | 所有顶点是否都连在一起 | 容易，本主题 |
| 最小生成树 | 以最低代价连起所有顶点的方法 | 容易，本主题 |
| 欧拉回路 | 有没有恰好经过每条边一次的环 | 容易，$$O(V + E)$$ |
| 哈密顿回路 | 有没有恰好经过每个顶点一次的环 | NP-complete |
| 双连通性 | 有没有删掉后图就断开的顶点 | 容易 |
| 平面性 | 能否在平面上画出且边不相交 | $$O(V)$$，但实际实现很复杂 |
| 图同构 | 两个邻接表是否是同一个图 | 至今没人知道 |

欧拉回路源自把柯尼斯堡的七座桥各走一次的散步问题。欧拉回路和哈密顿回路
表面上几乎是同一个问题，但前者能在与边数成正比的时间内解出，后者至今不知道有
高效的解法。图的问题就是这样，差之毫厘，难易立判。

## 图的表示 \{#representation}

在软件里存放图的方法有三种。用一个 13 个顶点、13 条边的图来看。

### 边的列表 \{#edge-list}

把边按对排开，存在数组或链表里。这最简单，但要问"顶点 0 的邻居是谁"时，
就得把整个列表扫一遍。

```plaintext
0-1  0-2  0-5  0-6  3-4  3-5  4-5  4-6  7-8  9-10  9-11  9-12  11-12
```

对无向图，有时会把同一条边记两次，写成 `0-1` 和 `1-0`。

### 邻接矩阵 \{#adjacency-matrix}

在 $$n \times n$$ 的矩阵 A 里写 0 和 1。$$A_{ij} = 1$$ 表示 i 和 j 之间有边。
也有变形。

- 有平行边时，在 $$A_{ij}$$ 里写 i-j 边的**条数**。
- 有权重时，在 $$A_{ij}$$ 里写 i-j 边的**权重**。
- 有向图用 $$A_{ij} = +1$$（i → j）、$$-1$$（i ← j）这样记下方向。

所需空间与边数无关，都是 $$\Theta(n^2)$$。

### 邻接表 \{#adjacency-list}

每个顶点有一张邻居列表。它由顶点数组、边数组，以及边和顶点互相指向的指针
组成。所需空间是 $$\Theta(n + m)$$。
每个顶点一格，每条无向边在两端的列表里各占一格，共 $$2m$$ 格。

用三种方式同时存同一个图。它和前面术语演示的图相同，BFS 和 DFS 的例子也会一直用到。
点击图中的边会删除它，点击矩阵的格子会加入或删除那一对顶点之间的边。点击顶点，
会显示查找它的邻居时两种表示各要看几格：矩阵要看完一行 7 格，邻接表只看邻居个数那么多。

- **邻接表**：空间 $$O(V + E)$$。这个例子里是 4 格顶点加 $$2 \times 3 = 6$$ 格邻居。
  只记真正相连的顶点，所以节省内存。

| 操作 | 邻接矩阵 | 邻接表 |
| --- | --- | --- |
| 添加顶点 | $$O(V^2)$$（重建矩阵） | $$O(1)$$ |

| 所有相邻顶点 | $$O(V)$$ | $$O(\text{degree})$$ |
| 添加边 | $$O(1)$$ | $$O(1)$$（接在列表末尾） |
| 删除边 | $$O(1)$$ | $$O(\text{degree})$$（要在列表里找） |

本主题的实践代码全部使用邻接表。因为搜索算法最常问的问题就是
"这个顶点的邻居是谁"。

## 图的搜索 \{#search}

### 要做什么 \{#search-goal}

- 找出从起点 s **能到达的所有顶点**。
- **任何顶点都不搜索两次。**
- 所以在 $$O(m + n)$$ 时间内结束。

### 通用搜索算法 \{#generic-search}

给定图 G 和起点 s，最通用的形式如下。

1. 一开始只有 s 已探索（explored），其余都未探索。
2. 只要可能就重复：
   - 选一条一端 u 已探索、另一端 v 未探索的边 (u, v)。
   - 把 v 标记为已探索。

**命题**：算法结束时 v 已被探索 ⇔ G 中存在从 s 到 v 的路径。

用反证法证明右边（⇐）。假设存在从 s 到 v 的路径，但结束时 v 没有被探索。

- s 一开始就已探索，v 未被探索。
- 那么在这条路径上的某处，一定有一条边 (u, x)，u 已探索而紧接着的 x 未探索。
  x 可能就是 v，u 也可能就是 s。
- 可是只要还剩这样的边，算法就不会结束。矛盾。

剩下的问题只有一个：**横跨边界的边有好几条时，先选哪一条？**
从已探索区域中近的先选就是 BFS，从刚进入的地方再往深处走就是 DFS。

| | BFS | DFS |
| --- | --- | --- |
| 扩展方式 | 按层（layer），近的先 | 一条路走到底，走不通就退回 |
| 数据结构 | 队列（FIFO） | 栈（LIFO）或递归 |
| 运行时间 | $$O(m + n)$$ | $$O(m + n)$$ |
| 擅长的事 | 无权最短路径、连通分量 | 拓扑排序、连通分量、环检测 |

## 例 1. 广度优先搜索 \{#bfs}

[[bfs|广度优先搜索]] (breadth-first search, BFS) 先看与起点相距 1 条边的所有顶点，
再看相距 2 条、3 条的，**一层一层**向外扩散。

- 标记 s 并放入 FIFO 队列。
- 重复直到队列为空：
  - 从队列取出最早进入的顶点 v。
  - 把 v 的邻居中未标记的全部标记并放入队列。

为方便起见，邻居按编号从小到大查看。左边图的颜色：绿色是取出并看完的顶点，
蓝色是在队列里的顶点，橙色是刚取出的顶点。绿色粗边是每个顶点第一次被发现的
路径（from），顶点旁的蓝色数字是到起点的距离。

<GraphSearchDemo />

要把 1、2、5、6 全部取出之后才轮到 3 和 4。距离为 1 的一层没看完，就不会进入
距离为 2 的一层。

- 伪代码

```plaintext
ALGORITHM BFS(G, s)
    for each 顶点 v in G do
        marked[v] <- false, from[v] <- -1, dist[v] <- INF
    marked[s] <- true                   // 放入时标记
    dist[s] <- 0
    Q <- 空队列 (FIFO)
    enqueue s into Q
    while Q 不为空 do
        v <- dequeue from Q             // 最早进入的顶点
        for each w in adj[v] do         // 为方便起见按升序
            if not marked[w] then
                marked[w] <- true
                from[w] <- v
                dist[w] <- dist[v] + 1  // 下一层
                enqueue w into Q
```

- C 实现（`01_bfs/bfs.c` 中的搜索部分）

```c
marked[s] = 1;
dist[s] = 0;
queue[tail++] = s;
while (head < tail) {
    int v = queue[head++];
    order[n++] = v;
    for (int i = 0; i < deg[v]; i++) {
        int w = adj[v][i];
        if (!marked[w]) {
            marked[w] = 1;
            from[w] = v;
            dist[w] = dist[v] + 1;
            queue[tail++] = w;
        }
    }
}
```

### BFS 的性质 \{#bfs-properties}

- **命题 1**：BFS 结束时 v 已被探索 ⇔ 存在从 s 到 v 的路径。
  BFS 是通用搜索算法的一种，所以证明相同。
- **命题 2**：主循环的运行时间是 $$O(n_s + m_s)$$。
  - $$n_s$$ 是从 s 能到达的顶点数，$$m_s$$ 是从 s 能到达的边数。
  - 每个顶点只进队列一次、出队列一次。
  - 每条边在取出两端顶点时各看一次，共两次。

### 应用：无权最短路径 \{#bfs-shortest-path}

要求从 s 到 v **边数最少**的路径长度 dist(v)，只需给 BFS 加两行。
上面代码里的 `dist` 就是它。

- 一开始设 $$\text{dist}(v) = \infty$$，$$\text{dist}(s) = 0$$。
- 通过边 (v, w) 第一次发现 w 时，$$\text{dist}(w) = \text{dist}(v) + 1$$。

沿着 `from` 往回追，就得到路径本身。4 的 from 是 5，5 的 from 是 0，
所以是 0 → 5 → 4。

它之所以最短，是因为按层扩散。距离为 k 的顶点，要等距离为 k-1 的顶点全部取出
之后才会第一次被发现。不过这**只在所有边长度相同时**成立。如果每条边权重不同，
边数少的路就不一定更短。那时需要后面的 Dijkstra。

### 应用：连通分量 \{#bfs-components}

要找出无向图的所有连通分量，就依次查看每个顶点，从还没被探索的顶点各启动一次
BFS。

```plaintext
把所有顶点标记为未探索
for i <- 1 to n do
    if i 还未被探索 then
        BFS(G, i)                       // 从 i 能到达的顶点构成一个连通分量
```

虽然调用多次 BFS，但顶点和边总共只各看一次，所以是 $$O(m + n)$$。
同样的事也可以用 DFS 做，实践代码用的就是 DFS。

## 例 2. 深度优先搜索 \{#dfs}

[[dfs|深度优先搜索]] (depth-first search, DFS) 沿一条路**一直挖到底**，
走不通了再退回来换另一条路。就像在迷宫里扶着一侧墙走。

- 把顶点 v 标记为已访问。
- 对 v 的每个相邻且未标记的顶点 w，递归地做同样的事。
- 也可以用 LIFO 栈代替递归。实践代码用的是栈。

栈版本看起来就像把队列换成栈的 BFS。不同之处只有一点：
BFS 在**放入时**标记，这个 DFS 在**取出时**标记。所以同一个顶点可能两次进栈，
取出时如果已经访问过就丢弃。

<GraphSearchDemo mode="dfs" />

邻居按编号从小到大压栈，所以编号最大的在栈顶。0 之后依次挖到 6、4、5、3、2，
然后丢掉栈里剩下的过时项（3、5、2），最后访问 1。

- 伪代码

```plaintext
ALGORITHM DFS(G, s)                      // 用栈实现的迭代版
    for each 顶点 v in G do
        marked[v] <- false
    S <- 空栈 (LIFO)
    push (s, -1) into S
    while S 不为空 do
        (v, p) <- pop from S            // 最后放入的顶点
        if marked[v] then continue      // 已访问就丢弃
        marked[v] <- true               // 取出时标记
        from[v] <- p
        for each w in adj[v] do         // 为方便起见按升序压栈
            if not marked[w] then
                push (w, v) into S
```

- C 实现（`02_dfs/dfs.c` 中的搜索部分）

```c
while (top > 0) {
    top--;
    int v = stack[top][0];
    int p = stack[top][1];
    if (marked[v]) {
        continue;                       /* 已访问：过时项 */
    }
    marked[v] = 1;
    from[v] = p;
    order[n++] = v;
    for (int i = 0; i < g->deg[v]; i++) {
        int w = g->adj[v][i];
        if (!marked[w]) {
            stack[top][0] = w;          /* (顶点, 放入它的顶点) */
            stack[top][1] = v;
            top++;
        }
    }
}
```

### DFS 的性质 \{#dfs-properties}

- **命题 1**：DFS 结束时 v 已被探索 ⇔ 存在从 s 到 v 的路径。
  同样是通用搜索算法的一种。
- **命题 2**：运行时间是 $$O(n_s + m_s)$$。在 s 的连通分量内，
  每个顶点最多访问一次，每条边最多看两次（两端各一次）。

### 应用：连通分量 \{#dfs-components}

### 应用：拓扑排序 \{#topological-sort}

七门课程之间有先修关系。u → v 表示"先修 u 才能修 v"。在遵守所有先修关系的前提下
排出选课顺序，就是**拓扑排序**（topological sort）。

<GraphFigure graph="dag" caption="0 Algorithms · 1 Complexity Theory · 2 Artificial Intelligence · 3 Intro to CS · 4 Cryptography · 5 Scientific Computing · 6 Advanced Programming" />

有向图 G 的拓扑顺序就是给顶点编号 $$f(v) \in \{1, 2, \dots, n\}$$，
使得对所有边 (u, v) 都有 $$f(u) < f(v)$$。DFS 正好能给出这个编号。
**看完所有出边之后**才给编号，并且从大号往回倒着给。先结束的顶点，
后面没有要排在它之后的顶点了。蓝色是还在调用栈里、尚未结束的顶点，绿色是已结束
并得到编号的顶点。

```plaintext
    for each 顶点 v in G do
        if not marked[v] then Finish(v)

ALGORITHM Finish(s)
    marked[s] <- true
    for each 边 (s, v) do
        if not marked[v] then Finish(v)
    f[s] <- label                       // 看完所有出边后才给编号

```

### DFS 能做的其他事 \{#dfs-more}

- **找路径**：用 from 还原一条从 s 到 t 的路径。
- **可达性**
  - 程序分析：删除到达不了的代码（dead code）、检测无法跳出的循环
  - 标记-清除垃圾回收器：删掉从根出发到达不了的对象。
- **有向环检测**：Java 编译器的循环继承检查、Excel 的循环引用检查。
  先修条件或任务调度里有有向环，这个日程就排不出来。
  - 在无向图中，搜索时遇到通向已访问顶点的边（back edge）就是环。
  - 在有向图中，遇到通向**正在访问**（递归还没结束）的顶点的边就是环。
- **强连通分量**：有向图中彼此可达的顶点组。
  Kosaraju-Sharir 算法跑两次 DFS 来找。用于找出软件模块之间的相互依赖。

### BFS 与 DFS \{#bfs-vs-dfs}

| 特性 | BFS | DFS |
| --- | --- | --- |
| 数据结构 | 队列（FIFO） | 栈（LIFO）或递归 |
| 内存 | 一层的宽度（宽的图里会变大） | 路径的深度（深的图里会变大） |
| 最短路径 | 在无权图中保证 | 不保证 |
| 实现 | 循环 | 递归或循环 |
| 应用举例 | SNS 好友推荐（从近的人开始） | 走迷宫、网页爬虫、拓扑排序 |

## 最小生成树 \{#mst}

### 树、生成树、最小生成树 \{#mst-def}

- **树**：无环（acyclic）且连通（connected）的无向图。
  有 $$V$$ 个顶点时，边恰好有 $$V - 1$$ 条。
- **生成树**：包含图的所有顶点、连通且是树的子图。
- **最小生成树**（[[mst|MST]], minimum spanning tree）：边权之和最小的生成树。

MST 是许多领域的基础问题。

- 聚类分析
- 最大瓶颈路径（最弱的边最强的路径）
- 防止以太网网桥成环的生成树协议
- NP-hard 问题（旅行商问题、斯坦纳树）的近似算法
- 通信网、电网、水管、计算机网络、道路设计

把所有生成树都造出来，再挑最便宜的行不行？生成树的个数随顶点数指数增长，
这显然是个笨办法。

### 简化假设 \{#mst-assumptions}

例子图有 8 个顶点、16 条边。权重保留到小数点后两位。

<GraphFigure graph="mst" caption="8 个顶点，16 条边（Kruskal·Prim 的例子）" />

- 边权各不相同。这样 MST **只有一个**。有相同权重时 MST 可能有多个。
- 图是连通的。否则得到的不是 MST，而是每个连通分量各自的森林。

### 割的性质 \{#cut-property}

- 图的**割**（cut）是把顶点分成两个非空集合。
- **横切边**（crossing edge）是连接一个集合中的顶点与另一个集合中的顶点的边。
- **割的性质**：无论给定哪个割，权重最小的横切边都在 MST 里。

一开始的割把绿色 {0, 1, 4, 5, 7} 和蓝色 {2, 3, 6} 分开。蓝色虚线是横切边，最轻的
0-2（0.26）是橙色。点击顶点会把它移到另一边，多换几种割试试。无论哪个割，橙色的边
都是后面 Kruskal 和 Prim 求出的 MST 的边。

<CutDemo />

**证明**：假设最轻的横切边 e 不在 MST 里。

- 把 e 加进 MST，就会产生一个环。
- e 横跨了割，环要回到出发的一侧，必须再横跨一次割。
  所以环上的另一条边 f 也是横切边。
- 去掉 f、加入 e，仍然是一棵生成树。
- e 的权重比 f 小，所以新的生成树更轻。出现了比 MST 更轻的生成树，矛盾。

### Greedy MST \{#greedy-mst}

把割的性质直接写成算法，就是这样。

1. 一开始所有边都不涂色。
2. 任找一个没有已涂色横切边的割，把这个割中最轻的横切边涂色。
3. 重复，直到涂了 $$V - 1$$ 条边。

根据割的性质，涂色的边总是 MST 的边。并且只要涂色的边还少于
$$V - 1$$ 条，就总存在一个没有已涂色横切边的割：
把涂色边构成的一块和其余部分分开即可。所以结束时 MST 就完成了。
在例子图中，即使按各种方式选割，按 0-2、5-7、6-2、0-7、2-3、1-7、4-5 的顺序
涂色，也会得到和后面 Kruskal·Prim 相同的七条边。

上面演示里的<strong>给最轻的边涂色</strong>按钮就是这个通用形式。最轻的边如果已经涂过色，
就没有新边可涂，所以要把割换成"一个已涂色的连通块对其余顶点"，涂七次试试。总权重是 1.81。

这个通用形式没有规定"选哪个割"。把它规定下来的就是 Kruskal 和 Prim。

| | Greedy MST | Kruskal | Prim |
| --- | --- | --- | --- |
| 思路 | 直接用割的性质 | 以边为中心，全局最轻的边 | 以顶点为中心，从树一次扩展一个顶点 |
| 起点 | 任意 | 最轻的边 | 指定的一个顶点 |
| 时间 | 取决于实现 | $$O(E \log E)$$ | $$O(E \log V)$$ |
| 预处理 | 无 | 边排序 | 无 |
| 实现 | 难（管理割） | 中等（union-find） | 容易（优先队列） |

## 例 3. Kruskal 算法 \{#kruskal}

Kruskal 算法（1956）按权重从小到大查看边，**只要不形成环**就加入树。

环的判断用块编号来做。每个顶点有一个 `comp`（属于哪一块），一开始每个顶点
各自单独成一块。边的两端在不同块里就加入，并合并这两块。在同一块里说明已经有
路径，加入就会成环。

<KruskalDemo />

看了 13 条边，加入了 7 条。丢掉的六条（1-3、1-5、2-7、1-2、4-7、0-4）都是想连接
已经在同一块里的两个顶点。剩下的 3-6、6-0、6-4 连看都没看。

- 伪代码

```plaintext
ALGORITHM Kruskal(G)
    edges <- 把 G 的边按权重升序排序
    for each 顶点 v in G do
        comp[v] <- v                    // 一开始每个顶点各自一块
    mst <- 空列表
    for each (u, v, w) in edges do
        if comp[u] != comp[v] then      // 连接不同的块 -> 不成环
            把 (u, v, w) 加入 mst
            Merge(comp, comp[u], comp[v])
            if |mst| = V - 1 then break // 有 V-1 条边，树完成
        else                            // 在同一块里 -> 加入就成环
            丢弃 (u, v)
    return mst

ALGORITHM Merge(comp, a, b)
    small <- min(a, b)                  // 块编号取块中最小的顶点
    for each 顶点 x do
        if comp[x] = a or comp[x] = b then comp[x] <- small
```

- C 实现（取自 `03_mst_kruskal/kruskal.c`）

```c
int kruskal(int n, Edge edges[], int m, Edge mst[]) {
    int k = 0;
    qsort(edges, (size_t)m, sizeof(Edge), byWeight);
    for (int v = 0; v < n; v++) {
        comp[v] = v;
    }
    for (int i = 0; i < m; i++) {
        Edge e = edges[i];
        if (comp[e.u] != comp[e.v]) {
            mst[k++] = e;
            merge(n, comp[e.u], comp[e.v]);
            if (k == n - 1) {
                break;
            }
        }
    }
    return k;
}
```

这样两种语言在浮点比较和输出格式上就不会出现差异。

### 分析 \{#kruskal-analysis}

- **正确性**：Kruskal 是 Greedy MST 的特例。Kruskal 加入边 e = v-w 的那一刻，
  把 v 所在的块和其余部分看成一个割。横跨这个割的边中没有已加入的。
  如果加入过，w 就会在同一块里。也没有更轻的横切边。因为按权重升序查看，
  更轻的边都已看过，它们不是被加入就是因为在同一块里而被丢掉了。所以 e 就是
  这个割中最轻的横切边。
- **时间**：排序是 $$O(E \log E)$$。块的判断是 $$O(1)$$，合并要扫整个数组是
  $$O(V)$$，但合并只发生 $$V - 1$$ 次，总共 $$O(V^2)$$。
  把合并换成 **union-find**（并查集），判断和合并都接近常数时间，
  整体就取决于排序代价 $$O(E \log E)$$。

## 例 4. 优先队列与最小堆 \{#heap}

Prim 和 Dijkstra 每一步都要取出"当下最近的顶点"。每次全部扫一遍太慢，
需要一种能快速取出最小者的数据结构。主题 06 的霍夫曼编码也想要同样的东西。

### 优先队列 \{#priority-queue}

- **普通队列**是 FIFO。按 A、B、C、D 的顺序放入，就按 A → B → C → D 出来。
- [[priority-queue|优先队列]] (priority queue) 中每个元素都有**优先级**，
  优先级最高的元素先出来。
  - 用最小堆实现时，值越小优先级越高。最小值先出来。
  - 用最大堆实现时，值越大优先级越高。最大值先出来。

放入 A(3)、B(1)、C(5)、D(2) 后从小往大取，就是 B → D → A → C。

优先队列保证的只有**优先级高的先出来**这一点。
同优先级之间按什么顺序出来是不保证的。把 A(3)、B(1)、C(2)、D(2)
从大往小取，可能是 A → C → D → B，也可能是 A → D → C → B。取决于在堆里
是怎么存的。本主题的实践代码和演示规定：值相同时**先放入的先取出**。

### 堆 \{#heap-def}

**堆**（heap）是满足两个条件的树。

- **完全二叉树**（complete binary tree）：除最后一层外都是满的，最后一层从左往右填。
- **堆性质**（heap property）
  - 最小堆：父节点值 ≤ 子节点值。所以根是全体的最小值。
  - 最大堆：父节点值 ≥ 子节点值。所以根是全体的最大值。

因为是完全二叉树，所以能**不留空位地**存进数组。从上到下、从左到右编号即可。

```plaintext
           1                 数组   [1, 2, 3, 4, 5, 6, 7, 8, 9]
       2       3             下标    0  1  2  3  4  5  6  7  8
     4   5   6   7
    8 9                      i 的父 (i-1)/2,  子 2i+1, 2i+2
```

不用指针，只靠下标计算就能在父子之间往来。

### 插入与取出最小值 \{#heap-ops}

- **插入**（insert）
  1. 检查堆是否已满。
  2. 把新元素放到数组末尾的空位。在树上就是最后一层的下一个位置。
  3. 恢复堆性质。比父节点小就和父节点交换，上移一层再看。
     这叫做 sift up（上浮）。
- **取出最小值**（extract min）
  1. 检查堆是否为空。
  2. 把根保存为最小值。
  3. 把最后一个元素移到根。
  4. 恢复堆性质。比两个子节点中较小的那个大，就和它交换，下移一层再看。
     这叫做 sift down（下沉）。

在装着 1 到 9 的堆里放入 10 和 0，再取出一次最小值。橙色是正在移动的元素，
蓝色是与它比较的父节点或子节点。

<HeapDemo />

10 比父节点 5 大，留在原位。0 依次和父节点 5、2、1 交换，一直升到根。
取出时，末尾的 5 移到根，再和较小的子节点 1、2 交换着沉下去。最后的堆就是
开头的样子再接上 10。

- 伪代码

```plaintext
ALGORITHM Insert(heap, x)
    if heap.size = heap.capacity then return false
    heap[heap.size] <- x                // 放到末尾的空位
    heap.size <- heap.size + 1
    HeapifyUp(heap, heap.size - 1)

ALGORITHM HeapifyUp(heap, i)             // sift up
    while i > 0 do
        p <- (i - 1) / 2
        if heap[i] >= heap[p] then break    // 不比父节点小就留在原位
        swap heap[i], heap[p]
        i <- p

ALGORITHM ExtractMin(heap)
    min <- heap[0]                      // 根是最小值
    heap[0] <- heap[heap.size - 1]      // 最后一个元素移到根
    heap.size <- heap.size - 1
    HeapifyDown(heap, 0)
    return min

ALGORITHM HeapifyDown(heap, i)           // sift down
    loop
        m <- i, l <- 2i + 1, r <- 2i + 2
        if l < heap.size and heap[l] < heap[m] then m <- l
        if r < heap.size and heap[r] < heap[m] then m <- r
        if m = i then break             // 不比两个子节点大就留在原位
        swap heap[i], heap[m]           // 和较小的子节点交换
        i <- m
```

- C 实现（取自 `04_min_heap/minHeap.c`，去掉了打印行）

```c
void heapifyUp(Heap *h, int i) {
    while (i > 0) {
        int p = (i - 1) / 2;
        if (h->a[i] >= h->a[p]) {
            return;
        }
        swap(h, i, p);
        i = p;
    }
}

void heapifyDown(Heap *h, int i) {
    for (;;) {
        int m = i;
        int l = 2 * i + 1;
        int r = 2 * i + 2;
        if (l < h->size && h->a[l] < h->a[m]) m = l;
        if (r < h->size && h->a[r] < h->a[m]) m = r;
        if (m == i) {
            return;
        }
        swap(h, i, m);
        i = m;
    }
}
```

### 分析 \{#heap-analysis}

- 有 $$n$$ 个元素的完全二叉树高度是 $$\lfloor \log_2 n \rfloor$$。
  sift up 和 sift down 每层只做一次比较和交换，所以**插入和取出都是** $$O(\log n)$$。
  在 11 个元素的堆里，0 交换三次就到了根。
- **只看一眼**最小值，读根即可，是 $$O(1)$$。
- 把剩下的全部取出，就按升序出来。这就是**堆排序**，$$O(n \log n)$$。
- 在主题 06 的霍夫曼编码里，每次扫遍整片森林去找"最轻的两棵树"，
  $$k$$ 种字符要 $$O(k^2)$$。把森林放进最小堆，两次取出和一次放入
  都是 $$O(\log k)$$，于是变成 $$O(k \log k)$$。

## 例 5. Prim 算法 \{#prim}

Prim 算法（1959）从一个顶点出发，**贪心地**让树 T 长大。

- 从顶点 0 开始。
- 在恰好只有一端在 T 中的边里，把**最轻的那条**加进 T。
- 重复，直到边有 $$V - 1$$ 条。

主题 06 里说过"Prim 是挑选当下最近者的贪心"。那个"最近者"，正是以最轻的边接到
树上的顶点。

每个顶点有 `key`（接到树上的最轻边的权重）和 `via`（那条边在树一侧的端点），
从最小堆中取出 key 最小的顶点。接上一个顶点后，它的邻居的 key 可能变小。
变小时就修改 key 和 via，并**重新放入**堆。之前放入的项还留在堆里，
以后被取出时如果已在树中就丢弃。

<HeapGraphDemo mode="prim" />

优先队列栏里的 `0.26:2` 表示"以 key 0.26 对应顶点 2"这一项。划线的是过时项。
顶点 4 的 key 从 0.38 变成 0.37，又变成 0.35，减小了两次，过时的 0.37 和 0.38
后来被取出时都被丢掉。蓝色虚线是还没进树的顶点的 via 边。

- 伪代码

```plaintext
ALGORITHM Prim(G, s)
    for each 顶点 v in G do
        key[v] <- INF, via[v] <- -1, inTree[v] <- false
    key[s] <- 0
    PQ <- 空的最小堆
    insert (key[s], s) into PQ
    while PQ 不为空且 |mst| < V - 1 do
        (k, u) <- ExtractMin(PQ)        // 当下离树最近的顶点
        if inTree[u] then continue      // 丢弃过时项
        inTree[u] <- true
        if u != s then 把 (via[u], u, k) 加入 mst
        for each (u, v, w) in adj[u] do
            if not inTree[v] and w < key[v] then
                key[v] <- w             // 找到了更轻的边
                via[v] <- u
                insert (w, v) into PQ   // 不修改，而是重新放入
    return mst
```

- C 实现（取自 `05_mst_prim/prim.c`，去掉了打印行）

```c
key[s] = 0;
push(0, s);
while (heapSize > 0 && edges < n - 1) {
    Item it = pop();
    int u = it.v;
    if (inTree[u]) {
        continue;                       /* 过时项 */
    }
    inTree[u] = 1;
    if (u != s) {
        edges++;
        total += it.key;
    }
    for (int i = 0; i < deg[u]; i++) {
        int v = adj[u][i].v;
        int w = adj[u][i].w;
        if (!inTree[v] && w < key[v]) {
            key[v] = w;
            via[v] = u;
            push(w, v);
        }
    }
}
```

`push` 和 `pop` 就是前面最小堆的 sift up、sift down。区别只在元素是
（key，放入顺序，顶点）。Python 实现使用标准模块 `heapq`。

### 分析 \{#prim-analysis}

- **正确性**：Prim 也是 Greedy MST 的特例。每一步都把"当前的树 T"和
  "其余部分"看成一个割。横跨这个割的边还一条都没选过，
  Prim 选其中最轻的。根据割的性质，这条边在 MST 里。
- **时间**：放进堆的项每条边最多一个。放入和取出各是
  $$O(\log E)$$，所以是 $$O(E \log E)$$；又因为 $$E \le V^2$$，有 $$\log E \le 2 \log V$$，
  所以是 $$O(E \log V)$$。

## 最短路径 \{#shortest-path}

> 在这里先停一下。前半部分我们描述了图、遍历了图、以最低代价把它连起来，
> 并做出了支撑这些工作的堆。  
> 后半部分用同样的堆框架寻找**最短的路**。  
> 把 Prim 的代码改一行就成了 Dijkstra，给 Dijkstra 加上一个估计值就成了 A*。

给定带权有向图（edge-weighted directed graph）$$G = (V, E)$$，
从顶点 s 到 t 的[[shortest-path|最短路径]] (shortest path) 是边权之和最小的路径。
无向图可以看成每条边换成两条方向相反的边的有向图，所以有向图就够了。

- **单对**：从 s 到 t
- **单源**：从 s 到其他所有顶点。Dijkstra 解的就是这个。
- **所有点对**：所有顶点对之间

最短路径的长度不是边数，而是**权重之和**。经过四条边的路，
可能比只有一条边的路更短。

### 为什么还需要另一个算法 \{#why-dijkstra}

BFS 不是已经能在线性时间内求最短路径了吗？是的，但只在**所有边的权重都是 1 时**
才行。经过三条边的路是 3 + 3 + 3 = 9，而只有一条边的路是 20，BFS 会先找到只有
一条边的那条并就此停下。有权重时需要别的方法。

## 例 6. Dijkstra 算法 \{#dijkstra}

Dijkstra 算法求从一个出发顶点到**其他所有顶点的最短距离**。
就像从首尔出发，分别求到釜山、大邱、大田、海南的最短距离。

- 把距离数组初始化为 $$\infty$$，只把起点的距离设为 0。
- 从优先队列取出距离最小的顶点，**确定**它的距离。
- 用从这个顶点出发的边，尝试缩短邻居的距离。
- 重复直到队列为空。

可以理解为按与起点的距离由近到远，一个一个确定顶点。
说得更准确一些，就是这样：

1. 对所有顶点设 $$\text{dist}[s] = 0$$，$$\text{dist}[v] = \infty$$。
2. 设 $$X = \{s\}$$。X 是到目前为止已确定的顶点。
3. 当 $$X \ne V$$ 时，在所有 v 在 X 中、w 不在 X 中的边 (v → w) 里，
   选 $$\text{dist}[v] + w(v, w)$$ 最小的那条，把 w 放进 X。
4. 对 w 的每条出边 (w → z)，把 $$\text{dist}[z]$$ 改成
   $$\min(\text{dist}[z], \text{dist}[w] + w(w, z))$$。这叫做
   **松弛**（relaxation）。

### 与 Prim 并排看 \{#dijkstra-vs-prim}

二者都是用最小堆挑"当下值最小的顶点"的贪心。每一步都选当下的最优，
选过的不撤回。不同的只是放进堆的值。

| | Dijkstra | Prim |
| --- | --- | --- |
| 目的 | 最短路径 | 最小生成树 |
| 修改时用的值 | $$\text{dist}[u] + w(u, v)$$ | $$w(u, v)$$ |
| 值的含义 | 从起点**累积**的距离 | 接到树上的**一条**边的权重 |
| 结果 | 从起点到所有顶点的最短距离 | 连起所有顶点的最小代价 |

绿色边是已确定顶点的 from，蓝色虚线是尚未确定顶点的 from。

- 伪代码

```plaintext
ALGORITHM Dijkstra(G, s)
    for each 顶点 v in G do
        dist[v] <- INF, from[v] <- -1, done[v] <- false
    dist[s] <- 0
    PQ <- 空的最小堆
    insert (dist[s], s) into PQ
    while PQ 不为空 do
        (d, u) <- ExtractMin(PQ)        // 未确定的顶点中最近的
        if done[u] then continue        // 丢弃过时项
        done[u] <- true                 // 这个距离以后不再改变
        for each (u, v, w) in adj[u] do
            if not done[v] and dist[u] + w < dist[v] then
                dist[v] <- dist[u] + w  // 松弛：找到了更短的路
                from[v] <- u
                insert (dist[v], v) into PQ
    return dist, from
```

和 Prim 的伪代码并排放，几乎只有 `key[v] <- w` 变成了 `dist[v] <- dist[u] + w`。

### 为什么正确 \{#dijkstra-proof}

Dijkstra 算法在权重非负的有向图中求出最短路径树。

- 边 v → w 在确定 v 时**恰好松弛一次**。紧接着
  $$\text{dist}[w] \le \text{dist}[v] + w(v, w)$$ 成立。
- 这个不等式一直保持到算法结束。
  - $$\text{dist}[w]$$ 只会减小，不会增大。
  - $$\text{dist}[v]$$ 在 v 确定之后不再改变。因为每一步都选距离最小的顶点，
    而权重非负，经过之后才确定的顶点再回到 v 的路，
    不可能比当前的 $$\text{dist}[v]$$ 更短。
- 于是结束时对所有边都有 $$\text{dist}[w] \le \text{dist}[v] + w(v, w)$$，
  沿着任何路径走都不可能比 $$\text{dist}$$ 更短。所以 $$\text{dist}$$ 就是最短距离。

### 运行时间 \{#dijkstra-time}

每个顶点各做一次放入和取出最小值，每条边各做一次修改值（update-key）。
所以结果取决于用什么实现优先队列。

| 数据结构 | 放入 | 取出最小值 | 修改值 | 合计 |
| --- | --- | --- | --- | --- |
| 无序数组 | $$1$$ | $$V$$ | $$1$$ | $$V^2$$ |
| 二叉堆 | $$\log V$$ | $$\log V$$ | $$\log V$$ | $$E \log V$$ |
| d 叉堆 | $$\log_d V$$ | $$d \log_d V$$ | $$\log_d V$$ | $$E \log_{E/V} V$$ |
| 斐波那契堆 | $$1^*$$ | $$\log V^*$$ | $$1^*$$ | $$E + V \log V$$ |

$$^*$$ 表示均摊（amortized）代价。

- 边非常多的**稠密**图，数组实现（$$O(V^2)$$）最好。
- **稀疏**图上二叉堆快得多。实践代码用的就是它。
- 性能要求高时，可以试试 4 叉堆。
- 斐波那契堆理论上最好，但不太值得去实现。

常有人把斐波那契堆的合计写成 $$E + \log V$$。取出最小值要发生
$$V$$ 次，所以正确的是 $$E + V \log V$$。

### 负环 \{#negative-cycle}

**负环**是边权之和为负的有向环。给前面 Dijkstra 的例子图加一条权重为
$$-8$$ 的边 5 → 7，7 → 5 → 7 就成了 $$6 - 8 = -2$$ 的环。

可以任意变短，一直降到 $$-\infty$$。

- 只有在 s 能到达的负环**不存在时**，最短路径树才存在。
- 所以处理负权重的算法还要一并报告是否有负环。

## 例 7. A* 算法 \{#a-star}

Dijkstra 求从起点到**所有**顶点的最短路径。可是导航应用想要的通常只是到**一个目标**
的路径。目标在东边，就没有理由老老实实地把西边的顶点也一一确定。

A* 算法用到目标剩余距离的**估计值**（启发式）先往目标方向找。
它广泛用于游戏、机器人的路径搜索、地理信息系统（GIS）。

- $$g(n)$$：从起始节点到当前节点 n 的**实际**距离（累积代价）
- $$h(n)$$：从 n 到目标剩余距离的**估计值**（启发式）
- $$f(n) = g(n) + h(n)$$：经过这个节点的路径的预计总代价

Dijkstra 从 $$g$$ 最小的节点开始打开，A* 从 $$f$$ 最小的节点开始打开。
$$h$$ 的准确程度会大大影响性能，所以 $$h$$ 是 A* 的核心。

### 启发式函数 \{#heuristic}

启发式就是**大致估一下**。假设要找从校园里的真理馆 A 出发到电影院的最快路线。
在宿舍 C 栋前给朋友打电话说：

- "我现在在 C 栋，到电影院大概 10 分钟。"接近实际且不超过，是好的估计。
- "啊快到了，2 分钟就到。"虽然没超过，但太乐观，分不出哪边更近。
  如果到处都说 0，就和 Dijkstra 一模一样。
- 把实际要 15 分钟的地方说成"至少 30 分钟"，就可能因为避开这条路而错过最短路径。
  **要找到最优解，就不能高估剩余距离。**

度量距离的启发式通常是下面三种之一。

- **直线距离**（Euclidean distance）：像地图那样可以朝任意方向走时
- **曼哈顿距离**（Manhattan distance）：在网格上只能上下左右走时
- **切比雪夫距离**（Chebyshev distance）：在网格上走对角线也是同样代价时

### 看起来近的不一定是答案 \{#f-choice}

走到这里已经用了 2 分钟，从这一点能去的地方有三处。

| 下一个地点 | 从这里要花的时间 | $$g$$（确定的信息） | $$h$$（预计） | $$f = g + h$$ |
| --- | --- | --- | --- | --- |
| A 栋 | 5 分钟 | $$2 + 5 = 7$$ | 10 | 17 |
| C 栋 | 3 分钟 | $$2 + 3 = 5$$ | 10 | **15** |
| 综合馆 | 1 分钟 | $$2 + 1 = 3$$ | 17 | 20 |

最近的综合馆（1 分钟）方向是远离目标的，所以 $$h$$ 很大。A* 选 $$f$$
最小的 C 栋。这就是它和只看眼前远近的贪心的不同之处。

### 例子图 \{#a-star-graph}

在和 Dijkstra 相同的图里，以 0 为起点、6 为目标。顶点旁的数字是各顶点的 $$h$$。

A* 使用两张列表。

- **开放列表**（open list）：已发现但尚未关闭的候选。以 $$f$$ 为键存进最小堆。
- **关闭列表**（closed list）：已经取出并看过邻居的顶点

0 → 4 → 5 → 2 → 6，**25**。26 不是最短路径。很容易以为 A* 总能找到

分歧出现在关闭 5 的时候。经 4 到达的 5 再到 2，$$g = 14$$，比经 7 到达的

后面的 6 也定在 26。

### 哪里出了问题：两个条件 \{#a-star-optimality}

启发式可以满足的条件有两个。

- **可采纳性**（admissible）：对所有节点 $$h(n) \le h^*(n)$$。这里 $$h^*(n)$$ 是
  从 n 到目标的实际最短距离。意思是不高估剩余距离。
- **一致性**（consistent, monotonic）：对所有边 n → n' 有
  $$h(n) \le c(n, n') + h(n')$$。意思是每走一步，估计值的减少不超过这一步的代价。
  一致且 $$h(\text{目标}) = 0$$ 时，也一定是可采纳的。

这个例子的 $$h$$ 是可采纳的。实际剩余距离从 0 开始依次是 25、22、11、9、16、12、
0、18，$$h$$ 在哪里都没有超过它。但是它**不一致**。

- $$h(4) = 11 > c(4, 5) + h(5) = 4 + 6 = 10$$
- $$h(5) = 6 > c(5, 2) + h(2) = 1 + 4 = 5$$

只有可采纳性时，A* 也能找到最短路径，但**即使是已关闭的顶点，找到更短的路时
也必须重新打开**。只有同时满足一致性，才可以不重新打开。
因为一致时，顶点关闭的那一刻它的 $$g$$ 已经是最短的。只检查可采纳性就使用
不重新打开的 A*，就会像这个例子一样得出不是最优的答案。这是常见的错误。

修正方法有两种。

- 找到通向已关闭顶点的更短路径时，**重新打开**这个顶点。
- 从一开始就使用**一致的** $$h$$。地图上的直线距离总是一致的。

### 一步一步：重新打开 \{#a-star-reopen}

用同样的 $$h$$，这次允许重新打开已关闭的顶点。

<HeapGraphDemo mode="astar" />

关闭 5 时重新打开 2。以 $$f = 18$$ 再次取出 2，修正 3 和 6，以 $$g = 25$$ 到达 6。
路径 0 → 4 → 5 → 2 → 6，和 Dijkstra 一样是 **25**。

- 伪代码

```plaintext
ALGORITHM AStar(G, h, s, t, reopen)
    for each 顶点 v in G do
        g[v] <- INF, cameFrom[v] <- -1, closed[v] <- false
    g[s] <- 0
    open <- 空的最小堆
    insert (g[s] + h[s], s) into open   // f = g + h
    while open 不为空 do
        (f, u) <- ExtractMin(open)      // f 最小的顶点
        if closed[u] then continue      // 丢弃过时项
        if u = t then return PathTo(cameFrom, t), g[t]
        closed[u] <- true               // 放进关闭列表
        for each (u, v, w) in adj[u] do
            if g[u] + w >= g[v] then continue   // 不更短就保持不变
            if closed[v] and not reopen then continue
            closed[v] <- false          // （reopen 时）重新打开已关闭的顶点
            g[v] <- g[u] + w
            cameFrom[v] <- u
            insert (g[v] + h[v], v) into open
    return 没有路径
```

和 Dijkstra 不同的地方有三处：堆的键不是 $$g$$ 而是 $$g + h$$；
取出目标就立即结束；已关闭的顶点可以重新打开。

- C 实现（`07_a_star/aStar.c` 中查看邻居的部分，去掉了打印行）

```c
for (int i = 0; i < gr->deg[u]; i++) {
    int v = gr->adj[u][i].v;
    int ng = g[u] + gr->adj[u][i].w;
    if (ng >= g[v]) {
        continue;                       /* 不更短就保持不变 */
    }
    if (closed[v] && !reopen) {
        continue;                       /* 不看已关闭的顶点 */
    }
    closed[v] = 0;                      /* 重新打开 */
    g[v] = ng;
    cameFrom[v] = u;
    push(ng + h[v], v);
}
```

### 分析 \{#a-star-analysis}

A* 的性能取决于 $$h$$。在同一个图上只换 $$h$$ 看看。点击标签会从头重新运行，标签下方
显示运行到底时关闭的次数和找到的路径。$$h^*$$ 是每个顶点到目标的真实最短距离。

<HeapGraphDemo mode="astar" hChoices />

| $$h$$ | 关闭次数 | 路径 | 代价 |
| --- | --- | --- | --- |
| 示例 $$h$$（重新打开） | 8 | 0 → 4 → 5 → 2 → 6 | 25 |
| $$h = 0$$ | 7 | 0 → 4 → 5 → 2 → 6 | 25 |
| $$h = h^*$$ | 4 | 0 → 4 → 5 → 2 → 6 | 25 |
| $$h = 2h^*$$ | 2 | 0 → 4 → 6 | **29** |

$$2h^*$$ 高估了剩余距离，所以不是可采纳的。它关闭的顶点最少，却给出不是最短路径的 29。

- **时间**：最坏情况 $$O(b^d)$$。$$b$$ 是分支因子（顶点的平均邻居数），
  $$d$$ 是最优解的深度。实际性能很大程度上取决于启发式。
  - 完美的启发式（$$h = h^*$$）只打开最短路径上的顶点，是 $$O(d)$$。
    在这个例子里把 $$h$$ 换成实际剩余距离，只关闭 0、4、5、2 就到达目标。
  - 毫无信息的启发式（$$h = 0$$）和 Dijkstra 相同。
- **空间**：$$O(b^d)$$。开放列表和关闭列表都要保存。
- **最优性**：$$h$$ 可采纳时（允许重新打开时）能找到最短路径；一致时
  不重新打开也能找到最短路径。一致性是更强的条件，还能保证效率。

| 算法 | 搜索方式 | 最优性 | 效率 | 内存 |
| --- | --- | --- | --- | --- |
| BFS | 盲目搜索 | 保证（单位权重） | 低 | 高 |
| Dijkstra | 以距离为准 | 保证（非负权重） | 中 | 中 |
| A* | 目标导向 | 有条件保证（可采纳性·一致性） | 高 | 高 |
| Greedy Best-First | 只用启发式（$$h$$） | 不保证 | 很高 | 低 |

改进 A* 的方法也很多。

- **减少内存**：IDA*（Iterative Deepening A*）逐步放宽深度限制反复搜索，
  用在内存少的环境里。
- **减少计算**：从两头同时搜索的双向 A*（Bidirectional A*）、把地图分成大块
  先在块之间搜索的分层寻路（Hierarchical Pathfinding）
- **改进启发式**：预先计算的模式数据库、用机器学习学到的启发式

## 要带走的 \{#takeaway}

- **图的表示**：邻接矩阵空间 $$\Theta(n^2)$$、判断边 $$O(1)$$；邻接表
  空间 $$\Theta(n + m)$$、遍历邻居快。搜索适合用表。
- **BFS 和 DFS** 是同一种通用搜索的两副面孔。用队列就按层走（无权最短路径），
  用栈或递归就先往深处走，用于拓扑排序和环检测。二者都是
  $$O(m + n)$$。
- **割的性质**：无论哪个割，最轻的横切边都在 MST 里。Kruskal 和
  Prim 是只在选割方式上不同的贪心。例子的 MST 是 1.81。
- **最小堆**：放入时用 sift up 上浮，取出时用 sift down 下沉。二者都是
  $$O(\log n)$$，是优先队列的基础。
- **Prim 和 Dijkstra 是同一个框架**。区别只在放进堆的值是一条边的权重，
  还是累积的距离。Dijkstra 在负权重时会出错。
- <strong>A*</strong> 用 $$f = g + h$$ 先往目标方向找。$$h$$ 可采纳时允许重新打开、
  一致时不重新打开，都能找到最短路径。
