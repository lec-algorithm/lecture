## 그래프란 \{#graph}

[[graph|그래프]] (graph) G는 **정점**(vertex)들의 집합 V와, 정점을 둘씩 잇는
**간선**(edge)들의 집합 E로 이루어집니다.

- **정점**: 노드(node)라고도 합니다. 개수를 보통 $$n$$ 또는 $$V$$로 씁니다.
- **간선**: 정점의 쌍입니다. 개수는 $$m$$ 또는 $$E$$로 씁니다.
  - **무방향**(undirected): 순서 없는 쌍. 친구 관계처럼 양쪽이 같습니다.
  - **방향**(directed): 순서 있는 쌍. 팔로우처럼 한쪽으로만 갑니다.
- **경로**(path): 간선으로 이어진 정점들의 순서열입니다. 두 정점 사이에
  경로가 있으면 두 정점이 **연결되어** 있다고 합니다.
- **사이클**(cycle): 첫 정점과 마지막 정점이 같은 경로
- **차수**(degree): 한 정점에 붙은 간선의 수

세상의 많은 것이 그래프입니다.

- **소셜 네트워크**: 친구 관계(Facebook), 팔로워 관계(Instagram)
- **교통**: 지하철 노선도, 도로망, 항공편
- **웹**: 웹 페이지의 링크 구조. 검색 순위를 매기는 PageRank가 이 그래프 위에서 돕니다.
- **추천 시스템**: 사용자와 상품의 관계(주제 15)
- **생물정보학**: 단백질 상호작용 네트워크

같은 두 정점을 잇는 간선이 두 개 이상이면 **평행 간선**(parallel edges, multi-edges)이라고 합니다.
이 주제의 그래프에는 평행 간선이 없습니다.

### 간선은 몇 개까지 \{#edge-count}

정점이 $$n$$개이고 평행 간선이 없는, 연결된(한 덩어리인) 무방향 그래프를
생각해 봅시다. 간선은 최소 몇 개, 최대 몇 개일까요.

- **최소** $$n - 1$$개: 정점을 한 줄로 잇는 것이 가장 적게 쓰는 방법입니다.
  하나라도 빼면 덩어리가 둘로 갈라집니다.
- **최대** $$\dfrac{n(n-1)}{2}$$개: 모든 쌍을 잇습니다. 첫 정점이 고를 수 있는
  상대가 $$n-1$$개, 둘째는 이미 이은 것을 빼고 $$n-2$$개, … 이므로
  $$(n-1) + (n-2) + \dots + 1$$입니다. 정점이 5개면 $$4 + 3 + 2 + 1 = 10$$개입니다.

이 차이가 그래프 알고리즘의 비용을 가릅니다.

- **희소**(sparse) 그래프: 간선 수가 정점 수에 가깝습니다. $$m = O(n)$$, 소셜 네트워크가 그렇습니다.
- **밀집**(dense) 그래프: 간선 수가 정점 수의 제곱에 가깝습니다. $$m = O(n^2)$$, 완전 그래프가 그렇습니다.

그 밖에 방향이 있는지(방향/무방향), 사이클이 있는지(cyclic/acyclic)로도
그래프를 나눕니다. 방향이 있고 사이클이 없는 그래프를 **DAG**(directed acyclic graph)라고 부릅니다.

나왔습니다. 오일러 투어와 해밀턴 사이클은 겉보기에 거의 같은 질문인데, 앞의 것은
간선 수에 비례하는 시간에 풀리고 뒤의 것은 효율적인 풀이가 알려져 있지 않습니다.
그래프 문제는 이렇게 한 끗 차이로 쉬움과 어려움이 갈립니다.

### 간선의 목록 \{#edge-list}

간선을 쌍으로 늘어놓습니다. 배열이나 연결 리스트에 담습니다. 가장 단순하지만
"정점 0의 이웃은 누구인가"를 물으면 목록 전체를 훑어야 합니다.

```plaintext
0-1  0-2  0-5  0-6  3-4  3-5  4-5  4-6  7-8  9-10  9-11  9-12  11-12
```

무방향 그래프라면 같은 간선을 `0-1`, `1-0` 두 번 적어 두기도 합니다.

### 인접 행렬 \{#adjacency-matrix}

$$n \times n$$ 행렬 A에 0과 1을 적습니다. $$A_{ij} = 1$$이면 i와 j 사이에 간선이
있다는 뜻입니다. 변형도 있습니다.

- 평행 간선이 있으면 $$A_{ij}$$에 i-j 간선의 **개수**를 적습니다.
- 가중치가 있으면 $$A_{ij}$$에 i-j 간선의 **가중치**를 적습니다.
- 방향 그래프는 $$A_{ij} = +1$$(i → j), $$-1$$(i ← j)처럼 방향을 담습니다.

필요한 공간은 간선 수와 상관없이 $$\Theta(n^2)$$입니다.

### 인접 목록 \{#adjacency-list}

정점마다 이웃의 목록을 둡니다. 정점 배열, 간선 배열, 그리고 간선과 정점이 서로를
가리키는 포인터로 이루어집니다. 필요한 공간은 $$\Theta(n + m)$$입니다.
정점마다 칸 하나, 무방향 간선마다 양 끝의 목록에 한 칸씩 $$2m$$칸입니다.

같은 그래프를 두 방식으로 담아 봅니다. 아래 그래프는 BFS와 DFS 예제에서 계속
씁니다.

질문이 "이 정점의 이웃은 누구인가"이기 때문입니다.

## 그래프 탐색 \{#search}

### 무엇을 하려는가 \{#search-goal}

- 시작 정점 s에서 **갈 수 있는 모든 정점**을 찾습니다.
- **어떤 정점도 두 번 탐색하지 않습니다.**
- 그래서 $$O(m + n)$$ 시간에 끝납니다.

### 일반 탐색 알고리즘 \{#generic-search}

그래프 G와 시작 정점 s가 주어졌을 때 가장 일반적인 꼴은 이렇습니다.

1. 처음에 s만 탐색했고(explored), 나머지는 탐색하지 않았습니다.
2. 가능한 동안 되풀이합니다.
   - 한 끝 u는 탐색했고 다른 끝 v는 탐색하지 않은 간선 (u, v)를 하나 고릅니다.
   - v를 탐색한 것으로 표시합니다.

**주장**: 알고리즘이 끝났을 때 v가 탐색되어 있다 ⇔ G에 s에서 v로 가는 경로가 있다.

오른쪽(⇐)을 귀류법으로 보입니다. s에서 v로 가는 경로가 있는데 끝났을 때 v가
탐색되지 않았다고 해 봅시다.

- s는 처음부터 탐색했고 v는 탐색되지 않았습니다.
- 그러면 그 경로 위 어딘가에 탐색한 u 바로 다음에 탐색하지 않은 x가 오는 간선 (u, x)가
  있어야 합니다. x가 v일 수도 있고 u가 s일 수도 있습니다.
- 그런데 그런 간선이 남아 있으면 알고리즘은 끝나지 않습니다. 모순입니다.

남은 질문은 하나입니다. **경계에 걸친 간선이 여럿일 때 무엇부터 고르는가.**
이미 탐색한 영역에서 가까운 것부터 고르면 BFS, 방금 들어간 곳에서 더 깊이 들어가면
DFS입니다.

| | BFS | DFS |
| --- | --- | --- |
| 넓히는 방식 | 층(layer)별로, 가까운 것부터 | 한 갈래를 끝까지, 막히면 되돌아온다 |
| 자료구조 | 큐(FIFO) | 스택(LIFO) 또는 재귀 |
| 실행 시간 | $$O(m + n)$$ | $$O(m + n)$$ |
| 잘하는 일 | 가중치 없는 최단 경로, 연결 요소 | 위상 정렬, 연결 요소, 사이클 탐지 |

## 예제 1. 폭 우선 검색 \{#bfs}

[[bfs|폭 우선 검색]] (breadth-first search, BFS)은 시작점에서 간선 1개 거리인
정점을 모두 보고, 그다음 2개 거리, 3개 거리로 **층별로** 퍼져 나갑니다.

- s를 표시하고 FIFO 큐에 넣습니다.
- 큐가 빌 때까지 되풀이합니다.
  - 큐에서 가장 먼저 들어온 정점 v를 꺼냅니다.
  - v의 이웃 중 표시되지 않은 것을 모두 표시하고 큐에 넣습니다.

이웃은 편의상 작은 번호부터 봅니다. 왼쪽 그래프의 색은 초록이 꺼내서 다 본 정점,
파랑이 큐에 들어 있는 정점, 주황이 지금 꺼낸 정점입니다. 초록 굵은 간선은 각
정점이 처음 발견된 길(from)이고, 정점 옆 파란 숫자는 시작점에서의 거리입니다.

<GraphSearchDemo />

큐에서 1, 2, 5, 6을 모두 꺼낸 뒤에야 3과 4를 꺼냅니다. 거리 1인 층을 다 보기
전에는 거리 2인 층으로 넘어가지 않습니다.

- 의사코드

```plaintext
ALGORITHM BFS(G, s)
    for each 정점 v in G do
        marked[v] <- false, from[v] <- -1, dist[v] <- INF
    marked[s] <- true                   // 넣을 때 표시한다
    dist[s] <- 0
    Q <- 빈 큐 (FIFO)
    enqueue s into Q
    while Q가 비어 있지 않은 동안 do
        v <- dequeue from Q             // 가장 먼저 들어온 정점
        for each w in adj[v] do         // 편의상 오름차순
            if not marked[w] then
                marked[w] <- true
                from[w] <- v
                dist[w] <- dist[v] + 1  // 한 층 아래
                enqueue w into Q
```

- C 구현 (`01_bfs/bfs.c`에서 탐색 부분)

```c
marked[s] = 1;
dist[s] = 0;
queue[tail++] = s;
while (head < tail) {
    int v = queue[head++];
    order[n++] = v;
    for (int i = 0; i < deg[v]; i++) {
        int w = adj[v][i];
        if (!marked[w]) {
            marked[w] = 1;
            from[w] = v;
            dist[w] = dist[v] + 1;
            queue[tail++] = w;
        }
    }
}
```

### BFS의 성질 \{#bfs-properties}

- **주장 1**: BFS가 끝났을 때 v가 탐색되어 있다 ⇔ s에서 v로 가는 경로가 있다.
  BFS는 일반 탐색 알고리즘의 한 경우이므로 증명이 같습니다.
- **주장 2**: 메인 반복문의 실행 시간은 $$O(n_s + m_s)$$입니다.
  - $$n_s$$는 s에서 갈 수 있는 정점의 수, $$m_s$$는 s에서 갈 수 있는 간선의 수입니다.
  - 정점은 큐에 한 번만 들어가고 한 번만 나옵니다.
  - 간선은 양 끝 정점을 꺼낼 때 한 번씩, 두 번 봅니다.

### 응용: 가중치 없는 최단 경로 \{#bfs-shortest-path}

s에서 v까지 **간선 수가 가장 적은** 경로의 길이 dist(v)를 구하려면 BFS에 두 줄만
더하면 됩니다. 위 코드의 `dist`가 그것입니다.

- 처음에 $$\text{dist}(v) = \infty$$, $$\text{dist}(s) = 0$$으로 둡니다.
- 간선 (v, w)로 w를 처음 발견하면 $$\text{dist}(w) = \text{dist}(v) + 1$$입니다.

`from`을 거슬러 올라가면 경로 자체가 나옵니다. 4의 from은 5, 5의 from은 0이므로
0 → 5 → 4입니다.

이것이 최단인 이유는 층별로 퍼지기 때문입니다. 거리 k인 정점은 거리 k-1인
정점을 모두 꺼낸 뒤에야 처음 발견됩니다. 다만 **모든 간선의 길이가 같을 때만**
그렇습니다. 간선마다 가중치가 다르면 간선 수가 적은 길이 더 짧은 길이라는
보장이 없습니다. 그때는 뒤의 Dijkstra가 필요합니다.

### 응용: 연결 요소 \{#bfs-components}

무방향 그래프의 연결 요소를 모두 찾으려면 모든 정점을 차례로 보며, 아직 탐색되지
않은 정점에서 BFS를 한 번씩 시작하면 됩니다.

```plaintext
모든 정점을 탐색되지 않음으로 표시
for i <- 1 to n do
    if i가 아직 탐색되지 않았으면 then
        BFS(G, i)                       // i에서 닿는 정점이 한 연결 요소
```

BFS를 여러 번 부르지만 정점과 간선은 통틀어 한 번씩만 보므로 $$O(m + n)$$입니다.
같은 일을 DFS로도 할 수 있고, 실습 코드는 DFS로 합니다.

## 예제 2. 깊이 우선 검색 \{#dfs}

[[dfs|깊이 우선 검색]] (depth-first search, DFS)은 한 갈래를 **끝까지 파고든 뒤**
막히면 되돌아와 다른 갈래로 갑니다. 미로에서 한쪽 벽을 짚고 걷는 것과 같습니다.

- 정점 v를 방문한 것으로 표시합니다.
- v에 인접하고 표시되지 않은 정점 w마다 같은 일을 재귀적으로 합니다.
- 재귀 대신 LIFO 스택을 쓸 수도 있습니다. 실습 코드는 스택을 씁니다.

스택 버전은 큐를 스택으로 바꾼 BFS처럼 생겼습니다. 다른 점이 하나 있습니다.
BFS는 **넣을 때** 표시하지만, 이 DFS는 **꺼낼 때** 표시합니다. 그래서 같은 정점이
스택에 두 번 들어갈 수 있고, 꺼냈는데 이미 방문했으면 버립니다.

이웃을 작은 번호부터 넣으니 가장 큰 번호가 스택 맨 위에 옵니다. 0 다음에 6, 4,
5, 3, 2로 파고든 뒤, 스택에 남은 낡은 항목(3, 5, 2)을 버리고 마지막에 1을 방문합니다.

- 의사코드

```plaintext
ALGORITHM DFS(G, s)                      // 스택으로 도는 반복형
    for each 정점 v in G do
        marked[v] <- false
    S <- 빈 스택 (LIFO)
    push (s, -1) into S
    while S가 비어 있지 않은 동안 do
        (v, p) <- pop from S            // 가장 나중에 넣은 정점
        if marked[v] then continue      // 이미 방문했으면 버린다
        marked[v] <- true               // 꺼낼 때 표시한다
        from[v] <- p
        for each w in adj[v] do         // 편의상 오름차순으로 넣는다
            if not marked[w] then
                push (w, v) into S
```

- C 구현 (`02_dfs/dfs.c`에서 탐색 부분)

```c
while (top > 0) {
    top--;
    int v = stack[top][0];
    int p = stack[top][1];
    if (marked[v]) {
        continue;                       /* 이미 방문: 낡은 항목 */
    }
    marked[v] = 1;
    from[v] = p;
    order[n++] = v;
    for (int i = 0; i < g->deg[v]; i++) {
        int w = g->adj[v][i];
        if (!marked[w]) {
            stack[top][0] = w;          /* (정점, 넣은 정점) */
            stack[top][1] = v;
            top++;
        }
    }
}
```

### DFS의 성질 \{#dfs-properties}

- **주장 1**: DFS가 끝났을 때 v가 탐색되어 있다 ⇔ s에서 v로 가는 경로가 있다.
  역시 일반 탐색 알고리즘의 한 경우입니다.
- **주장 2**: 실행 시간은 $$O(n_s + m_s)$$입니다. s의 연결 요소 안에서
  정점마다 많아야 한 번 방문하고, 간선마다 많아야 두 번(양 끝에서) 봅니다.

### 응용: 연결 요소 \{#dfs-components}

앞의 정점 13개 그래프에서 아직 방문하지 않은 정점마다 DFS를 시작하고, 한 번의
DFS로 닿는 정점에 같은 번호(id)를 붙입니다. 이번에는 재귀형 DFS를 씁니다.

```plaintext
ALGORITHM Components(G)
    count <- 0
    for each 정점 v in G do
        if not marked[v] then
            Visit(v, count)             // v에서 닿는 정점이 모두 같은 id
            count <- count + 1

ALGORITHM Visit(v, c)
    marked[v] <- true
    id[v] <- c
    for each w in adj[v] do
        if not marked[w] then Visit(w, c)
```

### 응용: 위상 정렬 \{#topological-sort}

과목 일곱 개에 선수 관계가 있습니다. u → v는 "u를 먼저 들어야 v를 들을 수 있다"는
뜻입니다. 모든 선수 관계를 지키며 수강 순서를 정하는 것이 **위상 정렬**(topological sort)입니다.

<GraphFigure graph="dag" caption="0 Algorithms · 1 Complexity Theory · 2 Artificial Intelligence · 3 Intro to CS · 4 Cryptography · 5 Scientific Computing · 6 Advanced Programming" />

방향 그래프 G의 위상 순서는 정점에 번호 $$f(v) \in \{1, 2, \dots, n\}$$를 붙이되,
모든 간선 (u, v)에 대해 $$f(u) < f(v)$$가 되게 하는 것입니다. DFS가 이 번호를
그대로 만들어 줍니다. **나가는 간선을 다 본 뒤에** 번호를 주되, 큰 번호부터
거꾸로 줍니다. 먼저 끝나는 정점은 그 뒤에 올 것이 없는 정점이기 때문입니다.

```plaintext
ALGORITHM TopologicalSort(G)
    label <- V
    for each 정점 v in G do
        if not marked[v] then Finish(v)

ALGORITHM Finish(s)
    marked[s] <- true
    for each 간선 (s, v) do
        if not marked[v] then Finish(v)
    f[s] <- label                       // 나가는 간선을 다 본 뒤에 번호를 준다
    label <- label - 1
```

### DFS로 하는 다른 일 \{#dfs-more}

- **경로 찾기**: s에서 t로 가는 경로 하나를 from으로 복원합니다.
- **도달 가능성**
  - 프로그램 분석: 닿지 않는 코드(dead code) 제거, 빠져나올 수 없는 반복 탐지
  - 마크 스윕 가비지 컬렉터: 루트에서 닿지 않는 객체를 지웁니다.
- **방향 사이클 탐지**: Java 컴파일러의 순환 상속 검사, 엑셀의 순환 참조 검사.
  선수 조건이나 작업 스케줄에 방향 사이클이 있으면 그 일정은 짤 수 없습니다.
  - 무방향 그래프에서는 탐색 중에 이미 방문한 정점으로 가는 간선(back edge)을 만나면 사이클입니다.
  - 방향 그래프에서는 지금 **방문 중인**(재귀가 아직 끝나지 않은) 정점으로 가는 간선을 만나면 사이클입니다.
- **강하게 연결된 요소**: 방향 그래프에서 서로가 서로에게 닿는 정점 묶음입니다.
  Kosaraju-Sharir 알고리즘은 DFS를 두 번 돌려 찾습니다. 소프트웨어 모듈의
  상호 의존을 찾을 때 씁니다.

### BFS와 DFS \{#bfs-vs-dfs}

| 특성 | BFS | DFS |
| --- | --- | --- |
| 자료구조 | 큐(FIFO) | 스택(LIFO) 또는 재귀 |
| 메모리 | 한 층의 폭만큼 (넓은 그래프에서 커진다) | 경로의 깊이만큼 (깊은 그래프에서 커진다) |
| 최단 경로 | 가중치 없는 그래프에서 보장 | 보장하지 않음 |
| 구현 | 반복문 | 재귀 또는 반복문 |
| 응용 예 | SNS 친구 추천(가까운 사람부터) | 미로 찾기, 웹 크롤링, 위상 정렬 |

## 최소 스패닝 트리 \{#mst}

### 트리, 스패닝 트리, 최소 스패닝 트리 \{#mst-def}

- **트리**: 사이클이 없고(acyclic) 연결된(connected) 무방향 그래프입니다.
  정점이 $$V$$개면 간선은 정확히 $$V - 1$$개입니다.
- **스패닝 트리**: 그래프의 모든 정점을 포함하는, 연결된 부분 그래프이면서 트리인 것입니다.
- **최소 스패닝 트리**([[mst|MST]], minimum spanning tree): 간선 가중치의 합이
  가장 작은 스패닝 트리입니다.

MST는 여러 분야의 바탕이 되는 문제입니다.

- 클러스터 분석
- 최대 병목 경로(가장 약한 간선이 가장 강한 경로)
- 이더넷 브리지의 루프를 막는 스패닝 트리 프로토콜
- NP-hard 문제(외판원 문제, 슈타이너 트리)의 근사 알고리즘
- 통신망, 전기망, 수도관, 컴퓨터망, 도로 설계

모든 스패닝 트리를 만들어 보고 가장 싼 것을 고르면 될까요. 스패닝 트리의 수는
정점 수에 대해 지수적으로 늘어나므로 분명히 어리석은 생각입니다.

### 단순화 가정 \{#mst-assumptions}

예제 그래프는 정점 8개, 간선 16개입니다. 가중치는 소수 둘째 자리까지입니다.

<GraphFigure graph="mst" caption="정점 8개, 간선 16개 (Kruskal·Prim 예제)" />

- 간선 가중치가 모두 다릅니다. 그러면 MST가 **하나뿐**입니다. 같은 가중치가
  있으면 MST가 여러 개일 수 있습니다.
- 그래프가 연결되어 있습니다. 아니면 MST 대신 연결 요소마다의 숲이 나옵니다.

### Cut 속성 \{#cut-property}

- 그래프의 **cut**은 정점들을 비어 있지 않은 두 집합으로 나누는 것입니다.
- **crossing edge**는 한쪽 집합의 정점과 다른 쪽 집합의 정점을 잇는 간선입니다.
- **cut 속성**: 어떤 cut이 주어지든, 가중치가 가장 작은 crossing edge는 MST에 들어 있습니다.

<GraphFigure graph="mst" nodeTones={{ 0: 'done', 1: 'done', 4: 'done', 5: 'done', 7: 'done', 2: 'open', 3: 'open', 6: 'open' }} edgeTones={{ '1-3': 'cand', '1-2': 'cand', '2-7': 'cand', '0-2': 'tree', '6-0': 'cand', '6-4': 'cand' }} caption="초록 {0, 1, 4, 5, 7}과 파랑 {2, 3, 6}을 가르는 cut. 파란 점선이 crossing edge, 가장 가벼운 0-2(0.26)가 초록" />

**증명**: 가장 가벼운 crossing edge e가 MST에 없다고 해 봅시다.

- MST에 e를 더하면 사이클이 하나 생깁니다.
- e는 cut을 건너므로, 그 사이클이 출발한 쪽으로 돌아오려면 cut을 한 번 더
  건너야 합니다. 사이클의 다른 간선 f도 crossing edge입니다.
- f를 빼고 e를 넣어도 여전히 스패닝 트리입니다.
- e의 가중치가 f보다 작으므로 새 스패닝 트리가 더 가볍습니다. MST보다 가벼운
  스패닝 트리가 생겼으니 모순입니다.

### Greedy MST \{#greedy-mst}

cut 속성을 그대로 알고리즘으로 옮기면 이렇습니다.

1. 모든 간선을 칠하지 않은 채 시작합니다.
2. 이미 칠한 crossing edge가 하나도 없는 cut을 아무거나 찾아, 그 cut의 가장
   가벼운 crossing edge를 칠합니다.
3. 칠한 간선이 $$V - 1$$개가 될 때까지 되풀이합니다.

칠한 간선은 cut 속성에 따라 언제나 MST의 간선입니다. 그리고 칠한 간선이
$$V - 1$$개보다 적은 동안에는 칠한 crossing edge가 없는 cut이 언제나 있습니다.
칠한 간선이 만든 덩어리 하나와 나머지로 가르면 됩니다. 그러니 끝나면 MST가 완성됩니다.
예전 자료의 예에서는 0-2, 5-7, 6-2, 0-7, 2-3, 1-7, 4-5 순서로 칠했습니다.

이 일반형은 "어떤 cut을 고르는가"를 정하지 않았습니다. 그것을 정한 것이 Kruskal과 Prim입니다.

| | Greedy MST | Kruskal | Prim |
| --- | --- | --- | --- |
| 접근 | cut 속성을 직접 쓴다 | 간선 중심, 전역에서 가장 가벼운 간선 | 정점 중심, 트리에서 한 정점씩 확장 |
| 시작점 | 아무 데나 | 가장 가벼운 간선 | 정한 정점 하나 |
| 시간 | 구현에 따라 | $$O(E \log E)$$ | $$O(E \log V)$$ |
| 전처리 | 없음 | 간선 정렬 | 없음 |
| 구현 | 어려움 (cut 관리) | 중간 (union-find) | 쉬움 (우선순위 큐) |

## 예제 3. Kruskal 알고리즘 \{#kruskal}

Kruskal 알고리즘(1956)은 간선을 가중치 오름차순으로 보며, **사이클을 만들지 않는
한** 트리에 넣습니다.

사이클 판정은 덩어리 번호로 합니다. 정점마다 `comp`(어느 덩어리에 속하는가)를
두고, 처음에는 저마다 자기 혼자 한 덩어리입니다. 간선의 두 끝이 다른 덩어리면
넣고 덩어리를 합칩니다. 같은 덩어리면 이미 경로가 있으므로 넣으면 사이클입니다.

모두 이미 한 덩어리 안에 있는 두 정점을 이으려던 것입니다. 남은 3-6, 6-0, 6-4는

- 의사코드

```plaintext
ALGORITHM Kruskal(G)
    edges <- G의 간선을 가중치 오름차순으로 정렬
    for each 정점 v in G do
        comp[v] <- v                    // 처음에는 정점마다 따로 한 덩어리
    mst <- 빈 목록
    for each (u, v, w) in edges do
        if comp[u] != comp[v] then      // 다른 덩어리를 잇는다 -> 사이클 없음
            mst에 (u, v, w) 추가
            Merge(comp, comp[u], comp[v])
            if |mst| = V - 1 then break // 간선 V-1개면 트리 완성
        else                            // 같은 덩어리 안 -> 넣으면 사이클
            (u, v)를 버린다
    return mst

ALGORITHM Merge(comp, a, b)
    small <- min(a, b)                  // 덩어리 번호는 그 안의 가장 작은 정점
    for each 정점 x do
        if comp[x] = a or comp[x] = b then comp[x] <- small
```

- C 구현 (`03_mst_kruskal/kruskal.c`에서)

```c
int kruskal(int n, Edge edges[], int m, Edge mst[]) {
    int k = 0;
    qsort(edges, (size_t)m, sizeof(Edge), byWeight);
    for (int v = 0; v < n; v++) {
        comp[v] = v;
    }
    for (int i = 0; i < m; i++) {
        Edge e = edges[i];
        if (comp[e.u] != comp[e.v]) {
            mst[k++] = e;
            merge(n, comp[e.u], comp[e.v]);
            if (k == n - 1) {
                break;
            }
        }
    }
    return k;
}
```

### 분석 \{#kruskal-analysis}

- **정확성**: Kruskal은 Greedy MST의 특수한 경우입니다. Kruskal이 간선 e = v-w를
  넣는 순간, v가 속한 덩어리와 나머지를 cut으로 봅니다. 이 cut을 건너는 간선 중
  이미 넣은 것은 없습니다. 넣었다면 w도 같은 덩어리에 있었을 것입니다. 더
  가벼운 crossing edge도 없습니다. 가중치 오름차순으로 보고 있으므로 더 가벼운 간선은 이미 다 봤고,
  그것들은 넣었거나 같은 덩어리 안이라 버렸기 때문입니다. 그러니 e가 이 cut의
  가장 가벼운 crossing edge입니다.
- **시간**: 정렬이 $$O(E \log E)$$입니다. 덩어리 판정은 $$O(1)$$, 합치기는 배열
  전체를 훑어 $$O(V)$$인데 합치기는 $$V - 1$$번만 일어나므로 통틀어 $$O(V^2)$$입니다.
  합치기를 **union-find**(서로소 집합)로 바꾸면 판정과 합치기가 거의 상수 시간이
  되어, 전체가 정렬 비용 $$O(E \log E)$$에 묶입니다.

## 예제 4. 우선순위 큐와 최소 힙 \{#heap}

Prim과 Dijkstra는 매 걸음 "지금 가장 가까운 정점"을 꺼냅니다. 매번 전부 훑으면
느리니, 가장 작은 것을 빨리 꺼내 주는 자료구조가 필요합니다. 주제 06의 허프만
코드도 같은 것을 원했습니다.

### 우선순위 큐 \{#priority-queue}

- **일반적인 큐**는 FIFO입니다. A, B, C, D 순서로 넣으면 A → B → C → D로 나옵니다.
- [[priority-queue|우선순위 큐]] (priority queue)는 원소마다 **우선순위**가 있고, 우선순위가
  가장 높은 원소가 먼저 나옵니다.
  - 최소 힙으로 만들면 값이 작을수록 우선순위가 높습니다. 최솟값이 먼저 나옵니다.
  - 최대 힙으로 만들면 값이 클수록 우선순위가 높습니다. 최댓값이 먼저 나옵니다.

A(3), B(1), C(5), D(2)를 넣고 작은 값부터 꺼내면 B → D → A → C입니다.

우선순위 큐가 보장하는 것은 **우선순위가 높은 것이 먼저 나온다**는 것뿐입니다.
같은 우선순위끼리 어떤 순서로 나올지는 보장하지 않습니다. A(3), B(1), C(2), D(2)를
큰 값부터 꺼내면 A → C → D → B일 수도, A → D → C → B일 수도 있습니다. 힙 안에
어떻게 저장되었느냐에 따라 다릅니다. 이 주제의 실습 코드와 데모는 같은 값이면
**먼저 넣은 것부터** 꺼내도록 순서를 정해 두었습니다.

### 힙 \{#heap-def}

**힙**(heap)은 두 조건을 갖춘 트리입니다.

- **완전 이진 트리**(complete binary tree): 마지막 층을 빼고는 꽉 차 있고, 마지막 층은 왼쪽부터 채웁니다.
- **힙 속성**(heap property)
  - 최소 힙: 부모 값 ≤ 자식 값. 그래서 루트가 전체의 최솟값입니다.
  - 최대 힙: 부모 값 ≥ 자식 값. 그래서 루트가 전체의 최댓값입니다.

완전 이진 트리라서 **배열에 빈칸 없이** 담을 수 있습니다. 위에서 아래로, 왼쪽에서
오른쪽으로 번호를 매기면 됩니다.

```plaintext
           1                 배열   [1, 2, 3, 4, 5, 6, 7, 8, 9]
       2       3             인덱스  0  1  2  3  4  5  6  7  8
     4   5   6   7
    8 9                      i의 부모 (i-1)/2,  자식 2i+1, 2i+2
```

포인터 없이 인덱스 계산만으로 부모와 자식을 오갑니다.

### 삽입과 최솟값 꺼내기 \{#heap-ops}

- **삽입**(insert)
  1. 힙이 가득 찼는지 확인합니다.
  2. 새 원소를 배열 맨 끝 빈자리에 넣습니다. 트리로는 마지막 층의 다음 자리입니다.
  3. 힙 속성을 복구합니다. 부모보다 작으면 부모와 바꾸고, 한 층 올라가 다시
     봅니다. 이것을 sift up이라고 합니다.
- **최솟값 꺼내기**(extract min)
  1. 힙이 비었는지 확인합니다.
  2. 루트를 최솟값으로 저장합니다.
  3. 마지막 원소를 루트로 옮깁니다.
  4. 힙 속성을 복구합니다. 두 자식 중 더 작은 쪽보다 크면 그 자식과 바꾸고,
     한 층 내려가 다시 봅니다. 이것을 sift down이라고 합니다.

1부터 9가 든 힙에 10과 0을 넣고, 최솟값을 하나 꺼내 봅니다. 주황이 움직이는
원소, 파랑이 그와 비교하는 부모 또는 자식입니다.

<HeapDemo />

10은 부모 5보다 커서 제자리에 머뭅니다. 0은 부모 5, 2, 1과 차례로 자리를 바꿔
루트까지 올라갑니다. 꺼낼 때는 맨 끝의 5가 루트로 올라온 뒤 더 작은 자식 1, 2와
바꾸며 다시 내려갑니다. 끝난 힙은 처음 모습에 10이 붙은 것입니다.

- 의사코드

```plaintext
ALGORITHM Insert(heap, x)
    if heap.size = heap.capacity then return false
    heap[heap.size] <- x                // 맨 끝 빈자리에 넣는다
    heap.size <- heap.size + 1
    HeapifyUp(heap, heap.size - 1)

ALGORITHM HeapifyUp(heap, i)             // sift up
    while i > 0 do
        p <- (i - 1) / 2
        if heap[i] >= heap[p] then break    // 부모보다 작지 않으면 제자리
        swap heap[i], heap[p]
        i <- p

ALGORITHM ExtractMin(heap)
    min <- heap[0]                      // 루트가 최솟값
    heap[0] <- heap[heap.size - 1]      // 마지막 원소를 루트로
    heap.size <- heap.size - 1
    HeapifyDown(heap, 0)
    return min

ALGORITHM HeapifyDown(heap, i)           // sift down
    loop
        m <- i, l <- 2i + 1, r <- 2i + 2
        if l < heap.size and heap[l] < heap[m] then m <- l
        if r < heap.size and heap[r] < heap[m] then m <- r
        if m = i then break             // 두 자식보다 크지 않으면 제자리
        swap heap[i], heap[m]           // 더 작은 자식과 바꾼다
        i <- m
```

- C 구현 (`04_min_heap/minHeap.c`에서, 출력 줄은 뺐다)

```c
void heapifyUp(Heap *h, int i) {
    while (i > 0) {
        int p = (i - 1) / 2;
        if (h->a[i] >= h->a[p]) {
            return;
        }
        swap(h, i, p);
        i = p;
    }
}

void heapifyDown(Heap *h, int i) {
    for (;;) {
        int m = i;
        int l = 2 * i + 1;
        int r = 2 * i + 2;
        if (l < h->size && h->a[l] < h->a[m]) m = l;
        if (r < h->size && h->a[r] < h->a[m]) m = r;
        if (m == i) {
            return;
        }
        swap(h, i, m);
        i = m;
    }
}
```

### 분석 \{#heap-analysis}

- 원소가 $$n$$개인 완전 이진 트리의 높이는 $$\lfloor \log_2 n \rfloor$$입니다.
  sift up과 sift down은 한 층에 비교·교환 한 번이므로 **삽입과 꺼내기 모두** $$O(\log n)$$입니다.
  원소 11개인 힙에서 0은 세 번 바꿔 루트에 닿았습니다.
- 최솟값을 **보기만** 하는 것은 루트를 읽으면 되므로 $$O(1)$$입니다.
- 남은 것을 다 꺼내면 오름차순으로 나옵니다. 이것이 **힙 정렬**이고 $$O(n \log n)$$입니다.
- 주제 06의 허프만 코드에서 "가장 가벼운 두 트리"를 매번 숲 전체를 훑어 찾으면
  문자 $$k$$종에 $$O(k^2)$$였습니다. 숲을 최소 힙에 담으면 꺼내기 두 번과 넣기 한 번이
  모두 $$O(\log k)$$이므로 $$O(k \log k)$$가 됩니다.

## 예제 5. Prim 알고리즘 \{#prim}

Prim 알고리즘(1959)은 정점 하나에서 시작해 트리 T를 **욕심껏 키워** 나갑니다.

- 정점 0에서 시작합니다.
- 정확히 한 끝만 T에 있는 간선 중 **가장 가벼운 것**을 T에 더합니다.
- 간선이 $$V - 1$$개가 될 때까지 되풀이합니다.

주제 06에서 "Prim은 지금 가장 가까운 것을 고르는 그리디"라고 했습니다. 그 "가장
가까운 것"이 바로 트리에 가장 가벼운 간선으로 붙는 정점입니다.

정점마다 `key`(트리에 붙는 가장 가벼운 간선의 가중치)와 `via`(그 간선의 트리 쪽 끝)를
두고, 최소 힙에서 key가 가장 작은 정점을 꺼냅니다. 정점 하나를 붙이면 그 이웃의 key가
줄어들 수 있습니다. 줄어들면 key와 via를 고치고 힙에 **새로 넣습니다.** 예전 항목은
힙에 그대로 남아 있다가, 나중에 꺼내졌을 때 이미 트리에 있으면 버립니다.

<HeapGraphDemo mode="prim" />

우선순위 큐 칸의 `0.26:2`는 "key 0.26으로 정점 2"라는 항목입니다. 줄 그어진 항목이
낡은 항목입니다. 정점 4의 key는 0.38, 0.37, 0.35로 두 번 줄었고, 낡은 0.37과 0.38은
나중에 꺼내져 버려집니다. 파란 점선은 아직 트리에 들지 않은 정점의 via 간선입니다.

- 의사코드

```plaintext
ALGORITHM Prim(G, s)
    for each 정점 v in G do
        key[v] <- INF, via[v] <- -1, inTree[v] <- false
    key[s] <- 0
    PQ <- 빈 최소 힙
    insert (key[s], s) into PQ
    while PQ가 비어 있지 않고 |mst| < V - 1 동안 do
        (k, u) <- ExtractMin(PQ)        // 지금 트리에 가장 가까운 정점
        if inTree[u] then continue      // 낡은 항목은 버린다
        inTree[u] <- true
        if u != s then mst에 (via[u], u, k) 추가
        for each (u, v, w) in adj[u] do
            if not inTree[v] and w < key[v] then
                key[v] <- w             // 더 가벼운 간선을 찾았다
                via[v] <- u
                insert (w, v) into PQ   // 갱신 대신 새로 넣는다
    return mst
```

- C 구현 (`05_mst_prim/prim.c`에서, 출력 줄은 뺐다)

```c
key[s] = 0;
push(0, s);
while (heapSize > 0 && edges < n - 1) {
    Item it = pop();
    int u = it.v;
    if (inTree[u]) {
        continue;                       /* 낡은 항목 */
    }
    inTree[u] = 1;
    if (u != s) {
        edges++;
        total += it.key;
    }
    for (int i = 0; i < deg[u]; i++) {
        int v = adj[u][i].v;
        int w = adj[u][i].w;
        if (!inTree[v] && w < key[v]) {
            key[v] = w;
            via[v] = u;
            push(w, v);
        }
    }
}
```

- **정확성**: Prim도 Greedy MST의 특수한 경우입니다. 매 걸음 "지금의 트리 T"와
  "나머지"를 cut으로 봅니다. 이 cut을 건너는 간선은 아직 하나도 고르지 않았고,
  Prim은 그중 가장 가벼운 것을 고릅니다. cut 속성에 따라 그 간선은 MST에 있습니다.
- **시간**: 힙에 넣는 항목은 간선마다 많아야 하나입니다. 넣기와 꺼내기가 각각
  $$O(\log E)$$이므로 $$O(E \log E)$$이고, $$E \le V^2$$이라 $$\log E \le 2 \log V$$이므로
  $$O(E \log V)$$입니다.

## 최단 경로 \{#shortest-path}

> 여기서 한 번 끊어 갑니다. 앞 절반은 그래프를 적고, 훑고, 가장 싸게 잇고,
> 그 일을 받치는 힙을 만들었습니다.  
> 뒤 절반은 같은 힙 틀로 **가장 짧은 길**을 찾습니다.  
> Prim의 코드에서 한 줄을 바꾸면 Dijkstra가 되고, Dijkstra에 추정값 하나를
> 더하면 A*가 됩니다.

가중치가 있는 방향 그래프(edge-weighted directed graph) $$G = (V, E)$$가 주어졌을 때,
정점 s에서 t까지의 [[shortest-path|최단 경로]] (shortest path)는 간선 가중치의 합이
가장 작은 경로입니다. 무방향 그래프는 간선마다 양방향 간선 둘을 둔 방향 그래프로
볼 수 있으므로 방향 그래프로 충분합니다.

- **한 쌍**: s에서 t까지
- **단일 출발점**: s에서 다른 모든 정점까지. Dijkstra가 이것을 풉니다.
- **모든 쌍**: 모든 정점 쌍 사이

예전 자료의 예에서 0에서 6까지의 최단 경로는 0 → 2 → 7 → 3 → 6이고, 길이는
$$0.26 + 0.34 + 0.39 + 0.52 = 1.51$$이었습니다.

### 왜 또 다른 알고리즘이 필요한가 \{#why-dijkstra}

BFS가 이미 선형 시간에 최단 경로를 구하지 않았나요. 그렇습니다. 다만 **모든 간선의
가중치가 1일 때**만입니다. 간선 셋을 지나는 길이 3 + 3 + 3 = 9이고 간선 하나짜리
길이 20이라면, BFS는 간선 하나짜리를 먼저 찾고 거기서 멈춥니다. 가중치가 있으면
다른 방법이 필요합니다.

## 예제 6. Dijkstra 알고리즘 \{#dijkstra}

Dijkstra 알고리즘은 출발 정점 하나에서 **다른 모든 정점까지의 최단 거리**를 구합니다.
서울에서 출발해 부산, 대구, 대전, 해남까지 각각 가장 짧은 거리를 구하는 일입니다.

- 거리 배열을 $$\infty$$로 초기화하고, 출발점의 거리만 0으로 둡니다.
- 우선순위 큐에서 거리가 가장 작은 정점을 꺼내 그 거리를 **확정**합니다.
- 그 정점에서 나가는 간선으로 이웃의 거리를 줄여 봅니다.
- 큐가 빌 때까지 되풀이합니다.

출발점에서 거리가 멀어지는 순서대로 정점을 하나씩 확정해 나가는 셈입니다.
조금 더 정확히 적으면 이렇습니다.

1. 모든 정점에 대해 $$\text{dist}[s] = 0$$, $$\text{dist}[v] = \infty$$로 둡니다.
2. $$X = \{s\}$$로 둡니다. X는 지금까지 확정한 정점들입니다.
3. $$X \ne V$$인 동안, v는 X에 있고 w는 X에 없는 모든 간선 (v → w) 가운데
   $$\text{dist}[v] + w(v, w)$$가 가장 작은 것을 골라 w를 X에 넣습니다.
4. w에서 나가는 간선 (w → z)마다 $$\text{dist}[z]$$를
   $$\min(\text{dist}[z], \text{dist}[w] + w(w, z))$$로 고칩니다. 이것을
   **완화**(relaxation)라고 합니다.

### Prim과 나란히 \{#dijkstra-vs-prim}

둘 다 최소 힙으로 "지금 가장 작은 값을 가진 정점"을 고르는 그리디입니다. 매 단계
지금의 최선을 고르고, 고른 것은 되돌리지 않습니다. 다른 것은 힙에 넣는 값입니다.

| | Dijkstra | Prim |
| --- | --- | --- |
| 목적 | 최단 경로 | 최소 스패닝 트리 |
| 고칠 때 쓰는 값 | $$\text{dist}[u] + w(u, v)$$ | $$w(u, v)$$ |
| 값의 뜻 | 출발점부터 **쌓인** 거리 | 트리에 붙는 간선 **하나**의 가중치 |
| 결과 | 출발점에서 모든 정점까지의 최단 거리 | 모든 정점을 잇는 최소 비용 |

- 의사코드

```plaintext
ALGORITHM Dijkstra(G, s)
    for each 정점 v in G do
        dist[v] <- INF, from[v] <- -1, done[v] <- false
    dist[s] <- 0
    PQ <- 빈 최소 힙
    insert (dist[s], s) into PQ
    while PQ가 비어 있지 않은 동안 do
        (d, u) <- ExtractMin(PQ)        // 아직 확정 안 된 정점 중 가장 가까운 것
        if done[u] then continue        // 낡은 항목은 버린다
        done[u] <- true                 // 이 거리는 이제 바뀌지 않는다
        for each (u, v, w) in adj[u] do
            if not done[v] and dist[u] + w < dist[v] then
                dist[v] <- dist[u] + w  // 완화: 더 짧은 길을 찾았다
                from[v] <- u
                insert (dist[v], v) into PQ
    return dist, from
```

Prim의 의사코드와 나란히 놓으면 `key[v] <- w`가 `dist[v] <- dist[u] + w`로 바뀐
것이 거의 전부입니다.

- C 구현 (`06_dijkstra/dijkstra.c`에서, 출력 줄은 뺐다)

```c
dist[s] = 0;
push(0, s);
while (heapSize > 0) {
    Item it = pop();
    int u = it.v;
    if (done[u]) {
        continue;                       /* 낡은 항목 */
    }
    done[u] = 1;
    for (int i = 0; i < g->deg[u]; i++) {
        int v = g->adj[u][i].v;
        int nd = dist[u] + g->adj[u][i].w;
        if (!done[v] && nd < dist[v]) {
            dist[v] = nd;
            from[v] = u;
            push(nd, v);
        }
    }
}
```

### 왜 맞는가 \{#dijkstra-proof}

Dijkstra 알고리즘은 가중치가 음수가 아닌 방향 그래프에서 최단 경로 트리를 구합니다.

- 간선 v → w는 v를 확정할 때 **정확히 한 번** 완화됩니다. 그 직후
  $$\text{dist}[w] \le \text{dist}[v] + w(v, w)$$가 성립합니다.
- 이 부등식은 알고리즘이 끝날 때까지 유지됩니다.
  - $$\text{dist}[w]$$는 줄어들기만 하고 늘지 않습니다.
  - $$\text{dist}[v]$$는 v를 확정한 뒤로 바뀌지 않습니다. 매 단계 가장 작은 거리를
    가진 정점을 고르고, 가중치가 음수가 아니라서, 뒤에 확정되는 정점을 거쳐 v로
    돌아오는 길은 지금의 $$\text{dist}[v]$$보다 짧을 수 없기 때문입니다.
- 그러면 끝났을 때 모든 간선에 대해 $$\text{dist}[w] \le \text{dist}[v] + w(v, w)$$이고,
  어떤 경로를 따라가도 $$\text{dist}$$보다 짧아질 수 없습니다. 그러니 $$\text{dist}$$가 최단 거리입니다.

### 실행 시간 \{#dijkstra-time}

정점마다 넣기·최솟값 꺼내기가 한 번씩, 간선마다 값 고치기(update-key)가 한 번씩
일어납니다. 그래서 우선순위 큐를 무엇으로 만드느냐에 따라 달라집니다.

| 자료구조 | 넣기 | 최솟값 꺼내기 | 값 고치기 | 합계 |
| --- | --- | --- | --- | --- |
| 정렬 안 된 배열 | $$1$$ | $$V$$ | $$1$$ | $$V^2$$ |
| 이진 힙 | $$\log V$$ | $$\log V$$ | $$\log V$$ | $$E \log V$$ |
| d-way 힙 | $$\log_d V$$ | $$d \log_d V$$ | $$\log_d V$$ | $$E \log_{E/V} V$$ |
| 피보나치 힙 | $$1^*$$ | $$\log V^*$$ | $$1^*$$ | $$E + V \log V$$ |

$$^*$$는 분할 상환(amortized) 비용입니다.

- 간선이 아주 많은 **밀집** 그래프에서는 배열 구현($$O(V^2)$$)이 가장 낫습니다.
- **희소** 그래프에서는 이진 힙이 훨씬 빠릅니다. 실습 코드가 이것입니다.
- 성능이 중요하면 4-way 힙을 써 볼 만합니다.
- 피보나치 힙은 이론상 가장 좋지만, 구현할 만한 가치는 크지 않습니다.

예전 자료의 표에서 피보나치 힙의 합계가 $$E + \log V$$로 적혀 있었는데,
$$E + V \log V$$가 맞습니다. 최솟값 꺼내기가 $$V$$번 일어나기 때문입니다.

가중치가 음수이면 Dijkstra는 틀립니다. 정점 4개짜리 그래프로 봅니다.

### 음의 사이클 \{#negative-cycle}

**음의 사이클**은 간선 가중치의 합이 음수인 방향 사이클입니다. 앞의 0 → 6 예에서
5 → 4의 가중치를 $$-0.66$$으로 바꾸면, 4 → 5 → 4는 $$0.35 - 0.66 = -0.31$$인
사이클이 됩니다. 이 사이클을 돌 때마다 길이가 줄어드니, 0에서 6까지의 최단
경로는 **정의되지 않습니다.** 얼마든지 짧아져 $$-\infty$$로 내려갑니다.

- 최단 경로 트리는 s에서 닿는 음의 사이클이 **없을 때만** 있습니다.
- 그래서 음의 가중치를 다루는 알고리즘은 음의 사이클이 있는지도 함께 알려 줘야 합니다.

## 예제 7. A* 알고리즘 \{#a-star}

Dijkstra는 출발점에서 **모든** 정점까지의 최단 경로를 구합니다. 그런데 길찾기
앱이 원하는 것은 대개 **목표 하나**까지의 경로입니다. 목표가 동쪽에 있는데 서쪽
정점까지 성실히 확정할 이유가 없습니다.

A* 알고리즘은 목표까지 남은 거리의 **추정값**(휴리스틱)을 써서 목표 쪽부터
찾습니다. 게임, 로봇의 경로 탐색, 지리 정보 시스템(GIS)에서 널리 씁니다.

- $$g(n)$$: 시작 노드에서 지금 노드 n까지의 **실제** 거리(누적 비용)
- $$h(n)$$: n에서 목표까지 남은 거리의 **추정값**(휴리스틱)
- $$f(n) = g(n) + h(n)$$: 이 노드를 거쳐 가는 경로의 예상 총비용

Dijkstra는 $$g$$가 가장 작은 노드부터, A*는 $$f$$가 가장 작은 노드부터 엽니다.
$$h$$가 얼마나 정확한지에 따라 성능이 크게 달라지므로 $$h$$가 A*의 핵심입니다.

### 휴리스틱 함수 \{#heuristic}

휴리스틱은 **대충 예상해 보는 것**입니다. 캠퍼스의 진리관 A에서 출발해 메가박스까지
가장 빨리 가는 길을 찾는다고 해 봅시다. 기숙사 C동 앞에서 친구에게 전화로 말합니다.

- "나 지금 C동인데, 메가박스까지 한 10분이면 가." 실제에 가깝고 넘지 않으니 좋은 추정입니다.
- "아 다 왔어, 2분이면 가." 넘지는 않지만 너무 낙관적이라 어느 쪽이 가까운지
  가려 주지 못합니다. 모든 곳에서 0이라고 하면 Dijkstra와 똑같아집니다.
- 실제로 15분 걸리는 곳을 "30분은 걸려"라고 하면 그 길을 피하다가 최단 경로를
  놓칠 수 있습니다. **최적해를 찾으려면 남은 거리를 과대평가하지 않아야 합니다.**

거리를 재는 휴리스틱은 보통 이 셋 중 하나입니다.

- **직선 거리**(Euclidean distance): 지도처럼 어느 방향으로든 갈 수 있을 때
- **맨해튼 거리**(Manhattan distance): 격자 위에서 상하좌우로만 갈 수 있을 때
- **체비쇼프 거리**(Chebyshev distance): 격자에서 대각선까지 같은 비용으로 갈 수 있을 때

### 가까워 보이는 곳이 답은 아니다 \{#f-choice}

여기까지 2분 걸려 왔고, 이 지점에서 갈 수 있는 곳이 셋입니다.

| 다음 지점 | 여기서 걸리는 시간 | $$g$$ (확실한 정보) | $$h$$ (예상) | $$f = g + h$$ |
| --- | --- | --- | --- | --- |
| A동 | 5분 | $$2 + 5 = 7$$ | 10 | 17 |
| C동 | 3분 | $$2 + 3 = 5$$ | 10 | **15** |
| 종합관 | 1분 | $$2 + 1 = 3$$ | 17 | 20 |

가장 가까운 종합관(1분)은 목표에서 멀어지는 쪽이라 $$h$$가 큽니다. A*는 $$f$$가
가장 작은 C동을 고릅니다. 지금 가까운 것만 보는 그리디와 다른 점입니다.

A*는 두 목록을 씁니다.

- **열린 목록**(open list): 발견했지만 아직 닫지 않은 후보. 최소 힙에 $$f$$를 키로 담습니다.
- **닫힌 목록**(closed list): 이미 꺼내서 이웃까지 본 정점

### 한 걸음씩: 예전 자료의 방식 \{#a-star-demo}

예전 자료의 A*는 한 번 닫은 정점을 다시 보지 않았습니다. 그대로 돌려 봅니다.

<HeapGraphDemo mode="astar" reopen={false} />

경로 0 → 7 → 2 → 6, 비용 **26**이 나왔습니다. 그런데 같은 그래프에서 Dijkstra는
0 → 4 → 5 → 2 → 6, **25**를 찾았습니다. 예전 자료는 26을 최단 경로로 정리했는데,
이것은 틀렸습니다.

갈림길은 5를 닫을 때입니다. 4를 거쳐 온 5에서 2로 가면 $$g = 14$$로, 7을 거쳐
온 15보다 짧습니다. 그런데 2는 이미 닫혀 있어서 그냥 지나갑니다. 2의 $$g$$가
15로 굳고, 그 뒤의 6도 26으로 굳습니다.

### 무엇이 잘못되었나: 두 가지 조건 \{#a-star-optimality}

휴리스틱이 갖출 수 있는 조건은 둘입니다.

- **허용성**(admissible): 모든 노드에서 $$h(n) \le h^*(n)$$. 여기서 $$h^*(n)$$은
  n에서 목표까지의 실제 최단 거리입니다. 남은 거리를 과대평가하지 않는다는 뜻입니다.
- **일관성**(consistent, monotonic): 모든 간선 n → n'에 대해
  $$h(n) \le c(n, n') + h(n')$$. 한 걸음 옮길 때 추정이 그 걸음의 비용보다 많이
  줄지 않는다는 뜻입니다. 일관적이고 $$h(\text{목표}) = 0$$이면 허용적이기도 합니다.

이 예의 $$h$$는 허용적입니다. 실제 남은 거리는 0부터 차례로 25, 22, 11, 9, 16, 12,
0, 18이고, $$h$$는 어디서도 그것을 넘지 않습니다. 그러나 **일관적이지 않습니다.**

- $$h(4) = 11 > c(4, 5) + h(5) = 4 + 6 = 10$$
- $$h(5) = 6 > c(5, 2) + h(2) = 1 + 4 = 5$$

허용성만 있으면 A*는 최단 경로를 찾지만, **닫힌 정점이라도 더 짧은 길을 찾으면
다시 열어야** 합니다. 다시 열지 않아도 되는 것은 일관성까지 갖췄을 때입니다.
일관적이면 정점을 닫는 순간 그 $$g$$가 이미 최단이기 때문입니다. 예전 자료는
허용성만 있는 $$h$$로 다시 열지 않는 A*를 돌려서 최적이 아닌 답을 냈습니다.

고치는 방법은 둘입니다.

- 닫힌 정점으로 가는 더 짧은 길을 찾으면 그 정점을 **다시 연다**.
- 처음부터 **일관적인** $$h$$를 쓴다. 지도에서의 직선 거리는 언제나 일관적입니다.

### 한 걸음씩: 다시 열기 \{#a-star-reopen}

같은 $$h$$로, 이번에는 닫힌 정점을 다시 열도록 돌립니다.

<HeapGraphDemo mode="astar" />

5를 닫을 때 2를 다시 엽니다. 2를 $$f = 18$$로 다시 꺼내 3과 6을 고치고, 6에
$$g = 25$$로 닿습니다. 경로 0 → 4 → 5 → 2 → 6, Dijkstra와 같은 **25**입니다.

- 의사코드

```plaintext
ALGORITHM AStar(G, h, s, t, reopen)
    for each 정점 v in G do
        g[v] <- INF, cameFrom[v] <- -1, closed[v] <- false
    g[s] <- 0
    open <- 빈 최소 힙
    insert (g[s] + h[s], s) into open   // f = g + h
    while open이 비어 있지 않은 동안 do
        (f, u) <- ExtractMin(open)      // f가 가장 작은 정점
        if closed[u] then continue      // 낡은 항목은 버린다
        if u = t then return PathTo(cameFrom, t), g[t]
        closed[u] <- true               // 닫힌 목록에 넣는다
        for each (u, v, w) in adj[u] do
            if g[u] + w >= g[v] then continue   // 더 짧지 않으면 그대로
            if closed[v] and not reopen then continue
            closed[v] <- false          // (reopen일 때) 닫힌 정점을 다시 연다
            g[v] <- g[u] + w
            cameFrom[v] <- u
            insert (g[v] + h[v], v) into open
    return 경로 없음
```

Dijkstra와 다른 곳은 셋입니다. 힙의 키가 $$g$$가 아니라 $$g + h$$이고, 목표를
꺼내면 바로 끝나고, 닫힌 정점을 다시 열 수 있습니다.

- C 구현 (`07_a_star/aStar.c`에서 이웃을 보는 부분, 출력 줄은 뺐다)

```c
for (int i = 0; i < gr->deg[u]; i++) {
    int v = gr->adj[u][i].v;
    int ng = g[u] + gr->adj[u][i].w;
    if (ng >= g[v]) {
        continue;                       /* 더 짧지 않으면 그대로 */
    }
    if (closed[v] && !reopen) {
        continue;                       /* 닫힌 정점은 보지 않는다 */
    }
    closed[v] = 0;                      /* 다시 연다 */
    g[v] = ng;
    cameFrom[v] = u;
    push(ng + h[v], v);
}
```

### 분석 \{#a-star-analysis}

- **시간**: 최악의 경우 $$O(b^d)$$입니다. $$b$$는 분기 계수(정점의 평균 이웃 수),
  $$d$$는 최적해의 깊이입니다. 실제 성능은 휴리스틱에 크게 달려 있습니다.
  - 완벽한 휴리스틱($$h = h^*$$)이면 최단 경로 위의 정점만 열어 $$O(d)$$입니다.
    이 예에서 $$h$$를 실제 남은 거리로 바꾸면 0, 4, 5, 2만 닫고 목표에 닿습니다.
  - 아무 정보 없는 휴리스틱($$h = 0$$)이면 Dijkstra와 같습니다.
- **공간**: $$O(b^d)$$. 열린 목록과 닫힌 목록을 모두 들고 있어야 합니다.
- **최적성**: $$h$$가 허용적이면(다시 열기를 허용할 때) 최단 경로를 찾고, 일관적이면
  다시 열지 않아도 최단 경로를 찾습니다. 일관성이 더 강한 조건이고, 효율까지
  보장합니다.

| 알고리즘 | 탐색 방식 | 최적성 | 효율 | 메모리 |
| --- | --- | --- | --- | --- |
| BFS | 무작정 탐색 | 보장 (단위 가중치) | 낮음 | 높음 |
| Dijkstra | 거리 기준 | 보장 (음 아닌 가중치) | 중간 | 중간 |
| A* | 목표 지향 | 조건부 보장 (허용성·일관성) | 높음 | 높음 |
| Greedy Best-First | 휴리스틱($$h$$)만 사용 | 보장 안 됨 | 매우 높음 | 낮음 |

A*를 더 다듬는 방법도 많습니다.

- **메모리 줄이기**: IDA*(Iterative Deepening A*)는 깊이 제한을 늘려 가며 되풀이해
  메모리가 적은 환경에서 씁니다.
- **계산 줄이기**: 양쪽에서 동시에 찾는 양방향 A*(Bidirectional A*), 지도를 큰
  덩어리로 나눠 먼저 찾는 계층적 경로 탐색(Hierarchical Pathfinding)
- **휴리스틱 다듬기**: 미리 계산한 패턴 데이터베이스, 머신러닝으로 배운 휴리스틱

## 이 주제에서 남길 것 \{#takeaway}

- **그래프 표현**: 인접 행렬은 $$\Theta(n^2)$$ 공간에 간선 확인 $$O(1)$$, 인접
  목록은 $$\Theta(n + m)$$ 공간에 이웃 훑기가 빠르다. 탐색에는 목록이 맞다.
- **BFS와 DFS**는 같은 일반 탐색의 두 얼굴이다. 큐면 층별로(가중치 없는 최단
  경로), 스택이나 재귀면 깊이 먼저 가서 위상 정렬과 사이클 탐지에 쓴다. 둘 다
  $$O(m + n)$$이다.
- **cut 속성**: 어떤 cut이든 가장 가벼운 crossing edge는 MST에 있다. Kruskal과
  Prim은 cut을 고르는 방식만 다른 그리디다. 예제의 MST는 1.81이다.
- **최소 힙**: 넣을 때는 sift up으로 올리고, 꺼낼 때는 sift down으로 내린다. 둘 다
  $$O(\log n)$$이고, 우선순위 큐의 바탕이다.
- **Prim과 Dijkstra는 같은 틀**이다. 힙에 넣는 값이 간선 하나의 가중치냐, 쌓인
  거리냐만 다르다. Dijkstra는 음의 가중치에서 틀린다.
- **A***는 $$f = g + h$$로 목표 쪽부터 찾는다. $$h$$가 허용적이면 다시 열기를
  허용할 때, 일관적이면 다시 열지 않아도 최단 경로를 찾는다.
