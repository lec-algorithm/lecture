## 추천 시스템이란 \{#overview}

**추천 시스템**(recommender system)은 사용자의 관심사와 선호도를 바탕으로
알맞은 항목을 제안하는 시스템입니다. 실생활 곳곳에 있습니다.

- **넷플릭스**: 사용자가 좋아할 영화
- **스포티파이**: 개인화된 음악
- **아마존**: 함께 살 만한 상품

사용자를 행, 아이템을 열로 두고 칸에 평점을 적으면 **평점 행렬**이 됩니다.
한 사람이 볼 수 있는 영화는 전체의 극히 일부라서 이 행렬은 대부분 빈칸입니다.
추천은 **빈칸에 들어갈 평점을 예측하고, 예측이 높은 것부터 보여 주는** 일입니다.
빈칸을 채우는 방법은 크게 둘입니다.

- **협업 필터링**(collaborative filtering): 다른 사람들의 평점을 단서로 쓴다.
- **콘텐츠 기반 필터링**(content-based filtering): 아이템의 특성(장르, 배우,
  감독)을 단서로 쓴다.

## 협업 필터링 \{#collaborative}

협업 필터링은 **사용자의 과거 행동 데이터**(별점, 구매 기록)를 바탕으로
비슷한 사용자나 아이템을 찾아 추천합니다. 다시 두 갈래입니다.

- **사용자 기반**(user-based): 나와 비슷한 취향을 가진 사용자들이 좋아한
  아이템을 추천합니다.
- **아이템 기반**(item-based): 내가 좋아했던 아이템과 비슷한 다른 아이템을
  추천합니다. 이때 "비슷하다"는 내용이 아니라 **같은 사람들에게 비슷한 평점을
  받았는가**로 잽니다.

## 유사도를 숫자로: 코사인 유사도 \{#cosine}

"겹치는 영화 수"는 거칩니다. 평점이 5점인지 1점인지를 보지 못합니다.
사용자 한 명의 평점을 벡터로 보고, **두 벡터가 같은 방향을 가리키는
정도**를 재면 평점의 크기까지 반영됩니다. 이것이 **코사인 유사도**(cosine
similarity)입니다.

$$
\text{cos}(a, b) = \frac{a \cdot b}{\lVert a \rVert \, \lVert b \rVert}
= \frac{\sum_i a_i b_i}{\sqrt{\sum_i a_i^2} \, \sqrt{\sum_i b_i^2}}
$$

- 두 벡터가 같은 방향이면 1, 직각이면 0, 반대 방향이면 -1입니다.
- 길이로 나누므로 **얼마나 많이** 줬는지가 아니라 **어떤 비율로** 줬는지를 봅니다.

작은 행렬로 재 봅니다. 사용자 4명, 아이템 4개이고 0은 아직 안 본
칸입니다.

| | 아이템 1 | 아이템 2 | 아이템 3 | 아이템 4 |
| --- | --- | --- | --- | --- |
| 사용자 A | 5 | 3 | 0 | 0 |
| 사용자 B | 4 | 0 | 0 | 0 |
| 사용자 C | 0 | 0 | 5 | 4 |
| 사용자 D | 0 | 0 | 4 | 0 |

A와 B는 아이템 3·4가 둘 다 0이므로, 아이템 1·2 평면에 그대로 그릴 수 있습니다.
끝점을 끌어 옮겨 보세요. 방향을 두고 길이만 바꾸면 코사인은 그대로이고, 한쪽을
축에 붙여 직각을 만들면 0이 됩니다. 평점은 0 이상이라 두 벡터는 90도보다 더
벌어질 수 없습니다.

<CosineDemo />

$$
\text{cos}(A, B) = \frac{5 \cdot 4 + 3 \cdot 0}{\sqrt{5^2 + 3^2} \, \sqrt{4^2}}
= \frac{20}{5.831 \times 4} = 0.857
$$

같은 방식으로 C와 D는 $$\dfrac{20}{\sqrt{41} \times 4} = 0.781$$이고, 겹치는
아이템이 하나도 없는 A와 C는 내적이 0이라 유사도도 0입니다. 실습 코드의
첫 표가 이 계산입니다.

## 예제 1. 사용자 기반 협업 필터링 \{#user-based}

조금 큰 행렬로 실제 예측까지 갑니다. 사용자 5명, 영화 6편이고, **A의 M3과
M6이 빈칸**입니다. 이 두 칸을 채워 A에게 무엇을 추천할지 정합니다.

| | M1 | M2 | M3 | M4 | M5 | M6 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 5 | 5 | **?** | 4 | 2 | **?** |
| B | 5 | 4 | 5 | 4 | 3 | 1 |
| C | 4 | 4 | 4 | 3 | 1 | 2 |
| D | 1 | 2 | 1 | 1 | 4 | 5 |
| E | 4 | 3 | 4 | 4 | 5 | 5 |

M1 범죄도시 3 · M2 탑건: 매버릭 · M3 아바타: 물의 길 · M4 스파이더맨: 노 웨이 홈 ·
M5 엘리멘탈 · M6 서울의 봄

A는 액션 영화(M1·M2·M4)에 높은 점수를, 엘리멘탈(M5)에 낮은 점수를 줬습니다.
절차는 세 단계입니다.

1. A와 다른 사용자 각각의 **유사도**를 잰다.
2. 유사도가 0보다 큰 사용자 중 큰 순서로 $$k$$명을 **이웃**으로 고른다.
3. 빈칸마다 이웃의 평점을 **유사도로 가중 평균**한다. 비슷한 이웃일수록 크게 반영된다.

$$
\hat{r}_{A,i} = \frac{\sum_{v \in N} \text{sim}(A, v) \, r_{v,i}}{\sum_{v \in N} \text{sim}(A, v)}
$$

### 코사인으로 이웃을 고르면 \{#user-cosine}

먼저 앞에서 쓴 코사인 유사도 그대로, $$k = 3$$으로 돌려 봅니다. 오른쪽 칸에
유사도가 하나씩 쌓이고, 이웃으로 뽑힌 사용자는 초록이 됩니다. 마지막에는
빈칸 열에서 이웃의 평점만 남아 가중 평균이 됩니다.

<CollabFilterDemo measure="cosine" />

B 0.835, C 0.820, E 0.705, D 0.466. 이웃은 B·C·E이고 M3은 4.354, M6은
**2.542**입니다. 그런데 이 숫자들은 좀 이상합니다.

- **D는 A와 취향이 정반대**입니다. A가 5를 준 영화에 1·2를, 2를 준 영화에 4를
  줬습니다. 그런데도 유사도가 0.466으로 꽤 높습니다.
- **E도 A와 다르게 움직입니다.** A가 가장 낮게 준 M5에 E는 가장 높은 5를
  줬습니다. 그런데 0.705로 이웃에 들었고, M6에 준 5점이 A의 M6 예측을 끌어올렸습니다.

평점은 1\~5로 **전부 양수**입니다. 양수 벡터끼리는 90도 넘게 벌어질 수 없으니
코사인이 0보다 작아질 수 없고, 정반대 취향도 꽤 비슷해 보입니다.

그림으로 봅니다. 왼쪽은 A가 본 영화 두 편으로 만든 평면이고, 오른쪽 막대는 안 본 칸을 그대로
0에 둔 여섯 칸 전체의 코사인입니다. 슬라이더로 본 칸의 평점마다 c를 빼 보세요.

<OriginShiftDemo />

$$c = 0$$이면 화살표가 모두 오른쪽 위 칸에 갇혀 있고 막대는 전부 0보다 큽니다. M1·M5
평면에서 $$c = 3$$이면 A는 $$(2, -1)$$, D는 $$(-2, 1)$$로 **180도 정반대**를 가리키고, 여섯 칸
코사인도 D가 -0.671로 내려옵니다. 사람마다 다른 눈금을 쓰므로 모두에게 같은 값을 빼는 것은
아직 어설픕니다. **각자의 평균**을 누르면 다음 절의 피어슨이 나옵니다.

### 피어슨 상관 \{#pearson}

해결책은 **각자의 평균을 빼고** 재는 것입니다. 그러면 "평소보다 높게 줬는가,
낮게 줬는가"만 남습니다. 둘 다 본 영화만 써서 이렇게 잰 코사인을 **피어슨
상관계수**(Pearson correlation coefficient)라고 합니다.

$$
\text{pearson}(a, b) = \frac{\sum_{i} (a_i - \bar{a})(b_i - \bar{b})}{\sqrt{\sum_{i} (a_i - \bar{a})^2} \, \sqrt{\sum_{i} (b_i - \bar{b})^2}}
$$

여기서 합은 두 사람이 **둘 다 본 영화**에 대해서만 하고, $$\bar{a}$$와
$$\bar{b}$$도 그 영화들에서의 평균입니다.

먼저 막대로 봅니다. 견줄 사용자를 고르고 **평균을 뺀 값**을 눌러 보세요. 둘 다
본 영화만 남고, 막대가 각자의 평균만큼 내려가 평소보다 낮게 준 영화는 0 아래로
섭니다. C를 고르면 두 막대 모양이 똑같아지고, D와 E는 서로 반대로 섭니다.

<PearsonDemo />

손으로 해 봅니다. A와 다른 네 사람이 둘 다 본 영화는 M1·M2·M4·M5입니다.

| | M1 | M2 | M4 | M5 | 평균 | 평균을 뺀 값 | 피어슨 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A | 5 | 5 | 4 | 2 | 4 | (1, 1, 0, -2) | |
| B | 5 | 4 | 4 | 3 | 4 | (1, 0, 0, -1) | 0.866 |
| C | 4 | 4 | 3 | 1 | 3 | (1, 1, 0, -2) | 1.000 |
| D | 1 | 2 | 1 | 4 | 2 | (-1, 0, -1, 2) | -0.833 |
| E | 4 | 3 | 4 | 5 | 4 | (0, -1, 0, 1) | -0.866 |

- **C는 A보다 1점씩 짜게 줄 뿐 취향이 똑같습니다.** 평균을 빼면 A와 같은
  벡터가 되어 1.000입니다. 코사인으로는 B보다 낮은 0.820이었습니다.
- A와 E는 $$\dfrac{0 - 1 + 0 - 2}{\sqrt{6} \times \sqrt{2}} = -0.866$$으로,
  **취향이 반대라는 것이 음수로 드러납니다.** D도 -0.833입니다.

같은 데모를 피어슨으로 돌립니다. 둘 다 본 칸만 밝게 남습니다.

<CollabFilterDemo />

이웃은 0보다 큰 C와 B 둘뿐입니다. $$k = 3$$이어도 음수인 D와 E는 뺍니다.

$$
\hat{r}_{A,\text{M3}} = \frac{1.000 \times 4 + 0.866 \times 5}{1.000 + 0.866} = 4.464,
\qquad
\hat{r}_{A,\text{M6}} = \frac{1.000 \times 2 + 0.866 \times 1}{1.000 + 0.866} = 1.536
$$

- 의사코드

```plaintext
ALGORITHM PearsonSimilarity(a, b, n)
    common <- a[i] > 0 이고 b[i] > 0 인 i들   // 둘 다 본 아이템만
    if common이 비었으면 return 0
    ma <- common에서 a의 평균,  mb <- common에서 b의 평균
    num <- 0,  da <- 0,  db <- 0
    for i in common do                       // 각자의 평균을 빼고 잰다
        num <- num + (a[i] - ma) * (b[i] - mb)
        da <- da + (a[i] - ma)^2
        db <- db + (b[i] - mb)^2
    if da = 0 or db = 0 then return 0
    return num / sqrt(da * db)

ALGORITHM PredictUserBased(R, sim, neighbors, item)
    num <- 0,  den <- 0
    for v in neighbors do                    // sim > 0 중 큰 순서로 k명
        if R[v][item] > 0 then               // 이웃이 본 아이템이면
            num <- num + sim[v] * R[v][item] // 비슷할수록 크게 반영
            den <- den + sim[v]
    if den = 0 then return 0
    return num / den                         // 유사도로 가중한 평균
```

- C 구현 (발췌)

```c
double predictUserBased(const int ratings[][ITEMS], const double sim[],
                        const int neighbors[], int count, int item) {
    double num = 0.0, den = 0.0;
    for (int i = 0; i < count; i++) {
        int v = neighbors[i];
        if (ratings[v][item] > 0) {
            num += sim[v] * ratings[v][item];
            den += sim[v];
        }
    }
    return den == 0.0 ? 0.0 : num / den;
}
```

`math.h`의 `sqrt`는 Linux에서 링크 옵션(`-lm`)이 따로 필요해서, 실습 코드는
제곱근을 뉴턴 방법으로 구하는 `squareRoot`를 직접 둡니다. Python도 같은 함수를 써서
출력이 글자 하나까지 같습니다.

### 짜게 주는 사람의 평점 옮기기 \{#mean-centered}

피어슨으로 C를 이웃으로 골랐지만, 가중 평균에는 여전히 C의 **원래 평점**이
들어갑니다. C는 A보다 1점씩 짜게 주므로 C의 4점은 A의 눈금으로 5점입니다.
그래서 실제로 많이 쓰는 식은 이웃이 **자기 평균에서 벗어난 만큼**을 가중
평균해 대상 사용자의 평균에 더합니다.

$$
\hat{r}_{A,i} = \bar{r}_A + \frac{\sum_{v \in N} \text{sim}(A, v) \, (r_{v,i} - \bar{r}_v)}{\sum_{v \in N} \lvert \text{sim}(A, v) \rvert}
$$

실습 코드는 단순한 가중 평균을 쓰고, 이 식은 바꿔 보기로 남겨 둡니다.

두 식을 나란히 돌려 봅니다. 이웃은 피어슨으로 뽑은 C와 B입니다. 평균은 각자 본 영화 전체로 재서
A 4, B 3.667, C 3입니다. **한 걸음**을 누르면 평균 중심 식을 차례로 따라가고, 슬라이더는 C의 평점 전체를
올립니다.

<MeanCenterDemo />

평균 중심 식은 M3 **5.155**, M6 **2.226**입니다. 단순 가중 평균은 4.464, 1.536입니다. C를 +1 올리면
피어슨은 1.000 그대로인데, 단순 가중 평균은 M3 5.000, M6 2.072로 움직이고 평균 중심은 움직이지
않습니다. **눈금이 달라도 같은 답이 나오는 것**이 이 식의 값입니다. 5.155처럼 눈금을 넘는 값은 쓸 때
5로 자릅니다.

### 아이템 기반 \{#item-based}

이번에는 행이 아니라 **열**을 맞댑니다. M3 열과 A가 이미 본 영화의 열을 하나씩

아이템 기반은 아이템 사이의 유사도가 사용자 사이보다 덜 흔들립니다. 사용자의
취향은 새 평점 하나에 바뀌지만, 수만 명이 매긴 영화 두 편의 관계는 잘 바뀌지
않습니다. 그래서 유사도를 미리 계산해 두고 쓰기 좋고, 아마존의 "이 상품을 산
사람들이 함께 산 상품"이 이 방식으로 알려져 있습니다. 미리 구하는 비용은
$$O(n^2 m)$$입니다.

정말 덜 흔들리는지 재 봅니다. 표는 영화 여섯 편의 코사인이고, 맨 위 줄은 A의 평점입니다. 물음표를
누르면 그 빈칸의 줄에서 값을 꺼내 예측하는 것이 칠해집니다. 숫자 칸을 눌러 A의 평점을 바꾸고,
슬라이더로 나머지 네 사람을 똑같이 늘려 보세요.

0.156, 사용자 코사인은 최대 0.112 움직입니다. 다른 사용자를 100배로 늘리면 표의 움직임은 0.002로

## 협업 필터링의 한계 \{#cf-limits}

### 데이터 희소성 \{#sparsity}

협업 필터링은 데이터가 많아야 하는데, 데이터가 많으려면 사용자가 많아야
합니다. 이것이 **데이터 희소성**(sparsity) 문제입니다.

- 실제 평점 행렬은 거의 빈칸입니다. 넷플릭스가 공개했던 대회용 데이터는
  칸의 99% 가까이가 비어 있었습니다.
- 그러면 둘 다 본 영화가 한두 편뿐인 쌍이 흔하고, 그런 쌍의 유사도는 믿기
  어렵습니다.

직접 칸을 지워 봅니다. 세 취향 무리로 만든 합성 데이터(영화 60편)이고, 칸의 10%는 정답을 알고
있는 시험 칸으로 떼어 둡니다. 슬라이더를 움직일 때마다 모든 쌍의 피어슨과 시험 칸의 예측
(피어슨, $$k = 5$$)을 실제로 다시 계산합니다.

<SparsityDemo />

사용자 40명이면 빈칸 59.8%에서 시험 칸을 전부 예측하고 오차가 0.588입니다. 빈칸 81.1%에서는 쌍당
함께 본 영화가 2.1편이고, 예측할 수 있는 칸이 68.8%로 줄며, 오차 1.206은 전체 평균으로 찍는
1.178보다도 나쁩니다. 빈칸 95.7%면 예측할 수 있는 칸이 없습니다.

- **함께 본 영화가 두 편이면 피어슨은 믿을 수 없습니다.** 점 두 개에는 언제나 직선이 그어지므로
  +1이나 -1, 아니면 평균을 뺀 값이 0뿐이라 잴 수 없습니다. 빈칸 81.1%에서 그런 쌍 216쌍을 세면
  ±1이 96쌍, 잴 수 없는 쌍이 120쌍이고 다른 값은 없습니다.
- **사용자가 많으면 버틸 수 있습니다.** 같은 빈칸 80%대에서 사용자를 320명으로 늘리면 예측할 수 있는
  칸이 99.9%, 오차가 0.823입니다. 협업 필터링에 사용자가 많아야 하는 이유입니다.

### 콜드 스타트 \{#cold-start}

기록이 없는 대상에게는 아무것도 할 수 없습니다. 이것을 **콜드 스타트**(cold
start) 문제라고 합니다. 사람 쪽과 아이템 쪽 둘 다 생깁니다.

- **새 사용자**: 사용자 E가 막 가입해 「엑시트」 하나만 봤습니다. 다른 누구와도
  겹치는 영화가 없으니 유사도가 모두 0이고, 이웃도 추천도 없습니다.

| 사용자 A | 사용자 B | 사용자 C | 사용자 E (새로 옴) |
| --- | --- | --- | --- |
| 범죄도시 3 | 엘리멘탈 | 서울의 봄 | 엑시트 |
| 탑건: 매버릭 | 알라딘 | 한산: 용의 출현 | |
| 아바타: 물의 길 | 아바타: 물의 길 | 아바타: 물의 길 | |
| 스파이더맨: 노 웨이 홈 | | 스파이더맨: 노 웨이 홈 | |

- **새 아이템**: 새 어벤져스 영화가 개봉했습니다. 본 사람이 없으니 그 열은
  전부 빈칸이고, 사용자 기반이든 아이템 기반이든 이 영화를 누구에게도 추천할 수
  없습니다.

위의 표로 직접 해 봅니다. 영화를 눌러 E가 좋아한 영화를 늘려 보세요. 「아바타: 물의 길」 한 편을 넣으면
A, B, C가 모두 1편씩 겹쳐 후보가 생기고, 그중 「스파이더맨: 노 웨이 홈」이 A와 C 두 사람이 좋아해서
2로 앞섭니다. 새 어벤져스는 E가 좋아해도 다른 누구도 좋아하지 않아 후보에 오르지 않습니다.

<OverlapDemo cold />

예제 1의 행렬에서 두 경우를 직접 만들어 봅니다. **새 영화 M7**을 켜면 아무도
보지 않은 열이, **새 사용자 F**를 켜면 평점이 없는 행이 생깁니다. 새 칸을 눌러
평점을 넣으면 피어슨($$k = 3$$) 예측을 다시 계산합니다. F에게 평점을 하나만 주면
평균을 뺐을 때 0만 남아 여전히 유사도를 잴 수 없고, 둘 이상 줘야 이웃이 생길 수
있습니다. M7은 이웃 중 누군가 평점을 줘야 예측이 나옵니다.

## 예제 2. 콘텐츠 기반 필터링 \{#content-based}

콘텐츠 기반 필터링은 **아이템 자체의 속성**(특징)을 바탕으로, 사용자가
좋아했던 아이템과 특징이 비슷한 다른 아이템을 추천합니다. 내가 좋아했던 영화가
액션이라면 다른 액션 영화를 추천합니다. 넷플릭스의 "액션 영화 추천 콘텐츠",
"코미디 액션 영화 추천 콘텐츠" 같은 줄이 이 모양입니다.

### 장르 벡터와 취향 벡터 \{#genre-vector}

영화마다 장르를 0과 1로 적은 벡터를 둡니다. 작은 예에서는 장르를 세 개(액션,
코미디, 드라마) 씁니다. 사용자는 액션과 코미디를 좋아하므로 취향 벡터는
(1, 1, 0)입니다.

| 영화 | 액션 | 코미디 | 드라마 | 취향 (1, 1, 0)과의 코사인 |
| --- | --- | --- | --- | --- |
| 영화 1 | 1 | 0 | 0 | 0.707 |
| 영화 2 | 1 | 1 | 0 | 1.000 |
| 영화 3 | 0 | 0 | 1 | 0.000 |

액션+코미디인 영화 2가 1위, 액션뿐인 영화 1이 $$\dfrac{1}{\sqrt{2}} = 0.707$$로
2위입니다. 코사인 유사도를 그대로 다시 쓴 것입니다.

### 평점으로 프로필 만들기 \{#profile}

취향 벡터를 사용자가 직접 적어 주지는 않습니다. 사용자가 준 평점에서 만듭니다.
본 영화마다 **(평점 - 3)만큼** 그 영화의 장르를 더합니다. 3점은 보통이라 0이고,
높게 준 영화의 장르는 +, 낮게 준 영화의 장르는 -가 됩니다. 이것을 **사용자
프로필**이라고 합니다.

예제 1의 A로 해 봅니다. 장르를 하나(SF) 늘리고, 막 개봉해 **아무도 평가하지
않은 M7**(새 어벤져스)을 더합니다.

| 영화 | 액션 | 코미디 | 드라마 | SF | A의 평점 | 가중치 |
| --- | --- | --- | --- | --- | --- | --- |
| M1 범죄도시 3 | 1 | 1 | 0 | 0 | 5 | +2 |
| M2 탑건: 매버릭 | 1 | 0 | 1 | 0 | 5 | +2 |
| M3 아바타: 물의 길 | 1 | 0 | 0 | 1 | | |
| M4 스파이더맨: 노 웨이 홈 | 1 | 0 | 0 | 1 | 4 | +1 |
| M5 엘리멘탈 | 0 | 1 | 1 | 0 | 2 | -1 |
| M6 서울의 봄 | 0 | 0 | 1 | 0 | | |
| M7 새 어벤져스 | 1 | 1 | 0 | 1 | | |

프로필이 맨 아래 줄에 쌓인 뒤, 안 본 영화마다 프로필과의 코사인이 오른쪽에
적힙니다.

<ContentFilterDemo />

프로필은 $$(5, 1, 1, 1)$$입니다. 액션이 압도합니다. 엘리멘탈에 준 낮은 점수가
코미디와 드라마를 1씩 깎았습니다.

- 의사코드

```plaintext
ALGORITHM BuildProfile(F, r, n, g)
    profile <- 0이 g개
    for i <- 0 to n-1 do
        if r[i] > 0 then
            w <- r[i] - 3                   // 3점은 보통, 높으면 +, 낮으면 -
            for t <- 0 to g-1 do
                profile[t] <- profile[t] + w * F[i][t]
    return profile

ALGORITHM RankByContent(F, r, n, g, profile)
    candidates <- []
    for i <- 0 to n-1 do
        if r[i] = 0 then                    // 안 본 아이템만 (새 아이템도 포함)
            score[i] <- CosineSimilarity(profile, F[i], g)
            candidates에 i 추가
    candidates를 score 내림차순으로 정렬
    return candidates
```

- C 구현 (발췌)

```c
void buildProfile(const double features[][GENRES], const int ratings[],
                  int n, int g, double profile[]) {
    for (int t = 0; t < g; t++) {
        profile[t] = 0.0;
    }
    for (int i = 0; i < n; i++) {
        if (ratings[i] > 0) {
            int w = ratings[i] - 3;
            for (int t = 0; t < g; t++) {
                profile[t] += w * features[i][t];
            }
        }
    }
}
```

- 실행

```sh

- 결과

toy: genres (action, comedy, drama), user likes (1 1 0)

  movie 3 (0 0 1)  0.000

  M6  0 0 1 0   -
  M7  1 1 0 1   new, no ratings yet

  1. M3  0.802
  2. M7  0.764
  3. M6  0.189
```

- **M3(아바타)이 0.802로 1위, M6(서울의 봄)이 0.189로 꼴찌**입니다. 다른
  사람의 평점을 하나도 쓰지 않았는데 예제 1과 같은 결론입니다.
- **새 영화 M7이 0.764로 2위**입니다. 아무도 평가하지 않았지만 장르가 있으니
  점수를 받습니다. 협업 필터링이 못 하던 일입니다.

**비용**: 아이템 $$n$$개, 특성 $$g$$개라면 프로필 만들기와 점수 매기기가 각각
$$O(ng)$$, 줄 세우기가 $$O(n \log n)$$입니다. 다른 사용자 수와 상관이 없습니다.

재료를 직접 바꿔 봅니다. 장르 칸과 평점 칸을 누르면 프로필과 순위가 바로 바뀝니다. 기준 점수는
(평점 - 3)의 3을 바꾸는 칩입니다.

기준이 3이면 실습 코드와 같습니다. 기준을 0으로 두면 프로필이 $$(14, 7, 7, 4)$$가 되어 2점을 준
엘리멘탈까지 플러스로 더해지고, 순위가 **M7 0.820, M3 0.723, M6 0.398**로 뒤집힙니다. 기준을 4로

낮추면 드라마가 -3이 되어 M6이 -0.866입니다. 3을 빼는 것은 낮은 평점을 싫어함으로 읽겠다는 선택입니다.

### 콘텐츠 기반의 장점과 한계 \{#content-limits}

- **선행 분석이 필요합니다.** 이 영화가 액션인지 코미디인지를 누군가 먼저
  정해 줘야 합니다. 지금은 장르만 썼지만 배우, 감독 정보로도 할 수 있습니다.
  - 좋아하는 배우가 찍은 다른 영화
  - 좋아하는 배우와 비슷한 다른 배우의 영화
- **새 아이템의 콜드 스타트는 풀립니다.** 특성만 있으면 평점이 없어도
  점수를 매길 수 있습니다.
- **새 사용자의 콜드 스타트는 그대로입니다.** 평점이 하나도 없으면 프로필이
  0벡터라 모든 점수가 0입니다. 그래서 "다소" 해결할 뿐입니다.
- **비슷한 것만 추천합니다.** 액션을 좋아한 사람에게 액션만 보여 주므로,
  취향 밖의 좋은 영화를 만날 기회가 줄어듭니다. 협업 필터링은 C가 본
  「서울의 봄」처럼 장르를 건너뛰는 추천을 할 수 있습니다.

[콜드 스타트](#cold-start)의 데모에 콘텐츠 점수 줄을 붙였습니다. M7을 켜면 협업
필터링은 예측하지 못하지만 콘텐츠 기반은 0.764를 줍니다. F를 켜면 프로필이
0벡터라 콘텐츠 점수도 모두 0입니다. F에게 평점을 주면 프로필이 바로 생깁니다.

## 두 방식의 차이 \{#comparison}

| | 협업 필터링 | 콘텐츠 기반 필터링 |
| --- | --- | --- |
| 보는 것 | 다른 사용자들의 평점 | 아이템의 특성과 내 평점 |
| 콘텐츠 분석 | 필요 없음 | 필요함 |
| 다른 분야로 옮기기 | 영화에서 연구한 방법을 음악·음식에 바로 적용 | 음악은 장르·만든 사람 같은 분석을 새로 해야 함 |
| 새 아이템 | 추천할 수 없음 | 특성만 있으면 추천 |
| 새 사용자 | 추천할 수 없음 | 추천할 수 없음 |
| 추천의 폭 | 장르를 건너뛸 수 있음 | 비슷한 것에 갇히기 쉬움 |

협업 필터링에서 **방법 자체를 바꿔 보기도 쉽습니다.** 이 자료에서는 코사인과
피어슨을 썼지만, 다른 유사도를 쓰거나 이웃을 고르는 규칙을 바꾸거나, 일부러
예측이 낮은 것을 섞어 추천해 보는 식으로 실험할 수 있습니다. 아이템이 무엇인지와
상관없는 절차이기 때문입니다.

## 하이브리드 필터링 \{#hybrid}

**하이브리드 필터링**(hybrid filtering)은 두 방식을 결합합니다. 가장 단순한
방법은 두 결과를 가중치로 섞는 것입니다.

$$
\text{score}_i = \alpha \cdot \text{cf}_i + (1 - \alpha) \cdot \text{content}_i
$$

먼저 작은 예로 아이템 셋의 협업 필터링 점수 (0.8, 0.7, 0.3)과 콘텐츠 점수
(0.6, 0.9, 0.4)를 섞습니다. A에게는 예제 1의 피어슨 예측을
5로 나눠 0\~1로 맞춘 뒤 예제 2의 점수와 섞습니다. 협업 필터링 점수가 없는 M7은
콘텐츠 점수를 그대로 씁니다.

$$\alpha$$를 바꿔 보세요. 막대는 협업 필터링 몫과 콘텐츠 몫을 쌓은 것이고, 점수
순으로 줄이 자리를 바꿉니다. 작은 예는 $$\alpha$$가 0.75보다 커지면 아이템 1이
아이템 2를 앞섭니다. A의 순서는 $$\alpha$$를 어떻게 바꿔도 M3, M7, M6입니다.

<HybridDemo />

실습 코드는 반반($$\alpha = 0.5$$)으로 섞습니다.

- 결과 (`02_content_based_filtering` 이어서)

```console
hybrid = 0.5 * collaborative + 0.5 * content
  toy: 0.700 0.800 0.350
  A: M3  cf 0.893  content 0.802  -> 0.847
  A: M7  cf  none  content 0.764  -> 0.764
  A: M6  cf 0.307  content 0.189  -> 0.248
```

- 두 방식이 모두 높게 본 M3이 1위로 굳었습니다.
- 새 영화 M7은 콘텐츠 점수 덕에 추천 목록에 들어왔습니다. 평점이 쌓이면 협업
  필터링 점수도 붙습니다.
- 두 방식의 단점을 서로 메우지만, 두 시스템을 함께 돌리고 $$\alpha$$를 정해야
  하므로 **구현이 다소 복잡해집니다.**

실제 서비스는 가중 합 말고도, 새 사용자에게는 콘텐츠 기반을 쓰다가 기록이
쌓이면 협업 필터링으로 넘어가는 식의 전환도 씁니다.

## 이 주제에서 남길 것 \{#takeaway}

- 추천은 **평점 행렬의 빈칸을 예측하고 높은 것부터 보여 주는** 일이다.
- **협업 필터링**: 다른 사람의 평점만 본다. 사용자 기반은 비슷한 사람의 평점을,
  아이템 기반은 비슷한 아이템에 내가 준 평점을 유사도로 가중 평균한다.
- **코사인 유사도**는 두 벡터의 방향을 잰다. 평점이 전부 양수면 정반대 취향도
  비슷해 보이므로, **각자의 평균을 빼고 재는 피어슨 상관**이 낫다.
- 협업 필터링의 약점은 **희소성과 콜드 스타트**다. 새 사용자와 새 아이템
  모두 추천할 수 없다.
- **콘텐츠 기반 필터링**: 아이템의 특성과 사용자 프로필을 비교한다. 새 아이템은
  풀지만 새 사용자는 못 풀고, 콘텐츠 분석이 먼저 필요하다.
- **하이브리드**는 두 점수를 섞어 서로의 빈틈을 메운다.
