> 주제 07의 이진 탐색 트리는 키를 **비교하며** 찾았습니다. 균형이 잘 잡혀
> 있어도 $$O(\log n)$$번은 비교해야 합니다.  
> 이번 주제는 비교로 찾지 않습니다. **키에서 곧바로 자리를 계산합니다.**  
> 그 계산이 해시 함수입니다. 서로 다른 키가 같은 자리를 가리키는 충돌을
> 어떻게 푸느냐가 해시 테이블 설계의 나머지 전부입니다.

## 키를 배열 인덱스로 \{#key-as-index}

키가 1부터 8까지의 작은 정수라고 해 봅시다. 그러면 고민할 것이 없습니다.
키가 `i`인 항목을 배열의 `i`번 칸에 두면 됩니다.

```plaintext
칸    1   2   3   4   5   6   7   8
     [ ] [ ] [3] [ ] [5] [ ] [ ] [8]

find 3?  -> A[3]을 본다. 있다.
find 5?  -> A[5]를 본다. 있다.
find 7?  -> A[7]을 본다. 비어 있으니 없다.
```

비교를 한 번도 하지 않습니다. 키가 곧 주소이므로 어떤 키든 메모리 접근
한 번, $$O(1)$$에 끝납니다.

**해싱**(hashing)은 이 방법을 작은 정수가 아닌 키로 넓힌 것입니다. 주민등록번호,
이름, 학번과 문자열처럼 키가 크거나 정수가 아니어도 같은 일을 하고 싶습니다.
그러려면 두 가지가 필요합니다.

- **해시 함수**: 키를 배열 인덱스로 바꾸는 계산
- **충돌 해결**: 서로 다른 키가 같은 인덱스로 바뀌었을 때의 처리

### 시간과 메모리 사이 \{#time-memory}

해싱은 시간과 메모리 사이에서 균형을 잡는 방법이기도 합니다.

| 메모리가 | 할 수 있는 일 | 대가 |
| --- | --- | --- |
| 무한하다면 | 가능한 모든 키에 칸을 하나씩 주고 키를 그대로 인덱스로 쓴다 | 메모리. 주민등록번호면 $$10^{13}$$칸이다 |
| 아주 적다면 | 정렬하지 않은 배열 하나에 모아 두고 순차 탐색한다 | 시간. 찾을 때마다 $$O(n)$$이다 |
| 적당하다면 | **해싱**: 적당한 크기의 배열에 키를 흩어 두고, 겹친 것만 따로 처리한다 | 둘 다 조금씩 |

카페 계산대의 쿠폰 칸을 떠올려 보세요. 손님 이름의 첫 자음(ㄱ, ㄴ·ㄷ, ㅇ,
숫자·영문, …)마다 칸이 있어서, 쿠폰을 찾을 때 상자 전체를 뒤지지 않고 한 칸만
봅니다. 첫 자음을 고르는 것이 해시 함수이고, 한 칸에 여러 장이 꽂혀 있는 것이
충돌입니다. 칸 수가 손님 수보다 훨씬 적으니 메모리는 적게 쓰고, 칸 하나만
뒤지면 되니 시간도 적게 씁니다.

## 해시 함수 \{#hash-function}

[[hash-function|해시 함수]]는 키를 배열의 인덱스 값으로 바꿉니다. 배열 크기가
$$M$$이면 좋은 해시 함수는 셋을 갖춥니다.

1. 결과가 언제나 정수 $$[0, M-1]$$ 안에 든다.
2. 계산하기 쉽다.
3. 키를 배열 전체에 **고르게** 퍼뜨린다.

키의 종류에 따라 만드는 방법이 다릅니다.

- **주민등록번호**: 키가 숫자이면 숫자를 그대로 씁니다.
- **이름**: 키가 문자열이면 문자열을 숫자로 바꾸어 씁니다.
- **직접 만든 데이터 타입**: 해시 함수를 직접 만들어 주어야 합니다.

### 모듈러 해싱 \{#modular-hashing}

정수를 해싱할 때 가장 흔한 방법입니다. 양의 정수 키 $$k$$를 배열 크기
$$M$$으로 나눈 **나머지**를 인덱스로 씁니다.

$$
h(k) = k \bmod M
$$

나머지는 언제나 $$0$$ 이상 $$M-1$$ 이하이므로 첫 조건은 저절로 맞고, 나눗셈
한 번이니 둘째 조건도 맞습니다. 글자 `A`, `B`, `C`, `K`의 ASCII 코드를 크기
8인 배열에 넣어 봅니다.

<HashSlotDemo />

| 키 | 코드 | 해시 ($$M = 8$$) |
| --- | --- | --- |
| A | 65 | 1 |
| B | 66 | 2 |
| C | 67 | 3 |
| K | 75 | 3 |

마지막 줄에서 일이 생깁니다. `C`와 `K`는 다른 키인데 같은 3번 칸을
가리킵니다. 이것을 [[collision|충돌]]이라고 합니다. 영어로는 collision입니다. 이상적으로는 서로 다른
키가 서로 다른 인덱스로 가야 하지만, 실제로는 서로 다른 키가 같은 인덱스에
매핑될 수 있습니다.

### M은 소수로 \{#prime-m}

셋째 조건(고르게)은 $$M$$을 어떻게 고르느냐에 달려 있습니다. 키가 4의
배수로만 들어온다고 해 봅시다. $$M = 8$$이면 이렇습니다.

<HashSlotDemo keys={[0, 4, 8, 12, 16, 20, 24, 28]} m={8} />

여덟 칸 중 0번과 4번 두 칸만 쓰입니다. 키와 $$M$$이 공약수 4를 가지기
때문입니다. $$M$$을 소수 7로 바꾸면 같은 키가 일곱 칸에 다 퍼집니다.

<HashSlotDemo keys={[0, 4, 8, 12, 16, 20, 24, 28]} m={7} />

그래서 배열 크기 $$M$$은 **소수**(prime number)를 고릅니다. 소수는 어떤 키와도
자기 배수가 아닌 한 공약수가 없으므로, 키에 흔히 있는 패턴(짝수만, 10의
배수만)에 휘둘리지 않습니다. 다만 소수가 만능은 아닙니다. 키가 모두 7의
배수였다면 $$M = 7$$도 한 칸만 씁니다.

### 문자열 해싱 \{#string-hashing}

문자열은 먼저 숫자로 바꿔야 합니다. 가장 쉬운 생각은 글자 코드를 더하는
것입니다. 그런데 이러면 **같은 글자를 순서만 바꾼 문자열**이 모두 같은 값이
됩니다. `stop`, `pots`, `tops`, `spot`, `opts`, `post`는 글자 코드의 합이
전부 같습니다.

순서를 반영하려면 자리마다 가중치를 줍니다. 앞 글자까지의 값에 작은 수
$$R$$(보통 31)을 곱하고 다음 글자를 더합니다. 다항식을 계산하는 호너
방식(Horner's method)입니다. 매번 $$M$$으로 나눈 나머지를 취하면 값이 커지지
않습니다.

$$
h \leftarrow (R \cdot h + \text{code}(c)) \bmod M
$$

여섯 단어를 크기 97인 배열에 넣어 봅니다. 한 걸음에 글자 하나씩 $$h$$를
갱신하고, 마지막 글자까지 계산하면 단어가 아래 띠의 그 칸에 떨어집니다. 탭으로
더하기와 호너 방식을 바꿔 보세요.

<StringHashDemo />

- 의사코드

```plaintext
ALGORITHM SumHash(s, M)                 // 나쁜 예: 글자 순서를 보지 않는다
    h <- 0
    for 글자 c in s do
        h <- (h + code(c)) mod M
    return h

ALGORITHM HornerHash(s, M)              // 좋은 예: 자리마다 R을 곱해 순서를 반영한다
    h <- 0
    for 글자 c in s do
        h <- (R * h + code(c)) mod M    // 매번 나머지를 취해 h가 M보다 커지지 않는다
    return h
```

- C 구현

```c
int hornerHash(const char *s, int m) {
    const int R = 31;
    int h = 0;
    for (int i = 0; s[i] != '\0'; i++) {
        h = (R * h + (unsigned char)s[i]) % m;
    }
    return h;
}
```

```console
  key   sum  horner

  pots   66      79

```

더하기만 한 `sum` 열은 여섯 단어가 모두 66번 칸에 모입니다. 호너 방식은
다섯 칸으로 흩습니다. 그래도 `spot`과 `post`는 49번에서 만납니다. 좋은 해시
함수도 충돌을 없애지는 못합니다. **줄일 뿐입니다.**

## 충돌은 반드시 일어난다 \{#collisions-happen}

충돌이 일어나지 않는 해시 함수를 만들 수는 없을까요. 두 가지 이유로
불가능합니다.

- **비둘기집 원리**: 키가 칸보다 많으면($$N > M$$) 어떤 칸에는 키가 둘 이상
  들어갑니다. 키가 될 수 있는 값(모든 이름, 모든 문자열)은 언제나 배열
  크기보다 훨씬 많습니다.
- **생일 문제**: 키가 칸보다 훨씬 적어도 충돌은 금방 일어납니다. 23명이 모이면
  생일이 같은 두 사람이 있을 확률이 절반을 넘습니다.

키 $$N$$개를 $$M$$칸에 고르게 무작위로 넣는다면, 한 번도 충돌하지 않으려면
두 번째 키는 첫 키의 칸을, 세 번째 키는 앞의 두 칸을 피해야 합니다.

$$
P(\text{충돌이 한 번 이상}) = 1 - \frac{M}{M} \cdot \frac{M-1}{M} \cdots \frac{M-N+1}{M}
$$

키 수 $$N$$을 움직이며 이 확률이 얼마나 빨리 오르는지 봅니다. 곡선 위의 빈
점들은 아래 실행 결과가 찍는 값입니다. **무작위로 넣어 보기**를 여러 번 누르면
실제로 충돌이 난 비율이 곡선의 값에 다가갑니다.

```sh

```

- 결과 (마지막 덩어리)

```console

  N =  3, M =  16:  18.0%
  N =  5, M =  16:  50.0%
  N = 10, M =  16:  97.4%

```

16칸짜리 배열에 키를 다섯 개만 넣어도 충돌이 일어날 확률이 절반입니다. 열 개면
거의 확실합니다. 그러니 해시 테이블은 충돌을 **피하는** 것이 아니라 **처리하는**
방법을 갖고 있어야 합니다. 이 주제는 두 가지를 봅니다.

1. **개별 체이닝**(separate chaining): 칸마다 연결 리스트를 두고 충돌한 키를
   매단다.
2. **선형 탐지**(linear probing): 충돌하면 배열의 다음 빈칸을 찾아간다.

해시값으로 씁니다. 이 예제에서는 글자마다 정수를 아래 표처럼 정했습니다. 실제

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 코드 | 20 | 69 | 10 | 4 | 38 | 49 | 78 | 14 | 22 | 47 | 52 |

## 개별 체이닝 \{#separate-chaining}

크기 $$M$$인 배열의 칸마다 **연결 리스트**를 하나씩 둡니다. 해시값이 같은
키들은 그 칸의 리스트에 함께 매답니다. 충돌한 항목들을 칸별로 따로 사슬(chain)에
엮는다고 해서 개별 체이닝입니다.

찾는 일은 **두 단계 탐색**입니다.

1. **해시 탐색**: 해시 함수로 칸을 고른다. $$O(1)$$
2. **리스트 탐색**: 그 칸의 리스트를 앞에서부터 순차 탐색한다.

리스트가 짧으면 둘째 단계도 금방 끝납니다. 그래서 $$M$$을 충분히 크게 잡아야
합니다. 카페 쿠폰 칸이 바로 이 구조입니다.

### 삽입 \{#sc-insert}

`put(key, value)`는 해시로 칸을 찾고 그 칸의 리스트를 훑습니다. 같은 키가
있으면 **값만 바꾸고**, 끝까지 없으면 새 노드를 리스트 **맨 앞**에 붙입니다.
맨 앞에 붙이면 리스트 끝을 찾아갈 필요가 없습니다. 어차피 같은 키가 있는지
확인하려고 끝까지 훑었으니, 맨 뒤에 붙여도 비교 횟수는 같습니다.

크게 뜬 숫자가 이번 `put`에서 키를 비교한 횟수입니다.

<ChainingDemo />

`H`를 넣을 때 4번 칸에는 이미 `C`와 `R`이 있어 두 번 비교했고, `M`을 넣을
때는 세 번 비교했습니다. 두 번째 `E`(값 6)는 0번 칸에서 `A`를 지나 `E`를
만나 값만 1에서 6으로 바꿨습니다.

- 의사코드

```plaintext
ALGORITHM Put(T, key, value)            // T: 크기 M인 배열, 칸마다 연결 리스트
    i <- Hash(key, M)
    for 노드 x in T[i] do               // 1단계: 해시로 칸을 찾고
        if x.key = key then             // 2단계: 그 칸의 리스트를 순차 탐색
            x.value <- value            // 같은 키가 있으면 값만 바꾼다
            return
    T[i] <- 새 노드(key, value, next = T[i])   // 없으면 맨 앞에 붙인다
    N <- N + 1
```

- C 구현

```c
int put(ChainingTable *t, char key, int value, int *compares) {
    int i = hashOf(key, t->m);
    *compares = 0;
    for (Node *x = t->heads[i]; x != NULL; x = x->next) {
        (*compares)++;
        if (x->key == key) {
            x->value = value;
            return 0;
        }
    }
    Node *node = malloc(sizeof(Node));
    node->key = key;
    node->value = value;
    node->next = t->heads[i]; /* 맨 앞에 붙인다 */
    t->heads[i] = node;
    t->n++;
    return 1;
}
```

배열 `heads`의 칸 하나는 리스트 맨 앞 노드를 가리키는 포인터입니다. 처음에는
모두 `NULL`(빈 리스트)입니다.

### 검색 \{#sc-search}

`get(key)`도 같은 두 단계입니다. 있는 키 `E`와 없는 키 `Y`를 찾아봅니다.

<ChainingDemo mode="search" />

`E`는 0번 칸에서 `A`를 지나 두 번째 노드에서 찾았습니다. `Y`는 해시가 2라서
2번 칸의 `X`와 `S`를 보고 리스트 끝에 닿아 **없다**고 답합니다. 없다는 것을
확인하는 데도 그 칸의 리스트만 보면 됩니다. 다른 칸은 볼 필요가 없습니다.

```plaintext
ALGORITHM Get(T, key)
    i <- Hash(key, M)
    for 노드 x in T[i] do
        if x.key = key then return x.value
    return 없음                         // 리스트 끝까지 갔으면 없다
```

### 삭제 \{#sc-delete}

`delete(key)`는 키를 찾은 뒤 연결을 하나 바꿉니다. 찾은 노드가 맨 앞이면 칸이
다음 노드를 가리키게 하고, 중간이나 끝이면 앞 노드가 그 노드를 건너뛰게
합니다.

<ChainingDemo mode="delete" />

- 의사코드

```plaintext
ALGORITHM Delete(T, key)
    i <- Hash(key, M)
    prev <- 없음
    for 노드 x in T[i] do
        if x.key = key then

            N <- N - 1

    return 실패
```

- C 구현

```c
int delete(ChainingTable *t, char key, int *compares) {
    int i = hashOf(key, t->m);
    *compares = 0;
    Node *prev = NULL;
    for (Node *x = t->heads[i]; x != NULL; prev = x, x = x->next) {
        (*compares)++;
        if (x->key == key) {
            if (prev == NULL) {
                t->heads[i] = x->next; /* 맨 앞 노드 */
            } else {

            }
            free(x);
            t->n--;
            return 1;
        }
    }
    return 0;
}
```

### 분석 \{#sc-analysis}

키 $$N$$개를 $$M$$칸에 고르게 흩으면 리스트 길이의 평균은 $$N/M$$입니다. 이
값을 **적재율**(load factor) $$\alpha$$라고 합니다. 예제는 $$\alpha = 10/5 = 2$$이고,
검색 두 번이 모두 비교 두 번으로 끝났습니다.

| 연산 | 평균 | 최악 (모든 키가 한 칸) |
| --- | --- | --- |
| 검색 | $$O(1 + N/M)$$ | $$O(N)$$ |
| 삽입 | $$O(1 + N/M)$$ | $$O(N)$$ |
| 삭제 | $$O(1 + N/M)$$ | $$O(N)$$ |

$$M$$을 $$N$$에 비례하게 잡으면 $$N/M$$이 상수이므로 세 연산 모두 평균
$$O(1)$$입니다. 앞의 1은 해시 계산, $$N/M$$은 리스트 탐색입니다. 최악은 해시
함수가 나빠서 모든 키가 한 칸에 모인 경우이고, 그때 해시 테이블은 연결 리스트
하나가 됩니다.

$$M$$을 정하는 일은 저울질입니다.

- **$$M$$이 너무 크면** 비어 있는 칸(빈 리스트)이 많아져 메모리를 낭비합니다.
- **$$M$$이 너무 작으면** 리스트가 길어져 탐색이 느려집니다.

## 선형 탐지 \{#linear-probing}

체이닝은 리스트의 링크마다 메모리를 씁니다. 그 메모리로 차라리 배열을 키우면
어떨까요. 배열이 키보다 크면($$M > N$$) 빈칸이 언제나 남아 있으니, 충돌하면
**이미 있는 빈칸**을 찾아가 쓰면 됩니다. 이런 방식을 **개방형 주소 지정**(open
addressing) 해싱이라고 합니다. 키가 해시가 가리킨 칸이 아닌 다른 칸에도 살 수
있다는 뜻입니다.

그중 가장 단순한 것이 **선형 탐지**입니다. 충돌하면 테이블의 **다음 칸**을
보고, 또 차 있으면 그다음 칸을 봅니다. 빈칸을 만날 때까지 오른쪽으로 한 칸씩
갑니다. 배열 끝에 닿으면 0번 칸으로 돌아갑니다. 칸 하나를 들여다보는 것을
탐지(probe)라고 합니다.

배열은 키와 값을 담는 두 배열로 둡니다. 크기는 16입니다.

### 삽입 \{#lp-insert}

들여다본 칸 수이고, 아래 주황 막대는 차 있는 칸이 이어진 덩어리입니다.

- `P`(해시 14)는 14번 `R`, 15번 `X`를 지나 배열 끝을 넘어 **0번 칸**에

- 의사코드

```plaintext
ALGORITHM Put(T, key, value)            // T.keys, T.values: 크기 M인 배열 둘
    i <- Hash(key, M)
    while T.keys[i] ≠ 빈칸 do           // 빈칸을 만날 때까지 오른쪽으로
        if T.keys[i] = key then
            T.values[i] <- value        // 같은 키가 있으면 값만 바꾼다
            return
        i <- (i + 1) mod M              // 끝에 닿으면 0번 칸으로 돌아간다
    T.keys[i] <- key, T.values[i] <- value
    N <- N + 1
```

- C 구현

```c
int put(ProbingTable *t, char key, int value, int *probes, int *slot) {
    if (t->n * 10 > t->m * 7) { /* 적재율 N/M이 0.7을 넘으면 두 배로 */
        resize(t, 2 * t->m);
    }
    int i = hashOf(key, t->m);
    *probes = 1;
    while (t->keys[i] != EMPTY) {
        if (t->keys[i] == key) {
            t->values[i] = value;
            *slot = i;
            return 0;
        }
        i = (i + 1) % t->m; /* 끝에 닿으면 0번 칸으로 */
        (*probes)++;
    }
    t->keys[i] = key;
    t->values[i] = value;
    t->n++;
    *slot = i;
    return 1;
}
```

원형으로 만듭니다. 15번 다음이 0번입니다.

### 삭제: 뒤따르는 키를 다시 넣는다 \{#lp-delete}

그래서 삭제할 때는 지운 칸의 **오른쪽에 이어진 키들**을, 빈칸이 나올 때까지
하나씩 꺼냈다가 다시 넣습니다. 다시 넣는 키는 지금의 빈칸 배치에 맞춰 제
해시 칸에 더 가까운 자리를 찾아갑니다.

<ProbingDemo mode="delete" />

- `S`(해시 6)는 꺼냈다가 넣으니 그대로 6번입니다.
- `H`(해시 4)는 4번 `A` 다음 비어 있는 5번으로 당겨 들어옵니다.
- `L`(해시 6)은 6번 `S` 다음 비어 있는 7번으로 당겨 들어옵니다.
- 9번이 비어 있어 멈춥니다. 이제 `H`는 2칸 만에 찾습니다.

- 의사코드

```plaintext
ALGORITHM Delete(T, key)
    i <- Hash(key, M)
    while T.keys[i] ≠ key do            // 먼저 키를 찾는다
        if T.keys[i] = 빈칸 then return 실패
        i <- (i + 1) mod M
    T.keys[i] <- 빈칸, N <- N - 1
    i <- (i + 1) mod M
    while T.keys[i] ≠ 빈칸 do           // 같은 무리에서 뒤따르던 키들을
        k, v <- T.keys[i], T.values[i]
        T.keys[i] <- 빈칸, N <- N - 1
        Put(T, k, v)                    // 꺼냈다가 다시 넣는다
        i <- (i + 1) mod M
    if 0 < N ≤ M/8 then Resize(T, M/2)  // 너무 비면 절반으로 줄인다
```

- C 구현

```c
int delete(ProbingTable *t, char key, int *probes) {
    int i = hashOf(key, t->m);
    *probes = 1;
    while (t->keys[i] != key) {
        if (t->keys[i] == EMPTY) {
            return 0;
        }
        i = (i + 1) % t->m;
        (*probes)++;
    }
    t->keys[i] = EMPTY;
    t->n--;

    i = (i + 1) % t->m;
    while (t->keys[i] != EMPTY) { /* 같은 무리에서 뒤따르던 키들 */
        char k = t->keys[i];
        int v = t->values[i];
        int p, slot;
        t->keys[i] = EMPTY;
        t->n--;
        put(t, k, v, &p, &slot);
        printf("  reinsert %c: slot %d -> %d\n", k, i, slot);
        i = (i + 1) % t->m;
    }
    if (t->n > 0 && t->n <= t->m / 8) { /* 8분의 1 이하로 비면 절반으로 */

```

다시 넣는 키는 무리 하나만큼이므로, 무리가 짧으면 삭제도 싸게 끝납니다.

### 다른 방법: 지워짐 표시 \{#tombstone}

키를 다시 넣는 대신, 지운 칸에 **지워짐 표시**(tombstone, 묘비)를 남기는 방법도
있습니다. 실제로 칸을 비우지 않으니 길이 끊기지 않습니다. 이것을 게으른
삭제(lazy deletion)라고 합니다.

`C`를 표시로 지운 뒤 `H`를 찾고, `H`와 `Y`를 넣어 봅니다.

<ProbingDemo mode="tombstone" />

`get H`는 5번 표시를 차 있는 칸처럼 지나 7번에서 `H`를 찾습니다. `put H`는
5번 표시를 지나 7번의 `H`를 갱신하고, `put Y`는 9번 빈칸까지 가서 `Y`가 없음을
확인한 뒤에야 기억해 둔 5번 표시 칸에 들어갑니다. 실습 코드는 이 방식을 쓰지
않으므로, 이 데모의 숫자는 데모에서만 나옵니다.

- `get`은 표시가 있는 칸을 **차 있는 칸처럼** 지나갑니다. 빈칸에서만 멈춥니다.
- `put`은 표시가 있는 칸을 **빈칸처럼** 다시 쓸 수 있습니다.
- 삭제는 표시 하나로 끝나므로 빠릅니다.

다만 두 가지를 조심해야 합니다. 첫째는 구현할 때 흔히 빠지는 함정입니다.

- **`put`은 첫 표시 칸에 바로 넣으면 안 됩니다.** 같은 키가 그 뒤쪽에 살아
  있을 수 있기 때문입니다. 빈칸까지 가서 같은 키가 없음을 확인한 뒤, 지나온
  첫 표시 칸에 넣어야 합니다. 그렇지 않으면 같은 키가 두 칸에 생깁니다.
- **표시는 쌓입니다.** 지우고 넣기를 반복하면 표시가 무리를 이어 붙여 탐색이
  점점 느려집니다. 표시가 많아지면 테이블을 새로 만들어(재해싱) 청소합니다.

### 크기 조정 \{#lp-resize}

선형 탐지는 배열이 가득 차면 넣을 곳이 없습니다. 차 갈수록 무리가 길어져 느려지기도
합니다. 그래서 배열 길이를 고정하지 않고 **적재율을 보고 늘이고 줄입니다.**

- **넣을 때**: 배열이 일정 비율 이상 차면 두 배로 늘립니다. 기준은
  구현마다 다르고(절반을 쓰는 구현도 많습니다), 이 예제는 0.7을 씁니다.
- **지울 때**: $$0 < N \le M/8$$이면 절반으로 줄입니다.

크기를 바꾸면 $$M$$이 바뀌므로 해시값도 모두 바뀝니다. 그래서 칸을 그대로 옮길
수 없고, **모든 키를 새 배열에 다시 넣습니다.** 한 번에 $$O(N)$$이 들지만, 두
배씩 늘리므로 그 비용을 그동안의 삽입들에 나눠 매기면 삽입 한 번에 상수입니다.

예제의 표를 크기 32인 배열로 옮겨 봅니다. 옛 배열의 0번 칸부터 키를 하나씩
꺼내 새 해시로 다시 넣습니다. 칸 귀퉁이의 숫자는 그 키를 찾을 때 들여다보는
칸 수입니다.

## 키 무리와 적재율 \{#clustering}

선형 탐지에서 차 있는 칸이 빈칸 없이 이어진 덩어리를 **키 무리**(cluster)라고
합니다. 예제의 4번부터 8번(`A C S H L`)이 길이 5인 무리입니다. 14번에서 1번까지
(`R X P M`)도 배열 끝을 넘어 이어진 무리입니다.

무리는 스스로 자랍니다.

- 새 키의 해시가 무리 안 **어디에** 떨어지든, 그 키는 무리 오른쪽 끝 다음
  빈칸에 들어갑니다. 무리가 길수록 키를 받아들일 확률이 큽니다.
- 들어간 키는 무리를 한 칸 늘리고, 가끔은 옆 무리와 이어 붙여 더 긴 무리를
  만듭니다. 예제에서 `P`가 0번에 들어가자 14·15번의 `R X`와 1번의 `M`이 한
  덩어리로 이어졌습니다.
- 무리가 길면 그 안에 해시된 키의 검색도, 없는 키의 검색도 무리 끝까지 걸어야
  합니다.

같은 난수 해시값으로 키를 크기 512인 배열에 넣어 봅니다. 왼쪽은 선형 탐지,
오른쪽은 비교용으로 충돌할 때 아무 빈칸이나 새로 고르는 경우입니다. 키 수를
128, 256, 384로 바꾸거나 **자동 재생**으로 조금씩 늘려 보세요.

<ClusterDemo />

적재율이 1/2(키 256개)일 때 선형 탐지 쪽에는 주황색 긴 무리가 흔하게
나타납니다. 1/4(128개)로 낮추면 무리가 짧아지고, 3/4(384개)로 올리면 무리끼리
이어 붙어 배열의 큰 덩어리가 됩니다. 무리가 짧을수록 성능이 좋습니다.

### 적재율이 정하는 비용 \{#load-factor}

적재율을 움직여 두 방식의 평균 탐색 비용을 견주어 봅니다. 곡선은 아래 식의
이론값이고, 표의 작은 숫자는 크기 4096인 배열에 무작위 해시값으로 키를 실제로
넣고 센 실험값입니다. 세는 단위는 앞의 데모와 같습니다. 선형 탐지는 들여다본
칸 수, 체이닝은 비교한 노드 수입니다.

<LoadCostDemo />

해시가 고르다고 가정하면, 적재율 $$\alpha = N/M$$인 선형 탐지 테이블에서
들여다보는 칸 수의 평균은 크누스(Knuth)가 구한 근삿값을 따릅니다.

$$
\text{성공} \approx \frac{1}{2}\left(1 + \frac{1}{1-\alpha}\right) \qquad
\text{실패} \approx \frac{1}{2}\left(1 + \frac{1}{(1-\alpha)^2}\right)
$$

| 적재율 $$\alpha$$ | 성공 탐색 | 실패 탐색 |
| --- | --- | --- |
| 1/2 | 1.5 | 2.5 |
| 3/4 | 2.5 | 8.5 |
| 7/8 | 4.5 | 32.5 |

- 절반만 채우면 실패 탐색도 평균 2.5칸입니다. 반드시 절반일 필요는 없고, 감당할
  탐색 비용을 보고 기준을 정하면 됩니다.
- 3/4이면 실패 탐색이 8.5칸, 7/8이면 32.5칸입니다. 분모에 $$(1-\alpha)^2$$이
  있어 1에 가까워질수록 **급격히** 나빠집니다.
- 테이블 공간을 너무 알뜰하게 쓰면 시간에서 대가를 치릅니다. 그래서 선형 탐지는
  적재율을 1/2 근처로 지키도록 크기를 조정합니다.

적재율이 1에 가까우면 실험값이 근삿값보다 조금 작게 나옵니다. 7/8에서는 32.5
대신 약 30입니다. 크누스의 식은 배열이 아주 클 때의 근삿값이고, 크기가 정해진 배열에서는
실패 탐색 평균이 그보다 조금 작습니다. 배열을 키울수록 근삿값에 다가갑니다.

체이닝은 사정이 다릅니다. 리스트가 길어질 뿐 넘칠 곳이 없으므로 $$\alpha$$가 1을
넘어도 동작하고(예제는 2였습니다), 비용도 $$\alpha$$에 비례해 완만하게 늘어납니다.

## 두 방식 비교 \{#comparison}

| | 개별 체이닝 | 선형 탐지 |
| --- | --- | --- |
| 충돌한 키를 두는 곳 | 그 칸의 연결 리스트 | 배열의 다음 빈칸 |
| 적재율 | 1을 넘어도 된다 | 반드시 1보다 작아야 한다 (보통 1/2 근처) |
| 추가 메모리 | 노드마다 링크 | 빈칸 |
| 삭제 | 연결 하나만 바꾼다 | 뒤따르는 키를 다시 넣거나 지워짐 표시 |
| 성능을 해치는 것 | 긴 리스트 | 긴 키 무리 |
| 메모리 접근 | 노드가 흩어져 있다 | 이웃한 칸을 차례로 본다 |

메모리 사용량을 Sedgewick 교재의 Java 기준(키와 값이 참조 타입)으로 보면
이렇습니다. 이진 탐색 트리와 나란히 놓았습니다.

| 방법 | 키 $$N$$개의 공간 |
| --- | --- |
| 개별 체이닝 | 약 $$48N + 32M$$바이트 |
| 선형 탐지 | 약 $$32N$$에서 $$128N$$바이트 사이 |
| 이진 탐색 트리 | 약 $$56N$$바이트 |

선형 탐지의 폭이 넓은 것은 교재의 크기 조정 규칙에 따라 배열이 1/8에서 1/2
사이로 차 있기 때문입니다. 체이닝은 리스트 링크에 쓸 메모리를, 선형 탐지는 그 메모리를 빈칸에
씁니다. 이웃한 칸을 차례로 보는 선형 탐지는 CPU 캐시와 잘 맞아 실제로는 빠른
경우가 많습니다.

## 해시 테이블의 자리 \{#where-hashing-fits}

해시 테이블은 테이블 $$T$$와 레코드 $$x$$(키와 값)가 주어질 때 세 연산을
지원합니다.

- `Insert(T, x)`
- `Delete(T, x)`
- `Search(T, x)`

**탐색이 빠르기를 원하고 레코드의 정렬 순서는 고려하지 않을 때** 쓰는 자료
구조입니다. 대체로 $$O(1)$$에 찾기를 기대합니다.

그렇다고 해싱이 만병통치약은 아닙니다.

- 키 타입마다 **좋은 해시 함수**가 있어야 합니다.
- 성능 보장이 해시 함수의 품질에 달려 있습니다. 나쁜 해시 함수를 만나면 모든
  연산이 $$O(N)$$이 됩니다.
- 해시 함수 계산이 어렵고 비쌀 수 있습니다. 긴 문자열이면 글자 수만큼 계산합니다.
- **순서에 관한 연산이 쉽지 않습니다.** 가장 작은 키, 어떤 키 바로 다음 키,
  범위 안의 모든 키 같은 질문에는 해시값이 흩어 놓은 순서로 답할 수 없습니다.

| | 이진 탐색 트리 (균형) | 해시 테이블 |
| --- | --- | --- |
| 검색·삽입·삭제 | $$O(\log N)$$ | 평균 $$O(1)$$ |
| 최악 | $$O(\log N)$$ | $$O(N)$$ (나쁜 해시) |
| 최솟값, 범위 검색, 순서대로 나열 | 된다 | 안 된다 |
| 키에 필요한 것 | 비교 | 해시 함수와 같음 판정 |

순서가 필요하면 주제 07의 [[bst|이진 탐색 트리]], 순서가 필요 없고 빠르기만 하면
해시 테이블입니다.

## 이 주제에서 남길 것 \{#takeaway}

- **해싱**: 키에서 배열 인덱스를 계산해 비교 없이 찾는다. 시간과 메모리 사이의
  균형점이다.
- **좋은 해시 함수**: 결과가 $$[0, M-1]$$ 안에 들고, 계산이 쉽고, 키를 고르게
  퍼뜨린다. 정수는 $$k \bmod M$$(M은 소수), 문자열은 호너 방식으로 순서를 반영한다.
- **충돌은 반드시 일어난다.** 비둘기집 원리 때문에, 그리고 생일 문제 때문에 키가
  적어도 금방 일어난다.
- **개별 체이닝**: 칸마다 연결 리스트. 해시 탐색 뒤 리스트 탐색. 평균
  $$O(1 + N/M)$$, 삭제가 쉽다.
- **선형 탐지**: 충돌하면 다음 칸으로. 빈칸에서 검색이 멈추므로 **그냥 지우면
  안 되고**, 뒤따르는 키를 다시 넣거나 지워짐 표시를 남긴다.
- **키 무리와 적재율**: 선형 탐지는 무리가 스스로 자라 $$\alpha$$가 1에 가까우면
  급격히 느려진다. 그래서 크기를 조정해 $$\alpha$$를 1/2 근처로 지킨다.
- 해시 테이블은 **순서를 버리고 속도를 얻는다.** 순서가 필요하면 이진 탐색 트리다.
