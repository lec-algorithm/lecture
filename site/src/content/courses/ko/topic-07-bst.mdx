## 이진 트리 \{#binary-tree}

트리는 노드와 노드를 잇는 링크로 이루어진 구조입니다. 그중 이진 트리는
두 가지 성질을 갖춥니다.

- **성질 1**: 루트에서 다른 모든 노드까지 가는 경로가 **딱 하나**(unique)
  있습니다. 두 노드가 같은 자식을 함께 가리키거나, 링크가 돌아서 위로
  되돌아오면 트리가 아닙니다.
- **성질 2**: 각 노드는 자식을 **최대 두 개** 가집니다. 왼쪽 자식과 오른쪽
  자식입니다.

성질 1부터 확인해 봅니다. 노드를 누르면 루트에서 그 노드까지 가는 경로가
칠해집니다. 어느 노드를 눌러도 경로는 하나입니다. 이번에는 **링크 하나 더
잇기**를 눌러 C에서 E로 가는 링크를 더해 봅니다. E의 부모가 둘이 되면서 E와
그 아래 노드까지 가는 경로가 둘로 늘고, 링크가 돌아 되돌아오는 고리가 생깁니다.

<TreePropertyDemo mode="path" />

성질 2는 직접 트리를 키워 보며 확인합니다. 점선 자리(+)를 누르면 그 자리에
자식이 생깁니다. 자식이 하나뿐이어도 왼쪽인지 오른쪽인지는 정해져 있습니다.
왼쪽과 오른쪽이 다 찬 노드를 고르고 **자식 하나 더 달기**를 누르면 셋째
자리가 없어 거부됩니다.

### 용어 \{#terms}

트리를 말할 때 쓰는 이름을 하나씩 눌러 봅니다. 용어를 누르면 아래 트리에서
그 용어가 가리키는 부분이 칠해지고, 노드를 누르면 그 노드가 기준이 됩니다.
부모·자식, 서브트리, 레벨은 고른 노드를 기준으로 보여 줍니다. 이 트리는 일부러
full tree가 아니게 골랐습니다. 잎의 레벨이 서로 다르고 자식이 하나뿐인 노드가
있어야 잎, 높이, full tree의 차이가 보입니다.

<TreeTermsDemo />

정리하면 이렇습니다.

| 용어 | 뜻 |
| --- | --- |
| 노드(node) | 값을 담는 원 하나 |
| 링크(link) | 노드와 노드를 잇는 선. 간선(edge)이라고도 한다 |
| 루트(root) | 맨 위의 노드. 부모가 없는 유일한 노드 |
| 부모·자식(parent·child) | 링크로 바로 이어진 위·아래 노드 |
| 잎(leaf) | 자식이 없는 노드 |
| 서브트리(subtree) | 한 노드와 그 아래 전부. 그 자체로 트리다 |
| 레벨(level) | 루트에서 몇 링크 내려왔는가. 루트가 레벨 0 |
| 높이(height) | 레벨의 수. 루트만 있으면 1 |
| full tree | 잎이 아닌 노드는 모두 자식이 둘이고, 잎이 모두 같은 레벨에 있는 트리 |

위 그림은 full tree입니다. A, B, C, D가 잎이고 레벨 2에 모여 있습니다.
여기서 D를 빼면 full tree가 아닙니다.

높이는 이 과목에서 **레벨의 수**로 셉니다. 루트에서 가장 깊은 잎까지의
**링크 수**로 세는 교재도 있는데, 그러면 우리 값보다 1 작습니다. 다른
자료와 비교할 때는 이것만 맞추면 됩니다.

### 높이와 노드 수 \{#height}

레벨 $$l$$에는 노드가 최대 $$2^l$$개 들어갑니다. 레벨 0에 1개, 레벨 1에
2개, 레벨 2에 4개입니다. 한 걸음씩 레벨을 채워 보면 개수가 두 배씩 늘어
갑니다.

<TreePropertyDemo mode="count" />

높이가 $$h$$인 full tree는 모든 레벨이 꽉 차 있으므로 노드 수 $$N$$은
이렇습니다.

$$
N = 2^0 + 2^1 + \cdots + 2^{h-1} = 2^h - 1
$$

거꾸로 풀면 높이는 노드 수의 로그입니다.

$$
2^h = N + 1 \quad\Rightarrow\quad h = \log_2(N + 1) = O(\log N)
$$

반대로 가장 높은 트리는 어떤 모양일까요. 노드마다 자식이 하나뿐이면 트리가
한 줄로 늘어서서 높이가 $$N$$이 됩니다. 연결 리스트와 같은 모양입니다.
노드 수를 바꾸고 모양을 골라 보세요. 막대의 왼쪽 끝이 가장 낮은 높이,
오른쪽 끝이 가장 높은 높이이고, 점이 지금 모양의 높이입니다. **무작위**는
1부터 $$N$$까지를 무작위 순서로 넣은 BST 모양이라 누를 때마다 바뀝니다.

<TreeShapeDemo />

| 노드 수 $$N$$ | 가장 낮은 높이 | 가장 높은 높이 |
| --- | --- | --- |
| 7 | 3 | 7 |
| 1,023 | 10 | 1,023 |
| 약 100만 | 20 | 약 100만 |

같은 노드 수라도 높이는 $$\log_2 N$$부터 $$N$$까지 벌어집니다. 이 주제의
모든 연산은 결국 이 높이에 비례하므로, 이 표를 기억해 두면 됩니다.

## 이진 탐색 트리 \{#bst}

### 정의 \{#bst-definition}

[[bst|이진 탐색 트리]] (binary search tree, BST)는 모든 노드가 다음 규칙을
지키는 이진 트리입니다.

- **왼쪽 서브트리의 모든 키**가 그 노드의 키보다 작습니다.
- **오른쪽 서브트리의 모든 키**가 그 노드의 키보다 큽니다.
- 왼쪽과 오른쪽 서브트리도 각각 이진 탐색 트리입니다.

키는 모두 다르다고 둡니다. 같은 값을 다시 넣으면 아무것도 하지 않습니다.

부모·자식 쌍만 보고 "왼쪽 **자식**보다 크고 오른쪽 **자식**보다 작으면
된다"고 생각하기 쉽지만, 그것만으로는 부족합니다. 아래 트리는 모든
부모·자식 쌍이 그 규칙을 지키는데도 BST가 아닙니다.

<TreeFigure tree={{ v: "5", l: { v: "3", r: { v: "7", tone: "focus" } }, r: { v: "8" } }} caption="3 < 7이라 자식 규칙은 맞지만, 7이 5의 왼쪽 서브트리에 있다" />

두 가지 검사로 직접 돌려 봅니다. **자식과만 비교**는 이 트리를 통과시킵니다.
**범위로 검사**는 루트를 $$(-\infty, \infty)$$에서 시작해, 왼쪽으로 내려갈 때는
위 끝을, 오른쪽으로 내려갈 때는 아래 끝을 지금 키로 좁혀 내려보냅니다. 7에
이르면 범위가 $$(3, 5)$$로 좁아져 있어 걸립니다.

<BstCheckDemo />

7은 5보다 큰데 5의 왼쪽 서브트리에 들어가 있습니다. 7을 찾으면 5에서
오른쪽(8)으로 가게 되어 영영 찾지 못합니다. 규칙은 자식 하나가 아니라
**서브트리 전체**에 걸려야 합니다. 같은 이유로 앞 절의 2·7·5 트리도
BST가 아닙니다.

이 규칙을 지키는 트리입니다. 키 `7 4 14 1 6 16 2 5 15`를 차례로 넣으면 이
모양이 됩니다.

<TreeFigure tree={{ v: "7", l: { v: "4", l: { v: "1", tone: "eval", r: { v: "2" } }, r: { v: "6", l: { v: "5" } } }, r: { v: "14", r: { v: "16", tone: "focus", l: { v: "15" } } } }} caption="초록: 가장 작은 값 · 주황: 가장 큰 값" />

- **가장 작은 값**은 왼쪽으로만 끝까지 내려간 곳(1)에 있습니다.
- **가장 큰 값**은 오른쪽으로만 끝까지 내려간 곳(16)에 있습니다.
- 왼쪽부터 읽으면 `1 2 4 5 6 7 14 15 16`, 정렬된 순서입니다.

### 검색 \{#bst-search}

규칙이 있으니 한 번 비교할 때마다 한쪽을 통째로 버릴 수 있습니다. 6을
찾아봅니다. 주황 원이 찾는 값이고, 비교한 노드 옆, 다음에 갈 쪽에 섭니다.

<BstDemo keys={[7, 4, 14, 1, 6, 16, 2, 5, 15]} find={6} />

7과 비교해 작으니 오른쪽 서브트리 `14 15 16`은 볼 필요가 없습니다. 4와
비교해 크니 `1 2`도 버립니다. 비교 3번에 찾았습니다. 없는 값도 금방
알 수 있습니다. 13을 찾으면 14의 왼쪽이 비어 있으므로 비교 2번 만에
"없다"고 답합니다.

<BstDemo keys={[7, 4, 14, 1, 6, 16, 2, 5, 15]} find={13} />

점선 원이 13이 들어갈 자리입니다. **검색이 실패한 자리가 곧 삽입할
자리**라는 것을 기억해 두세요. 예제 1에서 그대로 씁니다.

주제 01의 [[binary-search|이진 검색]]과 같은 생각입니다. 이진 검색은 매번
가운데 값과 비교해 절반을 버렸습니다. 이진 탐색 트리는 그 "가운데"를 미리
루트에 세워 두고, 각 서브트리에도 그 부분의 기준값을 세워 둔 것입니다.
다른 점은 배열이 아니라 링크로 이어져 있어서 넣고 빼기가 쉽다는 것입니다.

```plaintext
ALGORITHM Search(root, key)
    node <- root
    while node != NULL do
        if key = node.key then
            return node                 // 찾았다
        if key < node.key then
            node <- node.left           // 작으면 왼쪽 서브트리만 보면 된다
        else
            node <- node.right          // 크면 오른쪽 서브트리만 보면 된다
    return NULL                         // 비어 있는 자리에 닿았다: 없다
```

루트에서 잎 쪽으로 한 길만 내려가므로 비교 횟수는 많아야 높이 $$h$$입니다.
검색은 $$O(h)$$입니다.

### 링크로 표현하기 \{#structure}

연결 리스트의 노드는 값 하나와 다음 노드의 주소 하나를 담았습니다. 이진
탐색 트리의 노드는 주소를 두 개 담습니다.

```plaintext
연결 리스트 노드        [ 값 | 다음 주소 ]

트리 노드          [ 왼쪽 주소 | 값 | 오른쪽 주소 ]
                        |              |
                        v              v
          [ 왼쪽 | 값 | 오른쪽 ]  [ 왼쪽 | 값 | 오른쪽 ]
```

C로 적으면 구조체 하나와 노드를 만드는 함수 하나입니다. 새 노드는 자식이
없으므로 두 주소를 `NULL`로 둡니다.

```c
typedef struct TreeNode {
    int key;
    struct TreeNode *left;   /* 왼쪽 자식의 주소 */
    struct TreeNode *right;  /* 오른쪽 자식의 주소 */
} TreeNode;

TreeNode *createNode(int key) {
    TreeNode *node = (TreeNode *)malloc(sizeof(TreeNode));
    node->key = key;
    node->left = NULL;
    node->right = NULL;
    return node;
}
```

## 예제 1. 검색과 삽입 \{#insert}

삽입은 **실패한 검색 + 그 자리에 매달기**입니다. 넣을 값을 찾듯이
내려가다가 비어 있는 자식 자리에 닿으면 거기에 새 노드를 답니다.
`5 9 7 3 8 12 6 4 20` 순서로 넣어 봅니다. 위쪽 줄이 넣을 순서이고, 주황
원이 지금 넣는 값입니다.

<BstDemo />

8을 넣는 장면을 보세요. 5보다 크니 오른쪽, 9보다 작으니 왼쪽, 7보다 크니
오른쪽인데 7의 오른쪽이 비어 있습니다. 거기에 8이 자리 잡습니다. 이미
있는 노드는 하나도 움직이지 않습니다. 배열에 끼워 넣을 때처럼 뒤를 밀 필요가
없습니다.

데모의 노드는 처음부터 제자리에 나타납니다. 가로 위치가 **정렬했을 때의
순번**이기 때문입니다. 노드를 모두 바닥으로 내려 한 줄에 모으면
`3 4 5 6 7 8 9 12 20`이 왼쪽부터 정렬되어 늘어섭니다. BST 규칙이 바로 이 성질입니다.

```plaintext
ALGORITHM Insert(root, key)
    if root = NULL then
        return 새 노드(key)             // 검색이 실패한 바로 그 자리
    if key < root.key then
        root.left <- Insert(root.left, key)
    else if key > root.key then
        root.right <- Insert(root.right, key)
    // 같으면 아무것도 하지 않는다 (키는 한 번만 넣는다)
    return root
```

재귀로 쓰면 짧습니다. 각 호출은 "이 서브트리에 key를 넣고 그 루트를
돌려준다"는 약속을 지킵니다. 빈 서브트리에 넣으면 새 노드가 그 서브트리의
루트가 되고, 부모는 돌려받은 주소를 `left`나 `right`에 다시 적습니다.

- C 구현

```c
TreeNode *insert(TreeNode *root, int key) {
    if (root == NULL) {
        return createNode(key);
    }
    if (key < root->key) {
        root->left = insert(root->left, key);
    } else if (key > root->key) {
        root->right = insert(root->right, key);
    }
    return root;
}
```

root = insert(root, 9);

  범위 밖이지만, 실제 라이브러리의 정렬된 맵(C++ `std::map`, Java `TreeMap`)이
  쓰는 것이 이것입니다.

데이터가 이미 정렬되어 들어오는 일은 드물지 않습니다. 날짜순 로그, 번호순
학번이 그렇습니다. 그래서 균형을 신경 쓰지 않는 BST는 실전에서 위험할 수
있습니다.

## 예제 2. 삭제 \{#delete}

삭제는 두 단계입니다. 지울 값을 **찾고**, 그 노드를 **지웁니다.** 조건은
하나입니다. 지운 뒤에도 **왼쪽이 작고 오른쪽이 크다**는 BST의 성질이 반드시
보존되어야 합니다. 지울 노드의 자식 수에 따라 세 경우로 나뉩니다.

| 경우 | 지울 노드 | 하는 일 |
| --- | --- | --- |
| 1 | 자식 0개 (잎) | 그냥 떼어 낸다 |
| 2 | 자식 1개 | 그 자식을 부모에 바로 잇는다 |
| 3 | 자식 2개 | 후속자를 그 자리에 복사하고, 원래 후속자를 지운다 |

`B A D C G F E`를 넣은 트리로 해 봅니다.
세 데모 모두 이 트리에서 새로 시작합니다.

### 경우 1: 자식이 0개 \{#delete-leaf}

E는 잎입니다. 떼어 내도 다른 노드의 위치 관계는 바뀌지 않습니다.

<BstDeleteDemo del="E" />

### 경우 2: 자식이 1개 \{#delete-one}

F는 왼쪽 자식 E 하나만 있습니다. F를 지우고 E를 F의 부모 G에 바로
잇습니다. E는 원래 G의 왼쪽 서브트리에 있었으니 G보다 작고, 여전히 G의
왼쪽이 맞는 자리입니다. 자식에 딸린 서브트리가 있어도 통째로 올라오면 됩니다.

<BstDeleteDemo del="F" />

### 경우 3: 자식이 2개 \{#delete-two}

D는 자식이 C와 G 둘입니다. D의 부모 B에게는 자식 자리가 하나뿐이니 둘을
다 이을 수 없습니다. 그래서 D를 지우는 대신 **D 자리에 들어갈 다른 값**을
찾습니다. 그 값은 D 왼쪽의 모든 값보다 크고 오른쪽의 모든 값보다 작아야
합니다. 후보는 둘입니다.

- **후속자**(successor): 오른쪽 서브트리에서 가장 작은 값. 오른쪽으로 한 번
  간 뒤 왼쪽 끝까지 내려가면 있습니다. 중위 순서로 D 바로 다음 값입니다.
- **선행자**(predecessor): 왼쪽 서브트리에서 가장 큰 값. 중위 순서로 D 바로
  앞 값입니다.

실습 코드는 후속자를 씁니다.

<BstDeleteDemo del="D" />

후속자 E를 D 자리에 복사하면 잠깐 E가 두 군데 있게 됩니다. 이제 원래 E를
지우면 됩니다. 후속자는 "왼쪽 끝"이므로 **왼쪽 자식이 없습니다.** 그래서
원래 후속자를 지우는 일은 언제나 경우 1이나 경우 2로 끝나고, 경우 3이 다시
나오지 않습니다.

`J B Q L R K N Z M P`를 넣은 트리에서 Q를 지워 봅니다. Q의 오른쪽 자식 R은 왼쪽 자식이 없으니 R 자신이 후속자입니다.
R을 복사하고 원래 R을 지우면 R의 오른쪽 자식 Z가 올라옵니다.

루트를 지워도 절차가 같습니다. J의 후속자를 찾아 오른쪽으로 한 번(Q), 왼쪽
끝까지(L, K) 내려갑니다.

경우 3에서 후속자 대신 선행자를 쓰면 D를 지울 때 왼쪽 서브트리의 가장 큰
값 C가, Q를 지울 때 P가 그 자리에 옵니다.

실습 코드와 나머지 데모는 후속자로 맞췄습니다.

### 절차와 코드 \{#delete-code}

삭제도 재귀로 생각하면 깔끔합니다.

- **문제의 크기**: 트리의 노드 수
- **베이스 케이스**: 지울 키를 찾은 경우. 세 경우 중 하나로 처리합니다.
- **일반 케이스**: 왼쪽 또는 오른쪽 서브트리를 골라 그 안에서 지웁니다.

```plaintext
ALGORITHM Delete(root, key)
    if root = NULL then
        return NULL                         // 지울 값이 없다
    if key < root.key then
        root.left <- Delete(root.left, key)
    else if key > root.key then
        root.right <- Delete(root.right, key)
    else                                    // root가 지울 노드다
        if root.left = NULL then            // 경우 1·2: 자식이 0개이거나 오른쪽 하나
            return root.right
        if root.right = NULL then           // 경우 2: 왼쪽 자식 하나
            return root.left
        succ <- FindMin(root.right)         // 경우 3: 후속자
        root.key <- succ.key                // 후속자의 키를 이 자리에 복사하고
        root.right <- Delete(root.right, succ.key)   // 원래 후속자를 지운다
    return root
```

경우 1과 경우 2(오른쪽 자식만 있음)가 한 줄로 합쳐진 것을 보세요. 왼쪽이
비어 있으면 오른쪽을 돌려주는데, 자식이 하나도 없으면 오른쪽도 `NULL`이라
그대로 "떼어 내기"가 됩니다.

- C 구현

```c
TreeNode *findMin(TreeNode *node) {
    while (node->left != NULL) {
        node = node->left;
    }
    return node;
}

TreeNode *deleteNode(TreeNode *root, char key) {
    if (root == NULL) {
        return NULL;
    }
    if (key < root->key) {
        root->left = deleteNode(root->left, key);
    } else if (key > root->key) {
        root->right = deleteNode(root->right, key);
    } else {
        /* 경우 1·2: 자식이 0개이거나 하나 */
        if (root->left == NULL) {
            TreeNode *temp = root->right;
            free(root);
            return temp;
        }
        if (root->right == NULL) {
            TreeNode *temp = root->left;
            free(root);
            return temp;
        }
        /* 경우 3: 자식이 둘. 후속자를 복사하고 원래 후속자를 지운다. */
        TreeNode *succ = findMin(root->right);
        root->key = succ->key;
        root->right = deleteNode(root->right, succ->key);
    }
    return root;
}
```

C에서는 떼어 낸 노드의 메모리를 `free`로 돌려줍니다. 그 전에 남길 자식의
주소를 `temp`에 받아 두어야 합니다. `free` 뒤에는 `root->right`를 읽을 수
없습니다.

## 예제 3. 순회 \{#traversal}

트리의 모든 노드를 한 번씩 방문하는 것을 순회(traversal)라고 합니다. 배열은
앞에서부터 읽으면 되지만 트리는 갈림길마다 어느 쪽을 먼저 볼지 정해야 합니다.
재귀로 쓰는 순회가 세 가지 있고, 차이는 **현재 노드를 언제 출력하느냐**
하나입니다.

| 순회 | 순서 | `D B F A C E G` 트리의 결과 |
| --- | --- | --- |
| 중위(inorder) | [왼쪽] [현재] [오른쪽] | `A B C D E F G` |
| 전위(preorder) | [현재] [왼쪽] [오른쪽] | `D B A C F E G` |
| 후위(postorder) | [왼쪽] [오른쪽] [현재] | `A C B E G F D` |

탭을 바꿔 가며 한 걸음씩 넘겨 보세요. 주황이 지금 노드, 주황 테두리가 아직
끝나지 않은 호출(호출 스택)이고, 출력한 노드에는 몇 번째로 나왔는지 번호가
붙습니다.

<TraversalDemo />

- **중위**는 노드마다 왼쪽을 다 본 뒤에 출력하므로, BST에서는 **언제나 정렬된
  순서**가 나옵니다. 넣은 순서와 상관없습니다.
- **전위**는 루트가 맨 앞에 나옵니다. 부모가 언제나 자식보다 먼저입니다.
- **후위**는 루트가 맨 뒤에 나옵니다. 자식이 언제나 부모보다 먼저입니다.

세 순회 말고 **레벨 순서**(level order)도 있습니다. 루트부터 레벨별로, 같은
레벨은 왼쪽부터 읽습니다. 재귀가 아니라 큐(queue)를 씁니다. 꺼낸 노드를
출력하고 그 자식을 큐 뒤에 넣는 것을 큐가 빌 때까지 되풀이합니다. 주제 12에서
그래프를 가까운 정점부터 훑는 [[bfs|BFS]]가 바로 이 방법입니다.

`P F B H G S R Y T W Z`를 넣은 트리로도 돌려 봅니다. 열한 개 노드라 순서의
차이가 더 잘 보입니다.

<TraversalDemo keys="PFBHGSRYTWZ" order="pre" />

```plaintext
ALGORITHM Inorder(node)                 // 중위: [왼쪽] [현재] [오른쪽]
    if node != NULL then
        Inorder(node.left)
        node.key를 출력
        Inorder(node.right)

ALGORITHM Preorder(node)                // 전위: [현재] [왼쪽] [오른쪽]
    if node != NULL then
        node.key를 출력
        Preorder(node.left)
        Preorder(node.right)

ALGORITHM Postorder(node)               // 후위: [왼쪽] [오른쪽] [현재]
    if node != NULL then
        Postorder(node.left)
        Postorder(node.right)
        node.key를 출력

ALGORITHM LevelOrder(root)              // 레벨 순서: 위 레벨부터, 같은 레벨은 왼쪽부터
    queue <- [root]
    while queue가 비어 있지 않은 동안 do
        node <- queue에서 맨 앞을 꺼낸다
        node.key를 출력
        if node.left != NULL then queue 뒤에 node.left를 넣는다
        if node.right != NULL then queue 뒤에 node.right를 넣는다
```

- C 구현 (중위와 레벨 순서)

```c
void inorderTraversal(TreeNode *root) {
    if (root != NULL) {
        inorderTraversal(root->left);
        printf(" %c", root->key);
        inorderTraversal(root->right);
    }
}

void levelorderTraversal(TreeNode *root) {
    TreeNode *queue[MAX_NODES];
    int head = 0;
    int tail = 0;
    if (root != NULL) {
        queue[tail++] = root;
    }
    while (head < tail) {
        TreeNode *node = queue[head++];
        printf(" %c", node->key);
        if (node->left != NULL) {
            queue[tail++] = node->left;
        }
        if (node->right != NULL) {
            queue[tail++] = node->right;
        }
    }
}
```

전위와 후위는 중위 함수에서 `printf` 한 줄의 자리만 옮긴 것입니다.

다릅니다. 재귀 순회는 호출 스택에 루트부터 지금 노드까지의 길을 쌓으므로
$$O(h)$$, 레벨 순서는 큐에 한 레벨이 통째로 들어갈 수 있어 최대 $$O(n)$$입니다.

## 예제 4. 출력·해제·복사 \{#print-free-copy}

트리 전체를 다루는 일은 모두 순회 하나로 끝납니다. 어느 순회를 쓸지는
**부모와 자식 중 누구를 먼저 다뤄야 하느냐**로 정합니다.

| 하는 일 | 순회 | 이유 |
| --- | --- | --- |
| 정렬된 순서로 출력 | 중위 | BST의 중위는 오름차순이다 |
| 모양대로 출력 | 전위 | 부모를 적어야 그 아래에 자식을 들여 적을 수 있다 |
| 해제(free) | 후위 | 부모를 먼저 지우면 자식으로 가는 주소를 잃는다 |
| 복사 | 전위 | 부모가 있어야 자식을 매달 수 있다 |

### 출력 \{#print}

정렬된 출력은 앞에서 본 중위 순회 그대로입니다. 트리의 **모양**을 글자로
찍으려면 노드를 먼저 적고 그 아래에 자식을 한 칸씩 들여 적습니다. 현재를
먼저 다루므로 전위입니다. 트리를 출력한다고 하면 중위 순회를 떠올리기
쉽지만, 출력 함수가 노드를 먼저 찍고 자식으로 내려가므로 전위입니다.
정렬된 출력(중위)과 모양 출력(전위)은 다른 일입니다.

```c
void printTree(TreeNode *root, const char *prefix, int isLast) {
    printf("%s%s", prefix, isLast ? "└── " : "├── ");
    if (root == NULL) {
        printf("-\n");
        return;
    }
    printf("%c\n", root->key);                       /* 현재 먼저 */

    if (root->left != NULL || root->right != NULL) {
        char next[256];
        snprintf(next, sizeof(next), "%s%s", prefix, isLast ? "    " : "│   ");
        printTree(root->left, next, 0);              /* 그다음 왼쪽 */
        printTree(root->right, next, 1);             /* 그다음 오른쪽 */
    }
}
```

### 해제 \{#free}

C에서 `malloc`으로 만든 노드는 다 쓰면 `free`로 돌려줘야 합니다. 부모를
먼저 `free`하면 그 안에 적힌 자식의 주소를 더는 읽을 수 없으므로, 자식부터
지우는 **후위**가 맞습니다. 아래 데모를 끝까지 넘기면 출력 줄이 곧 해제
순서입니다. 잎부터 지워지고 루트 P가 맨 마지막입니다.

<TraversalDemo keys="PFBHGSRYTWZ" order="post" />

```c
TreeNode *clearTree(TreeNode *root) {
    if (root != NULL) {
        clearTree(root->left);
        clearTree(root->right);
        free(root);              /* 자식이 모두 해제된 뒤라 안전하다 */
    }
    return NULL;
}
```

`NULL`을 돌려주는 것은 `root = clearTree(root);`로 써서 해제된 주소가 남지
않게 하려는 것입니다.

### 복사 \{#copy}

복사는 반대입니다. 새 부모 노드가 있어야 복사한 자식을 거기에 매달 수
있으므로 **전위**입니다.

```c
TreeNode *copyTree(TreeNode *root) {
    if (root == NULL) {
        return NULL;
    }
    TreeNode *copy = createNode(root->key);   /* 현재 먼저 */
    copy->left = copyTree(root->left);
    copy->right = copyTree(root->right);
    return copy;
}
```

### 저장했다가 다시 만들기 \{#rebuild}

트리를 파일에 써 두었다가 다음에 프로그램을 실행할 때 읽어서 다시 넣는다고
해 봅시다. 어떤 순회로 써야 할까요.

- **중위로 쓰면** 정렬된 순서가 저장됩니다. 그 순서대로 다시 넣으면 앞에서
  본 대로 한쪽으로만 자라는 트리가 됩니다. 원래 구조는 사라집니다.
- **전위로 쓰면** 언제나 부모가 자식보다 먼저 나옵니다. 그 순서대로 넣으면
  각 키가 원래 자리로 정확히 돌아가서 **같은 트리**가 됩니다.

중위 순서 `B F G H P R S T W Y Z`를 다시 넣어 보면 이렇습니다.

<BstDemo keys={['B', 'F', 'G', 'H', 'P', 'R', 'S', 'T', 'W', 'Y', 'Z']} />

전위 순서 `P F B H G S R Y T W Z`로 넣으면 이번에는 원래 트리가 그대로
돌아옵니다. 부모가 언제나 먼저 들어가 있으므로, 각 키는 비교하며
내려가다가 원래 부모 아래의 원래 자리에 닿습니다. 높이도 5 그대로입니다.

<BstDemo keys={['P', 'F', 'B', 'H', 'G', 'S', 'R', 'Y', 'T', 'W', 'Z']} />

## BST와 연결 리스트 \{#comparison}

같은 일을 정렬된 연결 리스트로 하면 어떻게 다를까요. 연결 리스트는 처음부터
하나씩 따라가야 하므로 찾기·넣기·빼기가 모두 $$O(n)$$입니다.

| 연산 | BST (균형일 때) | BST (최악) | 정렬된 연결 리스트 |
| --- | --- | --- | --- |
| 생성(constructor) | $$O(1)$$ | $$O(1)$$ | $$O(1)$$ |
| 해제(destructor) | $$O(n)$$ | $$O(n)$$ | $$O(n)$$ |
| 비었는가·꽉 찼는가 | $$O(1)$$ | $$O(1)$$ | $$O(1)$$ |
| 검색 | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |
| 삽입 | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |
| 삭제 | $$O(\log n)$$ | $$O(n)$$ | $$O(n)$$ |

BST를 $$O(\log n)$$이라고만 말할 때는 $$h = O(\log n)$$이라는 가정이
숨어 있습니다. 그 가정이 깨지면 BST도 연결 리스트와 같아진다는 것을 최악
열이 보여 줍니다. 검색·삽입·삭제는 정확히는 모두 $$O(h)$$이고, 높이 $$h$$가
$$\log_2 n$$과 $$n$$ 사이 어디에 있느냐가 전부입니다.

주제 01의 정렬된 배열과도 나란히 놓아 봅니다. 배열은 이진 검색으로 찾기는
$$O(\log n)$$이지만, 넣고 뺄 때 뒤의 원소를 밀고 당기느라 $$O(n)$$입니다.
균형 잡힌 BST는 셋 다 $$O(\log n)$$입니다. 링크를 바꾸는 것만으로 넣고 뺄 수
있기 때문입니다.

## 메모리 속의 트리 \{#memory}

지금까지 트리를 위아래로 가지를 뻗은 그림으로 그렸습니다. 그런데 컴퓨터의
메모리에는 위도 아래도 없습니다. 메모리는 주소가 붙은 바이트가 한 줄로 길게
늘어선 것입니다. 앞의 [링크로 표현하기](#structure)에서 본 구조체가 이 한 줄
위에 실제로 어떻게 놓이는지 봅니다.

### 노드 하나는 블록 하나 \{#memory-blocks}

`createNode`가 부르는 `malloc(sizeof(TreeNode))`은 메모리 어딘가에서 빈
블록 하나를 받아 그 **시작 주소**를 돌려줍니다. 64비트 컴퓨터에서
`TreeNode`는 24바이트입니다.

```plaintext
주소 0x2A40
┌──────────┬──────────┬──────────────┬──────────────┐
│ key = 5  │  (빈칸)  │ left  0x2A70 │ right 0x2A58 │
└──────────┴──────────┴──────────────┴──────────────┘
   4바이트    4바이트      8바이트         8바이트
```

- `key`는 `int`라 4바이트입니다.
- `left`와 `right`는 다른 블록의 **주소**를 담는 포인터라 8바이트씩입니다.
- 가운데 4바이트는 비워 둡니다. 포인터를 8의 배수 주소에 놓아야 빨리 읽을
  수 있어서, 컴파일러가 끼워 넣는 빈칸(padding)입니다.

블록이 어디에 놓일지는 `malloc`이 정합니다. 연달아 받은 블록이 붙어 있을
수도, 멀리 떨어져 있을 수도 있고, 그 사이에는 다른 데이터가 끼어 있습니다.
**주소의 순서는 트리의 모양과 아무 관계가 없습니다.** 노드를 부모와 자식으로
잇는 것은 오직 `left`·`right` 칸에 적어 둔 주소입니다.

### 넣으면 메모리에서는 \{#memory-insert}

`5 9 7 3 8 12 6`을 넣으며 메모리가 어떻게 바뀌는지 봅니다. 오른쪽 표는
메모리를 주소 순으로 늘어놓은 것이고, 맨 위의 `root`는 트리의 시작 주소를
담은 변수입니다. 노드나 표의 줄을 누르면 서로 짝이 표시됩니다. 주소는
설명을 위해 정한 값입니다. 실제 주소는 더 길고 실행할 때마다 달라집니다.

<MemoryTreeDemo />

값 하나를 넣을 때 메모리에서 일어나는 일은 셋입니다.

1. `malloc`으로 블록을 받아 `key`를 쓰고 `left`·`right`에 NULL을 씁니다.
2. `root`에 적힌 주소에서 출발해, 비교 결과에 따라 `left`나 `right` 칸에
   적힌 주소를 따라 내려갑니다.
3. NULL인 칸을 만나면 그 칸에 새 블록의 주소를 씁니다.

실습 코드의 `root->left = insert(root->left, key)`가 3을 합니다. 아래에서
돌려받은 새 블록의 주소를 부모 블록의 `left` 칸에 적는 것입니다. 이미 자식이
있던 칸이면 원래 주소를 그대로 다시 적으므로 아무것도 바뀌지 않습니다.

### 주소 따라가기 \{#memory-search}

검색도 같은 길을 갑니다. 코드의 `cur = cur->left`는 "지금 블록의 `left` 칸에
적힌 주소를 읽어, 그 주소로 간다"는 뜻입니다. 6을 찾아 봅니다.

<MemoryTreeDemo find={6} />

블록 네 개를 읽고 6을 찾았습니다. 높이가 $$h$$이면 블록을 많아야 $$h$$개
읽습니다. 앞에서 검색이 $$O(h)$$라고 한 것이 메모리에서는 이렇게 보입니다.

| 코드 | 메모리에서 하는 일 |
| --- | --- |
| `malloc(sizeof(TreeNode))` | 24바이트 빈 블록을 받고 그 주소를 돌려준다 |
| `node->key = key` | 그 주소의 `key` 칸에 값을 쓴다 |
| `cur = cur->left` | `cur` 블록의 `left` 칸에 적힌 주소를 읽어 `cur`에 넣는다 |
| `root->left = insert(root->left, key)` | 돌려받은 블록의 주소를 `left` 칸에 쓴다 |
| `free(node)` | 블록을 돌려준다. 그 주소를 적어 둔 칸은 더는 쓸 수 없다 |

후위 순회로 해제해야 하는 이유도 여기서 보입니다. 부모 블록을 먼저
`free`하면 그 안에 적혀 있던 자식의 주소를 더는 읽을 수 없습니다.

### 다른 방법: 배열에 담기 \{#memory-array}

주소를 적어 두지 않고 트리를 담는 방법도 있습니다. 배열 한 줄에 노드를
번호 순으로 놓고, **자식의 자리를 계산**합니다. 루트는 0번 칸이고, $$i$$번
칸의 왼쪽 자식은 $$2i+1$$번, 오른쪽 자식은 $$2i+2$$번, 부모는
$$\lfloor (i-1)/2 \rfloor$$번 칸입니다. 위 탭으로 넣는 순서를 바꿔 봅니다.

<MemoryTreeDemo mode="array" />

`5 9 7 3 8 12 6`은 값 7개에 칸 13개면 됩니다. 그런데 정렬된 `3 5 6 7 8`은
값 5개에 칸 31개가 필요합니다. 한쪽으로 기울면 레벨마다 칸이 두 배로 늘어,
높이 $$h$$에서 $$2^h - 1$$칸까지 갑니다. 그래서 둘은 쓰는 곳이 다릅니다.

| | 포인터 | 배열 |
| --- | --- | --- |
| 자식 찾기 | 칸에 적힌 주소를 읽는다 | $$2i+1$$, $$2i+2$$를 계산한다 |
| 노드마다 더 드는 것 | 주소 두 개 (16바이트) | 없음 |
| 기울어진 트리 | 노드 수만큼만 쓴다 | 칸이 $$2^h - 1$$개까지 늘어난다 |
| 넣고 빼기 | 주소만 바꾸면 된다 | 칸이 정해져 있어 옮기기 어렵다 |
| 어울리는 곳 | BST처럼 모양이 바뀌는 트리 | 힙처럼 늘 꽉 찬 트리 (주제 12) |

모양이 넣는 순서에 따라 바뀌는 BST는 포인터로 담습니다. 위에서부터 빈칸
없이 채워지는 트리라면 배열이 낫습니다. 주제 12의 힙이 바로 그런 트리입니다.

## 이 주제에서 남길 것 \{#takeaway}

- **이진 트리**: 루트에서 각 노드까지 경로가 하나이고, 자식은 최대 둘이다.
  노드 $$N$$개의 높이는 $$\log_2(N+1)$$부터 $$N$$까지 될 수 있다.
- **이진 탐색 트리**: 모든 노드에서 왼쪽 서브트리 전체가 작고 오른쪽
  서브트리 전체가 크다. 자식 하나와만 비교하는 규칙으로는 부족하다.
- **검색과 삽입**: 작으면 왼쪽, 크면 오른쪽. 삽입은 실패한 검색 자리에
  매다는 것이다. 비용은 $$O(h)$$다.
- **넣는 순서가 모양을 정한다.** 정렬된 순서로 넣으면 연결 리스트가 되고
  모든 연산이 $$O(n)$$으로 떨어진다. 균형 트리가 이것을 막는다.
- **삭제**: 자식 0개면 떼고, 1개면 잇고, 2개면 후속자(또는 선행자)로 바꾼 뒤
  원래 후속자를 지운다.
- **순회**: 중위는 정렬된 순서, 전위는 부모 먼저, 후위는 자식 먼저, 레벨
  순서는 큐. 출력·해제·복사는 각각 알맞은 순회 하나로 끝난다.
- **메모리 속의 트리**: 노드는 `malloc`이 준 블록이고, 블록의 위치는 모양과
  관계없다. 부모와 자식을 잇는 것은 `left`·`right` 칸에 적힌 주소다. 늘 꽉 찬
  트리는 주소 없이 배열에 담고 자식 자리를 계산한다.
