# 문서 작성 규칙

문서를 어디에 어떤 형식으로 두는지에 대한 규칙. 문장·마크다운 규칙은
[writing-rules.md](writing-rules.md)를 따른다.

## 문서의 위치

| 문서 종류 | 위치 |
| --- | --- |
| 수강생이 보는 콘텐츠 (강의·슬라이드·글·소개) | `site/src/content/` (사이트로 빌드된다) |
| 저장소 운영·개발 규칙 (이 문서 같은 것) | `docs/` |
| 학교 수업계획서 (외부 원본) | `docs/syllabus.md` (수정하지 않고 원본을 그대로 둔다) |
| 주제별 강의 문서 | `site/src/content/courses/ko/` |
| 사이트 개발 안내 (명령·콘텐츠 작성 위치) | `site/README.md` |
| AI 도구용 가이드 | 루트 `AGENTS.md` (요약과 링크만 두고, 실제 규칙은 `docs/`에 둔다) |

- 같은 내용을 두 곳에 쓰지 않는다. 상세는 한 곳에만 두고 나머지는 링크한다.
- 새 규칙 문서를 만들면 [docs/README.md](README.md) 목록에 추가한다.
- 저장소 구조가 바뀌면 루트 `README.md`의 "저장소 구조" 트리를 갱신한다.

## 다른 저장소와의 관계

이 저장소는 강의 자료만 담는다. 실습 코드는 `algorithm-code`, 시각화 자료는
`algorithm-viz`에 있다. 역할 분담은 [repositories.md](repositories.md) 참고

- 코드·실행 방법·재현 절차는 **각 저장소의 README가 단일 원본**이다.
  여기서는 요약하고 링크만 건다.
- 강의 문서에서 코드 지점을 가리킬 때는 저장소 안의 경로를 함께 적는다.
  예: `algorithm-code`의 `topic-03/01_merge_sort/mergeSort.c`

## 파일·형식 규칙

- **파일명**: 영어 kebab-case (`writing-rules.md`, `git-workflow.md`)
- **언어**: 본문은 한국어. 코드·명령·브랜치명·저장소명·식별자는 원문 그대로 쓴다.
- **구조**: 문서당 h1(`#`) 하나, 바로 아래에 문서의 목적 한두 문장, 이후
  h2(`##`) 섹션으로 나눈다.
- **링크**: 저장소 내부 문서는 상대 경로로 링크한다.
- **날짜**: "최근", "지난주" 같은 상대 표현 대신 절대 날짜(2026-08-25)를 쓴다.
