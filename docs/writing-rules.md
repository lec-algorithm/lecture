# 콘텐츠 작성 규칙

`site/` 아래 모든 콘텐츠(강의·글·슬라이드·페이지)와 저장소 문서(README 등)에
적용하는 기본 규칙. 사람이 쓰든 AI가 쓰든 동일하게 따른다.

예외: [syllabus.md](syllabus.md)는 학교 수업계획서를 그대로 옮긴 파일이라
이 규칙과 스타일 검사에서 제외한다.

## 한글 문장 스타일

- **닫는 괄호로 끝나는 문장에는 마침표를 겹치지 않는다.** `).` 형태를 만들지 않는다.
  - 좋음: `분할 정복으로 푼다 (머지 정렬, 퀵 정렬)`
  - 나쁨: `분할 정복으로 푼다 (머지 정렬, 퀵 정렬).`
- **문장 종결 마침표는 종결 형태로 판단한다.** 기준은 그 글이 어디에 있느냐가
  아니라 어떻게 끝나느냐다. 불릿이든 카드 설명이든 슬라이드 본문이든 똑같이
  적용한다.
  - 서술어(`~합니다`, `~입니다`, `~한다`, `~하세요` 등)로 끝나면 **마침표를 찍는다**.
    `머지 정렬은 항상 O(n log n)입니다.`
  - 명사·명사형(`~정렬`, `~함`, `~없음`, `~정리`, `~참고` 등 체언 종결)으로
    끝나면 **찍지 않는다**. `분할 정복 3단계` · `점근 표기법` · `배포는 deployment.md 참고`
  - 불릿이라고 마침표를 빼지 않는다. 짧아서 안 찍는 것이 아니라 명사로
    끝나서 안 찍는 것이다.
    - 나쁨: `- 같은 절차가 두 언어에서 어떤 모양이 되는지를 봅니다`
    - 좋음: `- 같은 절차가 두 언어에서 어떤 모양이 되는지를 봅니다.`
    - 좋음: `- 두 언어에서 같은 절차가 어떤 모양이 되는지` (명사형으로 바꾼 경우)
  - **예외는 셋**: 제목(`#` 헤딩), 표의 셀, 프론트매터 값. 여기서는 서술형으로
    끝나도 마침표를 찍지 않는다. 문장이 아니라 이름표이기 때문이다.
    `### 저장소는 셋입니다` · `| 클론해서 직접 돌립니다 |`
  - `check-style.py`가 검사한다. 예외 셋과 코드 블록은 검사에서 빠진다.
- **한글 문장에서 줄표(`—`)로 잇지 않는다.** 줄표(em dash, `—`)로 두 구절을
  잇거나 곁들이는 형태는 쓰지 않는다. 문장을 끊어 마침표로 맺거나, 리스트로
  나누거나, 쉼표·콜론·괄호로 바꾼다.
  - 나쁨: `퀵 정렬은 평균은 빠릅니다 — 최악에는 O(n^2)입니다`
  - 좋음: `퀵 정렬은 평균은 빠릅니다. 다만 최악에는 O(n^2)입니다`
  - 코드 블록·mermaid 블록 안의 `—`는 예외
- **길게 늘여 쓰기보다 리스트로 나눈다.** 항목·이유·조건·단계가 여럿이면 한
  문장에 줄줄이 잇지 말고, 리스트로 분리해 한 항목에 한 가지만 담는다. 문단은
  짧게 두고, 나열형 내용은 리스트를 기본으로 삼는다.
- **긴 문단은 하드 브레이크로 문장을 나눈다.** 인트로 blockquote나 여러 문장이
  이어지는 긴 문단은, 한 덩어리로 렌더링되면 읽기 어렵다. 문장(또는 의미 단위)이
  끝나는 곳에서 줄 끝에 스페이스 2개를 넣어(하드 브레이크, 방법은 아래 마크다운
  규칙 참고) 렌더링에서도 줄이 나뉘게 한다.
  - 리스트로 이미 쪼갠 내용에는 쓰지 않는다. 대상은 문장이 이어지는 산문 문단이다.

## 마크다운 규칙

- **소프트 줄바꿈(하드 브레이크)**: 같은 문단 안에서 줄을 바꾸고 싶으면
  줄 끝에 **스페이스 2개**를 붙이고 엔터. 스페이스 없이 엔터만 치면 렌더링될 때
  앞 줄에 그대로 이어진다. 빈 줄 하나는 문단 분리다.
- **표 안의 파이프는 이스케이프**: `|`는 표의 셀 구분자이므로, 셀 내용에
  파이프가 들어가면 `\|`로 쓴다. 위키링크도 마찬가지:
  - 표 안: `[[big-o\|Big-O]] 표기법`
  - 표 밖: `[[big-o|Big-O]]` 그대로 사용 가능
- **물결표(~) 주의**: 한 문단에 `~`가 두 개 있으면 그 사이가 취소선으로
  렌더링된다. 범위 표기는 `1\~100`, `3\~4개`처럼 이스케이프한다.
  코드 블록과 mermaid 블록 안에서는 이스케이프하지 않는다.
- **볼드 경계와 문장부호+한글**: 닫는 `**` 바로 앞이 닫는 괄호·따옴표 같은
  문장부호이고 바로 뒤에 한글(조사 등)이 붙으면, CommonMark 규칙상 강조로
  인식되지 않아 `**`가 화면에 그대로 노출된다.
  - 나쁨: `**분할 정복(divide and conquer)**이고` (`)**이` 지점에서 깨짐)
  - 해결 1 (권장): 볼드 뒤에 조사가 바로 붙지 않게 문장을 다듬는다.
    `**분할 정복(divide and conquer)** 방식이고`
  - 해결 2: 괄호를 볼드 밖으로 뺀다. `**분할 정복**(divide and conquer)`
  - 해결 3: 문장을 못 바꾸면 `<strong>…(divide and conquer)</strong>이고`처럼 HTML 태그를 쓴다.
- **코드 블록 두 개를 붙여 놓지 않는다.** 명령과 그 출력을 나란히 보일 때
  펜스를 연달아 두면 어디까지가 입력이고 어디부터가 결과인지 구분되지 않는다.
  각 블록 앞에 무엇인지 밝히는 라벨을 둔다.

  ````md
  - 실행

  ```sh
  docker compose exec lab python3 --version
  ```

  - 결과

  ```console
  Python 3.13.5
  ```
  ````

  - 명령과 출력이면 `- 실행` · `- 결과`를 쓴다.
  - 서로 다른 파일 두 개를 보일 때처럼 다른 관계면 파일명 등 내용에 맞는
    라벨을 쓴다. 예: `` - `compose.yml` ``
  - `check-style.py`가 빈 줄만 사이에 둔 펜스 두 개를 잡는다.
- **위키링크는 등록된 용어만**: `[[용어]]`는 `site/src/data/glossary.mjs`에
  등록된 키만 쓸 수 있다. 미등록 용어는 빌드가 실패하는데, 이는 의도된
  동작이다. 새 용어는 먼저 glossary.mjs에 추가한 뒤 본문에서 참조한다.
- **위키링크 바로 뒤에 괄호를 붙이지 않는다**: `[[big-o|Big-O]](표기법)`
  형태는 마크다운 파서가 `[텍스트](주소)` 링크로 먼저 읽어 위키링크가 깨진 채
  화면에 대괄호가 그대로 노출된다. 괄호 보충이 필요하면 문장을 다듬어
  띄운다: `[[big-o|Big-O]] 표기법(점근 상한)`. `check-style.py`가 `]](` 패턴으로
  잡는다.
- **사이트 내부 페이지 링크는 절대 경로로**: `[준비 가이드](/article/setup-guide/)`
  처럼 base 없이 `/`로 시작하는 경로를 쓴다. GitHub Pages의 base
  접두(`/lecture`)는 `site/astro.config.mjs`의 remarkBaseLinks가 빌드 때
  자동으로 붙인다. `../..` 상대 경로나 base를 직접 쓴 링크는 만들지 않는다.
  위키링크는 용어집 전용이므로 페이지 링크에 쓰지 않는다.
- **MDX에서는 꺾쇠 자동 링크 금지**: `.mdx` 파일에서 `<https://…>` 형태는
  JSX 태그로 해석되어 빌드가 실패한다. `[텍스트](URL)` 링크나
  `` `http://localhost:4321` `` 코드 스팬을 쓴다. 일반 `.md` 문서(docs/,
  README)에서는 꺾쇠 자동 링크를 써도 된다.

## 수식 (LaTeX)

테마 1.25.0부터 KaTeX가 붙었다. 수식은 **달러 두 개** 사이에 쓴다.

- `$$…$$`가 문장 안에 있으면 인라인, `$$` 펜스가 한 줄에 홀로 서면 가운데
  정렬된 디스플레이 블록이다.

  ````md
  재귀는 $$O(2^n)$$, 반복은 $$O(n)$$ 이다.

  $$
  F(n) = \begin{cases}
  0 & n = 0 \\
  1 & n = 1 \\
  F(n-1) + F(n-2) & n > 1
  \end{cases}
  $$
  ````

- **달러 하나(`$…$`)는 수식이 아니다.** 테마 기본값이 그렇고 이 사이트는
  켜지 않았다. 본문에 값이나 가격이 나와도 안전하다.
- KaTeX는 **빌드 시점에** 돈다. 페이지에는 HTML과 MathML만 실리고 수식
  런타임은 실리지 않는다.
- **KaTeX가 못 읽는 수식은 빌드를 세운다.** 미등록 위키링크와 같은 취급이고,
  파일과 `줄:칸`과 KaTeX의 진단 메시지를 함께 찍는다. 빨간 오류 글씨가
  페이지에 박힌 채 배포되는 일은 없다.
- **수식 안의 중괄호는 `.mdx`에서도 이스케이프하지 않는다.** 본문에서 `{`는
  JSX를 여는 문자라 `\{`로 써야 하지만, 수식은 파서에게 원시 구간이라
  `$$\frac{a}{b}$$`를 LaTeX 그대로 쓴다.
- 슬라이드에서도 똑같이 동작한다. 디스플레이 블록은 다이어그램이나 이미지처럼
  `aas-split`의 한쪽에 놓을 수 있다.

**복잡도 표기는 전부 수식으로 쓴다.** `$$O(n)$$`, `$$O(\log n)$$`,
`$$O(2^n)$$`, `$$O(n \log n)$$`. 산문 한가운데든 표 칸이든 슬라이드든
가리지 않는다. 이 과목에서 [[big-o\|Big-O]]는 계속 나오는 표기이므로 한 가지
모양으로 고정하는 편이 낫고, 평문으로 쓰면 `O(n^2)`의 위첨자와 `O(log n)`의
아래첨자를 표현할 수 없다. 볼드로 강조하려면 `**시간** $$O(n)$$`처럼 **한글 쪽에만 건다**. 수식을
`**`로 감싸면 닫는 `**` 앞이 `$`라 경계가 깨질 수 있다.

**나머지 수식은 기호가 밀집한 곳에만 쓴다.** 점화식 정의, 분수, 로그처럼
평문으로 쓰면 읽기 어려운 것이 대상이다. 자리를 맞춘 셈(세로셈 같은)도
`\begin{array}`가 코드 블록보다 낫다. 문장 안의 짧은 값(`n = 100`)까지
수식으로 올리면 글꼴만 흔들리고 얻는 것이 없다.

**표 칸의 분수는 `\dfrac`을 쓴다.** 슬라이드 표는 본문보다 글자가 작고, 거기에
`\frac`의 분자·분모는 한 단계 더 작아진다. `\dfrac{n+1}{2}`로 쓰면 분자·분모가
본문 크기를 지킨다.

## 인터랙티브 컴포넌트

교안에서 쓰는 데모는 `site/src/components/`에 두고 MDX에서 import한다.

```mdx
import SearchDemo from '@components/SearchDemo.astro';

<SearchDemo values={[6, 13, 14]} target={13} />
```

- **스크립트가 만드는 DOM에는 Astro의 scoped 스타일이 붙지 않는다.** 셀을
  JS로 생성하면 `<style>`의 규칙이 그 요소에 적용되지 않는다. `<style is:global>`로
  두고 선택자를 컴포넌트 루트 클래스 아래로 한정한다.
- 색은 새로 만들지 말고 테마의 `--aas-role-*` 팔레트를 쓴다. 라이트·다크
  공통 고정값이라 두 테마에서 모두 읽힌다.
- **데모가 내는 숫자는 실습 코드의 실행 결과와 같아야 한다.** 교안의 표,
  데모, `algorithm-code`의 출력이 서로 어긋나면 안 된다. 셋을 함께 확인한다.
- 한 페이지에 같은 컴포넌트를 여러 번 놓을 수 있어야 한다. 스크립트는 자기
  루트 요소 안에서만 동작하게 쓴다.
- **컴포넌트의 `data-*` 표식에는 접두를 붙인다.** `data-total`처럼 짧은 이름은
  테마의 덱 크롬(페이저·진행 막대·목차)도 쓴다. 슬라이드 안에서 같은 이름을
  쓰면 크롬이 그것을 자기 것으로 알고 내용을 덮어쓴다. 실제로 재귀 데모가
  `data-total` 때문에 통째로 슬라이드 수로 바뀐 적이 있다. 테마 1.25.3이 크롬
  조회에서 슬라이드 안쪽을 건너뛰게 고쳤지만, 컴포넌트 쪽에서도 `data-rd-*`처럼
  접두를 붙여 두는 편이 안전하다.
- **표만으로 설명하기 어려운 절차는 그림을 함께 둔다.** 이진 검색의 lo·hi·mid
  표는 숫자만 남고 "절반을 버린다"가 눈에 보이지 않는다. 정지 그림이면 스크립트
  없이 서버에서 다 그릴 수 있고, 그러면 `SearchTrace.astro`처럼 Astro의 scoped
  스타일이 그대로 먹는다. 그림의 단계는 손으로 적지 말고 컴포넌트 안에서 그
  알고리즘을 실제로 돌려 만든다. 손으로 적은 표는 코드와 어긋날 수 있다.
- **교안과 슬라이드가 같은 컴포넌트를 쓴다.** 슬라이드도 MDX라 import 방식이
  같다. 슬라이드용 조정이 필요하면 `slide` 같은 prop을 두고, 파일을 따로
  만들지 않는다.
- **슬라이드 변형은 줄이는 게 아니라 키우는 쪽이다.** 슬라이드는 강의실 뒤에서
  읽어야 하고 한 장에 하나만 담기므로, 교안보다 크게 잡는 것이 맞다. 안쪽
  치수를 전부 컴포넌트 루트에 대한 `em`으로 쓰고 루트의 `font-size` 하나만
  바꾸면, 칸·글자·버튼·간격이 비율을 지킨 채 함께 커진다. 값을 하나씩
  덮어쓰면 비율이 어긋난다.
- **문구는 로케일별로 받는다.** 컴포넌트 안에 문자열 표를 두고
  `Astro.currentLocale`로 고른다. 스크립트가 찍는 문장도 포함해야 하므로,
  표를 `data-strings`로 넘겨 스크립트가 읽게 한다. 하드코딩하면 영어·중국어
  페이지에 한국어가 남는다.

## 이 과정 고유의 표기

- **주제 번호**는 두 자리로 통일한다: `주제 01`, `주제 14`. 슬러그도
  `topic-01-intro-search`처럼 두 자리를 쓴다.
- **주차 표기**는 `1주차`\~`16주차`로 쓴다. 주제와 주차는 다른 축이므로
  섞어 쓰지 않는다. 대응표는 [course-plan.md](course-plan.md)에 있다.
- **저장소 이름**은 원문 그대로 코드 스팬에 넣는다: `` `algorithm-code` ``,
  `` `algorithm-viz` ``. 한글로 옮기거나 대소문자를 바꾸지 않는다.
- **복잡도 표기**는 언제나 수식으로 쓴다: `$$O(n \log n)$$`, `$$O(n^2)$$`.
  상세는 [수식 (LaTeX)](#수식-latex) 참고
- **알고리즘 이름**은 한글을 앞에, 영어를 괄호에 넣는다: `머지 정렬(merge sort)`.
  같은 문서 안에서는 처음 한 번만 병기하고 이후에는 한글로 쓴다.
- **코드 경로**는 저장소 루트 기준으로 쓴다: `` `topic-02/01_selection_sort/selectionSort.c` ``

## 다국어

이 사이트는 **한국어(기본) · 영어 · 중국어 간체** 세 로케일을 낸다. 콘텐츠는
로케일별 폴더에 같은 파일명으로 둔다. `courses/ko/topic-01-intro-search.mdx`가
있으면 `courses/en/…`, `courses/zh/…`도 같은 슬러그로 만든다.

- **로케일 코드는 두 글자다.** 중국어는 `zh-CN`이 아니라 `zh`를 쓴다. 테마가
  콘텐츠 id에서 로케일을 잘라낼 때 두 글자를 가정하기 때문이다. 표시 이름과
  날짜 형식만 `site.ts`에서 `简体中文` · `zh-CN`으로 준다.
- **한국어가 원본이다.** 내용을 고칠 때는 한국어를 먼저 고치고 나머지 둘을
  맞춘다. 세 파일이 어긋나면 한국어를 기준으로 삼는다.
- **이미지는 `src/assets/`에 두고 세 로케일이 공유한다.** 덱 폴더에 co-locate
  하면 로케일마다 사본이 생긴다.
- **중국어 문자열은 `site.ts`가 공급한다.** 테마는 en·ko만 내장하므로,
  채우지 않은 것은 한국어로 떨어진다. 채워야 할 자리는 넷이다.
    - `name`: 로케일별 사이트 이름
    - `ui.zh`: UI 문자열
    - `pricingLabels.zh`: 도구 카탈로그의 가격 칩
    - `difficultyLabels.zh`: 강의 난이도(별) 라벨
- **빌드 후 한국어가 새는지 확인한다.** 본문뿐 아니라 `title`·`alt`·
  `aria-label` 같은 속성에도 들어간다.

```sh
cd site && pnpm build && cd ..
python3 scripts/check-locale-leaks.py site/dist/zh
python3 scripts/check-locale-leaks.py site/dist/en
```

  grep으로 훑지 않는다. grep은 줄 단위라 텍스트 노드가 줄바꿈으로 끊기면
  놓친다. 실제로 그렇게 네 개를 놓쳤다.

## 슬라이드 규칙

- **줄바꿈 위치를 눈으로 확인한다.** 테마가 한글을 어절 단위로만 줄바꿈하도록
  처리하므로(word-break: keep-all) 글자 단위로 깨지지는 않지만, 마지막 어절
  하나만 다음 줄로 넘어가는 등 어색한 자리에서 꺾일 수 있다. 덱을 작성·수정한
  뒤에는 반드시 브라우저에서 슬라이드를 넘겨보며 제목·부제·리스트의 줄바꿈을
  확인한다.
- **어색하면 끊는 위치를 직접 정한다.** 하드 브레이크(스페이스 2개 + 엔터)로
  의도한 자리에서 줄을 나누거나, 문구 자체를 짧게 다듬는다.
- **넓은 표는 슬라이드에만 둔다.** 슬라이드 본문은 화면 폭을 거의 다 쓰지만
  교안(`prose`)의 열은 920px에 고정이라, 열다섯 칸짜리 배열 표는 교안에서
  언제나 넘쳐 가로 스크롤 상자가 된다. 같은 내용을 교안에서는 `plaintext`
  블록으로 두는 편이 낫다. 등폭 글꼴이라 자리가 그대로 맞는다.
- **본문 문단은 문장마다 줄을 나눈다.** 줄 끝에 **스페이스 두 개**를 붙이고
  엔터를 치면 하드 브레이크가 되어, 화면 폭이 어떻든 그 자리에서 줄이 바뀐다.
  그대로 두면 슬라이드가 알아서 감싸는데, 그 자리는 문장 중간의 아무 곳이라
  마지막 줄에 두세 단어만 남는 모양이 자주 나온다. 문장이 하나뿐이면 그냥 둔다.
- **굵은 머리말이 붙은 항목은 설명을 하위 항목으로 내린다.** 슬라이드의 불릿
  하나가 두 줄로 넘어가면 굵은 머리말과 설명이 한 덩어리로 뭉쳐 어디까지가
  제목인지 보이지 않는다. 머리말만 항목으로 두고 설명은 한 문장씩 하위
  불릿으로 내린다.

  ```md
  - **의사코드가 기준입니다.**
    - 예제마다 `.pseudo` 하나에 C와 Python이 붙습니다.
    - 언어가 아니라 **같은 절차가 두 언어에서 어떤 모양이 되는지**를 봅니다.
  ```

  번호 목록도 같다. 한 번호에 문장 두세 개를 이어 붙이지 않는다. 강의실에서
  읽는 사람은 줄을 눈으로 좇는 것이 아니라 덩어리를 본다.
- **코드 블록이 있는 슬라이드는 `<Slide class="compact">`로 연다.** 기본값은
  코드 블록을 슬라이드 높이만큼 늘리도록 되어 있어(다이어그램 슬라이드를 위한
  동작), 세 줄짜리 코드가 500px짜리 빈 검은 상자가 된다. `compact`를 주면
  내용 높이만 차지한다. 명령과 실행 결과를 두 블록으로 나란히 둘 때는 특히
  필수다.
- **한 슬라이드에 한 가지만 담는다.** 예전 Keynote 덱은 한 단계를 한 장씩
  넘기며 보여 주는 방식이라 장수가 많다. 웹 덱으로 옮길 때는 단계별 애니메이션을
  한 장에 표·다이어그램으로 접고, 실제로 움직여야 하는 것은 `algorithm-viz`의
  결과물을 임베드한다.
- 화면 크기에 따라 줄바꿈이 달라지므로, 창 폭을 좁혀가며 한 번 더 확인하면
  좋다.
