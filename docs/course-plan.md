원본에 무엇이 들어 있는지는 [source-materials.md](source-materials.md),
수업계획서 원문은 [syllabus.md](syllabus.md) 참고

## 두 개의 축

이 과정에는 축이 두 개 있고, 서로 1:1이 아니다.

- **주제**: 자료의 단위. 사이트의 강의 문서 한 편, 슬라이드 덱 한 개, 실습
  코드 폴더 하나가 주제 하나에 대응한다. 총 14개 + 보너스 1개
- **주차**: 진도의 단위. 수업계획서의 1주차\~16주차. 시험 2주를 빼면 실제
  진도는 14주다.

한 주제가 두 주에 걸치기도 하고, 한 주에 두 주제가 걸리기도 한다. 자료를
주제로 묶는 이유는 알고리즘 하나가 요일 경계에서 끊기지 않게 하기 위해서다.

## 콘텐츠 파일 구조

주제 하나가 파일 셋으로 나뉜다.

```plaintext
site/src/content/
├── courses/ko/topic-01-intro-search.mdx      # 교안 (읽는 자료)
├── slides/ko/topic-01-intro-search/index.mdx # 슬라이드 덱 (수업용)
└── articles/ko/…                             # 공지·안내 글
```

이미지를 함께 두는 주제는 `topic-01-intro-search/index.mdx` 형태의 폴더로
만든다. 슬러그는 그대로 유지된다.

### 프론트매터 규약

교안(`courses`)의 `order`는 **문자열 내림차순**으로 정렬된다. 주제 번호가
작을수록 위에 오게 하려면 값이 커야 한다. 규칙을 하나로 고정한다.

    order = 9100 - 주제번호   (예: 주제 01 → "9099", 주제 14 → "9086")

슬라이드(`slides`)의 `order`는 반대로 **숫자 오름차순**이다. 주제 번호를 그대로
쓴다. 주제 01은 `1`이다.

```yaml
# courses/ko/topic-01-intro-search.mdx
title: "주제 01. 소개와 탐색"
description: "알고리즘이란 무엇인가, 순차 검색과 이진 검색, 재귀와 반복"
category: foundations           # src/data/course-categories.ts의 id
order: "9099"
level: 1                        # 난이도 1\~5, 별로 표시된다
hours: "3:00"
slides: ["topic-01-intro-search"]
```

### 주제별 버전 관리

슬라이드의 `date` 필드는 날짜가 아니라 **주제 라벨과 버전**을 담는다.
덱 왼쪽 아래 푸터에 그대로 찍힌다. `presenter`는 쓰지 않는다.

    date: "주제 01 · v1"    (en: "Topic 01 · v1", zh: "主题 01 · v1")

강의 자료의 마지막 섹션은 `## 자료 이력 \{#changelog}` 표다. 열은
버전·날짜·내용 셋이고, 날짜는 그 버전이 `main`에 공개된 날이다.
슬라이드와 자료는 함께 버전을 올린다. 공개 후 내용이 의미 있게
바뀌면(오류 수정, 절 추가·삭제) 버전을 하나 올리고 세 로케일 모두에서
`date`와 이력 표에 한 줄을 더한다. 오타·줄바꿈 같은 표면 수정은 버전을
올리지 않는다.

   슬라이드 밀도, 코드 발췌 방식, 시각화 임베드 방식을 확정한다.

6. **보너스 주제 15**: 여유가 생기면
